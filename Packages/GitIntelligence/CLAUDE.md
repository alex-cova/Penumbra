# GitIntelligence

Loaded when working under `Packages/GitIntelligence`. Moved out of the root CLAUDE.md.

- **`GitIntelligence`** (`Packages/GitIntelligence`) — its own Swift package; its only dependency is `SubprocessKit`, which `SystemGitRunner` runs `/usr/bin/git` through. `GitRepository` wraps the git CLI (status including ignored paths, stage, commit, staged and unstaged diff, log, `GitGraphLayout`). `visibleFiles(under:)` is `git ls-files -z --cached --others --exclude-standard` as paths relative to a directory (nil when it is not a work tree), which is what `grep`, `glob` and Find in Files search. Umbra wires it through `IDEGitStatus` for explorer colors and the source-control panel (local branch switch and create, push, and fast-forward pull). `fileContents(at:path:)` reads a file at a `GitRevision` (`.head`, `.index`, `.commit`, `.parent(of:)`, `.ref`; nil when that version has no such file) and `applyPatch(_:toIndex:reverse:)` runs `git apply --unidiff-zero` from stdin, for the diff viewer's file sides and hunk staging.

- **State, progress and the console** (`Repository/GitRepositoryState.swift`, `Process/GitProgress.swift`). `GitRepository.gitDirectory` is the absolute git dir `discover` reads (`.git/worktrees/<name>` for a linked tree, so operation files are found there); `state()` reads HEAD (`branch`, `detached`, `ref`) and the operation in progress (`merge`, `rebase` with step/total/onto/branch, `cherryPick`, `revert`, `applyMailbox`, `bisect`, plus `MERGE_MSG`) straight from the `.git` files, no process, so a host can call it on every refresh. A rebase wins over a leftover `CHERRY_PICK_HEAD`. `GitRunning.run(…, onProgress:)` forwards stderr as `GitProgress` (phase, 0...1 fraction or nil, text) through `GitProgressParser`, which joins lines split across reads (`\r` ends a progress line, `\n` the others) and multi-byte characters. `SystemGitRunner(observer:)` reports every finished command as a `GitCommandRecord` (arguments, status, stderr, the first 4 KB of output, duration; `isReadOnly` is a `--no-optional-locks` query) to a `GitCommandObserving`; Umbra's Git console is one. Network commands use `GitRepository.network` (`GitNetworkEnvironment`: variables, and `failsInsteadOfPrompting` which adds `-o BatchMode=yes` to the user's `GIT_SSH_COMMAND`/`core.sshCommand` instead of replacing it). Tests: `GitRepositoryStateTests` (each state produced with real git, including a linked worktree), `GitParsersTests`, `SystemGitRunnerTests`.

- **Remotes, branches, tags** (`GitRepository+Remotes.swift`, `+Branches.swift`, `+Stash.swift`, `Models/GitRemoteModels.swift`, `Parsing/GitRefParsers.swift`). `branchList()` is one `for-each-ref` giving `GitBranch` (local/remote, upstream, ahead/behind from `%(upstream:track)`, `[gone]`, current, commit date). `fetch(remote:prune:)`, `pull(strategy: .fastForwardOnly|.merge|.rebase, autostash:)` (never opens an editor: `GIT_EDITOR=true`, `--no-edit`) and `push(GitPushOptions)` (remote, source, target branch, set-upstream, `--force-with-lease`, tags none/following/all; a remote or branch starting with `-` is refused before git runs) run with `network` and report progress to the `onProgress` handler or the one set by `withProgress(_:)`; `withNetwork(_:)` swaps the environment (Umbra's askpass). Branch commands: `renameBranch`, `deleteBranch(force:)`, `deleteRemoteBranch`, `checkoutRemoteBranch` (tracking, local name defaults to the part after the remote), `createBranch(_:startPoint:checkout:)`, `checkout(revision:)` (detached), `forceSwitchBranch` (`--discard-changes`), `mergedBranches(into:)`, `defaultBranchName()`. Tags: `tags()`, `createTag(_:at:message:)`, `deleteTag`, `pushTag`. `config(_:)` / `setConfig`. `compare(_:_:)` returns commits only in each side (`a..b`, `b..a`) and `diff --name-status` between the two tips. **Smart operations**: `preservingLocalChanges { … }` stashes (`--include-untracked`), runs the operation, pops; the operation failing restores the changes before rethrowing; a pop that conflicts returns `.restoredWithConflicts` (git keeps the stash) and one that cannot start `.keptInStash`. `GitSwitchConflictParser` reads the file list out of git's "would be overwritten" refusal. Tests: `GitRemoteIntegrationTests` (local bare remote), `GitParsersTests`.

- **Stash** (`GitRepository+Stash.swift`). `stashes()` is `stash list` as `GitStash` (hash, index, date, subject; `title`, `branch`, `ref`). Operations take a `GitStash` and resolve its *current* `stash@{n}` by hash first, so a stash added or dropped since the list was read cannot make Drop hit the wrong entry (a vanished one throws). `stashPush(message:includeUntracked:keepIndex:paths:)` reports whether a stash was created; `stashApply/Pop(reinstateIndex:)`, `stashDrop`, `stashClear`, `stashBranch`. `stashChanges(_:)` is the diff against `hash^1` plus the untracked files of `hash^3` (`GitStashChange.isUntracked`; read them with `.ref(hash + "^3")`). Tests: `GitStashIntegrationTests`.
- **Merge, rebase, conflicts** (`GitRepository+Operations.swift`). `merge`, `rebase(onto:)`, `continueOperation(_:message:)`, `skipOperation`, `abortOperation` return `GitIntegrationResult` (`.completed` / `.stopped`): a command that fails while an operation is in progress (`state().operation != nil`) is a stop, not an error, so the host shows its banner. No editor ever opens (`GIT_EDITOR=true`, `--no-edit`). `GitError.errorDescription` falls back to stdout, where `merge` and `rebase` print `CONFLICT`. `conflictedFiles()`, `conflictStages(of:)` (a missing side deleted the file), `resolve(paths:taking: .ours|.theirs)` (`checkout --ours/--theirs` then `add`, or `rm` when that side deleted it), `resolve(path:with:)` (write and stage), `markResolved`. `GitRevision.stage(1|2|3)` reads a side from the index: 2 is the branch merged into (or the commit rebased onto), 3 the branch merged (or the commit replayed). Tests: `GitOperationsIntegrationTests`.

- **History actions and interactive rebase** (`GitRepository+History.swift`, `Rebase/GitRebasePlan.swift`). `cherryPick(_:)` (oldest first), `revertCommits(_:)` (newest first), `reset(to:mode: .soft|.mixed|.hard|.keep)`, `undoLastCommit()`, `amendMessage(_:)` (`commit --amend --only`: staged changes stay out), `branchesContaining`, `remoteBranchesContaining` (remote-tracking refs that hold a commit: rewriting it needs a force push), `lineHistory(path:start:end:)` (`log -L`, parsed into commit + patch) and `log(paths:since:until:)`. A merge commit is refused by cherry-pick and revert. **Interactive rebase without an editor**: `rebasePlan(startingAt:)` returns `base` (the oldest commit's parent; the root has none) and the plain picks of `base..HEAD` oldest first, refusing a range with merges; `GitRebasePlan` (steps with `.pick/.reword/.edit/.squash/.fixup/.drop`, an optional final `message` on the commit a group ends up in) validates (first kept step cannot be squash/fixup, no empty reword) and renders the todo text; `interactiveRebase(onto:plan:)` re-checks that `base..HEAD` still equals the plan's commits, writes the todo and message files under `<git dir>/umbra-rebase/`, and runs `rebase --interactive --autostash` with `GIT_SEQUENCE_EDITOR='cp <todo>'` and `GIT_EDITOR=true`. A message becomes an `exec git commit --amend --no-verify -F <file>` line after its commit or, for a squash group, after the group's last step. Builders: `rewording`, `dropping`, `squashing` (selected commits move under the oldest one), `fixingUp(_:into:)`. `integrate` reports a stop from the repository state, because a rebase that reaches an `edit` step exits 0. Tests: `GitHistoryIntegrationTests`, `GitRebasePlanTests`.

- **Commit options, checks, clone, ignore files** (`GitRepository.commit(...signoff:skipHooks:)`, `GitRepository+Checks.swift`, `GitRepository+Clone.swift`). `commit` takes `signoff` and `skipHooks` and runs with the network environment so an SSH signing passphrase can be asked through the host's helper. `stagedCheckProblems()` is `diff --cached --check` parsed (`isConflictMarker`), `indexLineEndings(of:)` is `ls-files --eol` (the index side: `lf`, `crlf`, `mixed`, `-text`), `normalizeLineEndings(of:)` sets `core.autocrlf=input` and `add --renormalize`. `GitRepository.clone(url:into:recurseSubmodules:network:onProgress:)` (a static: there is no repository yet; refuses an option-looking address and a non-empty destination), `checkRemote(url:)` (`ls-remote`), `initialize(at:initialBranch:)`, `repositoryName(fromURL:)`. `GitIgnoreWriter.pattern(forRelativePath:isDirectory:)` escapes git's special characters (`\ * ? [ ]`, a leading `#`/`!`, trailing spaces), anchors with `/` and marks a folder with a trailing `/`; `appending(_:to:)` returns nil for a line already there. Tests: `GitCommitChecksIntegrationTests` (in `GitHistoryIntegrationTests.swift`), `GitCloneIntegrationTests`.
