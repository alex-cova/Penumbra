# AgentKit

Loaded when working under `Packages/AgentKit`. Plan, decisions and build order: `docs/AGENT_HARNESS_PLAN.md`.

- **What it is** — a coding-agent harness core in pure Swift: Foundation only, no third-party SDK, no `Penumbra` dependency. Only Umbra and test/eval targets depend on it. It makes network calls only when the host starts a run. Shell execution and anything touching the IDE live in `Example/Umbra`, never here.
- **Providers** — `OpenAIResponsesClient`, `OpenAIChatCompletionsClient` (`ChatCompletionsCapabilities` says what an endpoint accepts: strict tools, usage in the stream, `max_tokens` vs `max_completion_tokens`, reasoning effort, cache key) and `OllamaClient` (native `/api/chat`, not `/v1`: only it takes `options.num_ctx`; `think` is sent only to models that list the capability). All three are a request encoder plus a `StreamDecoder` on the shared `HTTPStreamClient`, which owns retries, SSE/NDJSON framing and error mapping; a new provider should be the same two pieces. A connection refused is `LLMError.unreachable` and not retried. `OllamaModelCatalog` reads capabilities and the model's own context limit from `/api/show` (`/api/tags` lists only `completion`). Decoder tests use responses captured from a real Ollama, kept verbatim in `Tests/AgentKitTests/Fixtures`; re-capture them if a server's format changes.
- **`LLMClient`** — `stream(_ request:) -> AsyncThrowingStream<LLMEvent, Error>`; the loop never sees which API sits behind it. `OpenAIResponsesClient` is stateless (`store: false`, full input every turn); `ResponsesRequestEncoder` and `ResponsesEventDecoder` are pure so fixtures test them without a network. Clients take an `LLMTransport` (`StubTransport` in the tests).
- **Retries** — `RetryPolicy` retries 429, 5xx and dropped connections. A retry resends the whole turn and emits `.retrying`; consumers must drop the partial turn they received. A stream that ends without `.finished` is a connection loss.
- **Byte-stable requests** — tool order is the caller's, JSON is encoded with `.sortedKeys`. Dictionary order changes between launches and would break the provider's prompt cache. `bodyIsByteIdenticalAcrossEncodings` guards this.
- **SSE** — each `data:` line is one event; don't depend on blank-line boundaries (`AsyncLineSequence` drops them).
- **Opaque items** — provider items such as Responses reasoning with `encrypted_content` are stored whole and replayed only to the client whose `providerID` produced them.
- **Tests** — `swift test` in this directory. Fixtures are hand-written from the API docs. Opt-in real-API smoke test: `AGENTKIT_OPENAI_KEY=sk-... swift test --filter OpenAISmokeTests`.
- **Loop** — `AgentSession` (actor): `send(_:)` returns an `AsyncStream<AgentEvent>` that ends with exactly one `.runEnded(RunEnding)`; `stop()` cancels, and dropping the stream stops the run. Invariants, each with a test: every tool call has exactly one output (unknown tool, bad arguments, timeout, cancel, length cut-off, repeat guard included), and a failed or stopped turn leaves nothing half-written. Consecutive read-only calls run concurrently, edits and commands one at a time in order, outputs in call order. The same call a third time gets a warning instead of a run, a fourth stops the run. Tools must honor cancellation: Stop and the per-tool timeout depend on it.
- **Workspace seam** — `AgentWorkspace` is what the generic tools see (text, listing, file walk, search). `DiskAgentWorkspace` is the disk implementation; Umbra passes `unsavedBuffers` so reads and `grep` see open edits instead of the stale file. `PathJail` is checked first by every file operation (symlinks resolved, sibling-prefix safe, new files checked through the nearest existing ancestor).
- **Editing** — `edit_file` (exact, unique `old_string`; CRLF files keep their line endings) and `write_file` (new file, or whole rewrite) both refuse a file the model has not read or that changed since (`ReadLedger`), and record in `CheckpointLog` before the first change in a run. Writes go through the workspace (`replaceText(expecting:)` re-checks the text it was based on). `WriteProtection` keeps the agent out of `.git`, `.gradle` and build output; `SecretFilePolicy` keeps credential files unread. `AgentSession.revertRun` restores a finished run: a file whose text still matches the agent's last write goes back (created files to the Trash), any other file is reported as a conflict and never overwritten; reverting twice, or retrying after a partial revert, is safe.
- **Approvals** — a tool with `risk == .command` may return an `ApprovalRequest` (command, working directory, reason, warnings, notes, editable argument). `AgentSession` emits `.approvalRequested`, sets the state to `.awaitingApproval`, and waits for `resolveApproval(callID:decision:)`: approve, approve with the user's edited command (the model is told it was edited), or deny with an optional note (returned to the model as an error output). Stop answers a pending question with a denial; a late or repeated answer is ignored. Only `resolveApproval` can approve: nothing a tool returns can. `ApprovalPolicy.approveAll` is for tests and the eval harness. `CommandWarnings` flags `sudo`, `rm -rf` on broad paths, force-pushes and the like, as a warning on the card, never a block. `ToolContext.progress` streams a tool's live output to the transcript as `.toolCallOutput`; the model still gets only the final output. AgentKit itself never spawns a process: commands live in the host app.
- **`apply_patch`** — `PatchParser` (strict structure; `@@` numbers and counts are hints) and `PatchPlanner`/`HunkMatcher` (exact content decides where a hunk goes; ambiguous or missing context names the hunk and the first line that differs). Every file is validated and computed before any is written; a write failure partway puts the written files back. Creation (`--- /dev/null`) works; deletion and renames do not.
- **On-device models** — `AgentKit` never links MLX. `Packages/AgentKitMLX` (see its `CLAUDE.md`) adds an `LLMClient` that runs a downloaded model in-process.
- **Smoke tests** — `OllamaSmokeTests` is opt-in: `AGENTKIT_OLLAMA_MODEL=<model with tools> swift test --filter OllamaSmokeTests`.
- **Tools** — conform to `AgentTool` (`definition`, `risk`, `run`); `execute(argumentsJSON:context:)` turns every thrown error into an output the model can act on. Output is capped and says how to continue (`offset=`). `ReadLedger` records a hash of what `read_file` showed, for `edit_file`.
- **Compaction** — `ContextCompaction` runs at the top of every loop iteration when `AgentConfiguration.contextWindow` is set. The estimate is `max(whole transcript bytes / 4, last reported input tokens + bytes appended since)`. Stage 1 replaces old tool outputs with one-line stubs (oldest first, in one batch so the request prefix stays cacheable, newest 4 kept); stage 2 asks the model once to summarize the oldest part, cutting only on turn boundaries so a tool call never loses its output. `.compacted(CompactionReport)` is emitted when anything changed. A provider `contextLengthExceeded` forces a pass (the window is treated as full) and retries once. A failed summary keeps the stubs and backs off for 6 items. Tests: `CompactionTests`, `SessionCompactionTests`; the real-model one is `OllamaSmokeTests.aLongSessionCompactsAndKeepsAnswering`.
- **Modes** — `AutonomyMode`: `autoApplyEdits` (default), `approveEachEdit` (an `.edit` tool with an `editPreview` asks first, with `ApprovalRequest.diff` from `UnifiedDiff`; a call that cannot be previewed is not asked about, it fails on its own), `planOnly` (only `.read` tools are offered, and a call to another known tool is answered "not available: this session is in plan mode"). Commands always ask. `SystemPrompt.make(projectRoot:notes:mode:)` adds the mode text and the project's instructions.
- **Persistence** — `SessionStore` writes `<dir>/<hash of project root>/<uuid>.json` atomically (file 0600, folder 0700): items, usage, and an opaque `host` blob for the app's own transcript. Never a credential. `SessionStore.title(from:)` skips the editor-state block.
- **Protected files** — `ReadOnlyTools.all(secretPatterns:)` adds user globs to `SecretFilePolicy` for `read_file` and `grep`; a pattern that does not parse is skipped.
- **Tool names in the prompt** — `SystemPrompt` tells the model to prefer `go_to_definition`/`find_usages` and `git_status`/`git_diff` "when available". Those tools live in Umbra; a session without them answers a call with the unknown-tool error, which lists what is offered.
- **`todo` and `ask_user`** (`Tools/InteractionTools.swift`) — `todo` takes the whole checklist as strings (`[ ] `, `[~] `, `[x] `) and replaces the list; `TodoList` (an actor on the session, `todoList`) emits `.todosUpdated` once per change and is rebuilt from the history by `TodoList.latest(in:)` (a host can also `setTodos`). `ask_user` calls `ToolContext.ask`, which the session turns into `.questionAsked` + `.awaitingAnswer` and waits for `answerQuestion(callID:answer:)` (`nil` = dismissed; Stop and cancellation also answer `nil`). `AgentTool.waitsForUser` makes a tool run alone and skips the tool timeout; `isExemptFromRepeatGuard` lets `todo` repeat unchanged (it then says "Checklist unchanged"). Both are read-risk, so plan mode keeps them.
- **Found by the eval CLI** (`Tools/AgentEval`), each with a test: (1) the repeat guard counts identical calls only until a file edit succeeds (`counts.removeAll()` after a successful `.edit` call), because edit, run the tests, edit, run the tests is the normal loop; three identical calls with nothing changed in between still warn and the fourth stops the run. (2) A call a local model wrote but nobody could read (`LLMEvent.unreadableToolCall`, today only from `MLXLLMClient`) no longer ends the run: the loop appends a user note (`unreadableCallNote`, says how to write newlines and quotes in JSON) and asks again, at most `maxUnreadableCalls` (3) per run, then fails with the reason. The note is an ordinary `.user` item marked "[Note from the editor, not from the user]". (3) `edit_file`'s "not found" error shows the file's real lines when the text matches ignoring leading or repeated whitespace, and says so when `new_string` is already in the file (`EditSupport.notFoundMessage`).
