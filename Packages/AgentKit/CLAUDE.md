# AgentKit

Loaded when working under `Packages/AgentKit`. Plan, decisions and build order: `docs/AGENT_HARNESS_PLAN.md`.

- **What it is** — a coding-agent harness core in pure Swift: Foundation only, no third-party SDK, no `Penumbra` dependency. Only Umbra and test/eval targets depend on it. It makes network calls only when the host starts a run. Shell execution and anything touching the IDE live in `Umbra/Sources/Umbra`, never here.
- **Providers** — `OpenAIResponsesClient`, `OpenAIChatCompletionsClient` (`ChatCompletionsCapabilities` says what an endpoint accepts: strict tools, usage in the stream, `max_tokens` vs `max_completion_tokens`, reasoning effort, cache key) and `OllamaClient` (native `/api/chat`, not `/v1`: only it takes `options.num_ctx`; `think` is sent only to models that list the capability). Meta's Muse models need no new client: the Meta Model API (`LLMEndpoint.meta`, `https://api.meta.ai/v1`) speaks the Responses format with a Bearer [REDACTED], so `OpenAIResponsesClient` drives it (Umbra's `.meta` provider; opt-in check: `MetaSmokeTests`). `HostedModelCatalog` (`GET {baseURL}/models`, Bearer key) lists what such an endpoint offers today, so hosts need not ship model ids. `AnthropicMessagesClient` (`Anthropic/`, `/v1/messages`; the key goes in `x-api-key` with `anthropic-version`, never a bearer header; `max_tokens` is always sent; models that take `thinking: {type: "adaptive"}` get it with `display: "summarized"` and `output_config.effort`, older ones a `budget_tokens`; tools carry `eager_input_streaming`; a `cacheKey` becomes top-level `cache_control`; `usage.inputTokens` adds the cache read and creation counts to Anthropic's, which leaves them out). A thinking block is kept as an `OpaqueItem` (provider `anthropic`, the whole block with its signature) and replayed first in its assistant message; one without a signature is dropped, and `redacted_thinking` is kept and never shown. All four are a request encoder plus a `StreamDecoder` on the shared `HTTPStreamClient`, which owns retries, SSE/NDJSON framing and error mapping; a new provider should be the same two pieces. A connection refused is `LLMError.unreachable` and not retried. `OllamaModelCatalog` reads capabilities and the model's own context limit from `/api/show` (`/api/tags` lists only `completion`). It also `pull`s (`/api/pull` NDJSON, layer totals added up in `OllamaPullProgress`; ends only at `success`, an `error` line throws) and `delete`s a model. Decoder tests use responses captured from a real Ollama, kept verbatim in `Tests/AgentKitTests/Fixtures`; re-capture them if a server's format changes.
- **`LLMClient`** — `stream(_ request:) -> AsyncThrowingStream<LLMEvent, Error>`; the loop never sees which API sits behind it. `OpenAIResponsesClient` is stateless (`store: false`, full input every turn); `ResponsesRequestEncoder` and `ResponsesEventDecoder` are pure so fixtures test them without a network. Clients take an `LLMTransport` (`StubTransport` in the tests).
- **Retries** — `RetryPolicy` retries 429, 5xx and dropped connections: 8 tries, 2 s doubling to a 20 s cap, and a delay the server asked for (`Retry-After`) is honored up to `maxServerDelay` (300 s; before, it was clamped to the backoff cap, so a 60 s rate limit was retried at 30 s and failed again). A timeout (`URLError.timedOut`) is retried only for the first `maxTimeoutRetries` (3) tries. A retry resends the whole turn and emits `.retrying`, which the session turns into `.turnRestarted` (consumers must drop the partial turn they received) followed by `.retryScheduled(attempt:delay:)` so a host can show the wait; Umbra's status line reads "Retrying in N s (try K)…". It retries only while nothing has streamed: once a text delta or a tool-call event has been yielded, a dropped connection or an error event ends the stream with `LLMError.interruptedAfterOutput` instead (`HTTPStreamClient`), and the loop keeps what arrived (see *Cut-off responses*). A stream that ends without `.finished` is a connection loss. Tests: `RetryPolicyTests`.
- **Byte-stable requests** — tool order is the caller's, JSON is encoded with `.sortedKeys`. Dictionary order changes between launches and would break the provider's prompt cache. `bodyIsByteIdenticalAcrossEncodings` guards this.
- **SSE** — each `data:` line is one event; don't depend on blank-line boundaries (`AsyncLineSequence` drops them).
- **Opaque items** — provider items such as Responses reasoning with `encrypted_content` are stored whole and replayed only to the client whose `providerID` produced them.
- **Tests** — `swift test` in this directory. Fixtures are hand-written from the API docs. Opt-in real-API smoke test: `AGENTKIT_OPENAI_KEY=sk-... swift test --filter OpenAISmokeTests`.
- **Loop** — `AgentSession` (actor): `send(_:)` returns an `AsyncStream<AgentEvent>` that ends with exactly one `.runEnded(RunEnding)`; `stop()` cancels, and dropping the stream stops the run. Invariants, each with a test: every tool call has exactly one output (unknown tool, bad arguments, timeout, cancel, length cut-off, repeat guard included), and a failed or stopped turn leaves nothing half-written. Consecutive read-only calls run concurrently, edits and commands one at a time in order, outputs in call order. The same call a third time gets a warning instead of a run, a fourth stops the run. Tools should honor cancellation: Stop and the per-tool timeout stop waiting for a tool that does not, and drop its late result. Turn policies (`TurnPolicy`) are asked only at turn boundaries and never edit the history: `RunLimitPolicy` ends a run that has spent its token, time or cost budget, or its iteration cap, after one no-tools grace turn (`graceTurnAtCap`, default on). The token and cost budgets count the current run, not the session, so the next message starts with a fresh allowance. `VerifyBeforeStoppingPolicy` asks once per run (the session resets it at every run start; it used to ask once per session) before a run that edited files ends, and never in plan mode (off unless the host sets `verifyBeforeStopping`). `UnappliedEditsPolicy` (always on) tells the model once per run, before it ends, that no file changed when every edit call of the run failed (`TurnState.editCalls` / `failedEditCalls`; a run with one applied edit, or in plan mode, is left alone), so a final answer does not claim a change that was refused. The system prompt also says to report only changes a tool result confirmed. Tests: `UnappliedEditsTests`.
- **Cut-off responses and the output budget** — A `length` finish no longer ends the run on the spot. The calls that arrived whole (`Turn.isComplete`: `.toolCallFinished` seen and the arguments parse, since Anthropic closes a block cut by `max_tokens`) run; the others are answered "Not run: the output token limit was reached before the arguments were complete…" (`execute(…unrunnable:)`, not counted by the repeat guard). A cut-off with no calls gets the editor note `outputLimitNote` ("Do not apologize, recap, or repeat yourself… smaller pieces"). The run then goes on, up to `AgentConfiguration.maxLengthContinuations` cut-offs in a row (default 2, `0` is the old end-at-once; any other finish resets the count); a cut-off closing turn still ends `.lengthLimit`. `.continuing(reason:attempt:)` tells the host. A stream that drops after output (`interruptedAfterOutput`) is handled alike: `streamTurn` returns the partial `Turn` (`interruption` set, `finish` nil), whole calls run, the rest are answered, and `interruptedNote` follows the outputs; two in a row at most, then the run fails with the history ending on that note so Continue has a valid request; on the closing turn what arrived counts as the summary. `OutputBudget` fits `max_tokens` / `num_predict` to the room the window leaves (`window − measured − 1.15 × estimated`, never below 1,024, `contextTokenParts()` splitting the estimate into what the provider measured and what was added since); an unset limit stays unset while there is room. `LLMRequest.toolChoice = .disabled` (`tool_choice: none`) keeps the tool list on the closing turn where `LLMClient.supportsDisabledToolChoice` (Anthropic, Responses, Chat Completions with `ChatCompletionsCapabilities.toolChoiceNone`, on for `.openAI`); Ollama, MLX and `.compatible` endpoints still get `tools: []`. Tests: `OutputLimitTests`.
- **Saved tool output** (`Tools/ToolOutputStore.swift`) — with `AgentConfiguration.toolOutputStore`, output too large to show is kept whole and read back with `read_tool_output` (`id`, then `offset`/`limit` or a regex `pattern`; the session adds this `.read` tool itself, so plan mode keeps it). `OutputTruncation.headAndTailSaving` is `headAndTail` plus a saved copy and a marker with the id and the line the omitted part starts at. The copy is scrubbed with `ToolContext.redactOutput`, the configured shaper bound to that call's own tool name and risk (`redactForMemory`, used by `remember`, calls the shaper as tool `remember` with risk `.edit`, so a shaper keyed on risk must also match that name, as Umbra's does). `ToolOutputNet` runs in `historyOutput` after the shaper (errors bypass it) and saves what no tool bounded (over 2,500 lines or 100 KB), keeping the first lines. Ids are random (`ToolOutputID.make()`: providers reuse call ids across turns) and validated to `[A-Za-z0-9_-]`. A compaction stub keeps the pointer. AgentKit never touches the disk; the host implements `ToolOutputStore`. Tests: `ToolOutputStoreTests`.
- **Workspace seam** — `AgentWorkspace` is what the generic tools see (text, listing, file walk, search). `DiskAgentWorkspace` is the disk implementation; Umbra passes `unsavedBuffers` so reads and `grep` see open edits instead of the stale file. `visibleFiles`, when the host sets it, replaces the walk for `glob` and a directory `grep` with the paths git lists; nil (not a repository, or git could not answer) keeps the walk, and an empty set does not. The fixed `FileFilter` still drops hidden names, build folders and binaries, and unsaved buffers are included even when git hides them. A `grep` of one named file opens that file. `PathJail` is checked first by every file operation (symlinks resolved, sibling-prefix safe, new files checked through the nearest existing ancestor).
- **Editing** — `edit_file` (exact, unique `old_string`, then a unique canonical match for line endings, trailing whitespace and a few Unicode punctuation characters; a shared indentation shift only when `EditTolerance.local` is set; CRLF files keep their line endings) and `write_file` (new file, or whole rewrite) both refuse a file the model has not read or that changed since (`ReadLedger`), and record in `CheckpointLog` before the first change in a run. Writes go through the workspace (`replaceText(expecting:)` re-checks the text it was based on). `WriteProtection` keeps the agent out of `.git`, `.gradle` and build output; `SecretFilePolicy` keeps credential files unread. `AgentSession.revertRun` restores a finished run: a file whose text still matches the agent's last write goes back (created files to the Trash), any other file is reported as a conflict and never overwritten; reverting twice, or retrying after a partial revert, is safe.
- **Commands that change files** (`Session/WorkspaceSnapshot.swift`) — a command can touch any file, so with `AgentConfiguration.snapshotter` (`WorkspaceSnapshotter`: `capture()`, `diff(from:to:)`, `text(of:at:)`; AgentKit reads no disk and runs no process here) the session captures before and after each approved `.command` call (`execute`, around `runBatch`; captured on detached tasks with a 5 s race, so Stop, which kills the command, still records what it had already changed, and a hung host cannot hold the run) and `CommandChangeTracker.record` files the differences in the run's `CheckpointLog` like an edit's. A path the agent may not write (`checkWritable`), a credential file (`SecretFilePolicy`) and a file whose snapshot text is not what the disk holds (a line-ending or content filter, or changed again since) are left out; binary or oversize files, and changes past the host's cap, are named in a trailing editor note on the command's output because Revert cannot restore them. A removed file is a deletion (`FileChange.isDeletion`, `CheckpointLog.didDelete`, saved as `ChangeSnapshot.isDeletion`): Revert writes the original back only while nothing has taken its place, else it is a conflict. Fails open: any `nil` from the host means the command's changes go unrecorded. Tests: `CommandSnapshotTests` (with a directory-comparing fake).
- **Approvals** — when `PermissionPolicy` says ask, the session builds an `ApprovalRequest` (a `.command` tool describes itself with `approvalRequest`; one that does not still asks, with a generic card; an `.edit` call shows `editPreview`'s diff; `suggestedRule` is what an "Always allow" button would add) (command, working directory, reason, warnings, notes, editable argument). `AgentSession` emits `.approvalRequested`, sets the state to `.awaitingApproval`, and waits for `resolveApproval(callID:decision:)`: approve, approve with the user's edited command (the model is told it was edited), or deny with an optional note (returned to the model as an error output). Stop answers a pending question with a denial; a late or repeated answer is ignored. Only `resolveApproval` can approve: nothing a tool returns can. `ApprovalPolicy.approveAll` is for tests and the eval harness. `CommandWarnings` flags `sudo`, `rm -rf` on broad paths, force-pushes and the like, as a warning on the card, never a block. `ToolContext.progress` streams a tool's live output to the transcript as `.toolCallOutput`; the model still gets only the final output. AgentKit itself never spawns a process: commands live in the host app.
- **`apply_patch`** — `PatchParser` (strict structure; `@@` numbers and counts are hints) and `PatchPlanner`/`HunkMatcher` (exact content decides where a hunk goes, then the same canonical match as `edit_file`, and an indentation shift when the tolerance allows it; a match that changes nothing is reported and not written; ambiguous or missing context names the hunk and the first line that differs). The third failed `edit_file` or `apply_patch` of one path in a run suggests `write_file`. Every file is validated and computed before any is written; a write failure partway puts the written files back. Creation (`--- /dev/null`) works; deletion and renames do not.
- **ACP** (`ACP/`, plan: `docs/ACP_PLAN.md`) — Agent Client Protocol client support, additive in this target: handwritten `JSONValue`-based JSON-RPC (`JSONRPC.swift`), typed v1 subset (`ACP.swift`, unknown variants tolerated), injected `ACPTransport` (never spawned here; in-memory pair in `Testing/`), `ACPConnection` (framing, correlation, concurrent request handlers), and `ACPClientSession`, which maps `session/update` to `AgentEvent` with exactly one terminal `.runEnded` and bridges `session/request_permission` to `ApprovalRequest`. Host effects go through `ACPHostServices`; Umbra provides the process transport over SubprocessKit. Tests: `Tests/AgentKitTests/ACP/` with a scripted fake-agent oracle. Phase 2 (same folder): `ACPAgentEndpoint` wraps any `AgentSession` as an ACP agent (reversed mapping; option-less `ask_user` elicits free text over `elicitation/create`; a local file miss reads the remote client when it advertised `fs.readTextFile`, via `ACPRemoteWorkspace`; sessions persist through an optional `SessionStore`, so `session/load` survives a restart and is advertised only then); Umbra ships it as the `UmbraACP` stdio executable built from the user's configured provider.
- **On-device models** — `AgentKit` never links MLX. `Packages/AgentKitMLX` (see its `CLAUDE.md`) adds an `LLMClient` that runs a downloaded model in-process.
- **Tests that spend money** — **never in CI.** Every such test goes through `PaidTests` (`Tests/AgentKitTests/PaidTests.swift`): it is off whenever `CI` or `GITHUB_ACTIONS` is set (anything but empty, `false` or `0`), whatever else is set, and a variable that is **empty counts as unset** (a workflow passing `${{ secrets.MISSING }}` hands over an empty string). The workflow also runs `Scripts/refuse-paid-test-variables.sh` and fails if `AGENTKIT_EVAL`, `AGENTKIT_OPENAI_KEY`, `AGENTKIT_ANTHROPIC_KEY`, `AGENTKIT_META_KEY`, `AGENTKIT_OLLAMA_MODEL` or `AGENTKIT_OLLAMA_URL` has a value. (`editor-ci.yml` only builds Umbra today and has no `swift test` step or provider secret; this keeps it that way if one is added.) `swift test` makes no call to OpenAI, Anthropic or an Ollama server. Everything that does is skipped unless its variable is set: `OpenAISmokeTests` needs `AGENTKIT_OPENAI_KEY`, `AnthropicSmokeTests` needs `AGENTKIT_ANTHROPIC_KEY`, `MetaSmokeTests` needs `AGENTKIT_META_KEY`, `OllamaSmokeTests` needs `AGENTKIT_OLLAMA_MODEL`. The evals (`ToolLoadingEvalTests`, `ToolCostCalibrationTests`) need **all three** of: `AGENTKIT_EVAL`; the models **named** in `AGENTKIT_EVAL_MODELS` (`haiku-5.5`, `sonnet-5.5`, `gpt-4.1-mini`, `gpt-5-mini`, `bonsai-2`; there is no default list, so a key exported for the smoke tests does not start an eval); and each named model's `AGENTKIT_ANTHROPIC_KEY` / `AGENTKIT_OPENAI_KEY` / `AGENTKIT_OLLAMA_URL`. A run that would start more than `AGENTKIT_EVAL_MAX_RUNS` (default 40) model runs (variants × models × scenarios × trials, narrowed by `AGENTKIT_EVAL_VARIANTS`, `AGENTKIT_EVAL_SCENARIOS`, `AGENTKIT_EVAL_TRIALS`) is refused before the first call and says so. Nothing reads `openai.key` or `claude.key`; pass a key on the command line from the file when you mean to spend (`AGENTKIT_OPENAI_KEY=$(tr -d '[:space:]' < openai.key) swift test --filter OpenAISmokeTests`). The Umbra tests never call a provider.
- **Smoke tests** — **Checked against the real API on 2026-10-22**: `AnthropicSmokeTests` (3 tests) pass, and the full tool set (MCP, `web_fetch`, `explore`, `task`, background `task`) completed on `claude-haiku-5-5` and `claude-sonnet-5-5` (adaptive thinking, `reasoningEffort: low`) and on `claude-haiku-4-5-20251001` (the `budget_tokens` path), with thinking blocks replayed across tool round trips, raw MCP schemas accepted, and the top-level `cache_control` giving cached input tokens (about half of each run). `AnthropicSmokeTests` is opt-in too: `AGENTKIT_ANTHROPIC_KEY=sk-ant-… swift test --filter AnthropicSmokeTests` (a few cents; it is the only check of the real `/v1/messages` wire, since the decoder and encoder tests use events written from the API docs, and the first thing to run if a Claude request is ever rejected). `OllamaSmokeTests` is opt-in: `AGENTKIT_OLLAMA_MODEL=<model with tools> swift test --filter OllamaSmokeTests`.
- **Tools** — conform to `AgentTool` (`definition`, `risk`, `run`); `execute(argumentsJSON:context:)` turns every thrown error into an output the model can act on. Output is capped and says how to continue (`offset=`). `ReadLedger` records a hash of what `read_file` showed, for `edit_file`. `ToolArguments` reads the mistakes that cannot be misread and fails on the rest: `"20"` for an integer, `"true"`/`"false"` for a boolean, a list written as a JSON string, `{}` for an optional parameter that was skipped, and an object sent as a JSON string inside a string. A lone string is deliberately not read as a one-item list (`todo` taking `"not a list"` as a checklist item was the case that showed why). Tests: `ToolArgumentsTests`.
- **Web search** (`Tools/WebSearch.swift`) — `web_search` is a `.read` tool over `WebSearchClient`. The only client is `BraveWebSearchClient` (`GET https://api.search.brave.com/res/v1/web/search`, header `X-Subscription-Token`, host fixed). A host adds the tool only when the user has turned search on and saved a key. Queries over 400 characters are refused; results are titles, URLs and snippets with the provider's highlight tags stripped, marked untrusted, and capped. A 401 or 403 says the key was rejected and never echoes it; 429 and 5xx retry once. The production session refuses a redirect to any other host, and a redirect it does allow continues without the subscription token. `honorsDenyRules` lets a deny rule `web_search` (or `web_search(prefix:*)`) block a call; other read tools still ignore rules. Tests: `WebSearchTests`.
- **MCP** (`MCP/`) — a client for Model Context Protocol servers, **tools only**, over stdio. AgentKit starts nothing: the host gives `MCPHub` a `TransportFactory` that returns an `ACPTransport` (the same newline-delimited JSON-RPC pipe ACP uses, so `ACPConnection` does the framing, correlation and timeouts). `MCPClient` does the handshake (offers `2025-06-18`, accepts it and `2025-03-26`/`2024-11-05`, offers no client capabilities, answers `ping`, refuses every other server request), `tools/list` across pages (at most 10 pages and 200 tools) and `tools/call`; a result's content blocks become text (images, audio and binary resources are named, not carried; `structuredContent` is used when there is no content; `isError` is carried). `MCPConfigFile.parse` reads `{"mcpServers": …}` (Claude Code, Cursor) and `{"servers": …}` (VS Code): only entries with a `command` are used, `url`/`http`/`sse` entries are returned in `skipped` with the reason; `${VAR}` in the file is **not** expanded. `MCPHub.start()` connects all servers at once (each at most 30 s), reports a failed or hung one in `statuses` and carries on; the tool list is read once and does not change afterwards (it is part of the cached request prefix), `fingerprint` is for the host's session fingerprint. A server that stops mid-session is started again by the next call that needs it, at most `maxRestarts` (3) times per hub, then the call says it keeps stopping. `MCPTool` is `mcp__<server>__<tool>` (letters, digits, `-`, `_`, at most 64 characters; a name that does not fit keeps its start and ends in a short hash; two servers whose names clean up alike get distinct identifiers), risk **`.command`**: plan mode never offers it, Auto never runs it unasked, the approval card names the server and suggests the bare tool name as the "always allow" rule; a server's `readOnlyHint` is shown as its claim and relaxes nothing. Its output is wrapped `<untrusted source="mcp:server">`, cut at 30,000 characters (`headAndTailSaving`), and a tool error becomes an error output. `ToolDefinition.rawSchema` carries the server's JSON Schema unchanged (a non-object schema becomes an empty object schema, `$schema` is dropped) and such a tool is never marked `strict`; the arguments sent are the model's with the `null`s a strict-mode caller adds removed (`ToolArguments.presentValues`). Not built: HTTP/SSE servers, OAuth, resources, prompts, sampling, roots, elicitation, `list_changed`, cancelling a call on the server when Stop is pressed (the late result is dropped). Tests: `MCPTests` (`FakeMCPServer` over `ACPInMemoryTransport`), `MCPHubTests`.
- **A write that could not have seen the read beside it** (`AgentSession.emptyWriteBesideRead`) — a model that sends a read and a write in one step (parallel tool calls) has not seen the read's result when it writes, so the content of a write that depends on it comes out empty and the model then reports the file as written (seen with `gpt-4.1-mini` on the Responses API: 4 of 5 runs of "read note.txt, write its word to reply.txt"). `execute` answers such a write with `emptyWriteMessage` ("Not run: … issue the write again now that you have it") and runs the rest. Narrow on purpose: the call is `write_file` or `create_file` (built in, or an MCP tool whose name ends that way), a `content`/`contents`/`text`/`body`/`data` argument is the empty string, and another call in the same step reads (a `.read` tool, or a name starting `read`/`get`/`list`/`search`/`find`/`fetch`/`view`/`cat`/`grep`/`glob`/`tree`/`stat`, which covers MCP tools since those are all `.command`). A write with content, an empty write alone, or one beside another write runs as usual; refusing more than that, or switching parallel calls off, would slow models that do this right. After the guard the same scenario passed 6 of 6, the guard refusing 3 of them. Tests: `EmptyWriteTests`.
- **Tool definition cost** (`Tools/ToolCost.swift`, `MCP/ToolTrimming.swift`, `MCP/MCPGateway.swift`, plan and results: `docs/AGENT_TOOL_LOADING_PLAN.md`) — every request starts with the system prompt and every tool's name, description and schema; the providers cache it, but it fills the window and the prefill. `ToolCost` estimates it from characters with a factor per provider measured against their own counts (2026-10-22: Claude 2.4–2.65 characters per token, OpenAI 5.1–5.4, Ollama 3.2–3.7; good to about 15%; the provider's usage is the truth). Three levers for MCP tools, all fixed when `MCPHub` starts so the cached prefix never moves mid-session: **trimming** (`ToolTrimming.standard`: a description keeps whole sentences up to about 240 characters and at least the first, parameter notes 160 characters at a word, `title`/`examples`/`$comment`/`$schema` dropped, `required`/`enum`/`default`/names never touched; idempotent; `MCPToolSummary.description` keeps the server's own text for Settings), **hiding** (`MCPHub(hidden: [serverName: Set<toolName>])`: not listed, not callable, still in `summaries` for Settings; changes the hub fingerprint) and **deferral** (`MCPDeferral`: a server over `budgetTokens` (3,000) or `toolCount` (20), or one forced `.always`, is not listed; the model gets two fixed tools instead). `tool_search(query, server?, limit?)` is a `.read` tool, not offered in plan mode, whose description names the deferred services and counts; it scores the query's words against each tool's name (weight 3), server name and description and returns up to 10 matches with their schemas, wrapped untrusted. `tool_call(name, arguments)` is `.command` risk but **forwards**: `AgentTool.forwardedCall` lets `AgentSession.execute` swap in the real MCP tool and its arguments before the policy runs, so deny/ask/allow rules, the approval card (`toolName`, title, suggested rule), plan-mode offering and the untrusted wrapper are those of `mcp__server__tool` and a rule on `tool_call` allows nothing (tested). A call with missing required arguments, or an unknown name, is answered with the schema or a "did you mean". Opt-in evals that gate changes here: `ToolLoadingEvalTests` (scenarios with automatic pass/fail, variants direct/trimmed/trimmed-hidden/deferred/big-automatic) and `ToolCostCalibrationTests`; they spend money, see *Tests that spend money* below. Tests: `ToolCostTests`, `ToolTrimmingTests`, `MCPHubLoadingTests`, `MCPDeferralTests`, `MCPGatewaySessionTests`.
- **After an edit** (`AgentConfiguration.afterEdit`, `afterEditTimeout` 3 s, `Session/Deadline.swift`) — once per turn that changed files through the edit tools, `execute` asks the host with the project-relative paths those calls changed (`affectedPaths`: a patch names its files, other edit tools a `path`) and appends what it returns to the **last** edit call's output, so the model sees what it broke in the same step. Failed edits, read-only turns and a `task` child's own edits (`reportsOwnEdits`) add no paths; a host that is slow (`Deadline.run`, which races the callback and gives up without waiting for it), returns `nil` or an empty string adds nothing. The transcript's `.toolCallFinished` was already sent, so only the model sees the note. Tests: `AfterEditTests`.
- **Web fetch** (`Tools/WebFetch.swift`, `WebFetchClient.swift`, `HTMLText.swift`) — `web_fetch` (`url`, `format` markdown|text, `timeout` up to 60 s) reads one http(s) page. The host adds it only when the user turned it on. It is a `.read` tool with `asksUnlessAllowed`: unlike other reads it goes through the rules (`PermissionPolicy` read branch), runs alone, and asks in every mode (plan included) unless an allow rule names the address; the card shows the address (editable) and suggests `web_fetch(https://host/*)`; an address that can never run (another scheme, a username, `localhost` and other local names, a numeric address that is not public, a malformed one) is refused **before** any card through `AgentTool.refusalBeforeAsking` / `WebAddressPolicy.obviousRefusal`, so nobody approves something that would be refused; a public-looking name is still asked about and checked by the resolver later; deny and ask rules apply (`honorsDenyRules`). `PermissionSubject` is the normalized URL as text, matched like a command with `*` as a wildcard. `WebAddressPolicy.validate` runs before every hop: http/https only, no userinfo, no `localhost`/`.local`/`.internal`/`.lan`-style names, and the host is resolved (`getaddrinfo`) and **every** address must be public (loopback, RFC 1918, CGNAT, link-local incl. 169.254.169.254, multicast, IPv6 unique-local/link-local, IPv4-mapped and NAT64 forms are refused; decimal and hex IP spellings are normalized by the resolver). Known limit: the connection resolves the name again, so DNS rebinding is not caught. `URLSessionWebFetchClient` is GET only, no cookies or cache, 2 MB body limit, and follows redirects by hand: the same host (and an http-to-https upgrade) is followed up to 5 times with each hop re-validated; a redirect to another host is returned as `redirectedTo` and the tool tells the model to call again with that address (which asks again). Only text types are read (HTML, plain text, Markdown, JSON, XML, YAML…); anything else is an error naming the type. HTML goes through `HTMLText` (a small tokenizer, no WebKit: drops script/style/nav/footer/svg/iframe, keeps headings, lists, links resolved against the page, code and `pre` with a `language-x` fence, tables as rows, decodes entities); the result is capped at 30,000 characters keeping 80% from the start (`headAndTailSaving`, so `read_tool_output` pages the rest) and wrapped as `<untrusted source="web-fetch">`. Tests: `WebFetchTests`, `WebFetchClientTests` (a stub `URLProtocol`), plus a live check done by hand on 2026-10-22.
- **Compaction** — `ContextCompaction` runs at the top of every loop iteration when `AgentConfiguration.contextWindow` is set. The estimate is `max(whole transcript bytes / 4, last reported input tokens + bytes appended since)`. Stage 1 replaces old tool outputs with one-line stubs (oldest first, in one batch so the request prefix stays cacheable, newest 4 kept); stage 2 asks the model once to summarize the oldest part, cutting only on turn boundaries so a tool call never loses its output. A previous summary is passed as `<previous-summary>` and is not part of the transcript cut. The user's typed words from the summarized part are kept after the summary (6,000 characters, oldest dropped first); editor notes, editor state, attachments and shell context are summarized with the rest. The tail grows until it fills 30% of the window (20% on a forced pass) and never fewer than two model turns. `.compacted(CompactionReport)` is emitted when anything changed. A provider `contextLengthExceeded` forces a pass (the window is treated as full) and retries once; `MLXLLMClient` throws that when the prompt does not fit the window it was given, and an Ollama stream `{"error":…}` that is a context overflow does too. Umbra and AgentEval compact Ollama at 60% because a prompt past `num_ctx` can truncate without an error. A failed summary keeps the stubs and backs off for 6 items. `cacheFriendlySummaries` (default off) reuses the session prefix for the summary request and falls back to the dedicated summarizer if the model calls a tool or the pass was forced. Tests: `CompactionTests`, `SessionCompactionTests`, `HarnessImprovementTests`; the real-model one is `OllamaSmokeTests.aLongSessionCompactsAndKeepsAnswering`.
- **Permissions** (`Tools/Permissions.swift`, `PermissionPolicy.swift`, `CommandSegments.swift`) — `PermissionMode`: `manual` (every edit shows its diff and asks, every command asks), `acceptEdits` (the default: edits apply, commands ask), `auto` (edits apply; a command runs without asking only if every part is on the `SafeCommands` list or allowed by a rule, and nothing in it is opaque or risky), `plan` (only `.read` tools are offered; a call to another known tool is answered "not available: … plan mode"). `AgentSession.setMode` / `setRules` change them between or during runs: the tool list changes with the mode, and the model is told in a user note (`[Note from the editor, not from the user] …`) added at the next turn boundary, never between a call and its output (`announceModeChange`). `PermissionPolicy.evaluate` decides in this order: a deny rule refuses, the host's `PermissionGate` may ask or refuse, an ask rule asks, an allow rule allows, then the mode. Rules are `Bash(git status:*)`, `Edit(src/**)`, `run_command(npm test)` or a bare tool name, in `PermissionRules` (`allow` / `ask` / `deny`; `fromSettings` reads the `permissions` object of a Claude Code or Umbra settings file). An entry may also be an object with inline tests (`{"rule": "Bash(git status:*)", "match": […], "not_match": […]}`); `checkExamples()` reports the ones that do not hold, and the rules still apply. `Bash` covers every command tool, `Edit`/`Write` every file-changing tool. A command is split into segments (`CommandSegments.parse`: `&&`, `||`, `;`, `|`, `&`, newlines, quote and escape aware): a deny or ask rule matches if any segment (or the whole text) does, an allow rule only if every segment is covered. A substitution, subshell, heredoc, unterminated quote or a redirection to a file is never covered by an allow rule or by Auto, though deny and ask rules still see the parts they can. `SafeCommands` is strict on purpose: no variables, no path outside the project or to a likely credential file (`SecretFilePolicy`), no `find -exec/-delete`, no `rg --pre`, git only for reading. A tool says what rules match through `AgentTool.permissionSubject` (default: a `command` or `path` argument; `apply_patch` names its files; `web_search` names its query as text, matched like a command and not split into shell segments). `ApprovalPolicy.approveAll` skips the policy for tests and evals. Rules do not apply to read tools, except one that sets `honorsDenyRules` (`web_search`): a matching deny rule refuses it, and ask and allow rules still do not. Tests: `PermissionPolicyTests`, `CommandSegmentsTests` (also `SafeCommandsTests`), `PermissionSessionTests`, `ModeTests`.
- **Skills and commands** (`Skills/`) — pure reading, nothing is run. `MarkdownFrontmatter` parses the small YAML subset these files use (scalars, quotes, `[a, b]`, `- item` lists, `|`/`>` blocks; keys lowercased). `CommandTemplate` is a `commands/**/*.md` file: the path is the name (`ops/deploy.md` → `ops:deploy`), `description`, `argument-hint` and `allowed-tools` come from the header, and `expand(arguments:)` fills `$ARGUMENTS` and `$1`…`$9` (a body that mentions neither gets `ARGUMENTS: …` appended); `!`cmd`` lines are only reported (`usesShellSubstitution`). A `Skill` is `<name>/SKILL.md` plus whatever sits beside it. `SkillCatalog.load(skillFolders:commandFolders:)` takes the folders in the order they win (the project's before the user's), skips files over 256 KB, and gives `fingerprint` (names, descriptions, text; commands are not in it, since the model never sees them). `SkillTool` (`skill`, `.read`) lists skills in its description (capped at 8 KB). A skill with frontmatter `paths:` is listed only after a file tool has touched a matching path; a skill without `paths` stays listed. and returns a skill's instructions plus the names of the files beside them, or with `file:` one of those files; it reads only inside that skill's folder after resolving symlinks and `..`, which is what lets a user-level skill ship scripts and notes the project jail would hide. A host offers the tool only when there are skills and puts the fingerprint in its session fingerprint, so a changed skill starts a new session instead of changing a live request. Tests: `SkillTests`.
- **Plan approval** (`Tools/PlanTools.swift`) — `ExitPlanModeTool` (`exit_plan_mode`, `.read`, `waitsForUser`) is offered only in plan mode (`AgentTool.isOffered(in:)`, which defaults to what the mode offers by risk), so a host can always put it in the tool list. The model submits Markdown; the session emits `.planProposed(callID:plan:)` and `.stateChanged(.awaitingPlanApproval)` and waits in `waitForPlan` until `resolvePlan(callID:decision:)`: `.approve(mode)` switches the session to that mode first (Accept Edits or Manual; approving into Plan changes nothing) and sets `announcedMode`, so no mode note repeats what the tool's output says, then the tool answers "The user approved the plan…" and the next turn is offered the tools that change things; `.revise(feedback)` keeps plan mode and the model is told to revise and submit again. Stop answers `.revise("")` and ends the run as usual. `ToolContext.proposePlan` is the hook; a context without it makes the tool an error rather than a hang. Tests: `PlanModeTests`.
- **Checkpoints across a relaunch** — `CheckpointLog(blobs:)` also writes each original to a `CheckpointBlobStore` (keyed by run and path, best effort) as it records it. `snapshot()` gives the runs without their texts (`RunSnapshot`, Codable), and `restore(_:)` brings them back reading the originals from the store: a file whose original is gone is left out, a run left with no files is dropped, runs already known are kept, and the memory budget still applies (older runs lose Revert first). The host owns one log per conversation and passes it to each `AgentSession(…checkpoints:)`. Tests: `CheckpointPersistenceTests`.
- **Rewind** — `AgentSession.rewind(toBeforeItem:)` cuts the history before the `.user` item at an index and returns what it cut (an index that is not a user message, or any index while a run is going, throws `RewindError`). The read ledger is cleared, so the model must read a file again before editing it; the checklist is rebuilt from what is left (`TodoList.latest`); the token measure is forgotten. Files are untouched: `revertRuns(_:)` (and `CheckpointLog.revertRuns`) reverts several runs newest first, so a file that more than one changed ends as it was before the oldest. Tests: `RewindTests`.
- **Shortening on demand and messages mid-run** — `compactNow(focus:)` runs the same core as automatic compaction (`compact(window:force:manual:focus:)`) but skips the thresholds and the back-off after a failed summary, and works with no window configured (it assumes 128K for the stub and summary budgets); the focus is added to the summary request. It throws `CompactionError.runInProgress` mid-run and returns an empty report for a conversation too short to shorten. `estimatedContextTokens()` and `contextWindow` are public for a host's meter. `AgentConfiguration.pendingMessages` is asked at the top of each loop iteration and before a turn with no calls would end the run; what it returns joins `items` as user messages (so never inside a call and its output), and a run that would have ended carries on with them. It is told the item count so the host can record where each lands. Tests: `CompactNowTests`, `PendingMessageTests`.
- **Interrupted runs** — a history saved while a run was going can end in a tool call nobody answered; `AgentSession.init` repairs it (`ConversationItem.answeringUnansweredCalls`: "Tool execution interrupted: … may have partly run. Check the current state before repeating it"). `.stepFinished(items:)` follows each step that ran tools once every call has its output: the point where a host can save and the run could be resumed. `resume()` runs again from the history with an editor note (`resumeNote`) and no new user message (`retry()` adds neither). Tests: `CrashRecoveryTests`.
- **Persistence** — `SessionStore` writes `<dir>/<hash of project root>/<uuid>.json` atomically (file 0600, folder 0700): items, usage, and an opaque `host` blob for the app's own transcript. Never a credential. `SessionStore.title(from:)` uses `UserText.typed`, so a title comes from what the user wrote and skips editor notes, editor state, attachments and a compaction summary. `SessionSummary` (what a history menu lists) is the id, title, and updated time, plus the number of user messages and an optional cost read from the host blob's `cost` field; the snapshot's own keys are unchanged. `SessionSummary.projectRoot` names the project, and `listAll(limit:)` lists the newest conversations of every project (one folder level, so `blobs/` is never read; only the `limit` most recently written files are decoded, and `reusing:` a previous result skips a file not written since, so a list that refreshes on every save stays cheap).
- **Protected files** — `ReadOnlyTools.all(secretPatterns:)` adds user globs to `SecretFilePolicy` for `read_file` and `grep`; a pattern that does not parse is skipped.
- **Project instructions** — `ProjectInstructions` reads `AGENTS.md`, else `CLAUDE.md`, `GEMINI.md` or `.cursorrules` (16 KB, symlinks refused). The root file belongs in the system prompt. `ProjectNoteTracker` appends a nested file to the first file-tool output under that directory, once, and `reset()` after a summary. `grep` and `glob` do not attach one. A live session notices an edit to the root file: `AgentConfiguration.currentInstructions` is asked at each turn boundary (a small file read), `instructionsBaseline` is what the prompt was built from, and `InstructionState` turns a difference into an editor note with a unified diff (the whole file past 4 KB; a deleted file says its instructions no longer apply; every note repeats that the file does not override the rules above). The system prompt never changes, so the cached prefix survives. The agent's own edit (its path in `filesEditedThisRun`) is accepted silently; a rewind drops the notes it cut so the change is announced again; a summary over a note re-announces the file in full. Tests: `InstructionStateTests`.
- **Stop gate** — `StopGatePolicy: TurnPolicy` runs the host's check from `beforeEnding` only (stopped, budget, iteration-cap and failed runs skip it; never in plan mode, and never with no edits unless `checkWithoutEdits`). `.block(reason)` continues the run with the reason as a note (capped like tool output); after `maxContinuations` (default 3) the run ends `.completed` with a final turn that says the check did not pass. A check that throws, is cancelled or times out fails open, and every outcome emits `.stopGateChecked(passed:summary:)`. Per-run state resets in `AgentSession.run` through `TurnPolicy.reset()`. Tests: `StopGateTests`.
- **Output shaping** — `AgentConfiguration.shapeToolOutput` reshapes a tool's output before it enters `items` (and so the model, `SessionStore` and compaction); `.toolCallFinished` keeps the original. Errors, timeouts and the "Not run…"/cancel stubs bypass it, and a throwing shaper falls back. The shaper must be deterministic for a given input (prefix-cache stability); redaction belongs here, beside `SecretFilePolicy`. Tests: `ToolOutputShapingTests`.
- **Project memory** — `ProjectMemory` keeps `<SessionStore dir>/<project hash>/MEMORY.md` (0600, outside the repo): `load(at:)` caps at 8 KB with the oldest entries dropped first and refuses symlinks; `append` writes one dated 300-character line, deduplicated. The model writes only through the `remember` tool (`.edit` risk, so plan mode never offers it; `editPreview` feeds the approval card). Memory loads at session start into the system prompt as recall ("may be stale; the project's files and instructions win") and joins the session fingerprint, so a write never changes a live request. A run that used web search or read `<untrusted>` content (`sawUntrustedThisRun`, plus `honorsDenyRules` tools) still asks through `asksAfterUntrustedContent`, and the line passes through the output shaper (`ToolContext.redactForMemory`) before it is stored. Tests: `ProjectMemoryTests`.
- **Explore subagent** — `ExploreTool` (`explore`, `.read`) runs one child `AgentSession` in the foreground over the parent's workspace (with a copy of the `ReadLedger`), sharing client, model, rules and window; the child runs in plan mode with a hard iteration cap (default 15) over the parent's tools minus `ask_user`, `exit_plan_mode`, `todo`, `remember` and `explore` (a stub answers nested calls with the depth limit). The final text, capped at 6 KB and wrapped as untrusted, is the tool's output; the child's events forward as `.subagent(id:event:)`, its tokens join the parent run's budget (and meter), and Stop ends it with the parent. Late child events after the parent run drop, and late usage never leaks into the next run. Tests: `ExploreSubagentTests`.
- **`task` subagents** (`Tools/TaskTool.swift`, `Skills/AgentDefinition.swift`, "Subagents (`task`)" in `AgentSession`) — `task` (`agent`, `description`, `prompt`, optional `background`, optional `session`) hands work to a child `AgentSession` with its own window. It is an `.edit` tool on purpose: plan mode does not offer it (`explore` is the read-only path there), it runs alone, and so at most one foreground child exists at a time. An `AgentDefinition` is a built-in (`general`, can change files) or an `agents/<name>.md` file (`AgentCatalog.load(folders:)`, earlier folders win, a file may replace `general`): `description`, `tools: [..]` (allow list), `mode: read-only|edit` (read-only by default), `max-iterations`, and the body added to the child's system prompt. The list is in the tool's description and `AgentCatalog.fingerprint` belongs in the host's session fingerprint. A child gets this session's tools minus `ask_user`, `exit_plan_mode`, `todo`, `remember`, `explore`, `task`, `show_file` and every `.command` tool (it cannot ask, so a command could never run), only the `.read` ones unless the agent edits, narrowed by its list. A child that edits runs in Accept Edits and only when the parent is in Accept Edits or Auto (in Manual the user approves each edit and a child cannot ask; the call is refused with that reason); it files its changes under the parent's run (`AgentSession(inheritedRun:)`, the shared `CheckpointLog`), so Revert Run covers them, and its edited paths join the parent's `filesEditedThisRun` (`reportsOwnEdits`: the call itself is not counted as an edit). Only one child that edits may run at a time. Any approval a child raises is answered with a refusal rather than left waiting (the host shows no card for it). Child tokens join the parent run's budget (`TokenUsage.minus` for a continued child). `session` continues a child by the id in the previous output; children live as long as the parent session, at most 12, and do not survive a relaunch. `background: true` returns at once with the "do not poll or sleep" text; the child's report is queued and enters the history as an editor note (untrusted-wrapped) at the next turn boundary (`takeDelegationResults`), `.subagentFinished` tells the host, and a run does **not** end while a background child is running (the end-of-run branch waits in `waitForDelegationActivity`; Stop wakes it, and `endChildren` stops children and drops undelivered reports at the end of every run). A message the user queues meanwhile is delivered after the wait. `task` and `explore` have `runsWithoutTimeout`: a child is bounded by its iteration cap and Stop, and the 120 s tool timeout only cut off research that was going well. Tests: `TaskToolTests`, `TaskToolContinueTests`, `BackgroundTaskTests`, `AgentDefinitionTests`.
- **Pre-approved calls** — `approved()` records outright `.allow` verdicts (an allow rule or a safe default, not a card approval) in `preapprovedCalls`, and the run's `ToolContext` carries it as `preapproved`. A tool that degrades gracefully uses it to skip asking again: the sandbox retry outside the sandbox runs at once when pre-approved, else asks.
- **Tool names in the prompt** — `SystemPrompt` tells the model to start questions about code with `explore_symbol`/`find_symbol` (a name is enough), to prefer `go_to_definition`/`find_usages` for a symbol it sees in a file, and `git_status`/`git_diff` "when available", to call `show_file` to open a file for the user, that `gradle` / `run_tests` open the Gradle tool window while `run_command` runs in the integrated terminal, and to use `web_search`, when it is available, without putting file contents or secrets in the query. Those tools live in Umbra except `web_search`, which is AgentKit and only present when the host adds it; a session without them answers a call with the unknown-tool error, which lists what is offered.
- **`todo` and `ask_user`** (`Tools/InteractionTools.swift`) — `todo` takes the whole checklist as strings (`[ ] `, `[~] `, `[x] `) and replaces the list; `TodoList` (an actor on the session, `todoList`) emits `.todosUpdated` once per change and is rebuilt from the history by `TodoList.latest(in:)` (a host can also `setTodos`). `ask_user` calls `ToolContext.ask`, which the session turns into `.questionAsked` + `.awaitingAnswer` and waits for `answerQuestion(callID:answer:)` (`nil` = dismissed; Stop and cancellation also answer `nil`). `AgentTool.waitsForUser` makes a tool run alone and skips the tool timeout; `isExemptFromRepeatGuard` lets `todo` repeat unchanged (it then says "Checklist unchanged"). Both are read-risk, so plan mode keeps them.
- **Found by the eval CLI** (`Tools/AgentEval`), each with a test: (1) the repeat guard counts identical calls only until a file edit succeeds (`counts.removeAll()` after a successful `.edit` call), because edit, run the tests, edit, run the tests is the normal loop; three identical calls with nothing changed in between still warn and the fourth stops the run. (2) A call a local model wrote but nobody could read (`LLMEvent.unreadableToolCall`, today only from `MLXLLMClient`) no longer ends the run: the loop appends a user note (`unreadableCallNote`, says how to write newlines and quotes in JSON) and asks again, at most `maxUnreadableCalls` (3) per run, then fails with the reason. The note is an ordinary `.user` item marked "[Note from the editor, not from the user]". (4) A turn with no answer text, no calls and no unreadable calls is retried once with an editor note (`maxEmptyTurns`), then the run fails with "The model produced no output." instead of ending `.completed` (a local model that wrote only a stop token; `EmptyTurnTests`). (3) `edit_file`'s "not found" error shows the file's real lines when the text matches ignoring leading or repeated whitespace, and says so when `new_string` is already in the file (`EditSupport.notFoundMessage`).
- **Per-call untrusted gate and browser notes** — `AgentTool.asksAfterUntrustedContent(for:)` (default: the `asksAfterUntrustedContent` property) lets a tool decide per call whether to ask after the run read untrusted content even when a rule allows it; `untrustedAskNote` is what the card says (default: the old "saving asks first" text, which `remember` keeps). Umbra's `browser_act` asks after an untrusted read only for a site that is not on this Mac. `UserText.browserNotesLead` (`[Browser notes from the user.`) is a second block lead beside `attachmentLead`: `typed(_:)` cuts at whichever comes first, so a title and a compaction keep what was typed and summarize the block (the notes are the user's words but the block is context the editor added). Tests: `PerCallUntrustedGateTests`, `typedTextDropsEditorContextAndKeepsWhatTheUserWrote`.
