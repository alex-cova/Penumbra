# `Packages/AgentKit/Sources/AgentKit/Session`

Loaded when working under `Packages/AgentKit/Sources/AgentKit/Session`. Moved out of `Packages/AgentKit/CLAUDE.md`.

- **Announced, then stopped** (`AnnouncedAction`, `AnnouncedActionPolicy` in `Session/TurnPolicy.swift`; `AgentConfiguration.nudgeAnnouncedActions`, off by default in AgentKit; Umbra's Code chats turn it on) — a model that ends its run on "Fixing the config key." or "I'll update the imports now." with no tool call leaves the task undone (7 of 140 AgentEval trials on Muse Spark, all `completed` with nothing changed). From `beforeEnding`, once per run, the policy adds an editor note ("…you made no tool call, so nothing has changed. If you meant to do it, make the tool call now. If not, say plainly that no change is needed") when edit tools are offered (`TurnState.editToolsOffered`), it is not plan mode, no edit was attempted, and the last message reads as an announcement. The detector is narrow on purpose: at most 500 characters, not a question, and its last sentence starts with or follows a dash with an action verb in the -ing form, or has "I'll", "I will", "I'm going to", "let me" or "now" directly before one. A miss costs nothing and a false match costs one turn. Measured on Muse Spark (14 tasks × 5): fired in 4 trials, all 4 passed; one failure was a statement the detector does not match. Tests: `AnnouncedActionTests`. AgentEval: `--nudge-announced`.

- **Commands that change files** (`Session/WorkspaceSnapshot.swift`) — a command can touch any file, so with `AgentConfiguration.snapshotter` (`WorkspaceSnapshotter`: `capture()`, `diff(from:to:)`, `text(of:at:)`; AgentKit reads no disk and runs no process here) the session captures before and after each approved `.command` call (`execute`, around `runBatch`; captured on detached tasks with a 5 s race, so Stop, which kills the command, still records what it had already changed, and a hung host cannot hold the run) and `CommandChangeTracker.record` files the differences in the run's `CheckpointLog` like an edit's. A path the agent may not write (`checkWritable`), a credential file (`SecretFilePolicy`) and a file whose snapshot text is not what the disk holds (a line-ending or content filter, or changed again since) are left out; binary or oversize files, and changes past the host's cap, are named in a trailing editor note on the command's output because Revert cannot restore them. A removed file is a deletion (`FileChange.isDeletion`, `CheckpointLog.didDelete`, saved as `ChangeSnapshot.isDeletion`): Revert writes the original back only while nothing has taken its place, else it is a conflict. Fails open: any `nil` from the host means the command's changes go unrecorded. Tests: `CommandSnapshotTests` (with a directory-comparing fake).

- **Tool hooks** (`Session/ToolHooks.swift`, `AgentConfiguration.toolHooks`) — user-configured checks around the agent's tool calls. AgentKit never spawns anything: the host implements `ToolHooks` (`before` → `allow`/`deny(reason)`/`ask`, `after` → extra text or `nil`) and `execute` calls it. The before-hook runs ahead of the permission policy, so it covers concurrent reads and `.approveAll`; a deny is final and beats an allow rule (an allow never beats a deny rule), and ask forces an approval card. The after-hook's text joins the call's output for the model and still passes through the shaper; `.toolCallFinished` keeps the original. A throwing hook fails open. Children (`explore`, `task`, restored) get the same hooks. `HookStopPolicy: TurnPolicy` is the Stop hook, modelled on `StopGatePolicy` with the same cap, timeout and fail-open behavior, but it always runs when consulted — in plan mode too, and with no edits. Umbra implements the host side (`Umbra/Sources/Umbra/Agent/Hooks/`): shell hooks from the settings files (`IDEAgentHookConfig`), a runner on `SubprocessKit` with stdin JSON and exit-0/2 mapping (`IDEAgentHookRunner`), first-sight consent with a stored block fingerprint (`IDEAgentHookTrust`), wired in `IDEAgentConversation.currentSession` with the fingerprint in the session fingerprint. Tests: `ToolHooksTests`, `IDEAgentHookTests`.
