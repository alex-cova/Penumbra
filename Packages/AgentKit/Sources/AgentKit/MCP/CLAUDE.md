# `Packages/AgentKit/Sources/AgentKit/MCP`

Loaded when working under `Packages/AgentKit/Sources/AgentKit/MCP`. Moved out of `Packages/AgentKit/CLAUDE.md`.

- **MCP** (`MCP/`) — a client for Model Context Protocol servers, **tools only**, over stdio or streamable HTTP. AgentKit starts nothing: the host gives `MCPHub` a `TransportFactory` that returns an `ACPTransport` (the same newline-delimited JSON-RPC pipe ACP uses, so `ACPConnection` does the framing, correlation and timeouts). `MCPClient` does the handshake (offers `2025-06-18`, accepts it and `2025-03-26`/`2024-11-05`, offers no client capabilities, answers `ping`, refuses every other server request), `tools/list` across pages (at most 10 pages and 200 tools) and `tools/call`; a result's content blocks become text (images, audio and binary resources are named, not carried; `structuredContent` is used when there is no content; `isError` is carried). `MCPServerConfig` is `.stdio(command, args, env)` or `.http(url, headers)` (`MCPServerTransport`); `MCPConfigFile.parse` reads `{"mcpServers": …}` (Claude Code, Cursor) and `{"servers": …}` (VS Code), keeps `url` + `headers` for `http`-typed (or bare-URL) entries, and returns anything else remote (`sse`, non-http schemes) in `skipped` with the reason; `${VAR}` in the file is **not** expanded. `MCPHTTPTransport` posts each message and reads a JSON, batch or SSE reply, carries `Mcp-Session-Id`, sends `DELETE` on close, refuses cross-host redirects, and retries once on 401 with a token-provider closure (the OAuth flow itself is not built), sends the version the server negotiated in `MCP-Protocol-Version` on every request after `initialize` (and on the `DELETE`), and treats a 404 on a request that carried a session id as an expired session: the transport closes, so `MCPHub` starts the server again with a fresh one. A changed URL or header changes `canonicalText`, so trust is asked again. `MCPHub.start()` connects all servers at once (each at most 30 s), reports a failed or hung one in `statuses` and carries on; the tool list is fixed at start (it is part of the cached request prefix) and only `refreshStaleTools()` moves it, when a server announced `notifications/tools/list_changed` — the host calls that at turn boundaries, never mid-turn — and `fingerprint` is for the host's session fingerprint, so a refresh starts a new session with the history kept. A server that stops mid-session is started again by the next call that needs it, at most `maxRestarts` (3) times per hub, then the call says it keeps stopping. `MCPTool` is `mcp__<server>__<tool>` (letters, digits, `-`, `_`, at most 64 characters; a name that does not fit keeps its start and ends in a short hash; two servers whose names clean up alike get distinct identifiers), risk **`.command`**: plan mode never offers it, Auto never runs it unasked, the approval card names the server and suggests the bare tool name as the "always allow" rule; a server's `readOnlyHint` is shown as its claim and relaxes nothing. Its output is wrapped `<untrusted source="mcp:server">`, cut at 30,000 characters (`headAndTailSaving`), and a tool error becomes an error output. `ToolDefinition.rawSchema` carries the server's JSON Schema unchanged (a non-object schema becomes an empty object schema, `$schema` is dropped) and such a tool is never marked `strict`; the arguments sent are the model's with the `null`s a strict-mode caller adds removed (`ToolArguments.presentValues`). Not built: legacy SSE servers, full OAuth (only the token-provider retry exists), resources, prompts, sampling, roots, elicitation, cancelling a call on the server when Stop is pressed (the late result is dropped). Tests: `MCPTests` (`FakeMCPServer` over `ACPInMemoryTransport`, `MCPStubURLProtocol` over `URLSession` for the HTTP transport), `MCPHubTests` (including `list_changed` → `refreshStaleTools`).
