# `Packages/AgentKit/Sources/AgentKit/Skills`

Loaded when working under `Packages/AgentKit/Sources/AgentKit/Skills`. Moved out of `Packages/AgentKit/CLAUDE.md`.

- **Skills and commands** (`Skills/`) — pure reading, nothing is run. `MarkdownFrontmatter` parses the small YAML subset these files use (scalars, quotes, `[a, b]`, `- item` lists, `|`/`>` blocks; keys lowercased). `CommandTemplate` is a `commands/**/*.md` file: the path is the name (`ops/deploy.md` → `ops:deploy`), `description`, `argument-hint` and `allowed-tools` come from the header, and `expand(arguments:)` fills `$ARGUMENTS` and `$1`…`$9` (a body that mentions neither gets `ARGUMENTS: …` appended); `!`cmd`` lines are only reported (`usesShellSubstitution`). A `Skill` is `<name>/SKILL.md` plus whatever sits beside it. `SkillCatalog.load(skillFolders:commandFolders:)` takes the folders in the order they win (the project's before the user's), skips files over 256 KB, and gives `fingerprint` (names, descriptions, text; commands are not in it, since the model never sees them). `SkillTool` (`skill`, `.read`) lists skills in its description (capped at 8 KB). A skill with frontmatter `paths:` is listed only after a file tool has touched a matching path; a skill without `paths` stays listed. and returns a skill's instructions plus the names of the files beside them, or with `file:` one of those files; it reads only inside that skill's folder after resolving symlinks and `..`, which is what lets a user-level skill ship scripts and notes the project jail would hide. A host offers the tool only when there are skills the model may load (`SkillCatalog.modelSkills`) and puts the fingerprint in its session fingerprint, so a changed skill starts a new session instead of changing a live request. **Agent Skills conventions** (agentskills.io, 2026-11-07; tests `SkillContextTests`): `SkillCatalog.standardLocations(kind:projectRoot:home:includeUserFolders:appSupport:appLabel:)` is the one list of folders, shared by Umbra and `HeadlessRun`: the project's `.umbra/<kind>`, `.claude/<kind>` and for skills `.agents/skills`, then for skills the same `.claude/skills` and `.agents/skills` in each folder above the project up to the one holding `.git` (a file or a folder; at most 8 levels, none when the project is the repository, none without a `.git` in reach, never the home folder), then `~/.claude/<kind>` and `~/.agents/skills` when the host allows user folders, then the app's folder. Each `Location` has a `scope` (`project`, `ancestor`, `user`, `app`) that the `Skill` and `CommandTemplate` keep; `SkillScope.comesFromRepository` is what a host asks about before honoring `allowed-tools`. Loading is lenient and says so: `SkillCatalog.diagnostics` (`SkillDiagnostic`, not in `fingerprint`) records a name that differs from its folder, has untypable characters or is over 64 characters (loaded with a warning), a missing description (the first line of the body is used), and files left out (over 256 KB, not UTF-8, no description and no body); a skill that loses its name to an earlier folder goes to `shadowed` with a warning naming the winner. Frontmatter `disable-model-invocation: true` (`Skill.modelInvocable`: left out of the tool's list and refused with the `/name` path) and `user-invocable: false` (`Skill.userInvocable`: the host does not offer it after `/`) are read with `MarkdownDocument.flag`; `SkillCatalog.excluding(_:)` drops the skills a user switched off. The tool's `name` parameter is an enum of every model-invocable skill, including ones still hidden by `paths`, so the schema (part of the cached prefix) never changes when a file is touched; only the description does. A start returns `Skill.activationText()`: the body in `<skill_content name="…">`, the skill's absolute directory (so a script can be run by its path), and a `<skill_resources>` list of the files beside it (at most 60, never read). **Skills stay in context** (`SkillActivations`): `loaded(in:)` finds the genuine blocks only (the output of a `skill` call without `file`, and a user message outside any `<untrusted>` block; text a `read_file` or an attachment happens to hold proves nothing); a second `skill` call for a loaded skill answers "already loaded" (`ToolContext.isSkillLoaded`, a `file:` read is never deduplicated); `ToolOutputStubs` never stubs a start's output; after a summary the session adds one editor note with the instructions of skills it swallowed (`skillsLoaded(before:in:)`, `skillReminder(for:)`, at most 32 KB, newest first, the rest named), taken from the catalog through `AgentTool.activationText(forSkillNamed:)` and never copied from the history; `UserText.typed` cuts at `<skill_content` like it does at attachments. Tests: `SkillTests`, `SkillContextTests`.
