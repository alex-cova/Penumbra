# `Packages/AgentKit/Sources/AgentKit/ACP`

Loaded when working under `Packages/AgentKit/Sources/AgentKit/ACP`. Moved out of `Packages/AgentKit/CLAUDE.md`.

- **ACP** (`ACP/`, plan: `docs/ACP_PLAN.md`) — Agent Client Protocol client support, additive in this target: handwritten `JSONValue`-based JSON-RPC (`JSONRPC.swift`), typed v1 subset (`ACP.swift`, unknown variants tolerated), injected `ACPTransport` (never spawned here; in-memory pair in `Testing/`), `ACPConnection` (framing, correlation, concurrent request handlers), and `ACPClientSession`, which maps `session/update` to `AgentEvent` with exactly one terminal `.runEnded` and bridges `session/request_permission` to `ApprovalRequest`. A card nobody answers is finished, never left open: Stop and a disconnect answer `cancelled` and emit the call's `.toolCallFinished` ("Cancelled before it was answered…"), and a timeout (`permissionTimeout`, 300 s in Umbra) does the same with "Permission request timed out…", which stays in front of the agent's own later update for that call; an agent that then ends the turn `cancelled` without Stop (Codex does) ends the run `.failed(unansweredPermissionEnding)`, not `.stopped`. Measured against the real adapters on 2026-11-12 (`ExternalACPLiveTests`, `UMBRA_LIVE_ACP_PERMISSIONS=1`). Host effects go through `ACPHostServices`; Umbra provides the process transport over SubprocessKit. Tests: `Tests/AgentKitTests/ACP/` with a scripted fake-agent oracle. *Recordings* (`ACPRecording.swift`): `ACPRecordingTransport` reports every frame crossing a transport; `ACPReplayTransport` (`Testing/`) plays a recording's agent side back to a live client, matching its frames and remapping request ids, and lists `mismatches` (`docs/harness/agent-harness-11.md` item 3). Tests: `ACPReplayTests`. Phase 2 (same folder): `ACPAgentEndpoint` wraps any `AgentSession` as an ACP agent (reversed mapping; option-less `ask_user` elicits free text over `elicitation/create`; a local file miss reads the remote client when it advertised `fs.readTextFile`, via `ACPRemoteWorkspace`; sessions persist through an optional `SessionStore`, so `session/load` survives a restart and is advertised only then); Umbra ships it as the `UmbraACP` stdio executable built from the user's configured provider. *Provider support* (2026-11-16): `ACPSessionModelState` reads the session response's `models` (unstable in the spec; Kiro and Cursor send it) and `setModel` sends `session/set_model` only for an advertised id; `ACPConfigOption.category`. `observeConfigOptions` tells the host about every `config_option_update`, run or no run, and `setConfigOption` keeps an update that was handled while its request was out rather than overwriting it with the (possibly older) answer (`configOptionsRevision`; Kiro answers a model change with the old options and sends the new effort levels as an update). Test: `configOptionUpdatesReachTheObserver`. `ACPAuthenticationPolicy`: `.automatic` (default, authenticate with the first method on `-32000`) or `.userInitiated` (never; `authenticate(methodId:)` for an explicit sign-in). `ACPClientExtension` (`ACPClientExtension.swift`) is consulted only for methods the session does not implement (unclaimed requests get `-32601`, notifications are dropped, another session's traffic is refused/ignored); it reaches the user only through `emitToolCall` (deduplicated against standard `tool_call` updates), `finishToolCall`, `emit`, `askQuestion` → `ACPQuestionOutcome` and `proposePlan` → `PlanDecision?`, answered by `answerQuestion`/`resolvePlan` and bounded like permission cards (Stop, disconnect, `permissionTimeout`, and `.cancelled` at once with no run on screen). `Extensions/CursorACPExtension.swift` maps `cursor/ask_question`, `create_plan`, `update_todos`, `task`, `generate_image`. Tests: `ACPProviderExtensionTests`.
