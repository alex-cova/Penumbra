# AgentKitApple

Loaded when working under `Packages/AgentKitApple`. Apple's foundation models as an AgentKit `LLMClient`: the on-device model that ships with Apple Intelligence (`SystemLanguageModel.default`, macOS 26) and Private Cloud Compute (`PrivateCloudComputeLanguageModel`, macOS 27). Depends on `AgentKit` and the system `FoundationModels` framework; only Umbra and AgentEval link it. Declares macOS 26 (the other packages declare 14); the PCC code sits behind `#available(macOS 27, *)`. Public API only, no entitlement, nothing downloaded.

- **Providers.** `AppleLLMClient(kind:)` with `providerID` `apple` / `apple-pcc`. `AppleModelAvailability` mirrors `MLXAvailability`: `status(for:)`, `message(for:)` (the text Umbra shows), `contextSize`. The on-device window is 8,192 tokens on this Mac (macOS 27; 4,096 on 26) and PCC's 32,768, read at run time.
- **The tool bridge** (`AppleSessionHost`, an actor; the framework seam is `AppleResponseSource`). The framework *runs* a `Tool` in the middle of a response and waits; AgentKit's loop wants a turn to end with the call so it can check permissions, ask the user and run the tool itself. Each declared tool is an `AppleProxyTool`. When the model calls one, the host reports `toolCallStarted/Finished`, leaves the framework's call suspended, and (after a 30 ms settle window, so calls made together share a turn) ends the turn with `finished(.toolCalls)`. The next request carries the outputs; if it is exactly what the host expects (the items it has seen plus a `toolOutput` for each waiting call) the suspended calls are resumed and the **same response** goes on, streaming into the new turn. A new user message after a finished answer goes to the same live session. Anything else (compaction, a changed system prompt or tool list, a note the loop inserted between outputs, a stop, a failure) tears the session down, fails the waiting calls with `CancellationError` and rebuilds from `AppleTranscript` with one prompt. A rebuild that ends in tool outputs sends calls and results as one prompt ("Results of the tools you called…"), because a transcript ending in tool output has nothing to answer. Call ids are made here (`call_…`); the framework gives none.
- **Snapshots to deltas.** `streamResponse` yields cumulative text. The host emits the new suffix; text that does not extend what was emitted (a fresh answer after a tool call) is emitted whole. The framework's text after a tool call is not guaranteed to continue the earlier text, so both shapes are handled and tested.
- **Context.** `preflight` throws `LLMError.contextLengthExceeded` when the estimate (`ContextBudget`, the one compaction uses) leaves less than an eighth of the window free, so the session compacts. The framework's own overflow error maps to the same. `AppleSourceConfig`/`AppleTranscript` pass the system prompt as `Transcript.Instructions` with the tool definitions: a session with **no** instructions answered "what is my name?" with "I don't have a name" even though it had been told (also with a plain `respond`), so the smoke tests set a system prompt.
- **Usage.** macOS 27 reports `ResponseStream.Snapshot.usage` (cumulative); the host reports input as given and output as the difference across turns. Without it the `ContextBudget` estimate is reported so the context ring still moves.
- **Errors** (`AppleErrorMapping`). Context exceeded → `contextLengthExceeded`; guardrail or refusal → `finished(.contentFilter)`; rate limit and PCC quota → `rateLimited(retryAfter:)`; PCC network failure → `connectionLost` / `interruptedAfterOutput`; PCC service unavailable → `server(503)`; anything else → `api` with the innermost underlying error's domain and code (the framework throws an `NSError` whose own description is "error -1").
- **Tool choice.** `ToolChoice.disabled` is `toolCallingMode: .disallowed` on 27 (`supportsDisabledToolChoice`); on 26 the closing turn goes out without tools. Reasoning is not mapped: the provider offers "Off" only.
- **Schemas** (`AppleToolSchema`). `ToolDefinition.schema(strict: false)` (or the MCP raw schema) → `DynamicGenerationSchema`: objects, arrays, strings, numbers, booleans, enums. `anyOf`, `$ref` and untyped fields become a string. A tool whose schema cannot be built is left out of the session.
- **Code is gated, Chat is not.** About 5,000 tokens of instructions and tool definitions are resident in a Java project (measured: the 12 core tools are ≈1,500 tokens and the prompt ≈1,000, before Umbra's IDE tools), so the 8K on-device window is chat only; Umbra's gate is `IDEAgentSettings.minimumAppleCodeContext` (16,384) and `currentSession` refuses a session whose overhead is over half the window. A run on the on-device model through AgentEval (`--provider apple`) hallucinated the contents of a file it had not read; that is the model, not the bridge.
- **Not verified here: Private Cloud Compute generation.** `status` says available and the window is read (32,768), but the first request from the test host fails with `ModelManagerServices.ModelManagerError 1046`; confirm from the app (and whether it needs an entitlement) before relying on it.
- **Tests.** `swift test` runs the unit tests: `AppleSessionHostTests` (a scripted `AppleResponseSource`: deltas, a tool call that ends a turn and resumes the same response, parallel calls, continuing a session, rebuilds, stop, errors), schema, transcript and error-mapping tests. The real-model suite is opt-in: `AGENTKIT_APPLE_SMOKE=1 swift test --filter AppleSmokeTests` (needs Apple Intelligence on; covers a greeting, session reuse, a tool round trip and compaction on overflow), `AGENTKIT_APPLE_PCC_SMOKE=1` for PCC.
