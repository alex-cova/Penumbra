# GitHub test strategy

Use the existing Swift Testing/XCTest targets and deterministic fixtures. Inject a scripted transport, clock, account repository, credential store and isolated preferences. A Foundation URLProtocol test double covers generated request methods, headers, body encoding and cancellations. Add a local loopback server only for integration behavior the double cannot simulate, such as live redirect and streaming limits. Standard CI uses no network credentials, user Keychain entries, live GitHub requests, or external agent. Keep signed-app Keychain and live GitHub verification separate.

| Area | Verification |
| --- | --- |
| Auth and Keychain | Pending/slowdown/expiry/cancel/denial, malformed and oversize responses, browser URL checks, two account identities, duplicate sign-in, refresh rotation and persistence failure, sign-out while refresh awaits, and account restoration. Search captured logs and user-visible errors for synthetic secret values. |
| Transport | TLS and origin policy, cancellation, suspended clock, retries only where eligible, primary and secondary rate limits, ETag isolation and 304 miss, redirect/pagination validation, body caps, and no token on second-origin downloads. |
| Git and workspace | Git fixture repositories with multiple remotes, config rewrite, SCP syntax, invalid authority, distinct push URL, linked worktrees and root transitions. Run existing GitIntelligence and Penumbra Git suites. Use suspending stubs to prove network cancellation and stale-state suppression on workspace replacement, close and account changes. |
| Review | Added/deleted/renamed, binary, unsupported encoding, truncated patches, moved/outdated anchors, fork SHA, conflicting head changes, and both split and unified gutter events. Confirm no worktree write from review navigation. |
| Resource writes | Exact request counts for approved, changed, declined, invalid, expired and reused authorization. Test partial publishing success, 202 async outcomes, lost response, permission failures, stale head and rulesets. |
| UI and agent | Snapshot from idle to loading, data, empty, stale, retry, signed out and inaccessible. Cover switch, cancellation, keyboard focus, VoiceOver labels, and light/dark theme manually with native UI automation for actionable state transitions. Test mock native agent and ACP boundaries with injection-like text and secret sentinels. |

For each phase, run the full newly affected feature suites and the covered transitive regressions, build SwiftPM and the app distribution target, and record test totals with exact passed, failed, and skipped counts. Record which tests used prebuilt binaries. Compare counters and profiling runs using the [performance budget](PERFORMANCE_BUDGET.md). Publish an explicit device authorization and permissions smoke test checklist for an approved disposable GitHub installation. Test public/private repos, org restrictions, account switching, and signed Keychain restart on that installation. Record live operations independently from fixture results.
