# GitHub security model

## Credentials and authority

GitHub is the authority for the effective combination of account, installation, permissions and repository rules. Model each GitHub identity using verified numeric user ID, public Client ID and API authority. Only Settings initiates interactive authorization. The standard browser holds GitHub login state. The native sheet displays only the short-lived user code and uses the fixed verification URL. Keep device code, access token and refresh token in memory for the minimum necessary duration.

Store the rotating token pair and expirations in a separate non-synchronizable generic-password Keychain service scoped to Umbra's distribution identity. List account IDs and display logins from Keychain attributes without loading tokens. Store workspace account selections separately when the feature is wired into the UI. Use the macOS data-protection Keychain with device-only unlocked accessibility, and verify item access for each signing configuration. Keychain writes must be update-or-add with duplicate handling, and concurrent rotation/sign-out must be serialized. Keep device and refresh parameters out of URL query strings in application-generated requests. Use typed errors and structured allowlisted diagnostics with endpoint labels and numeric status. Exclude raw request, response, URL query, environment, signed URL, token and credential descriptions from logs, analytics, Git console and AI context. Never pass GitHub credentials through process arguments, environment, clipboard, or Git config. Copying a user code is a deliberate short-lived device authorization action.

Use ephemeral HTTPS transport with fresh request construction, exact allowed host/port, ordinary TLS validation, and no automatic redirects on credential-bearing requests. Validate pagination origin and route before reuse. Reject userinfo, unexpected query parameters and ambiguous path encodings. For a later validated asset redirect, use a separate request without GitHub authorization and discard the signed location after use. Browser-facing links have separate scheme and authority validation. Enforce bounded responses during receipt.

## Mutation authorization

The first repository client exposes only typed read operations. Authentication POSTs are reached through a user-initiated sign-in flow or its session renewal. Future resource mutations use typed intent containing host, account, immutable repository identity, operation and target, payload and revision preconditions, plus originating window and generation. Confirmation authorizes that specific intent only. Consume approval once at the dispatch boundary after revalidation. Account, root, repository, and head changes invalidate stale confirmations. Agent modes and agent tool input cannot mint approvals. Approval, transport and Git command paths must all pass negative tests for the network request count. Opening or refreshing a view must be read-only.

Publishing is a multi-step confirmed operation with visible recovery and no implicit repository deletion or commit creation. Fork checkouts and existing SSH/HTTPS transport keep the Git trust policy. Any direct token use with Git needs a validated remote, approved operation, authenticated scoped askpass handoff, and defense against Git URL rewriting and credential helper persistence.

## Untrusted remote content

Render titles, comments, logs, release notes, filenames, and AI tool data as untrusted. Bound Markdown parsing, strip unsafe links and HTML capabilities, and disable remote image fetching by default. Validate path containment and symlink resolution before opening local files. Archive extraction requires size and entry limits and rejects traversal and escaping links. Never execute text, attachments, suggestions, or workflow output automatically. Preserve review draft provenance and use exact pinned anchors. Agent prompts treat remote text as data, apply existing provider consent, and expose only bounded selected content. External ACP agents have no access to this credential service through Umbra tools or launch environment.
