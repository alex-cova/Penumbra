# Umbra GitHub architecture audit

Audit date 2026-11-24. Paths are relative to the repository root.

| Area | Current implementation and implications |
| --- | --- |
| Git | `Packages/GitIntelligence/Sources/GitIntelligence/GitRepository.swift` discovers roots with Git and exposes status, refs, history, blobs, staging, and local mutations. `GitRepository+Remotes.swift`, `+Branches.swift`, `+Operations.swift`, and `+Clone.swift` cover remotes, transport, and clone/init. `Process/GitRunner.swift` uses SubprocessKit and provides progress/cancellation. Reuse these entry points for Git operations. REST is for hosting resources. |
| Repository lifetime | `Umbra/Sources/Umbra/Workspace/IDEWorkspace.swift` owns `IDEGitStatusModel` per window, sets its root with workspace changes, refreshes it after file-watcher batches, and calls `setRoot(nil)` during teardown. `Git/IDEGitStatus.swift` tracks refresh epochs and publishes `GitWorkspaceSnapshot`. The snapshot exposes branch and upstream, while remote details are a separate Git read. Add a coalesced discovery trigger keyed to root, remote configuration changes, and actionable upstream changes. Avoid reacting to every status publication. |
| Remote recognition | `Git/IDEGitHostingURL.swift` builds browser URLs for several providers and uses host heuristics for presentation. API routing needs an explicit, exact authority policy. Reuse Git's parsed remote data and preserve browser-link behavior. Resolve upstream from fetch and branch tracking data. Treat push URL selection as an independent decision. `remoteDetails()` shells out to `git remote -v` and currently maps errors to an empty list. Add an error-preserving Git entry point if discovery needs to distinguish no remotes from config failure. |
| Git trust and authentication | `Git/IDEGitTrustRunner.swift` applies execution policy with Git config overrides. `Git/IDEGitAskPass.swift` routes prompts through a per-command Unix socket session for Git and SSH. Clone UI is already available through `IDEWorkspace+GitSetup.swift`, `IDEGitCloneModel.swift`, and existing sheets. The current credential mechanisms should remain usable for SSH and HTTPS. Any future automatic HTTPS credential injection needs a separate review of Git config rewrites, helpers, hooks, and process exposure. |
| Credential storage | `Umbra/Sources/UmbraAgentSupport/IDEAgentKeyStore.swift` defines an injectable store, an in-memory fake, and a Security.framework generic-password implementation. Its host-keyed agent service and delete-then-add update are unsuitable for rotating GitHub token pairs. Follow its injection pattern and use a separate service with atomic per-item updates and noninteractive reads. |
| Diff and gutter | `Diff/IDEDiffRequest.swift` already represents fixed text, immutable Git revisions, and working tree sources. `IDEDiffSessionStore`, `IDEDiffSession`, `IDEDiffComputer`, and `IDEDiffViewerView` manage rendering and session lifetime. `Sources/Penumbra/TextView/Gutter/GutterLineMarker.swift` and `GutterAnnotation.swift` provide extension markers and their presentation path. Anchor review content to the immutable comparison and reuse marker hit testing. Add logical source identity for remotely loaded text instead of using entire text values as tab identifiers. |
| Problems | `Panels/IDEProblemsStore.swift` aggregates diagnostic sources. Reuse navigation and diagnostic conversion for verified CI file annotations, with source ownership and cleanup. PR threads remain review data with their own lifecycle. Validate file paths and revision before navigating into a working tree. |
| Commands and settings | `IDEWorkspace.configurePalette` and `Git/IDEWorkspace+GitPalette.swift` register workspace commands. `App/IDEAppCommands.swift` adds menu commands and `Workspace/IDEToolWindows.swift` provides tool-window chrome. `Settings/IDEPreferencesDomain.swift` and `IDEPreferencesDetail.swift` route settings. Follow those entry points. Language modules supply a contribution precedent, but GitHub is a workspace service. |
| Networking and cache | `HTTP/HTTPClient.swift` uses an ephemeral session for interactive request documents with configurable cookies and redirects. `Packages/AgentKit/Sources/AgentKit/MCP/MCPHTTPTransport.swift` demonstrates an explicit redirect policy. Reuse Foundation and the redirect pattern. The inspected clients have different authorization and lifecycle contracts. GitHub requires its own bounded, account-scoped response cache and typed retry behavior. |
| Native agent and ACP | `Agent/IDEAgentConversation.swift` builds the native tool list. `Agent/IDEAgentGitTools.swift` bridges existing Git features. AgentKit handles permissions, while `Agent/ACP/IDEACPHostServices.swift` and ACP transports expose specific host capabilities to external agents. Reuse native consent and presentation, return bounded untrusted data, and add ACP capabilities only through explicit host support. |
| UI and design | `DesignSystem/IDEThemeStore.swift`, `IDEAppearance.swift`, `Appearance/IDEUIColorScheme.swift`, `IDEChromeTabItem.swift`, and `IDEMotion.swift` provide window appearance, chrome, and motion. Reuse the active theme and native accessible controls. Source-control panels, comparison tabs, settings, and clone sheets establish the interaction patterns. Keep feature observation local to the GitHub surface. |
| Worktrees | `GitRepository+Worktree.swift` offers porcelain list/add/remove. `Agent/IDEAgentWorktreeStore.swift` manages agent-created worktrees. `GitMutationLane.swift` serializes managed operations by supplied repository key. The current lane keys off the per-worktree Git directory, while refs and some configuration are shared. A PR checkout needs common-directory coordination verified across linked worktrees, separate working tree identities, safe ref ownership, and a dirty-window policy. Avoid adopting or removing user-created worktrees implicitly. |
| Build and test | Umbra uses Swift tools 6.2, Swift 6 mode, and macOS 26 minimum. GitIntelligence uses tools 6.0, Swift 6 mode, and macOS 14 minimum. The Xcode target uses a synchronized Umbra sources group. Use the existing Umbra module and test target. `docs/CI.md` describes credential-free CI and fixture-based ACP UI testing. See [progress](PROGRESS.md) for this checkout's runs. |
| Performance | `docs/PERFORMANCE_RULES.md` requires no new per-keystroke work, no editor-buffer materialization on main, and cancellation for stale results. `InteractivePathTests`, `IDEHostEditCostTests`, and `Tools/PerfHarness` provide work counters and timing. Historical measurements in `docs/EDITOR_PERFORMANCE_REPORT.md` are context. Capture a paired baseline on the same checkout and machine before evaluating a runtime integration. |

The initial dependency direction is Umbra UI → GitHub workspace state → GitHub client/account services, with Umbra's existing Git, diff, diagnostic, and agent adapters at the app boundary. GitIntelligence, Penumbra, and AgentKit remain provider-independent. The starting worktree already contains edits in workspace and agent files, so later integration needs narrow patches against the current contents.
