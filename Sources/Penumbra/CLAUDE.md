# Penumbra text engine (`TextView`)

Loaded when working under `Sources/Penumbra`. Feature catalog and behaviour notes moved out of the root CLAUDE.md. Several bullets describe how Umbra (`Example/Umbra`) consumes these APIs.

**Editing & input**
- Full `NSTextInputClient` compatibility for native macOS text input, IME, and accessibility.
- Undo/redo with timed grouping (`TimedUndoManager`) so rapid typing coalesces into one undo step.
- Character-pair auto-insertion and skip-over-trailing (`CharacterPair`, delegate hooks).
- TextFormation integration for tab expansion, bracket pairing, and whitespace cleanup (`TextFormationController`).
- Language-aware indent on line break, block indent/unindent (`shiftLeft`/`shiftRight`), and auto-detect tab vs. spaces (`detectIndentStrategy`).
- Move selected lines up/down (`moveSelectedLinesUp`/`moveSelectedLinesDown`).
- Move statement up/down respecting syntax (`EditorActionID.moveStatementUp`/`Down`, `StatementRangeService` walks the tree-sitter node then reuses `MoveLinesService`; falls back to line movement without a tree).
- Duplicate lines (`duplicateSelectedLines`/⌘D) and delete lines (`deleteSelectedLines`/⌘⌫) — multi-caret aware, one undo step each.
- Join lines (`EditorActionID.joinLines`, `JoinLinesService`) — collapses the line break + next line's indent to one space, comment-aware, multi-line aware, multi-caret aware (each caret ends at its own join point), one undo step.
- **Enter key** (`Sources/Penumbra/TextView/Enter/`): `IndentController.insertLineBreak` delegates to `EnterController`, which asks host `TextView.enterHandlerDelegates` (`EnterHandlerDelegate` → `EnterEdit`, a single replacement so undo stays one step and multi-caret works) and then the built-ins: block comments (`/**` generates ` * ` + `*/`, continues the ` * ` prefix), string-literal splitting (`"abc" +`), and bracket splitting (`{|}`). Otherwise it indents: structure-aware for languages whose `TreeSitterLanguage.enterBehavior` sets `cStyleIndent` (`CStyleLineIndentProvider` — block indent in `{}`, continuation indent (2 levels) in `()`/after an unfinished expression, +1 after brace-less `if/for/while/else/do`, `case` bodies; on for Java via `EnterBehavior.java`), tree-sitter indentation scopes where defined, else a literal copy of the current line's leading whitespace (plain text included). Start New Line (`EditorActionID.startNewLine`, ⇧⏎ in the IntelliJ keymap, `TextInputView.startNewLine`) moves every caret to its line end and runs the same Enter there; ⇧⏎ with the completion popup open closes it instead of accepting (only an unmodified ⏎ accepts).
- Surround selection with a template (`TextView.surroundSelection(with:)`, `SurroundTemplate` — if/while/for/try-catch/brackets/quotes, per-language + registerable, expanded via `EditorIntelligence`'s `SnippetExpander` with `$TM_SELECTED_TEXT`).
- Reindent fallback (`TextView.reindentSelectedLines()`) — bracket-depth reindent used for `EditorActionID.reformatCode` when no LSP formatter is wired.
- **Keymap layer** (`Sources/Penumbra/TextView/Keymap/`): `TextView.keymap` holds `[KeyStroke: EditorActionID]` bindings resolved by `KeymapDispatcher` (generic two-step chords like ⌘K ⌘D, plus double-⇧ via `DoubleModifierDetector` on `flagsChanged`). Presets `Keymap.default_` (historical shortcuts) and `Keymap.intelliJ`. Actions the core doesn't own return `false` from `TextInputView.performKeymapAction` and fall through to `TextView.editorActionHandler` / registered `addKeyDownInterceptor`s. Invoke any action directly with `TextView.perform(_:)`. In Umbra, menu items whose key differs per preset take it from `IDEMenuShortcuts` (`Example/Umbra/IDEMenuShortcuts.swift`) instead of a literal `.keyboardShortcut`, because a menu key equivalent is handled before the editor and would shadow the preset's `Keymap` binding; add new preset-dependent menu commands there. IntelliJ-keymap feature work is tracked in `docs/INTELLIJ_KEYMAP_FEATURES_PLAN.md`. `EditorActionID.findNext`/`findPrevious` (⌘G/⇧⌘G) step through the last find query with the panel open or closed (`FindPanelController.findNext`); `goToMatchingBracket` (⌃M, `BracketNavigation`: a bounded text scan of ±4096 UTF-16 units, brackets `()[]{}` only, strings and comments not skipped); `unselectLastOccurrence` (⌃⇧G). `toggleBlockComment` (⌥⌘/): `BlockCommentDelimiters` on `TreeSitterLanguage` (`blockCommentDelimiters:`), `BlockCommentService` finds comments by a bounded text scan, not the syntax tree. Replace in Files (⇧⌘R in the IntelliJ column): `ProjectReplacePlanner` builds a `WorkspaceEditPlan` (same regex as the search via `WorkspaceSearchQuery.compiledRegularExpression()`), `IDEWorkspace.replaceInFiles` previews it in the Rename sheet, `IDEReplaceInFilesGuard` drops any edit whose text moved since the search, and `IDEWorkspaceEditApplier` writes. Find and Replace in Files share one `ProjectSearchFilter` (`Sources/EditorIntelligence/Search/`): a `FileMask` (`*.java, !*Test.java, src/**`; name patterns match file names, `/` patterns the root-relative path, `!` always wins, an invalid pattern matches nothing; excluded directories are pruned from the walk), a directory scope inside the root, or an explicit file set (Open Files, Changed Files from git); Umbra's drawer has the mask field and scope menu (`IDEFindInFilesScope`) and the Explorer has "Find in Files Here…". The Replace preview sheet uses `.diff` style: `WorkspaceEditPlanEntry.previewLine()` splits the line around the edit and the sheet shows the old and the new line (`.singleLine`, what Rename uses, is unchanged). Git (IntelliJ column): `GitRepository.log(path:)`/`existsInHead`/`revertToHead`; `IDEGitStatusModel.showFileHistory`/`revert`; Git menu with Pull ⌘T, Push ⇧⌘K, Revert File… ⌥⌘Z (confirms first; the tab reloads even if it had unsaved edits); the Source Control panel reverts several files (⌘/⇧-click multi-select, row context menu, Revert All…) through `IDEWorkspace.revertChanges` / `IDEGitStatusModel.revert(paths:)` → `GitRepository.revert(paths:)`, which reverts the files in `HEAD` (`pathsInHead`, one `ls-tree` per 200 literal paths) and reports the rest as skipped. Go to Tool Window (`goToTool`): `ToolWindowsPaletteProvider` / palette mode `.toolWindows`, fed by the host through `CommandPaletteController.toolWindowEntriesProvider` (Umbra: `IDEWorkspace.toolWindowEntries()`). View commands in Umbra: `selectAdjacentTab`/`focusAdjacentPane` (⇧⌘]/⇧⌘[, ⌥⇥ in the IntelliJ column), `toggleAllToolWindows` (⇧⌘F12), session zoom via `IDEPreferences.zoomPercent` (not saved; `applyTheme` scales `fontSize` by it), `clearTerminal` (per-tab `clearRequestID`; ⌘K while a terminal has focus). Debugger (`Example/Umbra/JavaDebugSession.swift`, JDI adapter in `Example/Umbra/Tools/JavaDebugAdapter`, rebuilt with its `build.sh` and committed as `build/java-debug-adapter.jar`, which the app copies as a resource — rerun `build.sh` after editing the adapter; the protocol, breakpoint properties, evaluator tiers, test debugging and the Debug tool window are described under **Debugger** in `Example/Umbra/CLAUDE.md`). `JavaDebugAdapterTests` and `JavaDebugSessionEvaluateTests` drive the real adapter against a JVM. `JavaDebugSession` must read the adapter off the main actor. Program output: the adapter reads the target's stdout and stderr separately and sends `output` events of up to 200 `{stream, text, partial}` lines (every ~50 ms; a line still open after ~100 ms of silence goes out `partial: true` and the next chunk of that stream continues it; breakpoint log lines are stream `log`), and `terminated` carries the exit code of a launched program; `JavaDebugSession.console` (`IDEDebugConsoleLog`, bounded chunk list, cleared when a session starts) feeds the Debug panel's Console pane (`IDEDebugConsoleView`, read-only: the program's stdin is not connected; a Gradle attach session has no adapter-owned process, so its output stays in the Gradle tab). Run/Debug in Context (⌃⇧R/⌃⇧D, `IDEWorkspace.runInContext`, `JavaStructureProvider.caretContext`): a test method or class runs (or is debugged) as a test, a file with `main` as a configuration, anything else repeats the last one. `goToFileSymbol` (⌘F12, File Structure): palette mode `.fileSymbols` listing the focused document's declarations from `SymbolIndex.symbols(in:)` (`FileSymbolsPaletteProvider`, `CommandPaletteController.activeDocumentIDProvider`); `goToSymbol` (⌥⌘O in the IntelliJ preset) searches the open documents' symbols plus, for Java, every member the project's classes declare (`JavaIndex.members(matching:limit:)` in `Sources/JavaIntelligence/Index/JavaMemberIndex.swift`: methods, fields, enum constants and record components, not constructors, inherited members or javac's `values`/`valueOf`/record accessors; camel-hump matched; a table built lazily on the first query and dropped on `setSources`, with a small overlay table for open buffers, so there is no shard format change; entries are bucketed by word-initial letter and pre-checked before `CompletionMatcher`, ≤10 ms p95 for 150,000 members, `PerfHarness java-members`). The index stores no member positions: `JavaMemberLocator.nameRange(of:in:)` finds the member in its file as it is now on selection, and falls back to the class. `IDEJavaMembersPaletteSource` feeds the rows into the Symbols section through `CommandPaletteController.symbolsAdditionalItems`, and `symbolsExcludedDocuments` leaves the open Java files' tree-sitter symbols out so nothing is listed twice. `goToNextProblem`/`goToPreviousProblem` (F2/⇧F2): the core doesn't own a problem list, so Umbra handles them (`wireProblemNavigation` → `IDEWorkspace.goToProblem`) with `ProblemNavigator` over `IDEProblemsStore.files`; errors and warnings only, ordered by path, line, column, wrapping. `showParameterInfo` (⌘P): asks `signatureHelpProvider` at the caret from anywhere in the argument list. `goToTypeDefinition` (⌃⇧B, `NavigationKind.typeDefinition`): `JavaGoToTypeDefinition` types the expression or declaration under the caret with `JavaExpressionTyper` and goes to that type's declaration (a value of type `T` goes to the type parameter when the current file declares it, via `Typed.typeVariable`, else to its bound); `LSPTypeDefinitionProvider` is the LSP one. `completeStatement` (⇧⌘↵): `StatementCompletionService` decides on the caret line alone (close brackets and strings, then `;` or ` {}`), then Enter splits the braces; only for languages with `enterBehavior.cStyleIndent`, otherwise it is Start New Line. In Umbra, `.http` files show a `play.fill` gutter button on each request (`IDEWorkspace.refreshHTTPGutter`, refreshed on the debounce shared with the Java run button; `HTTPRequestParser.requestLocations`).
- Configurable `keyDownHandler` (single) or `addKeyDownInterceptor` (composable) for custom keybindings, both run before the keymap.
- Floating caret (long-press drag) for precise cursor placement on touch/trackpad.
- Smart text substitutions: autocorrection, smart quotes/dashes, spell checking (via UIKit-compat properties).

**Selection**
- Single and multiple cursors (`selectedRanges`, Option-click to add cursors, ⌥⌘↑/↓ to clone a caret vertically, `undoLastCaretChange()`/⌘U to step back).
- IntelliJ caret stops (`TextView/Core/TextInputView+CaretStops.swift`, applied to every caret): ⌥←/→ (+⇧, and ⌥⌫/⌦) use `WordCaretStops` (a port of `EditorActionUtil.isWordBoundary`: identifier and punctuation runs are words, whitespace is skipped, forward stops at word ends, backward at word starts, line breaks are stops; camel humps behind `TextView.isCamelHumpsNavigationEnabled`, off by default); ⌘←/→ and Home/End use Smart Home (`LineBoundaryNavigator`: first non-whitespace ↔ column 0, end of code before trailing whitespace, soft-wrap aware; `TextView.isSmartHomeEnabled`, on by default); ⌘↑/↓ go to the document start/end. Double-click word selection still uses `TextInputStringTokenizer`.
- Column/block (rectangular) selection: Option-drag or ⌃⇧-arrows (`beginBlockSelection(at:)`/`extendBlockSelection(to:)`/`extendBlockSelection(in:)`), with multi-caret-aware copy/cut/paste. Sticky column mode (`TextView.isColumnSelectionModeEnabled` / `EditorActionID.toggleColumnSelectionMode` / ⌘⇧8): the rectangle survives ordinary selection assignment and grows with plain arrows until toggled off.
- Progressive semantic selection (`EditorActionID.expandSelection`/`shrinkSelection`, ⌥↑/⌥↓ in the IntelliJ keymap): `SemanticSelectionController` walks a ladder of word → enclosing tree-sitter node ancestors (injection-aware via `TreeSitterInternalLanguageMode.treeSitterNode(at:)`); without a tree it degrades to word → line → paragraph → document.
- Select word (double-click), paragraph (triple-click), and line selections (`addSelectionsOnEachLine`).
- Select whole line(s) touched by each caret (`selectLines`/⌘L), including the trailing break.
- Select next occurrence (`selectNextOccurrence`/⌘⇧D), skip the current one (`skipCurrentOccurrence`/⌘K ⌘D), or select all occurrences (`selectAllOccurrences`/⌘⇧L).
- Selection handles and caret rendering with customizable colors.
- Shift-click range extension; column-aware line movement.
- Multi-cursor-aware indent/outdent, move-line, newline, and undo (the whole caret set is restored, not just the primary caret).

**Layout & display**
- Red-black-tree-backed `LineManager` for O(log n) line lookups on large documents.
- Line wrapping with configurable break mode; optional right-margin ruler at a configurable column (hairline-only by default, with optional reformatting-guide shading).
- Gutter with dynamic-width line numbers, leading/trailing padding, and line-selection highlights. The whole gutter is capped at `GutterWidthService.maximumGutterWidth` (70 pt): the line-number column gives way to the other columns, so digits that do not fit are clipped (defaults: decorations 16, ribbon 12, marker slot 16, padding 2+2).
- Gutter decorations and clicks (`TextView.gutterDecorations`, `GutterDecoration`, `GutterDecorationView`): icons in the leftmost column, each with an optional `tintColor`, a small `badgeSymbolName` drawn over it and a host `id`. They follow line-break edits with the line markers' rules (`GutterLineMarkerEdit.newRow(forRow:)`; one on a deleted line is dropped) and `gutterDecorationsDidMove` hands the host all of them afterwards, so it can keep its own record (Umbra's breakpoint lines) in step; the work is bounded by the number of decorations. `gutterDecorationHandler` gets clicks on a decoration; `gutterLineClickHandler` (`GutterLineClick`: line, `isSecondary`, event) gets clicks on a line number or an empty part of the decoration column — a plain click on mouse-up and only without a drag (a drag from the gutter still selects lines, the pending click lives in `TextInputView.pendingGutterClick`), a right or ⌃-click at once; returning `false` lets the click place the caret as before. The folding ribbon, line markers and annotations keep their own clicks. `alwaysShowGutterDecorationColumn` keeps the column when empty so the text does not move when the first breakpoint appears; setting decorations also marks the text view for layout (the column's frame is set there). `contextMenuItemsProvider` (`EditorContextMenuContext`: click offset, selection) appends host items to the editor's context menu (`EditMenuController.additionalItemsProvider`). `supplementaryInlayHints` is a second inlay-hint list shown with `inlayHints` (Umbra's inline debugger values next to parameter hints). Tests: `GutterLineClickTests`.
- Line-marker column (`TextView.lineMarkers`, `GutterLineMarker`, `GutterLineMarkerView`) between the line numbers and the fold ribbon: one vector-drawn icon per line (`GutterLineMarkerView.maximumSlots`; extra markers on a line are not drawn) (`GutterLineMarkerGlyphs`: implementing/implemented/overriding/overridden/sibling-inherited/recursive-call), tooltips, `lineMarkerHandler` clicks. Markers live in a line-sorted `GutterLineMarkerStore` and follow edits until the host replaces them: `TextInputView.replaceText` describes a line-break edit in rows (`GutterLineMarkerEdit`, a constant number of `LineManager` lookups) and the store shifts the markers below it, drops those on deleted lines and merges joined ones, like IntelliJ's range markers — never a per-marker line lookup; the column width (slot count) is only recounted when markers are replaced, dropped or merged. `reservedLineMarkerSlots` keeps the column's width while markers are still being computed, so the text does not shift when they arrive (Umbra reserves `TextView.maximumLineMarkerSlots` for Java files together with `alwaysShowGutterDecorationColumn`, in `scheduleJavaLineMarkers`). `GutterLineMarkerView` is viewport-sized (IntelliJ paints only visible lines), so every redraw — scroll, edit, fold, new markers — is bounded by the visible rows. `PerfHarness enter-session` measures Enter with markers on every method line (`markers_top`/`markers_middle`, `set_line_markers`). Umbra fills it for Java from `JavaLineMarkerProvider` (`Sources/JavaIntelligence/LineMarkers/`; per-kind toggles under Settings › Java › Gutter Icons); ↑ runs `EditorIntelligenceController.navigate(kind: .superMethod, atUTF16Offset:)`, ↓ `.implementation`.
- Annotation column (`TextView.setGutterAnnotations(_:edited:)`, `GutterAnnotation`, `GutterAnnotationView`/`GutterAnnotationStore` in `Sources/Penumbra/TextView/Gutter/`) between the gutter decorations and the line numbers: display-only text per line (consecutive lines sharing an `id` show it once), a tooltip on hover, no host types. The store keeps one `Int32` per row and follows edits like the line-marker store (a splice for line-count changes); lines an edit touched show the `edited` annotation until the host sends fresh ones. Viewport-sized like the marker column. Umbra fills it with Git blame (`Example/Umbra/IDEGitBlame.swift`: `IDEBlameController` runs `GitRepository.blame` against the live buffer off the main actor, per file, refreshed on save and git refresh; Git ▸ Show Git Blame, no key).
- Line backgrounds (`TextView.lineBackgrounds`, `LineBackground` in `TextView/Highlight/LineBackground.swift`): full-width bands behind whole lines (a `lineCount` of 0 draws a 2 pt rule at the line's top), non-overlapping, sorted in `LineBackgroundStore`. They follow line-break edits like the line markers (`GutterLineMarkerEdit`) and are cleared by `setState`. `LineBackgroundView` paints them under the glyphs for Core Graphics; with Metal, `CanvasPaintSpec.lineBackgroundFills` replays them into the canvas underlay. Only bands touching the visible rows are looked up. Umbra's diff viewer uses them with `yPosition(ofLine:)` / `line(atYPosition:)` (content-space geometry, folds included) and `foldingProviderOverride` (a host `FoldingProviding` that replaces the language's fold regions; `CodeFoldingManager.overrideProvider`). An annotation column also reserves gutter space when line numbers are off (`GutterWidthService.reservesGutterSpace`). Tests: `LineBackgroundTests`.
- Customizable themes (`Theme`, `DefaultTheme`, `HighlightName`) with font trait overrides, line height, and kern.
- Invisible-character rendering (tabs, spaces, non-breaking spaces, line breaks, soft line breaks) with custom symbols.
- Minimap with viewport indicator and click/drag scrolling (`showMinimap`).
- Floating overlay scrollers (`showsScrollers`, `Sources/Penumbra/TextView/Scroller/`): `TextView` is a clip-view-backed `UIScrollView` shim, not an `NSScrollView`, so AppKit provides no scrollers — `ScrollerOverlayController` owns a vertical and a horizontal `OverlayScrollerView` (geometry in the pure `ScrollerGeometry`) that fade with scrolling, widen on hover, and honor the system "Show scroll bars: Always" style. The vertical scroller is suppressed while the minimap is shown (its viewport indicator serves that role); the horizontal one is independent. Umbra exposes it as the `showScrollbars` preference.
- Background document preparation via `TextViewState` (parse + highlight off main thread before `setState`).

**Syntax highlighting**
- Incremental Tree-sitter parsing with language layers and injected-language support (e.g. CSS in HTML).
- Pluggable highlight providers (`HighlightProviding`): Tree-sitter queries + LSP semantic tokens (`SemanticTokenHighlightProvider`).
- `EmphasisManager` for transient highlights (search matches, bracket pairs, diagnostics).
- Bracket-pair matching with flash/emphasis at caret (`BracketMatchingController`).
- `syntaxNode(at:)` for querying the AST at a byte offset.

**Code folding**
- IntelliJ-style layers: `FoldingProviding` / `FoldingDescriptor` in `EditorIntelligence`, `CodeFoldingManager` (async descriptor fetch with generation stamp), `FoldingModel` / `FoldRegion` in Penumbra (`isLineFoldingEnabled`).
- Built-in providers: `TreeSitterFoldingProvider` (primary when a tree-sitter language mode is active; per-node placeholders like `{...}` / `/*...*/`) and `IndentationFoldingProvider` fallback; hosts can override via `EditorIntelligenceServices.foldingProvider`.
- Collapse/expand by zeroing hidden line heights in `LineManager` (no separate scroll model); gutter fold ribbons (`FoldRibbonView`), per-region placeholder chips, hover preview of collapsed bodies (`FoldPreviewController`), and editor actions (collapse/expand block, all, recursively — IntelliJ keymap ⌘-/⌘+, ⌘⇧-, ⌘⇧+, ⌘⌥-, ⌘⌥+).

**Search & replace**
- Programmatic search API (`SearchQuery`) with contains, full-word, starts/ends-with, and regex modes; case sensitivity and scoped range.
- Regex capture-group replacements (`$0`, `$1`, …) and batch replace (`BatchReplaceSet`).
- Built-in find/replace panel (`FindPanelController`, `showFindPanel`/`hideFindPanel`/`toggleFindPanel`).
- `UIFindInteraction` integration for system find UI.
- Highlighted-range navigation (`selectNextHighlightedRange`, looping modes).

**Navigation**
- Go to line (`goToLine`) with selection-at-beginning/end options.
- Navigation jumps (Go to Definition/Implementation/Super Method, gutter markers, ⌘-click, structure) center their target with `TextView.scrollRangeToCenter(_:)` (deferred until the view has a height); in Umbra a jump into another open tab goes through `IDEWorkspace.selectTab`, and one into a still-loading tab is applied by `IDEEditorPaneHost.pendingReveal`.
- `TextLocation` ↔ byte-offset conversion for line/column addressing.
- Cursor history (`TextView.navigationHistory`, `NavigationHistory`, `EditorActionID.navigateBack`/`navigateForward`, ⌘[ / ⌘]): a bounded back/forward stack of `NavigationEntry` (documentID/url/`TextLocation`) fed by significant cursor moves and `recordNavigationCheckpoint()` before programmatic jumps (`goToLine`, `selectHighlightedRange`). `TextView.navigationHistory` is settable, so `EditorWorkbench.navigationHistory` (one shared instance) + `PenumbraWorkbenchEditorAdapter.bindNavigationHistory(to:document:)` + `onOpenHistoryEntry` give cross-document ⌘[ end-to-end (wired in `Example/Umbra`).
- Command palette (`CommandPaletteController` in `Sources/Penumbra/TextView/CommandPalette/`; model/engine in `Sources/Penumbra/Workbench/CommandPalette/`; `Sources/Penumbra/EditorChrome/CommandPaletteView.swift`): Search Everywhere (⇧⇧), Find Action (⌘⇧A), Recent Files (⌘E), Go to File, Go to Line (⌘G, `EditorActionID.goToLine`), Find in Files (⌘⇧F, `EditorActionID.findInFiles`, backed by `EditorIntelligence.ProjectSearchEngine` when `CommandPaletteController.projectSearchEngine`/`workspaceRoot` are set) — a `SearchEverywhereEngine` fans a debounced query to concurrent `SearchEverywhereProvider`s (built-ins: commands/files/recent/symbols/go-to-line/in-buffer-text/project-search; host-extensible) and renders grouped results with `FuzzyMatcher.rankedWithMatches`-driven character highlighting. A leading sigil narrows the sources per keystroke in every palette mode, not just Search Everywhere (`PaletteQueryScope`: `>` commands, `@` symbols, `/` files, `#` in-buffer text, `:` go-to-line — Sublime's Goto Anything). `CommandRegistry.registerBuiltInActions(for:)` populates Find Action with every `EditorActionID` + its current shortcut. Recent Files (⌘E) is IntelliJ's switcher: a tool-window sidebar (`RecentFilesDestination`, filtered by the query too; Umbra builds it from `IDEWorkspace.toolWindows`, shared with the stripe), second-row preselection when the first row is the active file (`activeDocumentURLProvider`), ⌘E again toggles "Show edited only" (Umbra: recently edited files, persisted), ⌫ on an empty query removes a row (`onRemoveRecentFile`; Umbra closes clean tabs only) or hides a tool window, VCS-colored titles (`PaletteFileStatus`), ↩ with no match continues in Go to File. Recent Locations (`EditorActionID.recentLocations`, ⌘⇧E in the IntelliJ keymap, `recentLocationsProvider`) lists the navigation history's back stack.

**Diagnostics (rendering)**
- Squiggle underlines for `TextViewDiagnostic` values by severity (`DiagnosticEmphasisController`).
- `TextViewDiagnostic` carries `message` and `source`; `TextView.diagnostics(at:)` returns the ones covering an offset (hover tooltip, Show Error Description).
- Error stripe (`TextView.showsErrorStripe`, `errorStripeMinimumMarkHeight`; `ErrorStripeView`/`ErrorStripeController` in `TextView/Diagnostics/`): a 6 pt strip on the trailing edge with a tick per diagnostic at its fraction of the document height, over the minimap and under the scrollers, never taking mouse events. Positions are recomputed when diagnostics change and, debounced (0.2 s), when the content height changes — never per scrolled frame; at most `ErrorStripeController.maxMarks` ticks, most severe first.
- Current scope (`TextView.highlightsCurrentScope`, `ScopeHighlightController`): a bar in the fold ribbon (`FoldRibbonView.scopeRows`, via `LayoutManager.scopeHighlightRows`) beside the innermost fold region containing the caret. It uses the fold regions, so it needs `isLineFoldingEnabled`; lookup is debounced and skipped above `ScopeHighlightController.maxRegionCount` regions or with several carets.
- `TextView.addMouseMovedObserver(_:)` lets several owners watch pointer movement next to the single-owner `onHoverEvent` (used by the intelligence controller's hover tooltips).
