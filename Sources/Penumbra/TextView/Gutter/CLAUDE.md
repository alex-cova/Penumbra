# Gutter (`Sources/Penumbra/TextView/Gutter`)

Loaded when working under `Sources/Penumbra/TextView/Gutter`. Split out of `Sources/Penumbra/CLAUDE.md`.

- Gutter with dynamic-width line numbers, leading/trailing padding, and line-selection highlights. The whole gutter is capped at `GutterWidthService.maximumGutterWidth` (70 pt): the line-number column gives way to the other columns, so digits that do not fit are clipped (defaults: decorations 16, ribbon 12, marker slot 16, change stripe 4, padding 2+2).
- Gutter decorations and clicks (`TextView.gutterDecorations`, `GutterDecoration`, `GutterDecorationView`): icons in the leftmost column, each with an optional `tintColor`, a small `badgeSymbolName` drawn over it and a host `id`. `placement: .lineNumber` draws one in place of its line's number instead (`LayoutManager.lineNumberDecorations` → `LineNumberView.decoration`, Umbra's breakpoints); a click on it is a line-number click, and without line numbers it goes in the column. `placement: .lineMarkerColumn` puts one in the line-marker column right of the numbers (Umbra's run buttons): `GutterLineMarkerView.decorations` draws it in place of that line's markers, a click reaches `gutterDecorationHandler` (a secondary one `gutterLineClickHandler`, with `GutterLineClick.decoration` set so the host can tell a run button from the line's number), and the column is at least a slot wide while one is shown. `LineNumberView` lays its label out and `EditorLabel` redraws as soon as their size changes: the gutter narrows the digits when other columns appear, and a label drawn at the old width was stretched over the new one, off the column's right edge (`LineNumberViewTests`). They follow line-break edits with the line markers' rules (`GutterLineMarkerEdit.newRow(forRow:)`; one on a deleted line is dropped) and `gutterDecorationsDidMove` hands the host all of them afterwards, so it can keep its own record (Umbra's breakpoint lines) in step; the work is bounded by the number of decorations. `gutterDecorationHandler` gets clicks on a decoration; `gutterLineClickHandler` (`GutterLineClick`: line, `isSecondary`, event) gets clicks on a line number or an empty part of the decoration column — a plain click on mouse-up and only without a drag (a drag from the gutter still selects lines, the pending click lives in `TextInputView.pendingGutterClick`), a right or ⌃-click at once; returning `false` lets the click place the caret as before. The folding ribbon, line markers and annotations keep their own clicks. `alwaysShowGutterDecorationColumn` keeps the column when empty so the text does not move when the first breakpoint appears; setting decorations also marks the text view for layout (the column's frame is set there). `contextMenuItemsProvider` (`EditorContextMenuContext`: click offset, selection) appends host items to the editor's context menu (`EditMenuController.additionalItemsProvider`). `supplementaryInlayHints` is a second inlay-hint list shown with `inlayHints` (Umbra's inline debugger values next to parameter hints). Hints are painted from an `InlayHintAppearance` (font, text and chip colors) that each `LineInlayHint` carries, so a theme or font change re-typesets exactly the lines that have hints: the system UI font two points below the editor font by default, or the editor font one point smaller with `TextView.inlayHintsUseEditorFont`; colors from `Theme.inlayHintTextColor` / `inlayHintBackgroundColor` (nil: shades of the text color; `DefaultTheme(inlayHintTextColor:inlayHintBackgroundColor:)`). The intelligence controller asks for hints again once scrolling leaves the range of the last request (viewport ± one screen, 150 ms after scrolling pauses) and finds line/column through the line index, not by scanning text. Geometry around a chip is measured from glyph positions (`InlayChipGeometry.chipEnd`), not `CTLineGetOffsetForStringIndex`, which on current macOS returns the middle of the kern gap inside a line and the position before it at a line's end (pinned by `InlayHintTests.testChipEndIsTheLeadingEdge…`): `LineController.caretX` puts a caret at a hint's offset behind the chip, or in front of it (`beforeInlayHint`); a click on the chip lands on the hint and one on the character before it splits at that character's middle; a selection that ends at a hint, and a block/underline caret on the character before one, stop in front of the chip. Plain ←/→ take two steps through a chip (`TextInputView.caretIsBeforeInlayHint`, reset by any other selection change) at one offset; typing inserts in front of the hint either way. A line controller made outside a layout pass (caret and hit-test queries) gets its hints in `lineControllerStorage(_:didCreate:)`. A hint at a line's first character is still not shown. Tests: `InlayHintCaretTests`. Tests: `GutterLineClickTests`.
- Line-marker column (`TextView.lineMarkers`, `GutterLineMarker`, `GutterLineMarkerView`) between the line numbers and the fold ribbon: one vector-drawn icon per line (`GutterLineMarkerView.maximumSlots`; extra markers on a line are not drawn) (`GutterLineMarkerGlyphs`: implementing/implemented/overriding/overridden/sibling-inherited/recursive-call), tooltips, `lineMarkerHandler` clicks. Markers live in a line-sorted `GutterLineMarkerStore` and follow edits until the host replaces them: `TextInputView.replaceText` describes a line-break edit in rows (`GutterLineMarkerEdit`, a constant number of `LineManager` lookups) and the store shifts the markers below it, drops those on deleted lines and merges joined ones, like IntelliJ's range markers — never a per-marker line lookup; the column width (slot count) is only recounted when markers are replaced, dropped or merged. `reservedLineMarkerSlots` keeps the column's width while markers are still being computed, so the text does not shift when they arrive (Umbra reserves `TextView.maximumLineMarkerSlots` for every Java file in `scheduleJavaLineMarkers`, since its run buttons share the column). `GutterLineMarkerView` is viewport-sized (IntelliJ paints only visible lines), so every redraw — scroll, edit, fold, new markers — is bounded by the visible rows. `PerfHarness enter-session` measures Enter with markers on every method line (`markers_top`/`markers_middle`, `set_line_markers`). Umbra fills it from whichever language's `LineMarkerProviding` the registry returns (`LanguageServiceRegistry.lineMarkers(for:)`; Java's is `JavaLineMarkerProvider`, `Sources/JavaIntelligence/LineMarkers/`; per-kind toggles under Settings › Java › Gutter Icons); ↑ runs `EditorIntelligenceController.navigate(kind: .superMethod, atUTF16Offset:)`, ↓ `.implementation`.
- Annotation column (`TextView.setGutterAnnotations(_:edited:)`, `GutterAnnotation`, `GutterAnnotationView`/`GutterAnnotationStore` in `Sources/Penumbra/TextView/Gutter/`) between the gutter decorations and the line numbers: display-only text per line (consecutive lines sharing an `id` show it once), a tooltip on hover, no host types. The store keeps one `Int32` per row and follows edits like the line-marker store (a splice for line-count changes); lines an edit touched show the `edited` annotation until the host sends fresh ones. Viewport-sized like the marker column. Umbra fills it with Git blame (`Umbra/Sources/Umbra/Git/IDEGitBlame.swift`: `IDEBlameController` runs `GitRepository.blame` against the live buffer off the main actor, per file, refreshed on save and git refresh; Git ▸ Show Git Blame, no key).
- Change stripe (`TextView.showsGutterChangeStripe`, `setGutterChanges(_:)`, `GutterChange` in `TextView/Gutter/GutterChange.swift`): a 4 pt column immediately to the right of the line numbers (a 3 pt bar, centered), reserved while it is on even when nothing changed, and still reserved when line numbers are off. Added lines are green, modified lines blue, and a deletion is a triangle on the boundary before `line` (past the last line, on the bottom edge). Consecutive lines of one kind are one rect. Hover shows "Added", "Modified", or "N line(s) deleted"; a click is not a line-number click. `GutterChangeStore` shifts each span with a constant number of `GutterLineMarkerEdit.newRow(forRow:)` calls and marks the rows an edit produced until the host replaces them; a span whose rows were all deleted is dropped. `setState` clears the spans and leaves the flag. Colors follow the gutter background. Penumbra does not ask git. Tests: `GutterChangeTests`.
