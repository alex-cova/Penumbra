# Keymap layer (`Sources/Penumbra/TextView/Keymap`)

Loaded when working under `Sources/Penumbra/TextView/Keymap`. Split out of `Sources/Penumbra/CLAUDE.md`.

- **Keymap layer** (`Sources/Penumbra/TextView/Keymap/`): `TextView.keymap` holds `[KeyStroke: EditorActionID]` bindings resolved by `KeymapDispatcher` (generic two-step chords like ⌘K ⌘D, plus double-⇧ via `DoubleModifierDetector` on `flagsChanged`). Presets `Keymap.default_` (historical shortcuts) and `Keymap.intelliJ`. Actions the core doesn't own return `false` from `TextInputView.performKeymapAction` and fall through to `TextView.editorActionHandler` / registered `addKeyDownInterceptor`s. Invoke any action directly with `TextView.perform(_:)`. In Umbra, menu items whose key differs per preset take it from `IDEMenuShortcuts` (`Umbra/Sources/Umbra/App/IDEMenuShortcuts.swift`) instead of a literal `.keyboardShortcut`, because a menu key equivalent is handled before the editor and would shadow the preset's `Keymap` binding; add new preset-dependent menu commands there. IntelliJ-keymap feature work is tracked in `docs/INTELLIJ_KEYMAP_FEATURES_PLAN.md`. `EditorActionID.findNext`/`findPrevious` (⌘G/⇧⌘G) step through the last find query with the panel open or closed (`FindPanelController.findNext`); `goToMatchingBracket` (⌃M, `BracketNavigation`: a bounded text scan of ±4096 UTF-16 units, brackets `()[]{}` only, strings and comments not skipped); `unselectLastOccurrence` (⌃⇧G). `toggleBlockComment` (⌥⌘/): `BlockCommentDelimiters` on `TreeSitterLanguage` (`blockCommentDelimiters:`), `BlockCommentService` finds comments by a bounded text scan, not the syntax tree. Replace in Files (⇧⌘R in the IntelliJ column): `ProjectReplacePlanner` builds a `WorkspaceEditPlan` (same regex as the search via `WorkspaceSearchQuery.compiledRegularExpression()`), `IDEWorkspace.replaceInFiles` previews it in the Rename sheet, `IDEReplaceInFilesGuard` drops any edit whose text moved since the search, and `IDEWorkspaceEditApplier` writes. Find and Replace in Files share one `ProjectSearchFilter` (`Sources/EditorIntelligence/Search/`): a `FileMask` (`*.java, !*Test.java, src/**`; name patterns match file names, `/` patterns the root-relative path, `!` always wins, an invalid pattern matches nothing; excluded directories are pruned from the walk), a directory scope inside the root, or an explicit file set (Open Files, Changed Files from git); Umbra's drawer has the mask field and scope menu (`IDEFindInFilesScope`) and the Explorer has "Find in Files Here…". The Replace preview sheet uses `.diff` style: `WorkspaceEditPlanEntry.previewLine()` splits the line around the edit and the sheet shows the old and the new line (`.singleLine`, what Rename uses, is unchanged). Git (IntelliJ column): `GitRepository.log(path:)`/`existsInHead`/`revertToHead`; `IDEGitStatusModel.showFileHistory`/`revert`; Git menu with Pull ⌘T, Push ⇧⌘K, Revert File… ⌥⌘Z (confirms first; the tab reloads even if it had unsaved edits); the Source Control panel reverts several files (⌘/⇧-click multi-select, row context menu, Revert All…) through `IDEWorkspace.revertChanges` / `IDEGitStatusModel.revert(paths:)` → `GitRepository.revert(paths:)`, which reverts the files in `HEAD` (`pathsInHead`, one `ls-tree` per 200 literal paths) and reports the rest as skipped. Go to Tool Window (`goToTool`): `ToolWindowsPaletteProvider` / palette mode `.toolWindows`, fed by the host through `CommandPaletteController.toolWindowEntriesProvider` (Umbra: `IDEWorkspace.toolWindowEntries()`). View commands in Umbra: `selectAdjacentTab`/`focusAdjacentPane` (⇧⌘]/⇧⌘[, ⌥⇥ in the IntelliJ column), `toggleAllToolWindows` (⇧⌘F12), session zoom via `IDEPreferences.zoomPercent` (not saved; `applyTheme` scales `fontSize` by it), `clearTerminal` (per-tab `clearRequestID`; ⌘K while a terminal has focus). Debugger (`Umbra/Sources/Umbra/Debug/JavaDebugSession.swift`, JDI adapter in `Umbra/Sources/Umbra/Tools/JavaDebugAdapter`, rebuilt with its `build.sh` and committed as `build/java-debug-adapter.jar`, which the app copies as a resource — rerun `build.sh` after editing the adapter; the protocol, breakpoint properties, evaluator tiers, test debugging and the Debug tool window are described under **Debugger** in `Umbra/CLAUDE.md`). `JavaDebugAdapterTests` and `JavaDebugSessionEvaluateTests` drive the real adapter against a JVM. `JavaDebugSession` must read the adapter off the main actor. Program output: the adapter reads the target's stdout and stderr separately and sends `output` events of up to 200 `{stream, text, partial}` lines (every ~50 ms; a line still open after ~100 ms of silence goes out `partial: true` and the next chunk of that stream continues it; breakpoint log lines are stream `log`), and `terminated` carries the exit code of a launched program; `JavaDebugSession.console` (`IDEDebugConsoleLog`, bounded chunk list, cleared when a session starts) feeds the Debug panel's Console pane (`IDEDebugConsoleView`, read-only: the program's stdin is not connected; a Gradle attach session has no adapter-owned process, so its output stays in the Gradle tab). Run/Debug in Context (⌃⇧R/⌃⇧D, `IDEWorkspace.runInContext`, `JavaStructureProvider.caretContext`): a test method or class runs (or is debugged) as a test, a file with `main` as a configuration, anything else repeats the last one. `goToFileSymbol` (⌘F12, File Structure): palette mode `.fileSymbols` listing the focused document's declarations from `SymbolIndex.symbols(in:)` (`FileSymbolsPaletteProvider`, `CommandPaletteController.activeDocumentIDProvider`); `goToSymbol` (⌥⌘O in the IntelliJ preset) searches the open documents' symbols plus, for Java, every member the project's classes declare (`JavaIndex.members(matching:limit:)` in `Sources/JavaIntelligence/Index/JavaMemberIndex.swift`: methods, fields, enum constants and record components, not constructors, inherited members or javac's `values`/`valueOf`/record accessors; camel-hump matched; a table built lazily on the first query and dropped on `setSources`, with a small overlay table for open buffers, so there is no shard format change; entries are bucketed by word-initial letter and pre-checked before `CompletionMatcher`, ≤10 ms p95 for 150,000 members, `PerfHarness java-members`). The index stores no member positions: `JavaMemberLocator.nameRange(of:in:)` finds the member in its file as it is now on selection, and falls back to the class. `IDEJavaMembersPaletteSource` feeds the rows into the Symbols section through `CommandPaletteController.symbolsAdditionalItems`, and `symbolsExcludedDocuments` leaves the open Java files' tree-sitter symbols out so nothing is listed twice. `goToNextProblem`/`goToPreviousProblem` (F2/⇧F2): the core doesn't own a problem list, so Umbra handles them (`wireProblemNavigation` → `IDEWorkspace.goToProblem`) with `ProblemNavigator` over `IDEProblemsStore.files`; errors and warnings only, ordered by path, line, column, wrapping. `showParameterInfo` (⌘P): asks `signatureHelpProvider` at the caret from anywhere in the argument list. `goToTypeDefinition` (⌃⇧B, `NavigationKind.typeDefinition`): `JavaGoToTypeDefinition` types the expression or declaration under the caret with `JavaExpressionTyper` and goes to that type's declaration (a value of type `T` goes to the type parameter when the current file declares it, via `Typed.typeVariable`, else to its bound); `LSPTypeDefinitionProvider` is the LSP one. `completeStatement` (⇧⌘↵): `StatementCompletionService` decides on the caret line alone (close brackets and strings, then `;` or ` {}`), then Enter splits the braces; only for languages with `enterBehavior.cStyleIndent`, otherwise it is Start New Line. In Umbra, `.http` files show a `play.fill` gutter button on each request (`IDEWorkspace.refreshHTTPGutter`, refreshed on the debounce shared with the Java run button; `HTTPRequestParser.requestLocations`).
