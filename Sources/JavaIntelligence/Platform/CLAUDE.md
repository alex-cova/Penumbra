# `Sources/JavaIntelligence/Platform`

Loaded when working under `Sources/JavaIntelligence/Platform`. Moved out of `Sources/JavaIntelligence/CLAUDE.md`.

- **Release-aware platforms** (`Platform/JavaPlatform.swift`, `Scanning/JavaIndexableRoot.swift`). Each source set records what its build declares (`JavaCompilerSettings`: `release`, `toolchainVersion`, `sourceCompatibility`, `targetCompatibility`; Gradle model format 9 reads them per compile task, Maven from `maven-compiler-plugin` config over the `maven.compiler.*` properties, `testRelease` for tests, and `maven-toolchains-plugin`), and `JavaPlatformAPI` decides the API as javac does: `--release N` → release N; a toolchain JDK N → N; source/target alone → the selected JDK's whole platform (never `--release`: the build accepts newer APIs); a pre-format-9 model → `legacy`, unrestricted. `JavacInvocationBuilder.platformFlags` follows the same decision (`-source N -target N -Xlint:-options` for source-only modules). A release other than the JDK's own is indexed on demand from the JDK's `ct.sym` (`JDKPlatformRoot.make(for:release:)`, shard kind `ctsym-release-N`, `supportedReleases(of:)`; JDK 21's `ct.sym` holds 8…20, 22+ also their own) and published at precedence 3 with `JavaPlatformScope.token(release:)` as its `shardPath`; the JDK's own platform carries its feature version's token and `isDefaultPlatform`. `JavaGradleProjectModel.visibleShardPaths` adds the source set's token, so every feature that already scopes by module (completion, auto-import, navigation, hover, inspections, batch) resolves classes *and members* against that release; `JavaIndex.isVisible` shows exactly one platform per query (the scope's token, else the default; memoized per scope), and the unscoped package pool is the default platform's. `JavaFileResolutionScopes` makes the token a required shard, so a release still indexing, failed, or absent from `ct.sym` keeps the module pending instead of judging it against another release. Umbra: `IDEJavaSupport.refreshPlatformReleases` (after a model applies and after the JDK indexes; drops releases no module needs, discards results for a JDK that changed meanwhile, records `unavailablePlatformReleases` for the Problems note). Not modelled: `-source` below 9 without `--release` (javac then sees non-exported JDK packages; Umbra the exported API), a toolchain JDK other than the selected one is approximated by its release's `ct.sym` signatures, and JDK 8 itself (no `ct.sym`) is indexed only as a selected JDK. Tests: `JavaPlatformReleaseTests`, `JavaPlatformReleaseDifferentialTests` (javac, every installed JDK), `JavaImportDifferentialTests`, `IDEJavaPlatformReleaseIntegrationTests`; costs: `swift run -c release PerfHarness java-platform-release synthetic [--releases 8,11,17]`, and `PERF_JAVA_PLATFORM_RELEASES=8,11,17` on `java-completion`.
