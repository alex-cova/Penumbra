# `Sources/JavaIntelligence/Modules`

Loaded when working under `Sources/JavaIntelligence/Modules`. Moved out of `Sources/JavaIntelligence/CLAUDE.md`.

- **Modules and Lombok (F16).** `Modules/JavaModuleDescriptor` parses `module-info.java`; `JavaGradleProjectModel.moduleVisibility(forFile:paths:)` gives a file in a named module the exported-packages-only view of the modules it reads, installed as `JavaIndex.queryModules` around completion and the import code actions. It narrows name listings only (`classes(simpleNamePrefix:)`, `(simpleName:)`, `(matching:)`, `(inPackage:)`), never `classStub(qualifiedName:)`, and fails open (no `module-info`, an unrequired module, an unknown package). Jar `module-info.class` and the JDK's `requires` are not modelled. `Syntax/JavaLombokMembers` adds the members of `@Getter`/`@Setter`/`@Data`/`@Value` and the constructor annotations to source stubs (only in a file importing `lombok`; `@Accessors` honoured; `@Builder` and the rest are not); changing it means bumping `JavaIndexShardWriter.formatVersion`. Tests: `JavaModuleVisibilityTests`, `JavaLombokMembersTests`; details and limits: `docs/audit/findings/F16-module-visibility.md`.
