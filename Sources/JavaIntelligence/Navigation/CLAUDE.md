# `Sources/JavaIntelligence/Navigation`

Loaded when working under `Sources/JavaIntelligence/Navigation`. Moved out of `Sources/JavaIntelligence/CLAUDE.md`.

- **Go to Definition coverage** (`Sources/JavaIntelligence/Navigation/`). `JavaGoToDefinition.resolve` tries three classifiers in order: a click inside a `/** */` comment (`JavadocReferenceScanner`, pure text: `{@link X}`, `{@link X#m(T)}`, `{@link #m}`, `@see`, `@throws`, `@param`, `@param <T>`; resolved by `JavaNavigationSession.javadocHits`), then `JavaNavigationExtras` (references only navigation understands, kept out of `JavaReference` so Find Usages, Rename and Hover do not change: `break`/`continue` labels, method references `Foo::bar` / `this::bar` / `Foo::new` (typed through `JavaExpressionTyper.receiverInfo` with the `::` as the separator; `::new` lists every constructor), annotation element keys, bare `case ADMIN` labels (typed from the `switch` selector, falling back to the ordinary bare-name lookup), and package segments), then the shared `JavaReferenceClassifier`. Locals, parameters, catch and pattern bindings and labels come from the memoized scope tree (`scopeDeclarationRange`), with `JavaDeclarationLocator.localDeclarationRange` as the fallback for `ERROR` regions. A click on a declaration name selects the declaration itself when there is nothing better: abstract declarations go to their implementations, overriding methods to the overridden method, and anything else (fields, plain methods, constructors, types, enum constants, parameters) falls back to its own name range — which can never be a wrong answer — except local variable declarators, which stay silent as the corpus pins (`JavaNavigationSession.declarationSelectsItself`, `LocalDeclarationNone`). The editor never reselects that self result: `JumpToDefinitionController` and `EditorIntelligenceController` turn a lone self-result into Find References instead (IntelliJ's Go to Declaration or Usages) — the provider answers self, the controller shows usages. A chain such as `com.acme.util.Strings.isBlank(s)` resolves segment by segment (`qualifiedNameHits`: a type if the dotted name is one, else a package). **Packages** (`JavaPackageNavigation`): a project package returns one `Location.Target.directory` per source root that holds it (main and test, several modules; a prefix such as `com.acme` with no class of its own is found through its nearest subpackages and the extra folders stripped), a JDK or dependency package returns one `.package(name)`; the host decides what to show (Umbra: `revealInExplorer`, or `IDEWorkspace.showLibraryPackage`, which lists the classes and opens the chosen one through `openJavaType`). `JumpToDefinitionController` and `EditorIntelligenceController.focus` hand any non-`.source` target to `onOpenInOtherDocument` and never move the selection. Same-arity method overloads are narrowed by argument types (`refine`, shared with Find Usages; constructors still list every same-arity match). Lombok `getX`/`isX`/`setX` have no declaration, so they go to the field they are generated from (`generatedAccessorHits`, access not checked: the field is private). An enum's `values()`/`valueOf()` go to the enum. An unqualified call or name inside `new Named() { ... }` looks at `Named` first (`anonymousClassSupertypes`). `JavaMemberLookup` judges protected access against the ancestors of every enclosing type, so a nested subclass reaches its inherited protected members. Tested by the golden corpus `Tests/PenumbraTests/Fixtures/JavaNavigationCorpus` (`cases/*.java` with a `/*|*/` click and `//! target: model/Dog.java:fetch`, `targets: N`, `none`, `package-dirs:` or `package:` expectations, a `gap:` tag for a known failure, `baseline.json` ratchet; `JavaNavigationCorpusTests`, `JAVA_NAVIGATION_CASE=Prefix`, `UPDATE_JAVA_NAVIGATION_BASELINE=1`), `JavadocReferenceScannerTests` and `JumpToDefinitionTargetTests`.

- **Show Siblings, Method Hierarchy, scopes** (`Navigation/JavaGoToSiblings.swift`, `Hierarchy/JavaMethodHierarchy.swift`, `Hierarchy/JavaHierarchyScope.swift`). `JavaNavigationSession.methodAtCaret()` is the method a call names, else the declaration the caret is inside (shared by both). Show Siblings asks `JavaSuperMethods.overridden` for the nearest super declarations and lists the project implementations of each (`implementationHits(forMethod:)`, anonymous classes included) minus the caret's own method. `JavaMethodHierarchyProvider` (over a `JavaTypeHierarchyProvider`) roots at the topmost class declaring the method (`JavaMethodFamily.family` for who declares it, `topmost` picking the declaration no other is above) and marks each class `defines`, `inherits`, or `shouldDefine` (concrete, nearest declaration abstract, not itself abstract — the abstractness comes from the class stub's modifiers, since a node has none); going up starts a fresh path so the classes above are not read as a cycle. `JavaHierarchyScope.contains` tells test sources from production ones (a Gradle source set whose name has "test" in it, else a `src/test` or `test/java` folder) for subtype and caller searches. Call Hierarchy roots at a field too: its callers are the methods that read or write it (`.read`/`.write` usages), it has no callees. Tests: `JavaMethodHierarchyTests`, `JavaHierarchyScopeTests`, `JavaCallHierarchyTests`.
