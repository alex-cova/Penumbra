# JavaIntelligence

Loaded when working under `Sources/JavaIntelligence`. Moved out of the root CLAUDE.md; the root file keeps a one-line summary. Umbra's side of the wiring is in `Example/Umbra/CLAUDE.md`.

- **`JavaIntelligence`** — native Java indexing and completion (JDK discovery, source and JAR stubs, type resolution, completion) with **no dependency on `Penumbra`**. Umbra wires it through `Example/Umbra/IDEJavaSupport.swift`. Completion (`Sources/JavaIntelligence/Completion/`) parses with a dummy identifier at the caret (`JavaCompletionProvider.dummyIdentifier`), types lambdas and method references through the target parameter's functional interface, resolves source members against their declaring file's imports, classifies the site (`JavaCompletionContextClassifier`: member access, `::`, import/package, `@`, `new`, type-only, `case`, class body, statement), ranks by expected type (`JavaExpectedType`, `JavaAssignability`), auto-imports classes (`JavaImportInserter`), offers `@Override` stubs in class bodies, and doubles as parameter info (`JavaSignatureHelp.swift`). For a Gradle project, a trusted sync (`GradleCommandRunner` plus an init script) replaces the whole-folder `.java` walk with per-module source sets and resolved dependency JARs. Go to Definition (`Sources/JavaIntelligence/Navigation/`) resolves into attached sources when present (a JDK `lib/src.zip` or a dependency's adjacent `*-sources.jar`, via `JavaAttachedSources`) and otherwise falls back to decompiling the `.class` file with [Sunflower](https://github.com/alex-cova/sunflower) (`FernflowerKit`, `JavaClassDecompiler`) — gated by a one-time user agreement (`JavaDecompilerAgreement`) that only a manual navigation (never Cmd-hover) can trigger, via `JavaGoToDefinitionProvider.setDecompilerConsent(accepted:request:)`. Compiler diagnostics (`Sources/JavaIntelligence/Diagnostics/`): `JavaCompilerDiagnosticsService` is a `DiagnosticProvider` that runs the JDK's `javac` (`JDKInstallation.javac`) over the editor's text — `JavacInvocationBuilder` builds the command (Gradle source-set classpath/sourcepath, `--release` capped at the JDK, `-proc:none` except a project's own Lombok jar; a plain folder infers its package root), `JavacOutputParser` parses stderr — and returns the last result while a debounced (600 ms idle), cancellable, 2-at-a-time compile runs, pushing finished results through `setResultHandler`. It stays off until Umbra configures it (`IDEJavaSupport.refreshCompilerDiagnostics()`: a plain folder, or a Gradle project that has synced; the `javaCompilerDiagnostics` preference), and `compileNow(_:force:)` backs the recheck after save and after sync. Go to Implementation (`JavaGoToImplementation`) lists the project classes that extend or implement a type, or override a method (a scan of `JavaIndex.projectClassStubs()`, scoped to the file's Gradle source set). Hover (`Sources/JavaIntelligence/Hover/`): `JavaHoverProvider` shows the declaration (`JavaSignatureText`) and Javadoc (`JavadocMarkdown`) of the symbol at the caret, from source stubs or from an attached `src.zip` / `*-sources.jar` (never decompiled); a resting caret (`.idle`) only pops up when there is documentation, an explicit request (`.manual`) always does. `JavaCodeActionProvider` offers "Import `a.b.X`" for a `cannot find symbol … class X` error on the caret's line and a remove-unused-imports action (`JavaUnusedImports`, conservative: syntax errors yield no edits, Javadoc references keep their imports, `*` imports stay). `JavaBreadcrumbProvider` labels the caret's enclosing declarations (`Outer<T> › put(String, int)`). `JavacDiagnosticsMapper` turns a whole Gradle build's `javac` output into diagnostics per file, and `JavaRunConfiguration` / `JavaRunConfigurationStore` (`Sources/JavaIntelligence/Launch/`) hold the last launch (program arguments, VM options for single-file runs, environment) per project. `JavaFormatter` (`Sources/JavaIntelligence/Formatting/`) is a whitespace-only formatter over the tree-sitter tree — indentation (blocks, `case` labels, brace-less bodies, two-level continuation), spacing between tokens, trailing spaces, blank-line runs; it never joins, splits or moves lines, refuses a file that doesn't parse cleanly and any result whose non-whitespace changed. `JavaFormattingProvider` wraps it as a `FormattingProviding` (whole file, or only the selected lines with every line break kept), and `JavaFormatEdits` turns the result into minimal per-line edits so carets stay put. `JavaImportOrganizer` sorts and prunes imports (other, `javax`/`java`, static; a comment inside the block limits it to removal). The Gradle model (format version 4) records each source set's runtime jars, runtime project dependencies and output directories; `JavaGradleProjectModel.runtimeClasspath(forFile:)` returns them in `java -cp` order (used by the classpath run target). ⌘-click (Go to Definition) on the name of an abstract declaration — an interface, an abstract class, a non-static non-private interface method, or an abstract method — returns its implementations instead (`JavaGoToImplementation.isAbstractDeclaration`); several ⌘-click targets pop up next to the click in `NavigationChoicesView` (↑/↓, Return, Esc; `JumpToDefinitionController.onPresentChoicesAtClick`), while ⌘B/⌥⌘B still use `onPresentNavigationChoices`. Go to Implementation also finds generic overrides (`compareTo(Foo)` for `Comparable<T>`), anonymous classes and enum constant bodies, and labels/sorts its picker results. `JavaTypeHierarchyProvider` (`Sources/JavaIntelligence/Hierarchy/`) builds the supertype tree (superclass, then interfaces, cycle-safe) and lazily expanded project subtypes; Umbra shows it in the Hierarchy bottom-panel tab (`EditorActionID.typeHierarchy`, ⌃H in the IntelliJ keymap, `EditorIntelligenceController.onRequestTypeHierarchy`). `JavaSemanticTokenProvider` (`Sources/JavaIntelligence/Semantic/`) classifies identifiers (types by kind, methods, fields, enum constants, parameters, locals; locals shadow fields) in one scope-aware pass, and `TextView.setSemanticHighlights(_:)` (`SemanticHighlightStore`) paints them over the tree-sitter colours, colour only, following edits until the next set (Umbra: `semanticHighlighting` preference, on by default). `JavaInlayHintProvider` (`Sources/JavaIntelligence/Inlay/`) produces parameter-name hints for calls that bind to exactly one method; `TextView.inlayHints` (`InlayHint`) renders them by widening the preceding character, so they are display-only (Umbra: `javaInlayHints`, off by default; hints refresh after edits, not on scroll). `JavaRunConfiguration` is now named and kept in a per-project list with a selected entry (`JavaRunConfigurationStore`, old files still load); a `.classpathMain` target launches `java -cp <runtime classpath> pkg.Main`, building the module's `classes` task first when its outputs are missing, and Umbra shows a run configuration picker in the toolbar. References (`Sources/JavaIntelligence/References/`): a persistent identifier index (`JavaNameIndex`, `JavaIdentifierScanner`, `refs.idx` shards via `JavaNameIndexShardWriter/Reader`, beside `sources.idx`; per-file stamps, incremental, open-buffer overlay; Umbra refreshes it and force re-indexes stubs when `IDEProjectWatcher` reports `.java` changes on disk) lists the candidate files for an identifier, and usages are then verified on demand instead of stored: `JavaSymbolIdentity` maps the caret to a `JavaSymbolID` (type, method with parameter keys, constructor, field, local by declaration range), `JavaFileUsageResolver` resolves every same-named identifier in a file (one parse and reusable context per file; unresolvable overloads or receivers are `.ambiguous`), `JavaLocalUsages` handles locals without the index, and `JavaUsageSearch` fans out over the roots that can see the declaration. `JavaFindUsagesProvider` answers `.references` for Java (methods search every member of `JavaMethodFamily`, which is built from the index only, so unsaved buffers and anonymous classes are not in it); `JavaGoToSuperMethod` answers `.superMethod`. `JavaRenameProvider` (`Sources/JavaIntelligence/Refactoring/`, a `RenameProviding`) renames types (with imports, static imports, Javadoc links and the `Old.java` file), locals, parameters (`JavaRenameProvider`), and methods (the whole override family), fields, enum constants and record components (`JavaMemberRename`); a family member in a JAR, the JDK or a generated root blocks the rename, ambiguous or read-only usages are left out of the edit unless the user ticks them in the preview, and Umbra deliberately gives it a text-scan candidate source (always correct) rather than the name index. Completion quality is tracked by a golden corpus (`Tests/PenumbraTests/Fixtures/JavaCompletionCorpus`: `cases/*.java` with `/*|*/` caret and `//! key: value` expectations, a fixture `project/`, `baseline.json` ratchet; `JavaCompletionCorpusTests`, `JAVA_COMPLETION_CASE=Prefix` to run a subset, `UPDATE_JAVA_COMPLETION_BASELINE=1` to ratchet; plan and gap list in `docs/JAVA_COMPLETION_PLAN.md`) and release latency by `swift run -c release PerfHarness java-completion synthetic`. Semantics behind it: generic-aware assignability (`JavaAssignability`, `JavaMemberLookup.asSupertype`), JLS overload phases (`JavaExpressionTyper.resolveOverloads`), lambda/poly-expression targets (`JavaExpressionTarget`), type-variable bounds (`JavaResolutionContext.typeParameterBounds`), inherited and dotted nested types, class-file `$` names normalized to `.` (shard format v3). `JavaIndex` has package tables, a decoded-stub cache, a `generation` counter and a generation-scoped member-set cache; the completion provider reparses incrementally. Postfix templates (`JavaPostfixTemplates`), position-aware keywords (`JavaKeywordPosition`), and a completion documentation preview (`EditorIntelligenceController.showsCompletionDocumentation`, resolved through the hover engine) complete the UX; `CompletionItem.origin` names an inherited member's type. Gradle model format 5 adds per-source-set `generatedSourceDirs` (indexed as read-only `SourceRoot.isGenerated` roots, re-indexed after Build Project) and `annotationProcessorJars` (`JavacInvocationBuilder` takes Lombok from them first). JDK selection (`Sources/JavaIntelligence/Discovery/`): `JDKLocator.discoverAll(additionalHomes:)` finds JDKs (`java_home`, `JavaVirtualMachines`, SDKMAN, Gradle, Homebrew, asdf, jenv, mise, plus homes the user added), `installation(atUserSelected:)` validates a picked folder (home, `.jdk` bundle or `bin`), and `resolve(selection:minimumFeatureVersion:additionalHomes:)` applies project JDK > default JDK > automatic (an explicit choice ignores the language level; a saved path that is gone is reported as `staleSelection`). `JDKSelectionStore` keeps the per-project choice, the default and the added JDKs in `jdk-selection.json`. `JavaLaunchCommand.make(... javaHome:)` runs that JDK's `bin/java` or prefixes a Gradle launch with `JAVA_HOME`/`PATH`. In Umbra, `IDEJDKSelection` (owned by `IDEJavaSupport.jdk`) is the only place that asks for a JDK (indexing, javac diagnostics, Gradle sync and tasks, Run, Debug); the status bar `IDEJDKStatusItem`, Java ▸ Project JDK and Settings › Java › JDKs (`IDEPreferencesJDKSection`) change it, and a change re-indexes the JDK, refreshes diagnostics and re-syncs a trusted Gradle project only when Gradle would launch on a different JDK. Generate… (`EditorActionID.generate`, Java ▸ Generate…, unbound because ⌘N is New File): `CodeGenerationProviding` (`Sources/EditorIntelligence/Refactoring/`) offers a `CodeGenerationMenu` (constructor, getter and setter, getter, setter, `toString()`, each with its candidate fields) and plans one edit; `JavaGenerateMembers` (`Sources/JavaIntelligence/Refactoring/`, wrapped by `JavaCodeGenerationProvider`) works on the buffer's syntax tree alone — it inserts after the member the caret is in (a constructor with the caret outside the body goes after the last field, the rest at the end of the type), skips accessors and `toString()` that already exist, and handles classes and enums only. `EditorIntelligenceController.generate()` asks the host through `onRequestGeneration` (Umbra: `IDEGeneratePrompt`, a caret popover: pick, then tick fields) and applies the edit without a preview, as one undo step. It ignores superclass constructors (no `super(...)` call is written).
- **Suppression** (`Inspections/JavaSuppression.swift`). `JavaInspectionService` drops inspections silenced by an enclosing `@SuppressWarnings("<code>")` (or `"all"`) or a `//noinspection <code>[, …]` (`ALL`) comment on the line above an enclosing statement or declaration (inspection codes are the rule ids such as `unused-import`; javac lint warnings carry their category, e.g. `rawtypes`, and javac honours the annotation itself). `JavaCodeActionProvider` offers "Suppress '<code>' for variable/method/class" (innermost three; merged into an existing `@SuppressWarnings`) or, with `setSuppressionStyle(.comment)` or for an import, a `//noinspection` line. `JavaInspectionService.setIdleDelay` is the autoreparse delay.

- **Inspection rules** (`Sources/JavaIntelligence/Inspections/`). `JavaInspectionRule` is the catalogue: each case has a `code` (the id on `JavaInspection`/`Diagnostic.code`, also what `@SuppressWarnings`/`//noinspection` name), `title`, `summary`, `group` (`JavaInspectionGroup`, after Inspectopedia's categories) and `defaultSeverity`, in one table (`JavaInspectionRule(code:)` looks a rule up). `JavaInspection.Severity` is `error`/`warning`/`weakWarning`/`info`; `JavaInspectionService.setEnabledRules` and `setSeverityOverrides` take the user's choices. The six original rules (imports, `missing-override`, `unresolved-type`, `class-file-name-mismatch`) are called by hand from `runAnalysis`; every other rule is a `JavaNodeInspection` (`nodeTypes`, `check(node:context:report:)`, optional `fixes(for:tree:source:)`) listed in `JavaInspectionRegistry.nodeInspections`, and `JavaInspectionRunner` visits the tree once and hands each node to the enabled rules registered for its type, so adding a rule adds no tree walk. `Diagnostic` carries no edits, so `JavaCodeActionProvider.registeredInspectionFixes` rebuilds a rule's fixes from the diagnostic's range (`JavaInspectionSupport.node(of:for:tree:source:)` finds the reported node by exact range) against a fresh tree. Rules live in `ProbableBugs/`, `VerboseCode/` and `DeclarationRedundancy/` and are syntactic: `JavaDeclaredTypes` reads a variable's type from its declaration in the same file (locals, parameters, fields, `this.f`, `v.f` for a class in the file, literals, `"a" + x`) and answers `nil` for anything else, and a rule stays silent on `nil` rather than guess. `JavaDeclarationCache` (on `JavaSyntaxTree`) memoizes field tables, expression types and a `JavaPositionIndex` (byte offset to `TextPosition` by binary search; `JavaImportInserter.textPosition` decodes the whole prefix and is O(file) per call), which keeps a pass linear: about 10 ms per 1k lines in Release (`swift run -c release PerfHarness java-inspections synthetic --lines 20000`, or a path). Not covered yet: rules that need project-wide types (`access-static-via-instance`, `redundant-array-creation`; the typer needs a `JavaResolutionContext` and the locals at the node, which only completion builds) and anything that needs data flow (nullability, constant conditions, unused assignments). To check a new rule for false positives, run it over real sources (the JDK's `lib/src.zip`, `*-sources.jar` in the Gradle cache) and read the hits before trusting it; the `Tests/PenumbraTests/JavaIntelligence/JavaInspectionRulesTests.swift` cases give each rule a positive, a negative and its fix.

- **Debugger support** (`Sources/JavaIntelligence/Debug/`). `JavaCallSites.calls(onLine:in:)` lists a line's calls in the order they run (receiver and arguments first, lambda bodies left out; `<init>` for `new`) for Smart Step Into. `JavaStreamChain.chains(onLine:in:)` finds stream pipelines touching a line (a source such as `.stream()` or `IntStream.range`, known intermediate operations, a terminal one), `tracedExpression()` rewrites one to record `{time, value}` after every stage, and `links(from:to:operation:)` maps each element to its source (by time; `sorted`/`distinct` by identity). `JavaExpressionSyntax.problem(in:)` checks that a condition or watch parses. `JavaTestRunScope.tests(taskPath:filters:)` runs several `--tests` filters; `JavaTestRunner.gradleArguments(for:debug:)` adds `--debug-jvm` and `taskPaths(for:debug:)` puts `clean<Task>` first; `JUnitXMLReportParser` keeps each case's `output` (its own `system-out`/`system-err`, else its suite's). Tests: `JavaDebugSupportTests`.

- **Shared across windows.** `GradleTrustStore`, `JDKSelectionStore` and `JavaRunConfigurationStore` are used through one instance per app in Umbra, and each reloads its JSON file when it changed on disk (`FileChangeStamp`, which reads the modification date through `FileManager`: `URL.resourceValues` caches per `URL` value and would never see a change) before reading or merging its own change, so a second writer is not overwritten. `JavaSharedShardHub` (`Sources/JavaIntelligence/Scanning/`) runs one indexing pass per shard, hands the same parsed `JavaIndexShardReader` to every caller, and keeps at most four for the JDK shard. For dependency jars (`indexJars(_:)`, `readers(for:)`) it claims each shard once across callers, sends waiters a `rootSkipped` per jar so their counters reach their totals, parses missing readers in parallel, and holds readers weakly while any window uses them; release jars from Gradle/Maven caches (`JavaJarCachePolicy.isImmutableArtifact`) also stay in an LRU bounded by `maxRetainedNames`, and `trimMemory()` empties it. Every request compares the reader's stamp with the shard file's, and the scheduler's freshness check reads only the shard header (`JavaIndexShardReader.readStamp(at:)`), never the whole table. Shard files are written atomically, so another process never reads half of one.
