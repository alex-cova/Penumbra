# JavaIntelligence

Loaded when working under `Sources/JavaIntelligence`. Moved out of the root CLAUDE.md; the root file keeps a one-line summary. Umbra's side of the wiring is in `Umbra/CLAUDE.md`. Inspection rules: `Inspections/CLAUDE.md`; profiler model: `Profiling/CLAUDE.md`; semantic model: `Semantics/CLAUDE.md`.

- **`JavaIntelligence`** — native Java indexing and completion (JDK discovery, source and JAR stubs, type resolution, completion) with **no dependency on `Penumbra`**. Umbra wires it through `Umbra/Sources/Umbra/Intelligence/IDEJavaSupport.swift`. Completion (`Sources/JavaIntelligence/Completion/`) parses with a dummy identifier at the caret (`JavaCompletionProvider.dummyIdentifier`), types lambdas and method references through the target parameter's functional interface, resolves source members against their declaring file's imports, classifies the site (`JavaCompletionContextClassifier`: member access, `::`, import/package, `@`, `new`, type-only, `case`, class body, statement), ranks by expected type (`JavaExpectedType`, `JavaAssignability`), auto-imports classes and, for classes listed in `JavaImportPolicy.staticMemberClasses`, their public static members (`JavaImportInserter`, `JavaImportPolicy`; excluded classes stay out even on a second Ctrl+Space), offers `@Override` stubs in class bodies, and doubles as parameter info (`JavaSignatureHelp.swift`). For a Gradle project, a trusted sync (`GradleCommandRunner` plus an init script) replaces the whole-folder `.java` walk with per-module source sets and resolved dependency JARs. Go to Definition (`Sources/JavaIntelligence/Navigation/`) resolves into attached sources when present (a JDK `lib/src.zip` or a dependency's adjacent `*-sources.jar`, via `JavaAttachedSources`) and otherwise falls back to decompiling the `.class` file with [Sunflower](https://github.com/alex-cova/sunflower) (`FernflowerKit`, `JavaClassDecompiler`) — gated by a one-time user agreement (`JavaDecompilerAgreement`) that only a manual navigation (never Cmd-hover) can trigger, via `JavaGoToDefinitionProvider.setDecompilerConsent(accepted:request:)`. Compiler diagnostics (`Sources/JavaIntelligence/Diagnostics/`): `JavaCompilerDiagnosticsService` is a `DiagnosticProvider` that runs the JDK's `javac` (`JDKInstallation.javac`) over the editor's text — `JavacInvocationBuilder` builds the command (Gradle source-set classpath/sourcepath, `--release` capped at the JDK, `--add-modules` from the source set's `JavaCompile`, `-proc:none` except a project's own Lombok jar; a plain folder infers its package root), `JavacOutputParser` parses stderr — and returns the last result while a debounced (600 ms idle), cancellable, 2-at-a-time compile runs, pushing finished results through `setResultHandler`. It stays off until Umbra configures it (`IDEJavaSupport.refreshCompilerDiagnostics()`: a plain folder, or a Gradle project that has synced; the `javaCompilerDiagnostics` preference), and `compileNow(_:force:)` backs the recheck after save and after sync. Tree-sitter syntax errors (`JavaSyntaxDiagnostics`: a `SyntaxDiagnosticProvider` over the inspections' shared parse cache, token names in javac's spelling) arrive before `javac` is configured; `JavaSyntaxAwareDiagnostics` pairs them with the compiler run and drops `javac` parser errors on lines a syntax problem already covers. Go to Implementation (`JavaGoToImplementation`) lists the project classes that extend or implement a type, or override a method (a scan of `JavaIndex.projectClassStubs()`, scoped to the file's Gradle source set). Hover (`Sources/JavaIntelligence/Hover/`): `JavaHoverProvider` shows the declaration (`JavaSignatureText`) and Javadoc (`JavadocMarkdown`) of the symbol at the caret, from source stubs or from an attached `src.zip` / `*-sources.jar` (never decompiled); a resting caret (`.idle`) only pops up when there is documentation, an explicit request (`.manual`) always does. `JavaCodeActionProvider` offers "Import `a.b.X`" for the type name at the caret (from the index, without waiting for javac) and for a `cannot find symbol … class X` error on the caret's line, "Import static `Owner.member`" for an unqualified call or field, and "Replace with single class imports" on a star import. `JavaAutoImport` inserts the one unambiguous class after idle, and the names in a paste, and never imports `List` while both `java.util` and `java.awt` define it. It also offers a remove-unused-imports action (`JavaUnusedImports`, conservative: syntax errors yield no edits, Javadoc references keep their imports, `*` imports stay). `JavaBreadcrumbProvider` labels the caret's enclosing declarations (`Outer<T> › put(String, int)`). `JavacDiagnosticsMapper` turns a whole Gradle build's `javac` output into diagnostics per file, and `JavaRunConfiguration` / `JavaRunConfigurationStore` (`Sources/JavaIntelligence/Launch/`) hold a project's launches (see the run configuration paragraph below). `JavaFormatter` (`Sources/JavaIntelligence/Formatting/`) is a whitespace-only formatter over the tree-sitter tree — indentation (blocks, `case` labels, brace-less bodies, two-level continuation), spacing between tokens, trailing spaces, blank-line runs; it never joins, splits or moves lines, refuses a file that doesn't parse cleanly and any result whose non-whitespace changed. `JavaFormattingProvider` wraps it as a `FormattingProviding` (whole file, or only the selected lines with every line break kept), and `JavaFormatEdits` turns the result into minimal per-line edits so carets stay put. `JavaImportOrganizer` sorts and prunes imports (other, then `javax.*` and `java.*` as one group, then static; a comment inside the block limits it to removal and to point insertion) and collapses a package or static owner into a star at `JavaImportPolicy`'s counts (5 classes, 3 static names; 999 or a non-positive count never collapses). The Gradle model (format version 7) records each source set's runtime jars, runtime project dependencies and output directories; `JavaGradleProjectModel.runtimeClasspath(forFile:)` returns them in `java -cp` order (used by the classpath run target). ⌘-click (Go to Definition) on the name of an abstract declaration — an interface, an abstract class, a non-static non-private interface method, or an abstract method — returns its implementations instead (`JavaGoToImplementation.isAbstractDeclaration`); several ⌘-click targets pop up next to the click in `NavigationChoicesView` (↑/↓, Return, Esc; `JumpToDefinitionController.onPresentChoicesAtClick`), while ⌘B/⌥⌘B still use `onPresentNavigationChoices`. Go to Implementation also finds generic overrides (`compareTo(Foo)` for `Comparable<T>`), anonymous classes and enum constant bodies, and labels/sorts its picker results. `JavaTypeHierarchyProvider` (`Sources/JavaIntelligence/Hierarchy/`) builds the supertype tree (superclass, then interfaces, cycle-safe) and lazily expanded project subtypes; Umbra shows it in the Hierarchy bottom-panel tab (`EditorActionID.typeHierarchy`, ⌃H in the IntelliJ keymap, `EditorIntelligenceController.onRequestTypeHierarchy`). `JavaSemanticTokenProvider` (`Sources/JavaIntelligence/Semantic/`) classifies identifiers (types by kind, methods, fields, enum constants, parameters, locals; locals shadow fields) in one scope-aware pass, and `TextView.setSemanticHighlights(_:)` (`SemanticHighlightStore`) paints them over the tree-sitter colours, colour only, following edits until the next set (Umbra: `semanticHighlighting` preference, on by default). `JavaInlayHintProvider` (`Sources/JavaIntelligence/Inlay/`) produces, per `JavaInlayHintOptions` (a fixed value, or `setOptionsSource` asked at every request), parameter-name hints for calls that bind to exactly one method, and type hints (`InlayHint.Kind.type`, label `: List<String>`) after `var` locals, `for (var …)` variables and implicitly typed lambda parameters. Type hints type the declaration's initializer with `JavaExpressionTyper.resolvingVarLocals` against the locals of the enclosing block (candidates of one block share one resolution; at most 60 declarations per request), skip initializers that already say the type (`new`, a cast, a literal, a factory like `List.of`) and ones that can't be typed (`Object` is what a failed inference falls back to, so it is never shown). `resolvingVarLocals` resolves `var` locals in passes against every other local, because the list is source order within a block. `TextView.inlayHints` (`InlayHint`) renders them by widening the preceding character, so they are display-only (Umbra: `javaInlayHints`, `javaInlayVariableTypes`, `javaInlayLambdaTypes`, all off by default; hints refresh after edits and when scrolling leaves the requested range). Tests: `JavaInlayHintProviderTests`. `JavaCodeVisionProvider` (`CodeVisionProviding`, same folder) gives a lens to every class, interface, enum, record, method and constructor: `codeVisionAnchors(for:)` is one pass over the tree (at most 400, the room for all of them), `codeVision(for:anchors:)` then labels the anchors on screen — `N usages` from `JavaFindUsagesProvider.findUsages`, and for interfaces, abstract classes and abstract or interface methods `N implementations` from `JavaGoToImplementation.resolve`. A search is expensive (it parses the files that mention the name), so results are cached by declaration signature and `JavaIndex.generation` (counts follow what the index knows, i.e. saved files), two run at a time and at most 40 per request. Options (`JavaCodeVisionOptions`) are read through `setOptionsSource`. Tests: `JavaCodeVisionProviderTests`. `JavaRunConfiguration` is now named and kept in a per-project list with a selected entry (`JavaRunConfigurationStore`, old files still load); a `.classpathMain` target launches `java -cp <runtime classpath> pkg.Main`, building the module's `classes` task first when its outputs are missing, and Umbra shows a run configuration picker in the toolbar. References (`Sources/JavaIntelligence/References/`): a persistent identifier index (`JavaNameIndex`, `JavaIdentifierScanner`, `refs.idx` shards via `JavaNameIndexShardWriter/Reader`, beside `sources.idx`; per-file stamps compared with one `getattrlistbulk` pass per directory (`JavaSourceStampScan`), an in-place posting update (`rewrite(from:removing:replacing:to:)`, returning the reader it already built) when a readable shard exists, open-buffer overlay; Umbra refreshes it and force re-indexes stubs when `IDEProjectWatcher` reports `.java` changes on disk) lists the candidate files for an identifier, and usages are then verified on demand instead of stored: `JavaSymbolIdentity` maps the caret to a `JavaSymbolID` (type, method with parameter keys, constructor, field, local by declaration range), `JavaFileUsageResolver` resolves every same-named identifier in a file (one parse and reusable context per file; unresolvable overloads or receivers are `.ambiguous`), `JavaLocalUsages` handles locals without the index, and `JavaUsageSearch` fans out over the roots that can see the declaration. `JavaFindUsagesProvider` answers `.references` for Java (methods search every member of `JavaMethodFamily`, which is built from the index only, so unsaved buffers and anonymous classes are not in it); `JavaGoToSuperMethod` answers `.superMethod`. `JavaRenameProvider` (`Sources/JavaIntelligence/Refactoring/`, a `RenameProviding`) renames types (with imports, static imports, Javadoc links and the `Old.java` file), locals, parameters (`JavaRenameProvider`), and methods (the whole override family), fields, enum constants and record components (`JavaMemberRename`); a family member in a JAR, the JDK or a generated root blocks the rename, ambiguous or read-only usages are left out of the edit unless the user ticks them in the preview, and Umbra deliberately gives it a text-scan candidate source (always correct) rather than the name index. Completion quality is tracked by a golden corpus (`Tests/PenumbraTests/Fixtures/JavaCompletionCorpus`: `cases/*.java` with `/*|*/` caret and `//! key: value` expectations, a fixture `project/`, `baseline.json` ratchet; `JavaCompletionCorpusTests`, `JAVA_COMPLETION_CASE=Prefix` to run a subset, `UPDATE_JAVA_COMPLETION_BASELINE=1` to ratchet; plan and gap list in `docs/JAVA_PARITY.md`) and release latency by `swift run -c release PerfHarness java-completion synthetic [--jars N]` and `swift run -c release PerfHarness java-name-index <java-source-directory|synthetic> [--files N]`. Semantics behind it: generic-aware assignability (`JavaAssignability`, `JavaMemberLookup.asSupertype`), JLS overload phases (`JavaExpressionTyper.resolveOverloads`), lambda/poly-expression targets (`JavaExpressionTarget`), type-variable bounds (`JavaResolutionContext.typeParameterBounds`), inherited and dotted nested types, class-file `$` names normalized to `.` (shard format v3). `JavaIndex` has package tables, a decoded-stub cache that drops its oldest entry when full, a `generation` counter and a generation-scoped member-set cache; class names are bucketed by word start the same way members are (`JavaWordBuckets`); `classes(matching:)` ranks with `CompletionMatcher.tier` and decodes stubs only for the names it keeps; `classes(simpleName:)` is the exact simple-name lookup, and `classStub(qualifiedName:)` jumps to the shard that wins the name; the completion provider reparses incrementally. Postfix templates (`JavaPostfixTemplates`) are snippets (`$0`, `${1:name}`) chosen from the expressions that end at the dot (`JavaPostfixExpressions`, at most three, innermost first), and `JavaPostfixConfiguration` turns built-ins off, stores custom templates, and names the expansion key. `JavaInlineCompletionValidator` (an `InlineCompletionValidating` extension of the completion actor) splices an inline suggestion in and reparses that splice on the provider's incremental tree without replacing the document cache, rejects syntax errors inside the spliced range, checks each new identifier (receiver members via `JavaExpressionTyper`/`JavaMemberLookup`, locals, implicit-this members including inherited ones, static imports, declared and imported names), truncates before the first unresolved one, and turns a unique out-of-scope type into an auto-import edit. `JavaLiveTemplates` offers `sout` and `psvm` at statement and class-body sites once a prefix is typed, and ⌘J (`EditorActionID.insertLiveTemplate`, `CompletionContext.Filter.templates`) lists the templates that apply at the caret. Command completion (`CompletionContext.commandMode`): after `..` (or in the command section of a single `.`) `JavaCompletionProvider.commandItems` offers Extract Variable/Field/Constant and Surround With with the receiver expression as `selecting:`, and Extract Method on a preceding `for`/`while`/`if` block (`statementBlockRange`); `JavaSymbolReferenceProvider` gives Copy Reference (`pkg.Class#method(params)`, `pkg.Class.FIELD`) from the file's own stubs, then the index. Position-aware keywords (`JavaKeywordPosition`), and a completion documentation preview (`EditorIntelligenceController.showsCompletionDocumentation`, resolved through the hover engine) complete the UX; `CompletionItem.origin` names an inherited member's type. Gradle model format 5 adds per-source-set `generatedSourceDirs` (indexed as read-only `SourceRoot.isGenerated` roots, re-indexed after Build Project) and `annotationProcessorJars` (`JavacInvocationBuilder` takes Lombok from them first); format 7 adds `addModules` (the source set's `JavaCompile --add-modules`, replayed into the `javac` check, the warm server module, and classpath run/debug launches); format 8 adds `runMainClass` (the `run` task's effective main class, so Run offers a task picker instead of a `run` that would fail with "No main class specified"). JDK selection (`Sources/JavaIntelligence/Discovery/`): `JDKLocator.discoverAll(additionalHomes:)` finds JDKs (`java_home`, `JavaVirtualMachines`, SDKMAN, Gradle, Homebrew, asdf, jenv, mise, plus homes the user added), `installation(atUserSelected:)` validates a picked folder (home, `.jdk` bundle or `bin`), and `resolve(selection:minimumFeatureVersion:additionalHomes:)` applies project JDK > default JDK > automatic (an explicit choice ignores the language level; a saved path that is gone is reported as `staleSelection`). `JDKSelectionStore` keeps the per-project choice, the default and the added JDKs in `jdk-selection.json`. `JavaLaunchCommand.make(... javaHome:)` runs that JDK's `bin/java` or prefixes a Gradle launch with `JAVA_HOME`/`PATH`. In Umbra, `IDEJDKSelection` (owned by `IDEJavaSupport.jdk`) is the only place that asks for a JDK (indexing, javac diagnostics, Gradle sync and tasks, Run, Debug); the status bar `IDEJDKStatusItem`, Java ▸ Project JDK and Settings › Java › JDKs (`IDEPreferencesJDKSection`) change it, and a change re-indexes the JDK, refreshes diagnostics and re-syncs a trusted Gradle project only when Gradle would launch on a different JDK. Generate… (`EditorActionID.generate`, Java ▸ Generate…, unbound because ⌘N is New File): `CodeGenerationProviding` (`Sources/EditorIntelligence/Refactoring/`) offers a `CodeGenerationMenu` (constructor, getter and setter, getter, setter, `toString()`, each with its candidate fields) and plans one edit; `JavaGenerateMembers` (`Sources/JavaIntelligence/Refactoring/`, wrapped by `JavaCodeGenerationProvider`) works on the buffer's syntax tree alone — it inserts after the member the caret is in (a constructor with the caret outside the body goes after the last field, the rest at the end of the type), skips accessors and `toString()` that already exist, and handles classes and enums only. `EditorIntelligenceController.generate()` asks the host through `onRequestGeneration` (Umbra: `IDEGeneratePrompt`, a caret popover: pick, then tick fields) and applies the edit without a preview, as one undo step. It ignores superclass constructors (no `super(...)` call is written).
- **External libraries** (`Sources/JavaIntelligence/Libraries/`). Pure values for the Explorer's External Libraries section. `JavaLibraryCoordinates.parse(jar:)` reads group, artifact, version and classifier off a Gradle cache path (`modules-2/files-2.1/<group>/<artifact>/<version>/<hash>/<file>`) or a Maven repository path, anything else is `.local` (labelled by file name). `JavaExternalLibrary.list(from:)` is the deduplicated union of every source set's compile and runtime jars (not annotation processors), sorted by label. `JavaArchiveContents.nodes(entries:layout:)` builds the tree from central-directory names alone: flat dotted packages with their top-level types, resource-only folders, root resources; inner classes (`$`), `module-info`, `package-info` and `META-INF/versions/` are left out; `.moduleRooted` takes a JDK `src.zip` (or module-prefixed jmod names) and puts a module level on top. `JavaAttachedSources.extractResource` copies a non-class entry under `attached-sources/` so it opens read-only. `Document.isDependencySource` (path under `attached-sources`) marks such a file: `JavaCompilerDiagnosticsService.compilableURL`, `JavaInspectionService`, `JavaSyntaxAwareDiagnostics` and `JavaCodeActionProvider` all skip it, so a dependency is navigated, never analysed. Tests: `JavaExternalLibrariesTests`, `JavaInspectionServiceTests`, `JavaCompilerDiagnosticsServiceTests`.
- **Maven** (`Sources/JavaIntelligence/Maven/`, `Testing/MavenTestRunner.swift`, `Coverage/MavenCoverageArguments.swift`, `Diagnostics/MavenProblemMatcher.swift`). `MavenProjectReader.read` builds a reactor from `pom.xml` on disk: parents, BOMs and dependencies come from the local repository, `XMLParser.shouldResolveExternalEntities` stays false, and no Maven process runs. `MavenProjectModel.javaProjectModel` projects that reactor into a `JavaGradleProjectModel` (format version 8, `gradleVersion` `"maven"`) so indexing, `javac`, runtime classpaths and coverage scope stay on the Gradle-shaped model. A module path is `:` or `:` plus the relative directory with `:` between folders. Each module has `main` and `test` source sets and a test task `<path>:test` whose results directory is `target/surefire-reports`. `MavenVersion` orders versions the way Maven does (`1.0-SNAPSHOT` < `1.0` < `1.0-sp1`, including a qualifier glued to its number). `MavenReadOptions.disabledProfiles` keeps a profile off even when the POM would activate it. `MavenCommandRunner` runs goals only for a trusted root (`mvnw`, then a settings override, then `mvn` on `PATH`) through `SystemGradleProcessLauncher`. `MavenDependencyDownload` asks Maven for artifacts that are not in the local repository. `MavenTestRunner` builds `mvn test` with `-pl` / `-am` and a Surefire debug agent. `MavenCoverageArguments` injects a JaCoCo or JFR agent, and refuses when Surefire's `argLine` omits `@{argLine}`. `MavenProblemMatcher` turns Maven's `javac` lines into the same problems Gradle's matcher does; Maven's column is 1-based. Run configurations add `.mavenGoals` and `.mavenTest`. Tests: `MavenProjectReaderTests`, `MavenToolingTests`.
- **Run configurations** (`Sources/JavaIntelligence/Launch/`). `JavaRunConfiguration` has a target (`.gradleRun`, `.singleFile`, `.classpathMain`, `.gradleTest(taskPath:filters:sourceFile:)`), `kind` (application, javaFile, gradle, junit), arguments, VM options, environment, working directory, `jdkHome`, `buildBeforeRun` (default on), `allowMultipleInstances`, `beforeLaunch` (`.gradleTasks`, `.runConfiguration(id)`), `shortenCommandLine`, `redirectInputPath`, `folder`, `storeAsProjectFile` and `isTemporary` (an unnamed configuration is temporary unless said otherwise, which is also what files saved before the flag decode to; every new field decodes with a default). `supportsVMArguments` / `supportsEnvironment` / `supportsWorkingDirectory` / `supportsBuildBeforeRun` say which targets a field reaches (Gradle tasks take none of the process fields). `JavaRunConfigurationStore` keeps the Mac-local list, the selection, per-kind templates and the temporary limit (`setLast(…temporaryLimit:)` drops the oldest temporary ones, never the selected); `JavaProjectRunConfigurationFolder` reads and writes `<project>/.umbra/runConfigurations/*.json` (relative paths, no `jdkHome`, `.withoutEscapingSlashes`, re-read when a file's date changes, one file per configuration, renamed with it); `JavaRunConfigurationCatalog` merges the two (the selection is always local, a flag change moves a configuration and keeps its id) and is what Umbra talks to. `JavaRunConfigurationValidator.problems(for:context:)` finds what is wrong without launching. `JavaLaunchCommand.makeProcessLaunch` builds the process for a class or single file (`JavaProcessLaunch`: environment = base, then `JAVA_HOME` and `PATH`, then the configuration's own; `@argfile` for a classpath over 32 KB on Java 9+; `newLaunchProtocolArguments` adds the preview switches); `make(configuration:…)` still builds a shell string (tests, Gradle). `JavaCommandLine.split` is the one argument splitter (single and double quotes, backslash), `join` its inverse. `JavaVMOptions` (`JavaVMOptions.swift`) is the curated list behind the form's VM options picker (Vector API, preview, native access, `--add-opens`, heap sizes, collectors, assertions, GC log, system properties): each `JavaVMOption` names its tokens, the ones it `replaces` (`-Xmx*`, the other collectors) and `minimumFeatureVersion`; `isEnabled` / `adding` / `removing` edit the field's text and leave what the user typed as written (test: `JavaVMOptionsTests`). `JavaMainMethod.locations(in:fileName:)` returns one `main` per class, the one the JVM picks (static with arguments, static without, instance with arguments, instance without; not `private`, instance forms need a creatable class), and a compact source file's method as an implicit class named after the file; `usesNewLaunchProtocol` says whether Java 21+'s protocol is needed. Tests: `JavaRunConfigurationCatalogTests`, `JavaRunConfigurationValidatorTests`, `JavaProcessLaunchTests`, `JavaLaunchTests`.

- **Coverage and profiling** (`Sources/JavaIntelligence/Coverage/`, `Profiling/`, `Launch/JavaRunArtifacts.swift`; plan: `docs/JAVA_COVERAGE_PROFILING_PLAN.md`). Pure values and command builders; Umbra draws them (`Umbra/Sources/Umbra/Coverage/`, `Profiler/`) and decides where each file goes. `JavaRunConfiguration.instrumentation` (`JavaRunInstrumentation`: `none`, `coverage`, `profile`, decoded with a default and an unknown raw value reading as `none`; `supportsInstrumentation` is false for a debug launch) is the one switch, so Rerun and Run Last repeat it; the validator refuses coverage of a `.singleFile` (source-launch mode keeps its classes in memory), instrumentation with the debugger, and Profile below Java 11. **Coverage:** `JavaCoverageToolchain` locates the bundled `jacocoagent.jar` and `jacococli.jar` (pinned `version` 0.8.15, `supportedClassFileMajor` 70 = Java 26; `unsupportedLanguageLevel` turns a newer project into one sentence), `JavaCoverageCommand` builds the `-javaagent:` argument (`destfile=…,append=true,includes=…,output=file`; `nil` for a path JaCoCo's option syntax cannot carry, i.e. a comma) and the `report`/`--html` invocations as argument vectors, `JavaCoverageScope` / `JavaCoveragePackages` take `includes` from the *declared* packages of the main source sets (never directory names) and the class directories from the Gradle model, `JavaCoverageGradleScript` is the init script that adds the agent to every `Test` and `JavaExec` task (decided in `doFirst`, because the `jacoco` plugin adds its extension after init-script actions run; a project that applies `jacoco` itself keeps its own agent and only its `.exec` is reported through a `##umbra-coverage|exec|<path>` marker line), `JavaCoverageReportRunner` runs the CLI through SubprocessKit (missing or header-only `.exec` is `noExecutionData`, the CLI throws on a missing file), and `JaCoCoXMLReportParser` reads the XML with `shouldResolveExternalEntities = false` (the DOCTYPE's DTD is never fetched) into `JavaCoverageReport` (packages, classes, source files with a sorted line array, totals; a line is covered, partial or missed by JaCoCo's own rule, `bands` merges adjacent lines of one status). **Profiling:** `JavaFlightRecorder.vmArgument` (`-XX:StartFlightRecording=filename=…,settings=profile,dumponexit=true`, `%p` for a task that forks; the period option needs Java 17), `JavaProfileGradleScript` (the same for `JavaExec` and `Test` tasks), `JavaFlightRecordingDetector` (the `FLR\0` magic wins over the `.jfr` name), `JavaRecordingImporter` runs `jfr print --events … --stack-depth 128` and feeds the stream to `JFRTextParser` (bytes in any chunking, frames interned into `JavaProfileSymbols`, `...` marks a truncated stack) which `JavaProfile.ingest`s into `JavaProfileTree`s: a prefix tree of interned frames with self and total counts, memory bounded by distinct stacks and a 200 000-node cap that folds the rest into `(other)`, with `hotMethods` (lines merged, recursion counted once), `callers`/`callees` and `foldedStacks`. CPU also keeps a tree per thread (at most 64). Allocation (weight in bytes, class as the leaf), lock contention (`JavaMonitorEnter`, `ThreadPark`, weight in µs) and GC pauses are the other kinds. `JavaRunArtifacts` keeps `Caches/com.umbra.editor/{Coverage,Profiles}/<project hash>/<run id>/` (newest 5 coverage runs, 10 profiles, 500 MB per kind and project). `JavaLaunchCommand.makeProcessLaunch(extraVMArguments:)` puts the agent or recorder switch ahead of the user's VM options. Release numbers (`swift run -c release PerfHarness java-profile-import synthetic --samples 60000 --depth 128`, `java-coverage-bands synthetic --lines 20000`): a 193 MB dump in 1.4 s, a 20 000-line report in 26 ms. Tests: `JaCoCoXMLReportParserTests`, `JavaCoverageCommandTests`, `JavaCoverageScopeTests`, `JFRTextParserTests`, `JavaProfileTreeTests`, `JavaFlightRecorderTests`, `JavaRunArtifactsTests`, `JavaRunInstrumentationTests`, and `JavaInstrumentationRealJDKTests` (a real JVM with the agent and with JFR; skipped without a JDK, and without the jars for coverage).

- **Diagrams** (`Sources/JavaIntelligence/Diagrams/`, `Gradle/GradleDependencyGraph*.swift`). Both are pure values with no UI, which Umbra draws (`Umbra/Sources/Umbra/Diagrams/`). `JavaClassGraphBuilder.build(scope:options:)` returns a `JavaClassGraph` of `Node`s (kind, members as UML lines such as `+ latest(): Order` and `- orders: List<Order>`) and `Edge`s (inheritance, realization, association, aggregation, dependency; the strongest kind wins between two types). Scopes are `.types`, `.file`, `.package`, `.project`; `JavaClassGraphOptions` has `showMembers`, `showPrivateMembers`, `showExternalTypes`, `neighbourDepth` (0...2) and `nodeLimit` (150). The hierarchy is always drawn whatever the options: every project supertype above the scoped types, every subtype or implementer below them, and library supertypes (e.g. `Exception`); `neighbourDepth` and `showExternalTypes` only add field/method-type neighbours and library types outside the hierarchy. Relations are resolved with `JavaTypeResolver` and the declaring file's `JavaResolutionContext` (built from `JavaSourceStubBuilder`, over unsaved buffers when `openBuffer` is given): JDK containers (`List<Order>`) are looked through to their arguments and make a field an aggregation, `java.lang` and `Object` are skipped except as supertypes, and `throws` types (recorded by the stub builder; shards written before that lack them until re-indexed) count as dependencies. `GradleDependencyGraph` is one Codable type for two views: `moduleGraph(from:)` reads project-to-project dependencies out of `JavaGradleProjectModel` without running Gradle, and the library view comes from `GradleDependencyGraphExtractor`, which runs an init script (`GradleDependencyGraphScript`, Groovy, walking `ResolutionResult` of a configuration, default `runtimeClasspath`) through `GradleCommandRunner` and decodes its JSON (components keyed `group:name`, `project:<path>` or `unresolved:<x>`; `requestedVersion` on an edge only when conflict resolution replaced it; `limited(to: 800)` caps it breadth-first). Tests: `JavaClassGraphBuilderTests`, `GradleDependencyGraphTests` (one runs a real Gradle when a JDK and `gradle` are present).
- **Debugger support** (`Sources/JavaIntelligence/Debug/`). `JavaCallSites.calls(onLine:in:)` lists a line's calls in the order they run (receiver and arguments first, lambda bodies left out; `<init>` for `new`) for Smart Step Into. `JavaStreamChain.chains(onLine:in:)` finds stream pipelines touching a line (a source such as `.stream()` or `IntStream.range`, known intermediate operations, a terminal one), `tracedExpression()` rewrites one to record `{time, value}` after every stage, and `links(from:to:operation:)` maps each element to its source (by time; `sorted`/`distinct` by identity). `JavaExpressionSyntax.problem(in:)` checks that a condition or watch parses. `JavaTestRunScope.tests(taskPath:filters:)` runs several `--tests` filters; `JavaTestRunner.gradleArguments(for:debug:)` adds `--debug-jvm` and `taskPaths(for:debug:)` puts `clean<Task>` first; `JUnitXMLReportParser` keeps each case's `output` (its own `system-out`/`system-err`, else its suite's). Tests: `JavaDebugSupportTests`.

- **Shared across windows.** `GradleTrustStore`, `JDKSelectionStore` and `JavaRunConfigurationStore` are used through one instance per app in Umbra, and each reloads its JSON file when it changed on disk (`FileChangeStamp`, which reads the modification date through `FileManager`: `URL.resourceValues` caches per `URL` value and would never see a change) before reading or merging its own change, so a second writer is not overwritten. `JDKIndexRoot.make(for:)` picks the JDK's root: `ct.sym` unless it has no signatures for the JDK's own release (Oracle 21's does not), then `jmods/` under a different shard kind, so an empty `ctsym` shard is never read; `IDEJavaSupport.indexJDK` also keeps a working JDK reader when the new one has no classes. `JavaSharedShardHub` (`Sources/JavaIntelligence/Scanning/`) runs one indexing pass per shard, hands the same parsed `JavaIndexShardReader` to every caller, and keeps at most four for the JDK shard. For dependency jars (`indexJars(_:)`, `readers(for:)`) it claims each shard once across callers, sends waiters a `rootSkipped` per jar so their counters reach their totals, parses missing readers in parallel, and holds readers weakly while any window uses them; release jars from Gradle/Maven caches (`JavaJarCachePolicy.isImmutableArtifact`) also stay in an LRU bounded by `maxRetainedNames`, and `trimMemory()` empties it. Every request compares the reader's stamp with the shard file's, and the scheduler's freshness check reads only the shard header (`JavaIndexShardReader.readStamp(at:)`), never the whole table. Shard files are written atomically, so another process never reads half of one.

- **Warm `javac` analysis server** (`Umbra/Sources/Umbra/Tools/JavaAnalysisServer/`, client in `Sources/JavaIntelligence/AnalysisServer/`). The server (`com.umbra.analysis.JavaAnalysisServer`, built by `build.sh` with `javac --release 17`, bundled like `java-debug-adapter.jar`) reads JSON lines over stdio and runs a fresh `JavacTask` per `check` over a cached per-module `StandardJavaFileManager`, so classpath jars stay open; the checked file and every overlay are explicit in-memory units, so open buffers shadow the disk. It runs the full pipeline with class output discarded, and reports each diagnostic's `getCode()` key with exact UTF-16 offsets plus the CLI's line/column (which differ for keys like `missing.ret.stmt`, whose span covers the body but whose position is its end). `JavaAnalysisServerClient` (an actor over SubprocessKit, never `Foundation.Process`) starts the server lazily, restarts on crash with backoff, replays `configure` after every relaunch, shuts down after 10 idle minutes, and matches responses by request id; `JavaAnalysisServerHub` shares one client per JDK home across windows. The library ships no jar: Umbra injects the jar URL and JDK. Tests: `Tests/PenumbraTests/JavaIntelligence/Parity/JavaAnalysisServerTests` (skipped without a JDK; `testCheckMatchesCliJavac` proves `check` reports the same places as CLI `javac`).

- **Warm diagnostics in the editor (Phase 2).** `JavaCompilerDiagnosticsService` prefers the server when a backend is set (`setServerBackend`, one client per JDK home) and the cold CLI stays the fallback; `JavacInvocationBuilder.resolve` shares the classpath truth between both paths. The server module is reconfigured only on change, checks carry every open Java buffer as an overlay (async provider the host snapshots on the main actor), diagnostics map to exact ranges with `javac:<key>` codes, and the idle wait is host-set from the Autoreparse Delay (`setIdleDelay`; a warm-server backend, when one lands, splits it per backend with a zero server wait). Same-text refreshes never restart a waiting or running compile (`force` on `schedule` is the only restart channel). `JavaDiagnosticsMerger` (inside `JavaSyntaxAwareDiagnostics`, which now also folds the inspection service in — there is no separate inspections provider entry anymore) drops inspection findings that restate a fresh keyed `javac` error (`unresolved-*` against `cant.resolve*`, `unreachable-code` against `unreachable.stmt`); unkeyed CLI diagnostics and stale results suppress nothing. The first key-driven quick fixes live in `JavaCompilerQuickFixes` (import rekeyed on the code; *Add throws* / *Surround with try/catch* for unreported exceptions, *Implement methods* for unimplemented abstracts, *Add return statement* for missing returns). Umbra wires the backend in `IDEJavaSupport.refreshCompilerDiagnostics` (JDK 17+ only, jar from the bundle with a repo fallback) and runs `swift run -c release PerfHarness java-analysis-server synthetic` for the warm-check number (57 ms warm median on 2k lines here; the 300 ms exit gate wants the full idle-to-errors path on a synced Gradle project).

- **Go to Definition coverage** (`Sources/JavaIntelligence/Navigation/`). `JavaGoToDefinition.resolve` tries three classifiers in order: a click inside a `/** */` comment (`JavadocReferenceScanner`, pure text: `{@link X}`, `{@link X#m(T)}`, `{@link #m}`, `@see`, `@throws`, `@param`, `@param <T>`; resolved by `JavaNavigationSession.javadocHits`), then `JavaNavigationExtras` (references only navigation understands, kept out of `JavaReference` so Find Usages, Rename and Hover do not change: `break`/`continue` labels, method references `Foo::bar` / `this::bar` / `Foo::new` (typed through `JavaExpressionTyper.receiverInfo` with the `::` as the separator; `::new` lists every constructor), annotation element keys, bare `case ADMIN` labels (typed from the `switch` selector, falling back to the ordinary bare-name lookup), and package segments), then the shared `JavaReferenceClassifier`. Locals, parameters, catch and pattern bindings and labels come from the memoized scope tree (`scopeDeclarationRange`), with `JavaDeclarationLocator.localDeclarationRange` as the fallback for `ERROR` regions. A chain such as `com.acme.util.Strings.isBlank(s)` resolves segment by segment (`qualifiedNameHits`: a type if the dotted name is one, else a package). **Packages** (`JavaPackageNavigation`): a project package returns one `Location.Target.directory` per source root that holds it (main and test, several modules; a prefix such as `com.acme` with no class of its own is found through its nearest subpackages and the extra folders stripped), a JDK or dependency package returns one `.package(name)`; the host decides what to show (Umbra: `revealInExplorer`, or `IDEWorkspace.showLibraryPackage`, which lists the classes and opens the chosen one through `openJavaType`). `JumpToDefinitionController` and `EditorIntelligenceController.focus` hand any non-`.source` target to `onOpenInOtherDocument` and never move the selection. Same-arity method overloads are narrowed by argument types (`refine`, shared with Find Usages; constructors still list every same-arity match). Lombok `getX`/`isX`/`setX` have no declaration, so they go to the field they are generated from (`generatedAccessorHits`, access not checked: the field is private). An enum's `values()`/`valueOf()` go to the enum. An unqualified call or name inside `new Named() { ... }` looks at `Named` first (`anonymousClassSupertypes`). `JavaMemberLookup` judges protected access against the ancestors of every enclosing type, so a nested subclass reaches its inherited protected members. Tested by the golden corpus `Tests/PenumbraTests/Fixtures/JavaNavigationCorpus` (`cases/*.java` with a `/*|*/` click and `//! target: model/Dog.java:fetch`, `targets: N`, `none`, `package-dirs:` or `package:` expectations, a `gap:` tag for a known failure, `baseline.json` ratchet; `JavaNavigationCorpusTests`, `JAVA_NAVIGATION_CASE=Prefix`, `UPDATE_JAVA_NAVIGATION_BASELINE=1`), `JavadocReferenceScannerTests` and `JumpToDefinitionTargetTests`.

- **Show Siblings, Method Hierarchy, scopes** (`Navigation/JavaGoToSiblings.swift`, `Hierarchy/JavaMethodHierarchy.swift`, `Hierarchy/JavaHierarchyScope.swift`). `JavaNavigationSession.methodAtCaret()` is the method a call names, else the declaration the caret is inside (shared by both). Show Siblings asks `JavaSuperMethods.overridden` for the nearest super declarations and lists the project implementations of each (`implementationHits(forMethod:)`, anonymous classes included) minus the caret's own method. `JavaMethodHierarchyProvider` (over a `JavaTypeHierarchyProvider`) roots at the topmost class declaring the method (`JavaMethodFamily.family` for who declares it, `topmost` picking the declaration no other is above) and marks each class `defines`, `inherits`, or `shouldDefine` (concrete, nearest declaration abstract, not itself abstract — the abstractness comes from the class stub's modifiers, since a node has none); going up starts a fresh path so the classes above are not read as a cycle. `JavaHierarchyScope.contains` tells test sources from production ones (a Gradle source set whose name has "test" in it, else a `src/test` or `test/java` folder) for subtype and caller searches. Call Hierarchy roots at a field too: its callers are the methods that read or write it (`.read`/`.write` usages), it has no callees. Tests: `JavaMethodHierarchyTests`, `JavaHierarchyScopeTests`, `JavaCallHierarchyTests`.

- **⌘-click latency and misses** (follow-up). `JavaNavigationParseMemo` keeps the last 12 parses (24 MB) that Go to Definition asked for, keyed by length and a 64-bit hash of the text, with the file stubs per path: hovering a word, clicking it, hovering the next one, and a jump into a class that was just opened all reuse the parse (a warm request at 10,000 lines is about 5 ms, down from 28; the first on new text still parses, about 2.8 ms per 1,000 lines). It is not `JavaDocumentParseCache`: that one keys on document version, and a navigation snapshot can lag the buffer. `JumpToDefinitionController` copies the buffer once per `contentGeneration` and hands a click the result ⌘-hover already found for the same word in the same text (`cachedHoverResult`). Measure with `swift run -c release PerfHarness java-goto-definition synthetic [--lines N]` (click and hover, cold and warm, per kind of site; the request is built before the timer starts, and `PENUMBRA_GOTO_SITE=jdk_type` keeps one kind of site so a sampler sees only it). Warm costs that used to grow with the file or repeat per click: `SyntaxNode.children`/`namedChildren` were quadratic (`ts_node_child(i)` per index; now one cursor walk, which every Java feature that lists a type's members gained from), `JavaNavigationText.textRange`/`position` scanned the text through `NSString.character(at:)` once per end (now one pass over the UTF-8 bytes, `LineScan`), `utf8ByteOffset` copied the prefix, and a JDK or dependency click re-opened `src.zip` and parsed its ~30,000-entry central directory (`ZipArchiveCache`: six archives kept, re-opened when the file's size or modification date changes; the extracted copy under `attached-sources` is rewritten only when it is stale). Release, 20,000-line current file, warm click: project symbols 0.25 → 0.16 ms, local variable 3.2 → 0.6 ms, JDK type or method 5 → 0.3 ms; a click on a name the current class declares still costs ~1.8 µs per member of that class (the live stubs bypass the shared member cache), 6 ms at 3,300 members. Tests: `JavaNavigationTextTests` (against the `NSString` walk), `SyntaxNodeChildrenTests`, `ZipArchiveCacheTests`. Constructors narrow by argument types as methods do (`new Foo("m", cause)` goes to `Foo(String, Exception)`); an argument whose type cannot be determined leaves every candidate (`refine`), instead of letting the overload resolver guess. ⌘-click on the name of a method that overrides or implements another goes to that method. A request sees the buffer's own classes (`JavaIndex.liveStubs`, a task-local that `JavaNavigationSession.withLiveStubs` sets and that bypasses the shared member cache), so code typed a moment ago resolves before the overlay's 300 ms debounce catches up. Corpus: 172 cases, among them the shapes real services are made of (generic repositories, `Optional` and stream chains, builders, inherited generics, exceptions).
