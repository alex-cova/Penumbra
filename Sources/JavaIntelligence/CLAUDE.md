# JavaIntelligence

Loaded when working under `Sources/JavaIntelligence`. Moved out of the root CLAUDE.md; the root file keeps a one-line summary. Umbra's side of the wiring is in `Example/Umbra/CLAUDE.md`. Inspection rules: `Inspections/CLAUDE.md`; profiler model: `Profiling/CLAUDE.md`.

- **`JavaIntelligence`** — native Java indexing and completion (JDK discovery, source and JAR stubs, type resolution, completion) with **no dependency on `Penumbra`**. Umbra wires it through `Example/Umbra/IDEJavaSupport.swift`. Completion (`Sources/JavaIntelligence/Completion/`) parses with a dummy identifier at the caret (`JavaCompletionProvider.dummyIdentifier`), types lambdas and method references through the target parameter's functional interface, resolves source members against their declaring file's imports, classifies the site (`JavaCompletionContextClassifier`: member access, `::`, import/package, `@`, `new`, type-only, `case`, class body, statement), ranks by expected type (`JavaExpectedType`, `JavaAssignability`), auto-imports classes (`JavaImportInserter`), offers `@Override` stubs in class bodies, and doubles as parameter info (`JavaSignatureHelp.swift`). For a Gradle project, a trusted sync (`GradleCommandRunner` plus an init script) replaces the whole-folder `.java` walk with per-module source sets and resolved dependency JARs. Go to Definition (`Sources/JavaIntelligence/Navigation/`) resolves into attached sources when present (a JDK `lib/src.zip` or a dependency's adjacent `*-sources.jar`, via `JavaAttachedSources`) and otherwise falls back to decompiling the `.class` file with [Sunflower](https://github.com/alex-cova/sunflower) (`FernflowerKit`, `JavaClassDecompiler`) — gated by a one-time user agreement (`JavaDecompilerAgreement`) that only a manual navigation (never Cmd-hover) can trigger, via `JavaGoToDefinitionProvider.setDecompilerConsent(accepted:request:)`. Compiler diagnostics (`Sources/JavaIntelligence/Diagnostics/`): `JavaCompilerDiagnosticsService` is a `DiagnosticProvider` that runs the JDK's `javac` (`JDKInstallation.javac`) over the editor's text — `JavacInvocationBuilder` builds the command (Gradle source-set classpath/sourcepath, `--release` capped at the JDK, `-proc:none` except a project's own Lombok jar; a plain folder infers its package root), `JavacOutputParser` parses stderr — and returns the last result while a debounced (600 ms idle), cancellable, 2-at-a-time compile runs, pushing finished results through `setResultHandler`. It stays off until Umbra configures it (`IDEJavaSupport.refreshCompilerDiagnostics()`: a plain folder, or a Gradle project that has synced; the `javaCompilerDiagnostics` preference), and `compileNow(_:force:)` backs the recheck after save and after sync. Go to Implementation (`JavaGoToImplementation`) lists the project classes that extend or implement a type, or override a method (a scan of `JavaIndex.projectClassStubs()`, scoped to the file's Gradle source set). Hover (`Sources/JavaIntelligence/Hover/`): `JavaHoverProvider` shows the declaration (`JavaSignatureText`) and Javadoc (`JavadocMarkdown`) of the symbol at the caret, from source stubs or from an attached `src.zip` / `*-sources.jar` (never decompiled); a resting caret (`.idle`) only pops up when there is documentation, an explicit request (`.manual`) always does. `JavaCodeActionProvider` offers "Import `a.b.X`" for a `cannot find symbol … class X` error on the caret's line and a remove-unused-imports action (`JavaUnusedImports`, conservative: syntax errors yield no edits, Javadoc references keep their imports, `*` imports stay). `JavaBreadcrumbProvider` labels the caret's enclosing declarations (`Outer<T> › put(String, int)`). `JavacDiagnosticsMapper` turns a whole Gradle build's `javac` output into diagnostics per file, and `JavaRunConfiguration` / `JavaRunConfigurationStore` (`Sources/JavaIntelligence/Launch/`) hold a project's launches (see the run configuration paragraph below). `JavaFormatter` (`Sources/JavaIntelligence/Formatting/`) is a whitespace-only formatter over the tree-sitter tree — indentation (blocks, `case` labels, brace-less bodies, two-level continuation), spacing between tokens, trailing spaces, blank-line runs; it never joins, splits or moves lines, refuses a file that doesn't parse cleanly and any result whose non-whitespace changed. `JavaFormattingProvider` wraps it as a `FormattingProviding` (whole file, or only the selected lines with every line break kept), and `JavaFormatEdits` turns the result into minimal per-line edits so carets stay put. `JavaImportOrganizer` sorts and prunes imports (other, `javax`/`java`, static; a comment inside the block limits it to removal). The Gradle model (format version 4) records each source set's runtime jars, runtime project dependencies and output directories; `JavaGradleProjectModel.runtimeClasspath(forFile:)` returns them in `java -cp` order (used by the classpath run target). ⌘-click (Go to Definition) on the name of an abstract declaration — an interface, an abstract class, a non-static non-private interface method, or an abstract method — returns its implementations instead (`JavaGoToImplementation.isAbstractDeclaration`); several ⌘-click targets pop up next to the click in `NavigationChoicesView` (↑/↓, Return, Esc; `JumpToDefinitionController.onPresentChoicesAtClick`), while ⌘B/⌥⌘B still use `onPresentNavigationChoices`. Go to Implementation also finds generic overrides (`compareTo(Foo)` for `Comparable<T>`), anonymous classes and enum constant bodies, and labels/sorts its picker results. `JavaTypeHierarchyProvider` (`Sources/JavaIntelligence/Hierarchy/`) builds the supertype tree (superclass, then interfaces, cycle-safe) and lazily expanded project subtypes; Umbra shows it in the Hierarchy bottom-panel tab (`EditorActionID.typeHierarchy`, ⌃H in the IntelliJ keymap, `EditorIntelligenceController.onRequestTypeHierarchy`). `JavaSemanticTokenProvider` (`Sources/JavaIntelligence/Semantic/`) classifies identifiers (types by kind, methods, fields, enum constants, parameters, locals; locals shadow fields) in one scope-aware pass, and `TextView.setSemanticHighlights(_:)` (`SemanticHighlightStore`) paints them over the tree-sitter colours, colour only, following edits until the next set (Umbra: `semanticHighlighting` preference, on by default). `JavaInlayHintProvider` (`Sources/JavaIntelligence/Inlay/`) produces, per `JavaInlayHintOptions` (a fixed value, or `setOptionsSource` asked at every request), parameter-name hints for calls that bind to exactly one method, and type hints (`InlayHint.Kind.type`, label `: List<String>`) after `var` locals, `for (var …)` variables and implicitly typed lambda parameters. Type hints type the declaration's initializer with `JavaExpressionTyper.resolvingVarLocals` against the locals of the enclosing block (candidates of one block share one resolution; at most 60 declarations per request), skip initializers that already say the type (`new`, a cast, a literal, a factory like `List.of`) and ones that can't be typed (`Object` is what a failed inference falls back to, so it is never shown). `resolvingVarLocals` resolves `var` locals in passes against every other local, because the list is source order within a block. `TextView.inlayHints` (`InlayHint`) renders them by widening the preceding character, so they are display-only (Umbra: `javaInlayHints`, `javaInlayVariableTypes`, `javaInlayLambdaTypes`, all off by default; hints refresh after edits and when scrolling leaves the requested range). Tests: `JavaInlayHintProviderTests`. `JavaCodeVisionProvider` (`CodeVisionProviding`, same folder) gives a lens to every class, interface, enum, record, method and constructor: `codeVisionAnchors(for:)` is one pass over the tree (at most 400, the room for all of them), `codeVision(for:anchors:)` then labels the anchors on screen — `N usages` from `JavaFindUsagesProvider.findUsages`, and for interfaces, abstract classes and abstract or interface methods `N implementations` from `JavaGoToImplementation.resolve`. A search is expensive (it parses the files that mention the name), so results are cached by declaration signature and `JavaIndex.generation` (counts follow what the index knows, i.e. saved files), two run at a time and at most 40 per request. Options (`JavaCodeVisionOptions`) are read through `setOptionsSource`. Tests: `JavaCodeVisionProviderTests`. `JavaRunConfiguration` is now named and kept in a per-project list with a selected entry (`JavaRunConfigurationStore`, old files still load); a `.classpathMain` target launches `java -cp <runtime classpath> pkg.Main`, building the module's `classes` task first when its outputs are missing, and Umbra shows a run configuration picker in the toolbar. References (`Sources/JavaIntelligence/References/`): a persistent identifier index (`JavaNameIndex`, `JavaIdentifierScanner`, `refs.idx` shards via `JavaNameIndexShardWriter/Reader`, beside `sources.idx`; per-file stamps compared with one `getattrlistbulk` pass per directory (`JavaSourceStampScan`), an in-place posting update (`rewrite(from:removing:replacing:to:)`, returning the reader it already built) when a readable shard exists, open-buffer overlay; Umbra refreshes it and force re-indexes stubs when `IDEProjectWatcher` reports `.java` changes on disk) lists the candidate files for an identifier, and usages are then verified on demand instead of stored: `JavaSymbolIdentity` maps the caret to a `JavaSymbolID` (type, method with parameter keys, constructor, field, local by declaration range), `JavaFileUsageResolver` resolves every same-named identifier in a file (one parse and reusable context per file; unresolvable overloads or receivers are `.ambiguous`), `JavaLocalUsages` handles locals without the index, and `JavaUsageSearch` fans out over the roots that can see the declaration. `JavaFindUsagesProvider` answers `.references` for Java (methods search every member of `JavaMethodFamily`, which is built from the index only, so unsaved buffers and anonymous classes are not in it); `JavaGoToSuperMethod` answers `.superMethod`. `JavaRenameProvider` (`Sources/JavaIntelligence/Refactoring/`, a `RenameProviding`) renames types (with imports, static imports, Javadoc links and the `Old.java` file), locals, parameters (`JavaRenameProvider`), and methods (the whole override family), fields, enum constants and record components (`JavaMemberRename`); a family member in a JAR, the JDK or a generated root blocks the rename, ambiguous or read-only usages are left out of the edit unless the user ticks them in the preview, and Umbra deliberately gives it a text-scan candidate source (always correct) rather than the name index. Completion quality is tracked by a golden corpus (`Tests/PenumbraTests/Fixtures/JavaCompletionCorpus`: `cases/*.java` with `/*|*/` caret and `//! key: value` expectations, a fixture `project/`, `baseline.json` ratchet; `JavaCompletionCorpusTests`, `JAVA_COMPLETION_CASE=Prefix` to run a subset, `UPDATE_JAVA_COMPLETION_BASELINE=1` to ratchet; plan and gap list in `docs/JAVA_COMPLETION_PLAN.md`) and release latency by `swift run -c release PerfHarness java-completion synthetic [--jars N]` and `swift run -c release PerfHarness java-name-index <java-source-directory|synthetic> [--files N]`. Semantics behind it: generic-aware assignability (`JavaAssignability`, `JavaMemberLookup.asSupertype`), JLS overload phases (`JavaExpressionTyper.resolveOverloads`), lambda/poly-expression targets (`JavaExpressionTarget`), type-variable bounds (`JavaResolutionContext.typeParameterBounds`), inherited and dotted nested types, class-file `$` names normalized to `.` (shard format v3). `JavaIndex` has package tables, a decoded-stub cache that drops its oldest entry when full, a `generation` counter and a generation-scoped member-set cache; class names are bucketed by word start the same way members are (`JavaWordBuckets`); `classes(matching:)` ranks with `CompletionMatcher.tier` and decodes stubs only for the names it keeps; `classes(simpleName:)` is the exact simple-name lookup, and `classStub(qualifiedName:)` jumps to the shard that wins the name; the completion provider reparses incrementally. Postfix templates (`JavaPostfixTemplates`), position-aware keywords (`JavaKeywordPosition`), and a completion documentation preview (`EditorIntelligenceController.showsCompletionDocumentation`, resolved through the hover engine) complete the UX; `CompletionItem.origin` names an inherited member's type. Gradle model format 5 adds per-source-set `generatedSourceDirs` (indexed as read-only `SourceRoot.isGenerated` roots, re-indexed after Build Project) and `annotationProcessorJars` (`JavacInvocationBuilder` takes Lombok from them first). JDK selection (`Sources/JavaIntelligence/Discovery/`): `JDKLocator.discoverAll(additionalHomes:)` finds JDKs (`java_home`, `JavaVirtualMachines`, SDKMAN, Gradle, Homebrew, asdf, jenv, mise, plus homes the user added), `installation(atUserSelected:)` validates a picked folder (home, `.jdk` bundle or `bin`), and `resolve(selection:minimumFeatureVersion:additionalHomes:)` applies project JDK > default JDK > automatic (an explicit choice ignores the language level; a saved path that is gone is reported as `staleSelection`). `JDKSelectionStore` keeps the per-project choice, the default and the added JDKs in `jdk-selection.json`. `JavaLaunchCommand.make(... javaHome:)` runs that JDK's `bin/java` or prefixes a Gradle launch with `JAVA_HOME`/`PATH`. In Umbra, `IDEJDKSelection` (owned by `IDEJavaSupport.jdk`) is the only place that asks for a JDK (indexing, javac diagnostics, Gradle sync and tasks, Run, Debug); the status bar `IDEJDKStatusItem`, Java ▸ Project JDK and Settings › Java › JDKs (`IDEPreferencesJDKSection`) change it, and a change re-indexes the JDK, refreshes diagnostics and re-syncs a trusted Gradle project only when Gradle would launch on a different JDK. Generate… (`EditorActionID.generate`, Java ▸ Generate…, unbound because ⌘N is New File): `CodeGenerationProviding` (`Sources/EditorIntelligence/Refactoring/`) offers a `CodeGenerationMenu` (constructor, getter and setter, getter, setter, `toString()`, each with its candidate fields) and plans one edit; `JavaGenerateMembers` (`Sources/JavaIntelligence/Refactoring/`, wrapped by `JavaCodeGenerationProvider`) works on the buffer's syntax tree alone — it inserts after the member the caret is in (a constructor with the caret outside the body goes after the last field, the rest at the end of the type), skips accessors and `toString()` that already exist, and handles classes and enums only. `EditorIntelligenceController.generate()` asks the host through `onRequestGeneration` (Umbra: `IDEGeneratePrompt`, a caret popover: pick, then tick fields) and applies the edit without a preview, as one undo step. It ignores superclass constructors (no `super(...)` call is written).
- **Run configurations** (`Sources/JavaIntelligence/Launch/`). `JavaRunConfiguration` has a target (`.gradleRun`, `.singleFile`, `.classpathMain`, `.gradleTest(taskPath:filters:sourceFile:)`), `kind` (application, javaFile, gradle, junit), arguments, VM options, environment, working directory, `jdkHome`, `buildBeforeRun` (default on), `allowMultipleInstances`, `beforeLaunch` (`.gradleTasks`, `.runConfiguration(id)`), `shortenCommandLine`, `redirectInputPath`, `folder`, `storeAsProjectFile` and `isTemporary` (an unnamed configuration is temporary unless said otherwise, which is also what files saved before the flag decode to; every new field decodes with a default). `supportsVMArguments` / `supportsEnvironment` / `supportsWorkingDirectory` / `supportsBuildBeforeRun` say which targets a field reaches (Gradle tasks take none of the process fields). `JavaRunConfigurationStore` keeps the Mac-local list, the selection, per-kind templates and the temporary limit (`setLast(…temporaryLimit:)` drops the oldest temporary ones, never the selected); `JavaProjectRunConfigurationFolder` reads and writes `<project>/.umbra/runConfigurations/*.json` (relative paths, no `jdkHome`, `.withoutEscapingSlashes`, re-read when a file's date changes, one file per configuration, renamed with it); `JavaRunConfigurationCatalog` merges the two (the selection is always local, a flag change moves a configuration and keeps its id) and is what Umbra talks to. `JavaRunConfigurationValidator.problems(for:context:)` finds what is wrong without launching. `JavaLaunchCommand.makeProcessLaunch` builds the process for a class or single file (`JavaProcessLaunch`: environment = base, then `JAVA_HOME` and `PATH`, then the configuration's own; `@argfile` for a classpath over 32 KB on Java 9+; `newLaunchProtocolArguments` adds the preview switches); `make(configuration:…)` still builds a shell string (tests, Gradle). `JavaCommandLine.split` is the one argument splitter (single and double quotes, backslash), `join` its inverse. `JavaVMOptions` (`JavaVMOptions.swift`) is the curated list behind the form's VM options picker (Vector API, preview, native access, `--add-opens`, heap sizes, collectors, assertions, GC log, system properties): each `JavaVMOption` names its tokens, the ones it `replaces` (`-Xmx*`, the other collectors) and `minimumFeatureVersion`; `isEnabled` / `adding` / `removing` edit the field's text and leave what the user typed as written (test: `JavaVMOptionsTests`). `JavaMainMethod.locations(in:fileName:)` returns one `main` per class, the one the JVM picks (static with arguments, static without, instance with arguments, instance without; not `private`, instance forms need a creatable class), and a compact source file's method as an implicit class named after the file; `usesNewLaunchProtocol` says whether Java 21+'s protocol is needed. Tests: `JavaRunConfigurationCatalogTests`, `JavaRunConfigurationValidatorTests`, `JavaProcessLaunchTests`, `JavaLaunchTests`.

- **Coverage and profiling** (`Sources/JavaIntelligence/Coverage/`, `Profiling/`, `Launch/JavaRunArtifacts.swift`; plan: `docs/JAVA_COVERAGE_PROFILING_PLAN.md`). Pure values and command builders; Umbra draws them (`Example/Umbra/Coverage/`, `Profiler/`) and decides where each file goes. `JavaRunConfiguration.instrumentation` (`JavaRunInstrumentation`: `none`, `coverage`, `profile`, decoded with a default and an unknown raw value reading as `none`; `supportsInstrumentation` is false for a debug launch) is the one switch, so Rerun and Run Last repeat it; the validator refuses coverage of a `.singleFile` (source-launch mode keeps its classes in memory), instrumentation with the debugger, and Profile below Java 11. **Coverage:** `JavaCoverageToolchain` locates the bundled `jacocoagent.jar` and `jacococli.jar` (pinned `version` 0.8.15, `supportedClassFileMajor` 70 = Java 26; `unsupportedLanguageLevel` turns a newer project into one sentence), `JavaCoverageCommand` builds the `-javaagent:` argument (`destfile=…,append=true,includes=…,output=file`; `nil` for a path JaCoCo's option syntax cannot carry, i.e. a comma) and the `report`/`--html` invocations as argument vectors, `JavaCoverageScope` / `JavaCoveragePackages` take `includes` from the *declared* packages of the main source sets (never directory names) and the class directories from the Gradle model, `JavaCoverageGradleScript` is the init script that adds the agent to every `Test` and `JavaExec` task (decided in `doFirst`, because the `jacoco` plugin adds its extension after init-script actions run; a project that applies `jacoco` itself keeps its own agent and only its `.exec` is reported through a `##umbra-coverage|exec|<path>` marker line), `JavaCoverageReportRunner` runs the CLI through SubprocessKit (missing or header-only `.exec` is `noExecutionData`, the CLI throws on a missing file), and `JaCoCoXMLReportParser` reads the XML with `shouldResolveExternalEntities = false` (the DOCTYPE's DTD is never fetched) into `JavaCoverageReport` (packages, classes, source files with a sorted line array, totals; a line is covered, partial or missed by JaCoCo's own rule, `bands` merges adjacent lines of one status). **Profiling:** `JavaFlightRecorder.vmArgument` (`-XX:StartFlightRecording=filename=…,settings=profile,dumponexit=true`, `%p` for a task that forks; the period option needs Java 17), `JavaProfileGradleScript` (the same for `JavaExec` and `Test` tasks), `JavaFlightRecordingDetector` (the `FLR\0` magic wins over the `.jfr` name), `JavaRecordingImporter` runs `jfr print --events … --stack-depth 128` and feeds the stream to `JFRTextParser` (bytes in any chunking, frames interned into `JavaProfileSymbols`, `...` marks a truncated stack) which `JavaProfile.ingest`s into `JavaProfileTree`s: a prefix tree of interned frames with self and total counts, memory bounded by distinct stacks and a 200 000-node cap that folds the rest into `(other)`, with `hotMethods` (lines merged, recursion counted once), `callers`/`callees` and `foldedStacks`. CPU also keeps a tree per thread (at most 64). Allocation (weight in bytes, class as the leaf), lock contention (`JavaMonitorEnter`, `ThreadPark`, weight in µs) and GC pauses are the other kinds. `JavaRunArtifacts` keeps `Caches/com.umbra.editor/{Coverage,Profiles}/<project hash>/<run id>/` (newest 5 coverage runs, 10 profiles, 500 MB per kind and project). `JavaLaunchCommand.makeProcessLaunch(extraVMArguments:)` puts the agent or recorder switch ahead of the user's VM options. Release numbers (`swift run -c release PerfHarness java-profile-import synthetic --samples 60000 --depth 128`, `java-coverage-bands synthetic --lines 20000`): a 193 MB dump in 1.4 s, a 20 000-line report in 26 ms. Tests: `JaCoCoXMLReportParserTests`, `JavaCoverageCommandTests`, `JavaCoverageScopeTests`, `JFRTextParserTests`, `JavaProfileTreeTests`, `JavaFlightRecorderTests`, `JavaRunArtifactsTests`, `JavaRunInstrumentationTests`, and `JavaInstrumentationRealJDKTests` (a real JVM with the agent and with JFR; skipped without a JDK, and without the jars for coverage).

- **Diagrams** (`Sources/JavaIntelligence/Diagrams/`, `Gradle/GradleDependencyGraph*.swift`). Both are pure values with no UI, which Umbra draws (`Example/Umbra/Diagrams/`). `JavaClassGraphBuilder.build(scope:options:)` returns a `JavaClassGraph` of `Node`s (kind, members as UML lines such as `+ latest(): Order` and `- orders: List<Order>`) and `Edge`s (inheritance, realization, association, aggregation, dependency; the strongest kind wins between two types). Scopes are `.types`, `.file`, `.package`, `.project`; `JavaClassGraphOptions` has `showMembers`, `showPrivateMembers`, `showExternalTypes`, `neighbourDepth` (0...2) and `nodeLimit` (150). The hierarchy is always drawn whatever the options: every project supertype above the scoped types, every subtype or implementer below them, and library supertypes (e.g. `Exception`); `neighbourDepth` and `showExternalTypes` only add field/method-type neighbours and library types outside the hierarchy. Relations are resolved with `JavaTypeResolver` and the declaring file's `JavaResolutionContext` (built from `JavaSourceStubBuilder`, over unsaved buffers when `openBuffer` is given): JDK containers (`List<Order>`) are looked through to their arguments and make a field an aggregation, `java.lang` and `Object` are skipped except as supertypes, and `throws` types (recorded by the stub builder; shards written before that lack them until re-indexed) count as dependencies. `GradleDependencyGraph` is one Codable type for two views: `moduleGraph(from:)` reads project-to-project dependencies out of `JavaGradleProjectModel` without running Gradle, and the library view comes from `GradleDependencyGraphExtractor`, which runs an init script (`GradleDependencyGraphScript`, Groovy, walking `ResolutionResult` of a configuration, default `runtimeClasspath`) through `GradleCommandRunner` and decodes its JSON (components keyed `group:name`, `project:<path>` or `unresolved:<x>`; `requestedVersion` on an edge only when conflict resolution replaced it; `limited(to: 800)` caps it breadth-first). Tests: `JavaClassGraphBuilderTests`, `GradleDependencyGraphTests` (one runs a real Gradle when a JDK and `gradle` are present).
- **Debugger support** (`Sources/JavaIntelligence/Debug/`). `JavaCallSites.calls(onLine:in:)` lists a line's calls in the order they run (receiver and arguments first, lambda bodies left out; `<init>` for `new`) for Smart Step Into. `JavaStreamChain.chains(onLine:in:)` finds stream pipelines touching a line (a source such as `.stream()` or `IntStream.range`, known intermediate operations, a terminal one), `tracedExpression()` rewrites one to record `{time, value}` after every stage, and `links(from:to:operation:)` maps each element to its source (by time; `sorted`/`distinct` by identity). `JavaExpressionSyntax.problem(in:)` checks that a condition or watch parses. `JavaTestRunScope.tests(taskPath:filters:)` runs several `--tests` filters; `JavaTestRunner.gradleArguments(for:debug:)` adds `--debug-jvm` and `taskPaths(for:debug:)` puts `clean<Task>` first; `JUnitXMLReportParser` keeps each case's `output` (its own `system-out`/`system-err`, else its suite's). Tests: `JavaDebugSupportTests`.

- **Shared across windows.** `GradleTrustStore`, `JDKSelectionStore` and `JavaRunConfigurationStore` are used through one instance per app in Umbra, and each reloads its JSON file when it changed on disk (`FileChangeStamp`, which reads the modification date through `FileManager`: `URL.resourceValues` caches per `URL` value and would never see a change) before reading or merging its own change, so a second writer is not overwritten. `JavaSharedShardHub` (`Sources/JavaIntelligence/Scanning/`) runs one indexing pass per shard, hands the same parsed `JavaIndexShardReader` to every caller, and keeps at most four for the JDK shard. For dependency jars (`indexJars(_:)`, `readers(for:)`) it claims each shard once across callers, sends waiters a `rootSkipped` per jar so their counters reach their totals, parses missing readers in parallel, and holds readers weakly while any window uses them; release jars from Gradle/Maven caches (`JavaJarCachePolicy.isImmutableArtifact`) also stay in an LRU bounded by `maxRetainedNames`, and `trimMemory()` empties it. Every request compares the reader's stamp with the shard file's, and the scheduler's freshness check reads only the shard header (`JavaIndexShardReader.readStamp(at:)`), never the whole table. Shard files are written atomically, so another process never reads half of one.
