# Java inspections (`Sources/JavaIntelligence/Inspections`)

Loaded when working under `Sources/JavaIntelligence/Inspections`. Split out of `Sources/JavaIntelligence/CLAUDE.md`.

- **Suppression** (`Inspections/JavaSuppression.swift`). `JavaInspectionService` drops inspections silenced by an enclosing `@SuppressWarnings("<code>")` (or `"all"`) or a `//noinspection <code>[, …]` (`ALL`) comment on the line above an enclosing statement or declaration (inspection codes are the rule ids such as `unused-import`; javac lint warnings carry their category, e.g. `rawtypes`, and javac honours the annotation itself). `JavaCodeActionProvider` offers "Suppress '<code>' for variable/method/class" (innermost three; merged into an existing `@SuppressWarnings`) or, with `setSuppressionStyle(.comment)` or for an import, a `//noinspection` line. `JavaInspectionService.setIdleDelay` is an extra wait the host owns (Umbra passes zero: the adapter's content debounce is the only Autoreparse Delay); same-text refreshes never restart a waiting or running pass (`pendingHash`).

- **Inspection rules** (`Sources/JavaIntelligence/Inspections/`). `JavaInspectionRule` is the catalogue: each case has a `code` (the id on `JavaInspection`/`Diagnostic.code`, also what `@SuppressWarnings`/`//noinspection` name), `title`, `summary`, `group` (`JavaInspectionGroup`, after Inspectopedia's categories) and `defaultSeverity`, in one table (`JavaInspectionRule(code:)` looks a rule up). `JavaInspection.Severity` is `error`/`warning`/`weakWarning`/`info`; `JavaInspectionService.setEnabledRules` and `setSeverityOverrides` take the user's choices. The six original rules (imports, `missing-override`, `unresolved-type`, `class-file-name-mismatch`) are called by hand from `runAnalysis`; every other rule is a `JavaNodeInspection` (`nodeTypes`, `check(node:context:report:)`, optional `fixes(for:tree:source:)`) listed in `JavaInspectionRegistry.nodeInspections`, and `JavaInspectionRunner` visits the tree once and hands each node to the enabled rules registered for its type, so adding a rule adds no tree walk. `Diagnostic` carries no edits, so `JavaCodeActionProvider.registeredInspectionFixes` rebuilds a rule's fixes from the diagnostic's range (`JavaInspectionSupport.node(of:for:tree:source:)` finds the reported node by exact range) against a fresh tree. Rules live in `ProbableBugs/`, `VerboseCode/` and `DeclarationRedundancy/` and are syntactic: `JavaDeclaredTypes` reads a variable's type from its declaration in the same file (locals, parameters, fields, `this.f`, `v.f` for a class in the file, literals, `"a" + x`) and answers `nil` for anything else, and a rule stays silent on `nil` rather than guess. `JavaDeclarationCache` (on `JavaSyntaxTree`) memoizes field tables, expression types and a `JavaPositionIndex` (byte offset to `TextPosition` by binary search; `JavaImportInserter.textPosition` decodes the whole prefix and is O(file) per call), which keeps a pass linear: about 20 ms per 1k lines in Release, flow analysis included (`swift run -c release PerfHarness java-inspections synthetic --lines 20000`, or a path). Rules that need types resolved through the index are `JavaTypedInspection`s (`Inspections/Typed/`, `JavaInspectionRegistry.typedInspections`): `JavaInspectionRunner.runTyped` collects every candidate node of the types they ask for in one pass and hands the list over, and they build a `JavaNavigationSession` at a node (`JavaInspectionSupport.session(for:at:)`) to type a receiver or list a call's overloads (`receiverInfo(of:nameNode:)`, `allMethods`). They resolve once per (declared type, method, arity) and stop at a budget, and `maxTypedLineCount` (20,000 lines) skips them for huge files. `access-static-via-instance` needs a receiver variable of a declared type and only static overloads at that arity; `redundant-array-creation` needs one varargs overload with exactly that element type and no other overload that unwrapping the array could bind to (source stubs spell element types as `.unresolved`, library stubs as `.classType`). `StyleAndUsage/` rules share `JavaFileSymbolTable` (`JavaDeclarationCache.fileSymbols(context:)`: one extra `JavaSemanticWalker` pass with `localSink` gives every local's uses, plus every identifier by name): `local-can-be-final`, `mismatched-collection-query-update` (locals and private fields created with `new`; any escape silences it), `unused-private-member` (name scan of the file; annotated members and types, serialization hooks and no-argument private constructors are skipped), plus `for-can-be-foreach` and `try-finally-can-be-twr` in `VerboseCode/JavaLoopModernizationInspections.swift` (their tests are in `JavaStyleUsageInspectionTests`, and `JavaInspectionRulesTests` excludes these rules because they fire on almost any sample body). Class-structure rules (`ClassStructure/JavaClassStructureInspections.swift`, group `classStructure`, helpers in `JavaClassShape`): `utility-class-with-public-constructor` (all-static members, no supertypes; also reports the implicit constructor of a public class; skips a class that only holds `main`), `public-field`, `missing-serial-version-uid` (direct `Serializable`/`Externalizable` only; fix inserts the field), `clone-without-cloneable` (skipped for abstract classes, classes with any supertype or interface other than `Serializable`, and bodies that only throw), `final-method-in-final-class` and `protected-member-in-final-class` (explicit `final` classes and records; protected methods are skipped when the class has a supertype, since dropping `protected` could break an unannotated override), `class-may-be-interface`. Redundancy rules: `redundant-local-variable` (`T x = e; return x;` / `throw x;`; skipped for array initializers, lambdas and narrow-typed literals), `redundant-string-operation` (`toString()`, `substring(0)`, `new String(s)` on a declared String), `declaration-uses-concrete-class` (`StyleAndUsage/`: locals and private fields of `ArrayList`, `LinkedList`, `HashMap`, `LinkedHashMap`, `HashSet`, `LinkedHashSet` whose every use is a call of an interface method, a foreach source or an assignment target; passing it on, returning it or `Deque`/sequenced methods keep it; the fix adds `import java.util.X;` when needed), `static-via-subclass` (superclass chain inside the file only), and the typed `anonymous-can-be-lambda` (`Typed/JavaAnonymousLambdaInspection.swift`: the interface is resolved through the index and must have exactly one abstract method, `Object` methods and `default`/`static`/`private` methods excluded, source stubs name supertypes `.unresolved`; skipped for `this`/`super`, recursion, extra members and any name a lambda could not redeclare). Concurrency and collection rules (`ProbableBugs/JavaConcurrencyInspections.swift`, `JavaConstructionAndCollectionInspections.swift`): `overridable-method-called-in-constructor` (same-class methods, same arity, all overloads overridable; skipped for final classes and classes with only private constructors), `synchronization-on-string-literal`, `synchronization-on-this` (weak), `wait-not-in-loop` (receiver `this`, none, or declared `Object`), `sorted-collection-non-comparable` (a `TreeSet`/`TreeMap`/`PriorityQueue`/`ConcurrentSkipList*` created without arguments whose element class is declared in the file and is not `Comparable`; `JavaDeclaredTypeArguments` reads `<T>` from the creation or the declaration for `<>`), `suspicious-to-array` (`(T[]) c.toArray()` unless `T` is a type parameter, and `toArray(new A[0])` between two final JDK types), `list-remove-in-loop` (add/remove/clear on the collection a foreach or `i < c.size()` loop iterates; skipped when a `break`/`return`/`throw` follows in the block, or an index loop steps the index itself). Screened against the JDK 25 `java.base` util/io/lang/net slice: `final-method-in-final-class` (~570), `public-field` (~130), `synchronization-on-this` (~155) and `overridable-method-called-in-constructor` (~105) are noisy there by design and stay weak warnings or warnings the user can switch off. Metric rules (`Metrics/`: `cyclomatic-complexity`, `nesting-depth`, `parameter-count`, `method-length`, `class-length`) read their number from `JavaInspectionContext.thresholds` (`JavaInspectionThresholds`, set with `JavaInspectionService.setThresholds`; `JavaInspectionRule.limit` gives the label, default and range Settings shows). Javadoc rules (`Javadoc/`, group `javadoc`; `JavaJavadoc.above(_:)` reads the `/** */` comment that is a declaration's previous sibling): `javadoc-missing-param` (parameters and `<T>` type parameters), `javadoc-missing-return`, `javadoc-invalid-param` (unknown or duplicate names); comments with `{@inheritDoc}` are skipped and a fix needs a multi-line comment whose last line is just `*/`. Data-flow rules (`DataFlow/`, run by `JavaInspectionRunner.runFlow` after the node rules): `JavaDataFlowAnalyzer` is an abstract interpreter over each method, constructor, initializer and lambda body (structured control flow, not a CFG). Its state (`JavaFlowState`) maps each local to nullness, a bool/int constant and a resource state; loops widen the locals they assign, `try` makes what the body assigns unknown in handlers and `finally`, lambdas and switch expressions havoc. A `nil` state is javac's "cannot complete normally", so `unreachable-code` matches the compiler; a branch that only the facts rule out is run muted with the other side's state. Rules: `null-dereference` (certainly null, error), `nullable-dereference` (null on some path, weak warning: correlated conditions make it noisy, so it is separate), `redundant-null-check`, `condition-always-constant` (int/bool constants and tracked booleans; literal-only conditions stay with `constant-condition`), `unreachable-code`, `unused-assignment` (pending stores per local, a union over joined paths: a store is reported when some path overwrites it or leaves the method without a read and no path reads it; loops, handlers and closures that mention the local count as reads), `resource-not-closed` (a `new` of a known closeable in a local, not closed on every normal exit; passing it on, returning it or a `finally`/`try` touching it stops tracking). Project-wide rules (`Project/JavaProjectInspector.swift`, `JavaInspectionRegistry.projectRules`): `unused-declaration`, `declaration-access-can-be-weaker` (only "can be private": every usage inside the declaration's top-level type), `method-can-be-void` (every usage is an expression statement; skipped for overrides, `return this`, method references), `parameter-always-same-value` (two or more calls, all the same literal). They need usages, so `JavaInspectionService.runProjectInspections(for:)` runs them after a save or index change (Umbra: `IDEJavaSupport.compileNow` / `reanalyzeInspections`), one `JavaFindUsagesProvider.declarationUsages` per declaration (capped at 150 per file, with the override-family size), then re-runs `analyzeNow`; the findings are keyed to the text hash and vanish on the next edit. `JavaProjectInspectionOptions.treatsPublicApiAsUsed` (default on) leaves public and protected members, capped by their enclosing types, alone; annotated members (except `@Deprecated`, `@SuppressWarnings` and the like), `main`, `@Override`, `serialVersionUID` and types with `main` are never candidates. Tests: `JavaProjectInspectorTests`. Parameters start unknown (annotations are not trusted), fields and call results are unknown, and the analysis aborts a method over 300k steps or 150 nesting levels. Tests: `JavaDataFlowInspectionTests`; sweep real sources before loosening anything. `JavaSemanticWalker.run()` recurses, so it declines trees deeper than `maxTreeDepth` (a 400-term string concatenation overflowed a task thread's 512 KB stack): it returns `false` and collects nothing, which the inspection pass tolerates. **Second batch of rules** (15, all `JavaNodeInspection`s, tests in `JavaMoreInspectionsTests`, screened against the JDK's `java.base` util/lang/io/net/time sources: 1,193 files in 8 s). `ProbableBugs/JavaMoreProbableBugsInspections.swift`: `optional-get-without-check` (`get()` on a variable declared `Optional`, silent when the member calls `isPresent`/`isEmpty`/`ifPresent` on it), `switch-fall-through` (a non-last `case` group ending in an expression or declaration; a "fall through" comment at its end, between groups or after the next label silences it), `duplicate-condition` (an else-if repeating an earlier condition; conditions with calls, assignments or `new` are skipped), `thread-run-call` (fix: `start`), `format-argument-count` (`String.format`, `System.out/err.printf|format`, `"…".formatted`; indexed `%1$s` and `%<s` skip; a single argument of unknown or array type is assumed to be spread), `bigdecimal-equals`. `VerboseCode/JavaLambdaAndRedundancyInspections.swift`: `lambda-can-be-method-reference` (parameters forwarded in order to `Type.m`, `this.m`, a local's `m`, or `new T`; a field receiver is left alone because a method reference evaluates it once; fix), `lambda-body-can-be-expression` (a block with only a `return expr;` or a call/assignment statement, no comments; fix), `literal-equals-reversed` (declared-String receiver, non-empty literal; fix swaps), `redundant-field-initializer`, `unnecessary-super-constructor-call`, `redundant-interface-modifier` (interface fields are `constant_declaration` nodes), `string-length-zero-check` (declared-String receiver; fix `isEmpty()`). `StyleAndUsage/JavaUnusedLocalAndFinalFieldInspections.swift`: `unused-local-variable` (from `JavaFileSymbolTable`; the fix only when the initializer runs no code) and `field-can-be-final` (private, initialized, no assignment to that name anywhere in the file via `JavaDeclarationCache.assignedNames`, no annotation on the field or class). `literal-equals-reversed` and `redundant-field-initializer` start off (style preferences the JDK trips hundreds of times); `unused-local-variable` and `field-can-be-final` fire on `JavaInspectionRulesTests`' sample bodies, so that suite lists them in `coveredElsewhere`.

**Third batch of rules** (15, same shape, tests in `JavaThirdBatchInspectionsTests`, screened against the same JDK sources: 1,193 files in 12 s). New groups `threading`, `security` and `testFrameworks`. `ProbableBugs/JavaThirdBatchBugInspections.swift`: `split-regex-special-char` (declared-String receiver or a literal, a one-character metacharacter; `Pattern.split` is left alone; fix escapes it), `exception-cause-lost` (a `throw new …Exception/Error` in a `catch` that never mentions the caught variable; JDK exceptions with no cause constructor such as `UnknownHostException` are skipped), `floating-point-equality` (off by default: exact comparison is deliberate in numeric code; zero, NaN and infinities are skipped), `shift-out-of-range` (constant distance against the declared width), `assignment-as-condition` (only a literal or plain variable on the right, because `if (x = a != b)` is a deliberate idiom; fix `==`), `pattern-compile-in-loop`. `ProbableBugs/JavaThreadingInspections.swift`: `volatile-non-atomic-update` (`++`, compound assignment, `x = x + 1` on a volatile field of the nearest enclosing class that declares it, through `JavaDeclarationCache.fieldVolatility`; a parameter or `other.x` of the same name is not a read; skipped in synchronized code, private helpers and members that call `lock()`), `wait-notify-outside-synchronized` (the receiver's monitor must be held; private helpers are skipped), `static-non-thread-safe-format`, `double-checked-locking` (fix makes the field volatile). `Security/JavaSecurityInspections.swift`: `weak-cryptographic-algorithm` (`MessageDigest` MD2/MD4/MD5/SHA/SHA-1, `Cipher` DES/3DES/RC2/RC4/ECB, `AES` alone), `sql-string-concatenation` (a concatenation with SQL words and a non-literal passed to `executeQuery`, `prepareStatement`, …), `runtime-exec-concatenation`, `hardcoded-credential` (off by default; names ending in key, name, header and so on, and values that are themselves credential words, are skipped). `StyleAndUsage/JavaJUnitInspections.swift`: `assert-equals-argument-order` (only with an `org.junit` import and none of `org.testng`; JUnit 4 has the message first, Jupiter last; fix swaps the two).

**Language-level rules** (11, `Inspections/Migration/`, group "Java language level migration aids", tests in `JavaLanguageLevelInspectionsTests`). `JavaInspectionContext.languageLevel` (and `supports(_:)`) carries the file's Java level; the pipeline, `JavaBatchInspector` and `JavaBatchFixer` take it, `JavaInspectionService.setLanguageLevelResolver` supplies it per file, and a rule reports nothing while it is nil or too low. Umbra resolves it as the file's Gradle subproject level (`JavaGradleProjectModel.languageLevel(forFile:)`), else the selected JDK's feature version (`IDEJavaSupport.refreshInspectionLanguageLevel`). Rules: `instanceof-pattern` (16: `if (x instanceof Foo) { Foo f = (Foo) x; … }`; fix merges), `enhanced-switch` (14, Consideration: every merged `case` group ends in break/return/throw, no break left in a body, no local shared between groups; fix writes arrows), `text-block` (15: three or more literals, two or more `\n`, no trailing whitespace or unsupported escapes; fix), `local-variable-type-can-be-var` (10, off: `new`, cast and String literal only), `collections-empty-factory` (9, off: `List.of().contains(null)` throws), `string-is-blank` (11), `optional-is-empty` (11), `stream-to-list` (16, off: the result is unmodifiable), `sequenced-collection-access` (21, Consideration), `string-formatted` (15, Consideration), `map-get-or-default` (8: only a literal, variable or field as the default, since `getOrDefault` evaluates it eagerly). Screened on the JDK and on 26k files of older library sources.

**Fourth batch of rules** (21, tests in `JavaFourthBatchInspectionsTests`; screened on the JDK's `java.base` and 26k files of older library sources). `VerboseCode/JavaFourthBatchRedundancyInspections.swift`: `unnecessary-semicolon` (a `;` that is a direct child of a class or interface body or the file), `unnecessary-to-string` (only when the other operand of the `+` is a declared String), `string-index-of-contains` (declared-String receiver, String argument), `manual-array-copy` and `arrays-fill-loop` (both read one `for (int i = 0; i < n; i++) a[i] = …` shape, `ArrayLoop`; the fill fix qualifies `java.util.` unless `Arrays` is imported), `collections-sort-to-list-sort` (Java 8, declared List/ArrayList/LinkedList), `append-concatenation` (the chain must start with a String literal), `lowercase-long-literal`, `deprecated-tag-without-annotation` (uses `JavaJavadoc.above`). `ClassStructure/JavaStaticCandidateInspections.swift` works from declared types and the file's own members, with no index: `inner-class-may-be-static` and `method-may-be-static` (off) only in classes with no superclass anywhere in the chain, and they treat any mention of an instance member name, `this`, `Outer.this`, a type parameter or a non-static inner class as a use; `field-may-be-static`, `unused-parameter` (private methods; serialization hooks skipped), `non-serializable-field` (a short JDK list and same-file classes with no supertypes), `raw-type-usage` (off; JDK generics plus same-file generic classes via `JavaDeclarationCache.genericTypeNames`) and `unchecked-cast` (off). `ProbableBugs/JavaFourthBatchBugInspections.swift`: `switch-enum-missing-cases` (enum declared in the file, no default, every label a bare constant), `empty-synchronized-block`, `sleep-while-holding-lock`, `equals-incompatible-types` (declared wrapper types that differ), `integer-overflow-in-long-assignment` (int `*` chains and `<<`; literal products that fit an int are skipped; fix casts the first operand). New group `serialization`. The sweep tuned `integer-overflow-in-long-assignment` to bound each factor's magnitude (literals, `x % n`, `x & mask`, byte/short/char, and `final` fields with constant initializers, so `24 * ONE_HOUR` and `12 * (x % 2)` pass), kept `field-may-be-static` to private and package-private fields (a public one would change the API), and removed `ReentrantLock`, `Semaphore`, `Condition` and `Lock` from the non-serializable list (they are Serializable or ambiguous).

**Cost of a pass.** Timing every rule on real files found two quadratic costs, both fixed: `JavaDeclaredTypes.variableType` rescanned a block's statements on every lookup (now `JavaDeclarationCache.blockLocals`, a name table per block), and `typeDeclaration(named:in:)` searched the whole tree per call, so `static-via-subclass` cost 31 of the 49 seconds of a pass over `java.util` (now `typeDeclarationRanges`, built once; the pass is 11 s). A rule that visits siblings per declaration (`deprecated-tag-without-annotation`) should pair neighbours inside the parent's own visit instead of calling `previousNamedSibling`, which is a scan of all siblings. To find the next one, time each rule alone over a few hundred files (`JavaInspectionRunner.run(context:enabled: [rule])`): a rule far above the ~0.3 s median is the one.

**Fifth batch** (15, tests in `JavaFifthBatchInspectionsTests`). Four rules resolve through the index as `JavaTypedInspection`s (`Typed/JavaIndexBackedInspections.swift`; each keeps a per-file verdict cache and a resolution budget like the existing typed rules): `deprecated-constructor-usage` (`session.resolveType` then `JavaMemberLookup.constructors`; every constructor that fits the arity must be deprecated), `deprecated-field-usage` (`session.fieldAccessTarget`), `suspicious-collection-argument` (`receiverInfo` gives the collection's type arguments; compares the argument's declared wrapper type with the element or key type; `List.remove(int)` is an index and is skipped; an element type the index lacks arrives as `.unresolved`) and `field-hides-superclass-field` (the superclass is read from the `extends` clause and resolved by name, because the class being edited is usually not in the index, and the access check is off for the same reason, so only public and protected fields count). Eleven are syntactic (`ProbableBugs/JavaFifthBatchInspections.swift`): `package-directory-mismatch` (the JDK's `snippet-files` skipped), `unsafe-thread-method`, `volatile-array-field`, `clone-without-super-call` (not in a final class or record, not when it throws), `equals-without-type-check` (a cast of the parameter with no `instanceof`, `getClass()` or helper call that takes it), `to-string-returns-null`, and five that start off: `notify-instead-of-notify-all`, `system-exit-call`, `octal-literal`, `parameter-hides-field` (28,000 hits in 26k files) and `static-field-written-from-instance`. `JavaNodeInspection`s can reach `JavaDeclarationCache.fieldFlags(of:)` for a class body's static/final flags. `SyntaxNode.isQualifiedCreation` says whether an object creation has a qualifier, which the grammar does not give a field name.

**Pipeline, profiles and batch runs.** `JavaInspectionPipeline.inspect` (`Inspections/JavaInspectionPipeline.swift`) is the one path from a file's text to its findings (hand-called rules, node rules, flow, stored project findings, typed rules); when the tree has a syntax error the semantic context fails but unused and duplicate imports are still reported from the well-formed import list (error isolation for typing, diagnostics only — never edits); `finalize` then drops what `@SuppressWarnings` / `//noinspection` silences, applies the profile's severities for the file and splits off the "No highlighting" findings. The on-the-fly `JavaInspectionService` and `JavaBatchInspector` both call it, so a rule behaves the same in the editor and in Inspect Code. `JavaInspectionProfile` (`Inspections/Profiles/`) is a Codable value (rules by code, so unknown codes survive a round trip): `disabled`, `severities` (raw values), `limits`, `treatsPublicApiAsUsed` and ordered `scopedOverrides` (`.tests` or a `JavaPathGlob` on the project-relative path; the first match for a rule wins, "everywhere else" is the base). `JavaInspectionFileClassifier` says which files are tests (the Gradle test source dirs, or a `/src/test/` path). `JavaInspectionService.setProfile(_:projectRoot:testRoots:)` replaces the four setters, which stay as wrappers. Severity `.noHighlighting` ("No highlighting (fix available)") is not published as a diagnostic: the service keeps those per file (`quietFindings(for:)`) and `JavaCodeActionProvider.setQuietFindingsSource` brings their fixes back to ⌥↩. The provider also offers "Fix all '<rule>' problems in file" (`JavaBatchFixer.allEdits`) and three host commands (`JavaInspectionCommand.disable/quiet/configure`, argument = rule code). `JavaInspectionFixes` is the one place that builds a diagnostic's fixes (imports, `@Override`, the registry); `JavaInspectionRule.hasQuickFix` comes from `providesFixes` on each node/typed inspection (a static flag next to its `fixes`: set it when you add a fix). `JavaBatchInspector` (`Inspections/Batch/`) runs many files off the service actor (4 at a time, cancellable, an `AsyncStream` of `.started/.file/.progress/.finished`), with the project-wide rules only on request; `JavaInspectionScope` resolves project / module / directory / files to `.java` URLs with test and file-mask filters; `JavaBatchFixer.fixAll` re-inspects and applies preferred fixes in up to 3 passes, skipping overlaps and suppressed findings; `JavaInspectionReport` writes SARIF 2.1.0 or HTML; `JavaInspectionQuickFixes` gives a result's fixes and Suppress actions from its file's text. Tests: `JavaInspectionProfileTests`, `JavaBatchInspectionTests`, `JavaInspectionPipelineTests`.

To check a new rule for false positives, run it over real sources (the JDK's `lib/src.zip`, `*-sources.jar` in the Gradle cache) and read the hits before trusting it; the `Tests/PenumbraTests/JavaIntelligence/JavaInspectionRulesTests.swift` cases give each rule a positive, a negative and its fix.

**Limitations.** Inspection results belong to the exact text that was analyzed: `diagnosticsWithFreshness` reports `java-inspection` as stale until the new pass lands, so the host keeps showing the previous text's rows as pending instead of drawing them as current. On a broken tree the pipeline reports imports, `class-file-name-mismatch` and the node rules in `JavaInspectionPipeline.brokenTreeRules` (minus `brokenTreeExclusions`), with findings touching the error ranges dropped; data-flow, typed, project, unresolved and `missing-override` rules stay strict-only.
