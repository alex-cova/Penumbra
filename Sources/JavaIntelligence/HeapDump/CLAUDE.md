# `Sources/JavaIntelligence/HeapDump`

Loaded when working under `Sources/JavaIntelligence/HeapDump`. Moved out of `Sources/JavaIntelligence/CLAUDE.md`.

- **Heap dumps** (`Sources/JavaIntelligence/HeapDump/`; plan `docs/HEAP_DUMP_PLAN.md`, UI and numbers `Umbra/Sources/Umbra/HeapDump/CLAUDE.md`). HPROF 1.0.1/1.0.2 read with `pread` into per-worker buffers (`HprofByteReader`, never `mmap` of the dump: a dump truncated underneath ends a walk with an error, not `SIGBUS`); `HprofHeapWalker` is the one sub-record parser, generic over an `HprofHeapVisitor` (census, index collector, record writer). `HeapDumpCensus` is the histogram (phase 1); `HeapIndexBuilder` the object index (phase 2): objects numbered 1…N in id order (0 is the super-root), `HeapMappedArray` files for ids, record offsets, classes, kinds, lengths, out- and in-references (CSR, high bit = `Reference.referent`), each class's members, plus `classes.bin` (names and fields resolved), `roots.bin`, `meta.json` and a `complete` marker written last. `HeapDominatorBuilder` (format 2) adds semi-NCA dominators over strong references from the super-root, retained sizes, dominator children sorted by retained size, class retained sizes (an instance counts unless a dominator above it is of its class), breadth-first parents for shortest paths to roots, and unreachable totals by class; every working array is a mapped file and every traversal an explicit stack (paths run thousands deep: no recursion, no tree of objects owning each other). `HeapIndex` answers bounded queries (a page of instances, one object's fields, a range of referrers, a node's dominator children, a path to a root, merged paths, a retained set) and reads values from the dump; `HeapValueFormatter` previews strings (JDK 9+ Latin-1/UTF-16 and JDK 8 `char[]`), boxes, enums, threads, sizes. `HeapReports.swift`: `HeapLeakSuspects` (MAT-style suspects with accumulation points), `HeapInspections` (duplicate strings, wasted collections, zero arrays; cached as `report-*.json` in the index folder) and the threads (`HeapThreadBuilder`, `threads.json`, from STACK_TRACE/STACK_FRAME records and frame roots). `HprofGzip` decompresses `.hprof.gz` (every gzip member in turn, through the system zlib's gzip mode, which checks each trailer; not the Compression framework, which reads past a member's end). `JavaLiveCommands.dumpHeap` and `JavaVMOptions.heapDumpPathArguments` are phase 5's command builders. `HeapIndexStore` keys a folder by the dump's path, size, mtime and inode and deletes partial or stale ones. Tests: `HeapDumpCensusTests`, `HeapIndexTests` (a seeded random graph against a naive model; `UMBRA_HPROF=<file>` for a real one), `HeapDominatorTests` (brute-force dominators, retained sizes and shortest paths on random graphs), `HeapReportsTests`; `PerfHarness heap-dump-census|heap-dump-index|heap-dump-reports <file>`.
