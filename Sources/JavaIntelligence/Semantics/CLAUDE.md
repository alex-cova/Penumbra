# Java semantic model (`Sources/JavaIntelligence/Semantics`)

Loaded when working under `Sources/JavaIntelligence/Semantics`. The symbol/scope/type
foundation (Phase 3 of `docs/JAVA_PARITY.md`'s plan): names every declaration, builds JLS 6.3
scopes once per parse, and answers type operations in one place. No dependency on `Penumbra`;
Umbra reaches it through providers, never directly.

- **Symbols** (`Model/JavaSymbol.swift`, `References/JavaSymbolID.swift`). `JavaSymbol` names
  every declaration kind — local, parameter, field, method, constructor, type, local type,
  type parameter, package, label — each carrying its declaration site (file plus the UTF-8 byte
  range of the declaring name) and, where a stub model exists, its stub. `id` follows
  `JavaSymbolID`: declared signatures, never substituted types, so the same method yields the
  same ID however it was reached. Locals and parameters share the `.local` site identity;
  type parameters, packages and labels have no ID yet. `.localType` covers classes declared in
  a body and anonymous class bodies (empty name, sited at the `new` expression), which have no
  qualified name, so usages and rename name them by site. Tests: `JavaSymbolTests`.
- **Scope tree** (`Model/JavaScopeTree.swift`). The lexical scopes of one parse, built once and
  memoized on the parse (`JavaSyntaxTree.scopeTree(for:)`, via `JavaScopeTreeCache`) instead of
  re-walked per query like the walk it replaced. Each declaration carries
  the byte range it is visible in, so `locals(atByteOffset:)`, `symbol(named:atByteOffset:)`
  and `scopeChain(atByteOffset:)` are range checks, not tree walks. Covers file, types (member
  types qualify as `Outer.Inner`; body-local types identify by site), methods/constructors/
  initializers, blocks, `for`/enhanced-`for` (including `var` iteration variables with
  `initializerText`), try-with-resources (resources scope over the body, catches and finally,
  JLS 6.3), catch (multi-catch records every type in `alternativeTypes`; the scope tree's primary
  stays the first alternative, and both `typedIdentifier` and `resolvingVarLocals` replace that
  primary with `effectiveCatchType` through one function, leaving the alternatives in place so a
  later read can recompute it), lambdas
  (inferred parameters carry their
  `JavaLambdaOrigin`), one scope per `switch` block with rules beneath it, pattern bindings
  with polarity (`&&` left-to-right, `||` under negation, `!` flips; bindings also visible
  inside their own right operands in any statement position) and flow-out past guard returns,
  record patterns (components typed from the pattern itself), local types, labels, and member
  recovery inside `ERROR` regions. Deliberate JLS-closer deltas from that walk, pinned
  by tests: a local is visible in its own initializer, switch groups share one scope.
  Out of v1, documented at each site: qualifier resolution, single-static-import names,
  do-while pattern flow, `var` resources naming an existing variable, operand visibility under
  an explicit `!`. Cost: ~6 ms build on a 2k-line file in Release
  (`swift run -c release PerfHarness java-scope-tree synthetic --lines 2000`, exit ≤ 50 ms);
  the debug unit test only guards against pathological blowups (1 s). Tests:
  `JavaScopeTreeTests` (the basic shapes, the order callers depend on, plus every delta).
- **Type system** (`Model/JavaTypeSystem.swift`). The one place for operations over
  `JavaTypeRef`: `substitute` (absorbed from `JavaMemberLookup`, which delegates),
  `erasure` (JLS 4.6; unresolvable variables go to `Object`, unresolved names stay
  unresolved), `erasedName` (the `method:String(int)` identity keys), `lub` (JLS 4.10.4,
  v1: erased — one erasure returns the original reference with arguments, otherwise the most
  specific common supertype through the index, raw; `nil` when names are unattributed,
  a class has no stub, or hierarchies stay open — a meet of only `Object` is returned when
  every alternative is indexed), `effectiveCatchType` (the lub when the index proves it is `Throwable` or below
  it; otherwise `java.lang.Throwable` as a conservative completion receiver, not a verified lub, when an
  alternative or a supertype is missing or the meet climbs above `Throwable`; the old first-alternative fallback only
  without a `Throwable` stub, and `Throwable` for no alternatives), and `inferredVarType` (the `var` seam both `resolvingVarLocals` and member
  completion assign through). A `var` initializer is typed once against locals whose declaring
  name has already ended (`JavaLocalVariable.declarationEnd`), so `Optional<T> opt; var item = opt.get()`
  sees `opt` and the existing substitution of `T`. A later local is not in scope. A use of the
  variable's own name (`var n = n`, `var n = n + 1`) stays untyped; `n()` and `this.n` do not.
  An enhanced-`for` variable is not in scope in the iterated expression. `asSuper` stays on
  `JavaMemberLookup.asSupertype` until attribution; the lub reaches it through the public
  query. `lub` with no single most specific member returns the minimal class (else interface) as the
  representative of the intersection (`preferredMinimal`); `lubKeepingArguments` is the conditional /
  `switch` form (type arguments kept where the arms agree, `?` where they do not). There is no
  nominal `JavaType` or intersection type, deliberately (F01 notes). Tests: `JavaTypeSystemTests`
  (substitution, erasure, lub over a shard-built stub hierarchy, the var seam, the conditional rules).
- **Incumbents the model is absorbing.** `JavaExpressionTyper`
  keeps its public API (`receiverInfo`, `typeOfExpression`, `resolvingVarLocals`) and will
  become a façade over the attributor; `JavaMemberLookup` (generic-aware members,
  `asSupertype`, `supertypeClosure`) and `JavaTypeResolver` (simple names against
  `JavaResolutionContext`: package, imports, enclosing types, type parameters and bounds)
  stay the resolution workhorses. `JavaReceiverScanner` finds the pre-dot expression
  textually (reparsing a dangling `.` collapses too much into `ERROR`); `JavaStaticImports`
  names single and on-demand static-import members.
- **Locals** (`JavaSyntaxTree.visibleLocals(atByteOffset:)`, `Syntax/JavaSyntaxAliases.swift`). The one answer to "which locals are visible here", used by completion, receiver typing, usage resolution, inlay hints, go to type definition, the type intention and the extract refactorings; the per-query `JavaLocalScope` walk it replaced is gone (`Semantics/JavaLocalVariable.swift` keeps `JavaLocalVariable`, `JavaLambdaOrigin`, `JavaExpressionTarget` and `JavaExpressionTarget.target(of:)`). It is the scope tree's locals for the outermost method, constructor, static initializer, or instance-initializer block around the offset (`JavaScopeTree.locals(in:enclosingExecutableAtByteOffset:)`: no stub pass, so the cost follows that member, not the file; the whole-file tree added ~5 ms per large-file completion; memoized per parse). A local of an initializer is visible inside an anonymous class declared there, and not in a method of the same type. Plus `JavaErrorRecoveredLocals` for a method that collapsed into a flat `ERROR` (the parameters and the locals declared before the damage, which stay direct children in source order; a balanced block stays a `block` child that is never entered, so its locals do not leak), minus the variable whose own initializer holds the offset (JLS 6.3 keeps it in scope, javac rejects the use). Order is the contract: an inner scope first, a scope's locals in source order, then its parameters (`JavaScopeTreeTests`). Gives completion pattern bindings in `switch` rules (including a `switch` used as a value: `expressionScopes` builds its block) and negated `instanceof`. Corpus cases `AttrPattern*`, `Err*`.
- **Type-argument reads vs writes** (`JavaMemberLookup`). A `? super X` argument supplies `X` to parameters but only its upper bound to returns and fields (`readSubstitution`), through supertype levels (`inheritedLowerBounded`). Diamond: `JavaExpressionTyper.diamondResolved` binds class type parameters from constructor arguments; unbound leaves the type raw.
- **Anonymous and local classes** (`JavaAnonymousClass`). `new Foo() { … }` is a synthetic `JavaClassStub` (`$Anonymous<hash of the text>` under the top-level type; `JavaSourceStubBuilder.anonymousStub`) registered in a request-scoped task-local `JavaAnonymousClass.registry` that `JavaIndex.classStub` consults after `liveStubs`. The stub's `outerQualifiedName` is the enclosing top-level type, so a `private` member is visible throughout that type, and nested stubs are registered too. A local class uses the same registry: `owner.$Local<startByte>.SimpleName`, bound by `makeScopedRequest` from the locals visible at the caret (outermost first, so a nested local's owner is the enclosing local). The primary stub's outer name is rewritten to the real enclosing type; a member class of the local keeps the synthetic owner. `JavaResolutionContext.localTypes` maps the simple name to that synthetic qualified name, and `resolveSimpleName` consults it after type parameters. Only the completion provider sets a registry (`withAnonymousClasses`), so `JavaExpressionTyper` types the expression as the anonymous type there and as `Foo` everywhere else; the provider also enters the anonymous bodies around the caret as the innermost types. Member sets of synthetic types (`$Anonymous` or `$Local`) are never cached. A type declared directly in an anonymous body is a member of the anonymous class, not a local class: `bindLocalClasses` binds it as `Owner.$Anonymous<hash>.Name`, the name the anonymous stub registers for the same declaration, so `Cell c` in the body and `TreeMap<Cell, Cell>` reached through the anonymous field are one type (a `$Local` name gave one class two identities in a request, and a conditional over both lost the members). The hash covers the creation's text, which holds the caret's dummy identifier, so the name is stable within a request, not across requests; textually identical anonymous bodies share it. Tests: `AttrAnonymous*` and `GapLocalClass*`, `GapAnonymousClassFieldByName`, `JavaReceiverFidelityTests` (javac-checked identities and member sets).
- **Arrays and `getClass()`** (`JavaMemberLookup.members(of: .array)`, `JavaExpressionTyper.specializingGetClass`). An array type has `length`, a public `clone()` returning the array type, and `Object`'s public members (JLS 10.7; `Object`'s protected ones are not accessible through it, including from a `java.lang` source). `x.getClass()` is `Class<? extends |T|>` for the searched type `T` (the receiver's static type, or the enclosing class when unqualified; a type variable erases to its leftmost bound), JLS 4.3.2. javac captures that wildcard; the engine keeps it and member lookup reads it through the bound, so `getClass().cast(o)` is `T`'s erasure. No capture variable. `Class<? extends X>` is not contained in `Class<X>` or `Class<? super X>` (`JavaAssignability.contains`); it is contained in `Class<? extends Super>` and `Class<?>`. Corpus: `GapArrayObjectMembers`, `GapArrayGetClass`.
- **Protected access** (`JavaMemberLookup`, JLS 6.6.2.1). Same package, a static member, a constructor, `super`, and a simple name need only that an enclosing class (innermost first, interfaces skipped) subclasses the declaring class. An instance member through an expression also needs the receiver type to be that enclosing class or a subclass of it, so `sub.secret` is offered and `base.secret` is not. `Object.clone` and `Object.finalize` are offered on `this` and on a subclass receiver, and not on `Object`, another class, an interface (JLS 9.2 keeps only `Object`'s public instance methods when access is checked), or an array. An interface is queued before a superclass that has not yet reached `Object` (the walk is a FIFO). That public-only visit does not mark `Object` visited while access is checked, so the class chain still adds `clone` and `finalize`; the second walk skips the public members already recorded, and with access checks off one visit keeps the protected methods. A class with no recorded superclass still counts as a subclass of `Object`, so `this.clone()` is visible in a source class that does not write `extends`. The qualifier is part of the member-set cache key.
- **Qualified `super`** (`JavaExpressionTyper.typedQualifiedSuper`). tree-sitter keeps `super` as a sibling between the qualifier and the member (`object: Outer (super) name: action`), so the receiver span is the qualifier plus `super`, and `Outer.super;` is not parsed as an expression. Two forms, and neither is unqualified `super`. `TypeName.super` is legal when `TypeName` is a lexically enclosing class, enum or record, including the class that directly contains the expression (javac compiles `Outer.super` inside `Outer`); the type is that class's direct superclass, so an override there wins (`Mid.action`, not `Base.action`). Inside the class itself that is the same type as unqualified `super`; inside a nested class it is not. javac still attributes this from a static nested class, a static method, an enum or a record and reports the static-context error separately, so the receiver stays the superclass. A direct superinterface of the innermost type is the other form (`Speak.super`); an indirect superinterface, the superclass written by name, a sibling, the innermost type itself, and an enclosing interface (`I.super` from a local class in a default method) are not receivers. A direct-superinterface form inside a static method or static initializer is not attributed. A local that reuses the type's simple name does not hide it. Member lookup uses `.viaSuper`. Tests: `JavaReceiverFidelityTests`, `JavaCompletionProviderContextTests`.
- **Three scope readers.** `JavaScopeTree` (completion, receiver typing, local declaration lookup), `JavaSemanticWalker` (Find Usages of locals, Rename, highlighting) and `JavaDeclarationLocator.localDeclarationRange` (a use to its declaration; asks the tree first, its ancestor walk is the ERROR-region backstop). A binding form added to one has to be added to the others until they merge: `instanceof` bindings and record pattern components were missing from the walker, the classifier and the identity step (`JavaPatternBindingUsagesTests`).
- **Generic call inference** (`JavaExpressionTyper.typedMethodInvocation`, F01). Constraints are taken in javac's order (JLS 18.5): explicit type arguments, the call's own target, plain arguments (several for one variable meet in their lub, `argumentBindings`), then lambda bodies and method references typed against the functional interface with those bindings substituted; a generic call passed as an argument is retyped against its parameter with the known bindings substituted, and waits for the lambdas when the parameter still mentions a variable only a lambda binds. A method reference through an unbound receiver (`Map.Entry::getKey`) takes the functional interface's first parameter as its receiver, so the type arguments reach the result. Conditionals and `switch` expressions combine all their arms (`conditionalType`: null, numeric promotion, boolean, lub). Interface-typed receivers have `Object`'s public methods (JLS 9.2); a member class of a generic class carries the enclosing type (`attachingOuter`, one level). The corpus cases `Infer*`, `Infer2*` and `Cap*` are the specification; add a case before changing any of this.
- **Lambda parameter inference** (`JavaExpressionTyper.inferInvocation`, `infer`, `applyFunctional`; `docs/JAVA_COMPLETION_QUALITY.md`, "Contextual inference for lambdas and generic calls"). The call's own type and a lambda parameter's type come from the *same* routine; the parameter query leaves its own lambda out (its body holds the caret). Rules that are easy to break: (1) the callee's type parameters are renamed apart (`T#`, `renamedApart`) so a caller's `<T>` is a real type and never the callee's open variable; markers are stripped on the way out (`withoutInferenceMarkers`), and a leftover `T#` means "unknown", not a type. (2) Overloads are filtered by potential compatibility of lambda arity / method reference with the parameter (`FunctionalShape`, `resolveOverloads(shapes:)`); lambda bodies are deliberately not looked at, the one being typed is unfinished. (3) A target type binds type arguments as an equality but a *bare* return variable only as an upper bound, after arguments and lambda results and before an input is defaulted. (4) Lambdas run pertinent-first (zero-arg, explicit, method references), implicit ones once their inputs are known, the rest with inputs at their bounds. (5) `lambdaParameterType` is memoized for the outermost question (`LambdaParameterMemo`); without it the cost doubles per level of nested lambdas (`JavaLambdaInferenceBoundsTests`), and `maximumInferenceDepth` is the backstop. (6) The `Lam*` corpus cases carry `//! receiverType:` (full type), and `JavaLambdaInferenceOracleTests` checks them against javac; a case with an `//! oracle:` note is excluded and says why. **Incomplete code** (`docs/JAVA_COMPLETION_QUALITY.md`, "Inference while the code is incomplete"): (7) `JavaCompletionRepair.closingSequence` closes, on the caret's line, a `{` that follows `->` or `)` **only when it sits inside a `(` still open on that line** (`;}` before the call's `)`); a free-standing block, an array initializer and braces in literals are left alone, and `ReferenceRepair` (the test oracle) has its own implementation that must be changed with it. (8) A lambda under an `ERROR` node gets its call from `JavaExpressionTarget.recoveredCallArgumentTarget`: a forward scan of at most the last 4 KB of the statement's bytes, rebuilding `callee(earlier arguments, <parameters> -> {})`; it never runs on a clean tree and refuses `new X(`. (9) `buildLocalVariables` scopes the lambdas in a declaration's `ERROR` remnant (`String r = flag ? f(x -> x.`). (10) A *finished* lambda body selects overloads by `void`/value (`lambdaBody`, JLS 15.27.2); a body with a syntax error or the dummy identifier, and the lambda being asked about, stay compatible with every overload. Known gap `R2`: a doubly nested, multi-line, never closed lambda (the outer lambda is not a node). **Generic type system audit** (`docs/JAVA_GENERIC_TYPE_AUDIT.md`): capture is approximated by the bound inside each member walk and that is enough (the representation buckets did not move, and they still have the same members); do not add capture variables or a bound solver. The scope forms (varargs parameters, `for`-header variables, local/anonymous classes, interface constants, multi-catch, C-style dimensions) and the inference-variable wildcard in `JavaAssignability.contains` are fixed. On the same 16,436 sites, genuine receiver mismatches went from 87 to 12 after the scope pass, then to 10 after `var` inference (exact 14,673; the two `Optional.get()` locals are exact). Of the 10 that remained, `docs/JAVA_RECEIVER_FIDELITY_FINAL_AUDIT.md` fixed `array.getClass()` (arrays lacked `Object`'s members) and gave the eight `CellExtractor` sites one identity (`$Anonymous<hash>.CounterCell` both in the body and through the field; the audit prints both as `CounterCell`, so those eight stay in their buckets and are spelling-only, member sets checked against javac). The multi-catch whose Jackson jar is missing is `Throwable`; javac's `JsonPatchException` there is its error recovery on an incomplete classpath. `G1`–`G6` stay tagged `gap:`.
