# Diff viewer (`Umbra/Sources/Umbra/Diff`)

Loaded when working under `Umbra/Sources/Umbra/Diff`. Split out of `Umbra/CLAUDE.md`.

- **Diff viewer** (`Umbra/Sources/Umbra/Diff/`, `IDEWorkspace+Diff.swift`), after IntelliJ's Differences viewer. Diffs open as editor tabs: a `WorkbenchDocument` with `contentKind == .diff` (never restored with the session) whose `IDEDiffSession` lives in `IDEWorkspace.diffSessions`; the pane host lays `IDEDiffViewerView` over its editor while the tab is selected (`showDiffDocument`). An `IDEDiffRequest` names two `IDEDiffSource`s (a `GitRevision` of a path, the working tree, or fixed text). Entry points: double-click (or Show Diff) in the Changes list — unstaged rows compare index ↔ working tree, staged rows HEAD ↔ index, and Previous/Next File walk the rows of that section; the ↗ button over the sidebar preview; History's changed-files list under a commit (parent ↔ commit: a click shows the file in the pane's own viewer, a double-click opens a tab); Git ▸ Show Diff with HEAD / Compare with Branch / Compare with Clipboard, and the editor's context menu. The model is pure and tested (`IDEDiffComputer`: line LCS with whitespace policies none/trim/ignore/ignore + empty lines, then word, character or split highlighting inside changed blocks; `IDEDiffUnifiedLayout`; `IDEDiffPatchBuilder`). Two Penumbra `TextView`s show the sides with syntax colors (`TextView.lineBackgrounds` for the bands, `highlightedRanges` for words), `IDEDiffDividerView` draws the ribbons, the » chevron (left lines replace the right ones, ⌥-click appends; one undo step) and, for index comparisons, Stage / Unstage of one hunk (`git apply --cached --unidiff-zero`). Unified mode is one read-only text with old/new numbers in the annotation column. Toolbar: ⇧F7/F7 previous/next change (past the last change F7 moves to the next file), Previous/Next File, Jump to Source (F4), layout, whitespace and highlight menus, Collapse Unchanged Fragments (a `foldingProviderOverride` folding all but 3 lines around each change; `applyFolding` installs a provider only when the collapse flag or the changed ranges differ from what the view has, because a new provider re-folds what the user opened, and `applyPreferences` resets that memory since `IDEPreferences.apply(to:)` overwrites the views' folding switch; the ribbons redraw from `TextView.addFoldObserver`, as a fold scan lands without a scroll; switching collapse on or off centers the current change again, once every visible side has finished its fold scan, since thousands of lines fold or come back and the old scroll position points at nothing) and Synchronize Scrolling (viewport middles mapped through the chunks). The working-tree side is editable unless its editor tab has unsaved changes; edits are saved on ⌘S, when the tab is left or closed, and before switching files, then clean editor tabs reload. Every git refresh reloads open diffs; one whose texts did not change keeps its place. Options persist in `UserDefaults` (`umbra.diff.*`). **Embedded viewer** (`IDEEmbeddedDiffView`): the same `IDEDiffViewerView` outside a tab, in the History pane. `IDEWorkspace.makeEmbeddedDiffSession` has no document (no retitling) and its own options (`IDEDiffSettings.embeddedPrefix`, unified by default); the pane swaps files with `IDEDiffSession.show(request:siblings:)`, which is also what Previous/Next File call, and a move the viewer made itself (not the pane's) is reported through `onRequestChanged`. It is not in `diffSessions`, so git refreshes do not reload it (commit sides never change). Not done: three-way merge, aligned (padded) side-by-side, Compare Previous/Next File keys (⌃⌥←/→ belong to the terminal tabs). Tests: `IDEDiffComputerTests`, `IDEDiffPatchBuilderTests` (patches applied with real git), `IDEDiffTabTests`.
