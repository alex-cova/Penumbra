The chat opens docked beside the editor by default (a trailing panel, resizable, `IDEAgentPanel` in `IDERootView`), or expanded over the editor (`IDEAgentPage`: a tab bar with Close and a Side Panel button that docks it again, the conversation in a column at most 800 pt wide, the editor kept mounted). The brain button in the titlebar's trailing actions (left of the gear), View ▸ Toggle Agent and the palette command toggle it (`IDEWorkspace.toggleAgentPanel` / `hideAgentPage`, state in `agent.isPanelVisible`; disabled without an open folder). Only the page layout excludes Settings and closes when a tab or file is chosen (`agent.coversEditor`, `dismissPage()`, `onPanelRequested`); docked, the chat stays open while you work. Every opener goes through `IDEAgentController.showPanel()`. `IDEWorkspace.agent` is one `IDEAgentController` per window: it owns the panel state, the saved-history list and `conversations` (see *Agent: chat tabs*) (`IDEAgentConversation`, one transcript plus one `AgentSession` each; `selected` is the one the panel shows, and the controller's `entries`/`draft`/`send()`… forward to it). A conversation has a stable tab `id` and a `conversationID` that is the saved session's identity and changes on reset or load; the provider cache key is built from the project path hash and `conversationID` (never `hashValue`, which is seeded per process). Conversations reach the window only through `IDEAgentHost` (`IDEWorkspace+Agent.swift`) via a weak `IDEAgentHostBox`, and `IDEWorkspace.teardown()` ends its run, because a session that holds the workspace keeps the window alive (retention tests in `IDEAgentTests`). Streamed text is coalesced about every 50 ms; each user message carries a short editor-state block (active file, open files, problem counts) while the system prompt and tool list stay byte-identical. Tools: `read_file`, `list_dir`, `glob`, `grep` (AgentKit, over `DiskAgentWorkspace` with `agentUnsavedBuffers()` so open edits are seen; `glob` and `grep` also take `IDEGitVisibleFiles`, the files `git ls-files --exclude-standard` lists, and fall back to the fixed ignore list when the folder is not a repository) and `diagnostics` (`IDEDiagnosticsTool`, from `IDEProblemsStore`). `edit_file` and `write_file` change files through `IDEAgentWorkspace`, which applies them with `IDEWorkspaceEditApplier` (an open file's buffer in one undo group and left dirty, a closed file rewritten atomically, a new file through `WorkspaceEdit.fileCreations` / `IDEWorkspaceEditHost.createFile`). After a run that changed files the transcript shows an "N files changed" card (`IDEAgentChangesCard`): each file opens in the diff viewer (original ↔ now), and Revert Run restores the run, leaving any file the user edited afterwards alone and marking it "changed since". Commands run in `Umbra/Sources/Umbra` only (`AgentCommandRunner`, a thin adapter over SubprocessKit: `/bin/zsh -c` in its own process group, stdin `/dev/null`, a built environment with the selected JDK and the entries of the user's login-shell `PATH` (`IDELoginShellPath`: `zsh -lc` asked once per process, only `PATH` is taken, so sdkman's `gradle` is found while the rest of a login environment stays out), output bounded to head and tail; a timeout, Stop, or the command ending kills the whole group). Every command-risk call asks first on an inline card (`IDEAgentApprovalView`: Run, Edit…, Deny… with a note; `sudo`, `rm -rf` and similar are flagged): `show_file` (`IDEShowFileTool`, read-only, so Plan mode keeps it) opens a project file through `openAgentCitedFile` without changing it. `run_command`, `gradle` and `run_tests` (the last two only in a Gradle project; they go through `IDEGradleProjectSystem.runGradleTasks`, so the console, Problems, Test Results and the trust prompt apply, and the model gets `IDEGradleSummary`: compiler errors, failed tests with their first frames, Gradle's reason, never the log). A `gradle` or `run_tests` call reveals the Gradle sidebar and the Gradle console first (`agentRevealGradle`), including when the run refuses to start. In a Gradle project a plain `gradle …` / `./gradlew …` passed to `run_command` (`IDEGradleCommandLine.parse`: tasks, then options, no shell syntax at all) is sent to the same runner as the `gradle` tool, with a "Run Gradle" card, the `gradle …` permission subject and a note appended to the result; any other command, and any command outside a Gradle project, runs as below. A Maven project (and not a Gradle one: Gradle wins when both are present, `agentIsMavenProject`) gets the same: a `maven` tool (`IDEMavenTool`, goals and options, through `IDEMavenProjectSystem.runGoals`, so the Maven console, Problems and the trust prompt apply; the model gets `IDEMavenSummary`: compiler errors from `[ERROR] file:[line,col]` lines, failed tests from this run's `target/surefire-reports`, the failed goal), `run_tests` over `mvn test` (`-pl module -am`, `-Dtest=…`, `-Dsurefire.failIfNoSpecifiedTests=false`), `mvn …` / `./mvnw …` in `run_command` routed to it, and the "Run tests before finishing" gate on `mvn test`; `project_task` is not offered for either. The Maven panel's skip-tests toggle (`-DskipTests`) applies to the agent's runs too, and the summary says when Maven skipped the tests. `run_command` otherwise still executes through `AgentCommandRunner`; after approval its output is also fed into a new terminal tab that does not start a login shell, does not take the keyboard, and is left out of the saved session (`agentShowCommand`). Settings ▸ Agent ▸ \"Run commands in a sandbox\" (direct builds only; the toggle hides itself in the App Store build) wraps `run_command` in `sandbox-exec -p` under a workspace profile (`IDEAgentSandboxProfile`: reads everywhere except credentials, writes to the project, temp and build caches, `.git` read-only, network on unless blocked): the choice is per session, the first run carries the consent on its card, and a run the sandbox denies offers one retry outside it (pre-allowed when the rules already allowed the call, else asked). Tests: the sandbox cases in `IDEAgentCommandToolTests`. - **Agent: checkpoints on disk** (`IDEAgentCheckpointBlobs`, `CheckpointLog.snapshot/restore`). Revert Run survives a relaunch. Each chat has one `CheckpointLog` for its whole life (so a settings change that starts a new session no longer drops Revert for earlier runs); it writes every original through to `<project folder in Application Support>/Agent/<hash>/blobs/<run id>/<file>` as it is recorded (LZFSE, 0600/0700), keyed by run and path, never content-addressed. The run records without the texts (`RunSnapshot`) are saved with the chat in `IDEAgentSavedTranscript.checkpoints`, and the "N files changed" card is saved (`IDEAgentPersistedEntry` kind `changes`: run, paths, which were created, reverted). - **Agent: commands and Revert Run** (`IDEAgentSnapshots.swift`, AgentKit side: `Commands that change files`). `IDEAgentGitSnapshotter` is each chat's `WorkspaceSnapshotter`. A snapshot is a git tree built in a private copy of the repository's index (`GIT_INDEX_FILE` in a temp folder, kept for the chat so the next capture only hashes what changed): `git add -A --ignore-errors -- .` then `write-tree`, with `core.autocrlf=false`. The user's index, working tree and the Git console are untouched (it uses a plain `SystemGitRunner`, not `IDEGitSupport.runner`), `.gitignore` decides what is followed, and the blobs it writes are unreachable objects that `git gc` collects. Diffs come from `diff-tree --relative`, so a project below the repository root gets project-relative paths. Bounds: text over 1 MB or containing a NUL is `unavailable`, more than 200 changed files are counted as omitted, a capture slower than 4 s switches it off for the chat, and a folder that is not a repository switches it off at the first command. Measured 2026-10-22 on 20,000 tracked files: 30-40 ms for a capture with nothing changed, about 130 ms with 600 files changed. Limits: a repository whose `.gitattributes` converts line endings or runs a filter (LFS) makes the snapshot differ from the file, so those files are named in the note and not revertable; two chats running commands at once each see the other's changes. Commands still do not claim files in `IDEAgentFileClaims`. Tests: `IDEAgentSnapshotTests` (real git in temp repositories, including that the user's index and `status` are unchanged).

- **Agent: rewind and fork** (`IDEAgentRewind`, `IDEAgentRewindSheet`, `IDEAgentConversation.rewind/forkState`). Every user message records where it sits in the session's history (`IDEAgentEntry.itemIndex`, the index of its `.user` item; saved with the chat). That is what rewinding cuts before, so it must stay right: dropping provider-specific items (on a settings change or a load) moves the recorded positions with the items (`droppingOpaque`), and a compaction that summarizes (`summarizedItems > 0`) clears every recorded position, since the start of the history was replaced; later messages record fresh ones. `/rewind`, Esc twice in an empty message field, or the arrow on a message you hover opens the sheet (`rewindRequest`): pick a message and **Conversation only** (forget it and what followed; files stay), **Code only** (revert the files the agent changed from that message on, newest run first; the conversation stays and the cards say what happened) or **Code and conversation**; the message goes back into the field. Reverting uses the session if there is one and otherwise the checkpoint log and a workspace, so rewinding works right after a relaunch and needs no working provider. A file you edited since is left as it is and named. The history cut is `AgentSession.rewind(toBeforeItem:)` (read ledger cleared, so the model reads a file again before editing it; checklist rebuilt from what is left), or, with no session yet, the saved items themselves; the result is saved at once. Never while a run is going. *In an ACP chat* (`docs/harness/agent-harness-10.md` phase 5) positions are counted from the saved user/assistant history (`IDEAgentRewind.withTranscriptPositions`); Code only reverts through the checkpoint log and keeps the agent's session; going back in the conversation closes the agent's session (it would remember what was removed), forgets its id, and the next message starts a new one with the conversation up to there (`rewindACPConversation`). A fork of an ACP chat stays on its agent and hands its transcript to a new session. **Fork** (`/fork`, the branch arrow on a message, or in the sheet) opens a new tab holding the transcript and history up to before that message (all of it for `/fork`), named "… (fork)" and saved at once; the "files changed" cards are not copied, since their originals belong to the first chat. `IDEAgentController.fork` is async. Tests: `IDEAgentRewindTests`; AgentKit: `RewindTests`.

- **Agent: prompt history** (`IDEAgentPromptHistory`, `IDEAgentPromptRecall`). - **Agent: while it works** (`IDEAgentConversation`). *Queued messages*: Return during a run queues what you wrote (chips above the field, ✕ takes one back); `AgentConfiguration.pendingMessages` asks the conversation at every turn boundary, so the model sees it on its next step without the run stopping, and a final turn that would have ended the run continues with it. Mentions in it are resolved when it is delivered, it enters the transcript at that point with its history position (so it can be rewound to), and what the run did not take is sent as the next message when the run completes, or put back in the field if it was stopped or failed. A run you stopped is quiet. Tests: `IDEAgentQueueTests` (also the shell, notification and history-search suites); AgentKit: `PendingMessageTests`, `CompactNowTests`.

- **Agent: problems after an edit** (`IDEAgentEditProblems`, `IDEProblemsStore.noteAgentEdit/hasEditorReportSinceAgentEdit/currentErrors`, `IDEWorkspace.agentProblemsAfterEdit`; AgentKit: `After an edit`). Always on, bounded, never from typing. `agentReplaceText` and `agentCreateFile` mark the file in the store (`noteAgentEdit`: the editor's report count at that moment). After the turn's edits the host waits up to 1.5 s (`IDEAgentEditProblems.wait`, polling every 50 ms) until every **open** file it changed has had a *newer* editor report, then lists the editor's errors in those files (at most 5, 200 characters each) as `[Editor] N errors in the files you just changed, from the editor's own analysis (not a build; call diagnostics to compile)`. Left out on purpose: a file that is not open or that the editor has never analysed (it would only wait out the timeout), warnings, build output (it describes the last build), and rows from a source the report marks stale (older text). No new report within the timeout means no note: an older report would describe the text before the edit. Closed files get nothing; `diagnostics` is still the way to compile. Tests: `IDEAgentEditProblemsTests`, `IDEAgentEditProblemsWorkspaceTests` (a real window).
