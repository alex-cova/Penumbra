# `Umbra/Sources/Umbra/Agent/MCP`

Loaded when working under `Umbra/Sources/Umbra/Agent/MCP`. Moved out of `Umbra/Sources/Umbra/Agent/CLAUDE.md`.

- **Agent: MCP servers** (`Agent/MCP/`; AgentKit side: `MCP`). Settings ▸ Agent ▸ MCP Servers (`IDEMCPSettingsSection`). Two origins, each local or remote. *Added here* (`IDEMCPStore.servers`: a name and a typed command line with optional `KEY=VALUE` environment lines, or a URL with optional `KEY=VALUE` header lines; secret values go to the Keychain under `mcp.<id>.<key>`; names, URLs and key names are in `UserDefaults`): adding does not start it, **"Use" is the consent to run that command or contact that URL**. *Listed by the project* (`IDEMCPProjectConfig`: `.umbra/mcp.json`, then `.mcp.json`; a symbolic link is refused and reported): never started or contacted on their own. The first chat in the project asks (`IDEAgentHost.agentConfirmMCPServers`, an `NSAlert` sheet naming each command line or URL and the variables or headers it sets); the answer is remembered per **fingerprint** (SHA-256 of name, command, arguments, environment, URL and headers, `IDEMCPStore.fingerprint`), so a change to any of them asks again, "Not Now" is remembered too (Allow/Revoke in Settings change it), and the pane shows each server's state. `IDEMCPManager` (one per window, `IDEAgentController.mcp`, stopped in `teardown()`) works out the servers in use, and `prepare` is called from `currentSession` at every send: unchanged set, same hub; changed set, the old hub is closed and a new one started (status line "Starting MCP servers…"); it serializes callers, so two chats asking at once start the servers once, and it refreshes `list_changed` servers (`refreshStaleTools`) before reusing a hub, so new tools arrive with the next message. A server that does not start shows as a transcript notice with the reason (plus the last lines of its stderr for a local server). Local servers are `IDEACPTransport` processes (SubprocessKit, own process group, killed with the hub and with the window) started in the project folder with `AgentCommandEnvironment.make` plus the server's own variables, **not** Umbra's environment (a test checks this); remote servers are `MCPHTTPTransport`s over the endpoint's URL, which is fixed: a redirect to another host is refused. a bare command is looked up on that built `PATH` (the login shell's `PATH` entries, `/opt/homebrew/bin` and `/usr/local/bin` are in it; give the full path or add `PATH=` as an environment line for anything else). The hub's tools are appended after the built-in ones and `hub.fingerprint` is in the session fingerprint. A `task` child never gets them (commands are withheld from children). App Store build: this starts arbitrary programs the user named, like the ACP agents do; the consent above is the control. Tests: `IDEMCPStoreTests`, `IDEMCPManagerTests` (a real Python MCP server process: trust, reuse, environment, shutdown kills it), `IDEAgentControllerTests.testAProjectsMCPServerReachesTheModelOnlyAfterTheUserAllowsIt`.
