# `Umbra/Sources/Umbra/Agent/Commands`

Loaded when working under `Umbra/Sources/Umbra/Agent/Commands`. Moved out of `Umbra/Sources/Umbra/Agent/CLAUDE.md`.

- **Agent: commands and skills** (`Umbra/Sources/Umbra/Agent/Commands/`). A message that starts with `/name` and a space or the end is a command (`IDEAgentSlashInvocation`; `/usr/bin is missing` is a sentence, and an unknown name is sent as an ordinary message; a lone unknown `/word` with no arguments also gets a notice saying so, since it is probably a mistyped command). Return in the field calls `IDEAgentController.submit()`: a command runs, anything else is sent. Built-ins (`IDEAgentBuiltInCommand`): `/new` `/clear` `/resume [search]` `/rewind` `/fork` `/compact` `/plan [prompt]` `/mode` `/permissions` `/model` `/history` `/export` `/loop <interval> [count] <prompt>` `/schedule [<interval> [--auto] <prompt>]` `/init` `/cost` `/usage` `/rename` `/help`, and they work before the first-use disclosure is accepted. `/loop` resends its prompt on a timer in the same chat, one run at a time (skipped while a run or an approval is pending), stopping on Stop, an error, a budget stop or the count (default 10); `IDEAgentConversation` owns the repetition, so `/clear`, `load` and `teardown` end it silently. Tests: `IDEAgentCommandsTests` (interval parsing, count finish, usage, Stop). `/usage` opens `IDEAgentUsageSheet` (`Agent/Usage/`): token use and recorded cost across saved chats, this project or all (plus AI mode's Chat), by period, model, project and day, read by `IDEAgentUsageLoader` off the main actor; never re-priced (`docs/harness/agent-harness-11.md` item 1). Tests: `IDEAgentUsageTests`. `/schedule` (`Agent/Schedules/`, item 2): a project's prompts on a cadence (at least 5 minutes), saved in `<project folder>/schedules.json`, run by the window's `IDEAgentScheduler` (a tick every 30 s, only with a store) each in a new chat that does not take the selection, in the mode it was made in (Auto only with `--auto`); a run that fell due while the project was closed is offered in a chat with the prompt in the field, never sent on its own. `/schedule` alone opens `IDEAgentSchedulesSheet`. Tests: `IDEAgentScheduleTimingTests`, `IDEAgentSchedulerTests`. `IDEAgentCommandCatalog` adds the user's own through `SkillCatalog.standardLocations` (AgentKit): `.umbra/{commands,skills}`, `.claude/{commands,skills}` and `.agents/skills` in the project, the `.claude/skills` and `.agents/skills` of the folders above it up to its repository (a window that opens a subfolder of a monorepo), `~/.claude/…` and `~/.agents/skills` (Settings ▸ Agent ▸ "Offer commands and skills from ~/.claude and ~/.agents") and Umbra's folder in Application Support, the project's first. `allSkillsCatalog` is everything found (Settings lists it); `skillCatalog` leaves out the skills switched off in Settings ▸ Agent ▸ Skills (`IDEAgentSettings.disabledSkills`, lowercased names) and is what `/`, `@skill:` and the `skill` tool use. A skill with `user-invocable: false` is not offered after `/` or `@skill:`; one with `disable-model-invocation: true` is offered there but is not in the tool's list, and a session gets the `skill` tool only when `modelSkills` is not empty. A built-in keeps its name, a command beats a skill. The read is kept two seconds and dropped at every send. The list after `/` (`IDEAgentController.suggestions(for:)`, fuzzy by name) accepts a command that takes no arguments by running it; one that takes arguments is inserted, and the text after its name is then the argument list (`IDEAgentComposerTrigger.slashArgument`): `/resume ` lists the project's saved chats (`.resume` payload; selecting one shows its tab or opens it), `/mode ` the four modes. A custom command shows `/name args` in the transcript and sends `CommandTemplate.expand` (the row's "What the agent was sent" disclosure, `IDEAgentEntry.detail`, saved with the chat); its `allowed-tools` are permission rules for that run only. `/skill-name args` sends what was typed, then the skill's `<skill_content>` block (the same text the `skill` tool returns, with the skill's absolute directory and file list) and a closing line, so a second load is answered "already loaded" and a summary keeps it; the skills' fingerprint is in the session fingerprint. **Pre-approved tools need a yes for a repository's skill or command** (`IDEAgentSkillTrust`, `IDEAgentSkillConsent`, in `Commands/` because `Agent/Skills` is a bundled resource folder): a skill or command from the project or a folder above it (`SkillScope.comesFromRepository`) whose `allowed-tools` is not empty asks once through `IDEAgentHost.agentConfirmSkillTools` (an `IDEAlert` sheet naming the tools; `IDEWorkspace+Agent`) before `/name` turns them into rules for the run. The answer is stored by a fingerprint of kind, name, folder, sorted tools and a hash of the text (`umbra.agent.skillToolsTrusted` / `…Declined` in `UserDefaults`), so an edit asks again. "Run Without Them" still runs it, with every tool asking as usual, and a notice says so; the user's own folders and Umbra's never ask, and a host that does not implement the question answers no. A model-started skill never applies `allowed-tools`. The send waits for the answer in a task, so a test must wait for the user message, not only for `!isRunning`. **Settings ▸ Agent ▸ Skills** (`IDEAgentSkillsSection`) lists every skill with its folder, badges (only you / only the agent / conditional), a switch, Show in Finder and, for a repository's skill with tools, what was answered with Revoke; below it the skills a folder read earlier hides and the files that could not be loaded, each with its path and reason. Tests: `IDEAgentSkillConsentTests`, `IDEAgentCommandRunTests`. AI Chat has no project, tools or modes, so it offers its own subset through `IDEAIChatController` (`suggestions`/`submit`/`perform`): `/new` `/clear` `/resume` `/compact` `/model` `/export` `/cost` `/rename` `/help`. `!`cmd`` lines in a command are sent as text, with a notice. `/permissions` opens Settings on the Agent pane (`IDEWorkspace.requestedSettingsDomain`), `/model` opens the panel's settings sheet (`settingsRequest`), `/export` saves Markdown or JSON (`IDEAgentTranscriptExport`; `/export json` writes a scrubbed `SessionSnapshot` without the host blob, `--hide-tools` drops the tool-call cards; a shell, Gradle or test command includes the command and its output, a failed call says `Failed:` with the error, an edit shows its result line and `diagnostics` its first lines; tests replace `exportHandler`). Tests: `IDEAgentCommandsTests`.
