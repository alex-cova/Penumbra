# `Umbra/Sources/Umbra/Agent/AIMode`

Loaded when working under `Umbra/Sources/Umbra/Agent/AIMode`. Moved out of `Umbra/Sources/Umbra/Agent/CLAUDE.md`.

- **AI mode** (`Umbra/Sources/Umbra/Agent/AIMode/`). A window mode (`IDEWindowMode`: `editor` / `ai`, with `IDEAITab` `chat` / `code`; `IDEWorkspace.windowMode` / `aiTab`, saved in `IDEWindowSession.windowMode` / `aiTab`, which older files lack). `IDERootView` keeps the editor's `HStack` mounted and invisible and overlays `IDEAIModeView` (a list card and a conversation card, no status bar); entering clears Settings and the first responder (`prepareForAIMode`), so no keystroke reaches the hidden editor. The docked panel and expanded page are hidden while it shows. Entry points: the titlebar `bubbles.and.sparkles` button (next to the brain, and the way back in AI mode's own toolbar row, `IDEAIToolbarRow`), View ▸ AI Mode ⌃⌘I, palette `app.toggleAIMode` / `app.aiChat` / `app.aiCode`, the Welcome screen. Anything that shows a file or a diff (`openAgentCitedFile`, `agentShowDiff`, `agentOpenText`, `agentInsertAtCaret`, so `show_file` too) calls `leaveAIModeForEditor()` first. *Code* is the window's own agent: `IDEAICodeView` hosts `IDEAgentPanel(placement: .aiMode)` (no tab strip or history button, because `IDEAISidebar` lists the chats; an empty session shows a greeting above the message box (one composer for both states, so the field keeps focus when the first message is sent); the box holds the field, a project chip `IDEAIProjectChip`, a branch chip `IDEAIBranchChip` (the current git branch; opens `IDEGitBranchPopup` like the titlebar label; hidden outside a repository, disabled while the chat runs), the permission chip, the context ring and the model picker). It begins with a new session (`IDEAgentController.startFresh()`, so the first send does not restore the latest saved chat) and counts as the open chat for notifications (`isShownInAIMode`). With no project Code still sends: `IDEWorkspace.agentProjectRoot` falls back, in AI mode only, to a scratch folder (`IDEWorkspace.agentScratchFolder`, `Application Support/com.umbra.editor/Scratch`), so its chats are saved and listed under that folder; the docked panel and editor entry points still need a real project. The chip and the list's Projects section open a folder through `IDEWindowRegistry.open(urls:origin:aiOpen:)`, which carries an `IDEAIOpenRequest` (show AI mode, resume this chat) to whichever window the router picks, including a new one (`IDEWorkspace.pendingAIOpen`, applied in `openProjectFolder`). The list groups `agent.history` (this project, fresh) and `SessionStore.listAll` (other projects, read off the main actor by `IDEAISessions`) by project; a row of another project opens that project in AI mode and resumes it. *Chat* is a plain conversation with any model, no project and no tools (`IDEAIChatConversation` over an `AgentSession` with `tools: []`, the chat prompt `IDEAISettings.chatSystemPrompt`, a temporary-folder workspace nothing reads), so a model without tool support is fine (`makeClient(for:requiresTools: false)`); chats are saved in their own store (`Application Support/com.umbra.editor/Chats`, root `IDEAIChatConversation.storeRoot`), shared by windows and never in a project's list. A new chat starts with the model last picked for Chat, else the global one if it is ready, else the first usable (`IDEAIChatController.defaultChoice`), and keeps the model in use at its first send. *Per-chat model*: `IDEAIModelChoice` (provider, model, reasoning, optional ACP agent) in `IDEAgentConversation.modelChoice`, saved in `IDEAgentSavedTranscript.modelChoice`; `nil` follows Settings ▸ Agent, which is how the docked panel keeps working unchanged. Every provider-dependent member of `IDEAgentSettings` has a `(for:)` variant (endpoint, key, consent, context window, cost, fingerprint, `makeClient(for:requiresTools:)`) and the old ones delegate with `currentChoice`; a chat with a choice builds its client through `choiceClientFactory`. ACP is per chat too (`acpAgent(for:)`, allowed agents only; the picker asks once). `IDEAIModelPicker` lists Claude, the configured OpenAI models, installed Ollama and on-device models (Code disables those without tool support) and, for Code, external agents; `IDEAIModelsSheet` pulls and deletes Ollama models (`IDEOllamaModelsStore`, over `OllamaModelCatalog.pull`/`delete`), opens the on-device manager, and saves provider keys and model names. Anthropic is a provider (`.anthropic`, `AnthropicMessagesClient`, key per host in the Keychain, consent per host like the others, Claude rows in the price table: a saved table nobody edited is replaced by the new default). Meta is a provider the same way (`.meta`, `OpenAIResponsesClient` at `https://api.meta.ai/v1`, default `muse-spark-1.3`, Muse rows in the price table and a 1,048,576-token window in `hostedContextWindows`); its picker list is fetched live (`IDEAgentSettings.refreshMetaModels` over AgentKit's `HostedModelCatalog`, `GET /v1/models` with the saved key) and falls back to the shipped ids in `IDEAIModelNames.muse` before a key is saved or when the fetch fails, so new Muse models appear without an app update. The fetched list is filtered to chat models (`IDEAIModelNames.isMuseChatModel`: the endpoint also lists an image generator, a transcriber and `sam-3.1`), Muse always reasons so its Reasoning menu is `minimal` to `max` with no Off, and `minimal` is its default since 2026-11-03 (`IDEAgentProvider.reasoningEfforts`, `defaultReasoning`; an older saved `off` reads as the default, a saved level is kept), and its client is built by `OpenAIResponsesClient.meta` because Meta rejects `tool_choice: none` (`docs/harness/agent-harness-9.md`). *Model setup*: with no usable model, the red hint is replaced by a "Set up a model…" button (`IDEAISetupButton`) and a guided sheet (`IDEAIModelSetupSheet`: On This Mac with a one-click suggested download, Ollama, API key). It opens by itself once per window the first time a tab shows with an unusable model (`IDEWorkspace.offerAIModelSetupIfNeeded`, after the Ollama list is read; `hasOfferedAIModelSetup`), and whenever Send is pressed with one (`requestAIModelSetup(for:)`). Both pickers and the sheet's Use buttons go through `IDEWorkspace.selectAIModel(_:for:)`; `aiModelSetupHint(for:)` is the one "is it usable" check. Tests: `IDEAIModeTests`, `IDEAIModelChoiceTests`, `IDEAIChatTests` (with `IDEAISessionsTests`), `IDEAIModeSnapshotTests` (`AI_MODE_PNG_DIR=/path swift test --filter IDEAIModeSnapshotTests` writes PNGs of the views).

- **AI mode: Changes, Plan and Browser panel** (`Umbra/Sources/Umbra/Agent/AIMode/IDEAIInspector.swift`, `IDEAIChangesTab`, `IDEAIPlanTab`, `IDEAIBrowserTab`). A resizable card to the right of Code's conversation (Code only; Chat has no project, files or plan), like Cursor's agent panel. State on the workspace: `showsAIInspector` (off by default), `aiInspectorTab` (`IDEAIInspectorTab`: changes / plan / browser), `aiInspectorWidth` (mirrored from `IDERootView`'s `@State`, like `agentPanelWidth`, and part of its `PanelSizes` save key); all three are in `IDEWindowSession` (`isAIInspectorVisible`, `aiInspectorTab`, `aiInspectorWidth`, decoded with `try?` so older files lack them). Toggles: the `sidebar.right` button in `IDEAIToolbarRow` (Code only), View ▸ "AI Mode: Changes, Plan and Browser", palette `app.toggleAIInspector` / `app.aiChanges` / `app.aiPlan` / `app.aiBrowser` (`IDEWorkspace.toggleAIInspector(tab:)` opens AI mode on Code first; asking for the tab already showing hides the panel). `IDEAIModeView` lays it out after `IDEAIMainView` with an `IDESidebarResizeHandle(edge: .trailing)`. The tab bar copies the left sidebar's look (selected tab shows its title, the others icons) with badges: files changed, checklist done/total.
  - *Changes* lists what **this chat's runs** changed, not the git working tree. `IDEAIChangedFiles.summarize` (pure) merges the transcript's `.changes` cards into one row per path, the file touched last first (ties in the order the run listed them): the original is the one the earliest run that was **not reverted** recorded, so a row compares "before this chat" with "now"; a file whose runs were all reverted is dimmed and says so; a card's `conflicts` mark "changed since". While a run is going, `pendingPaths` lists the files of finished `edit_file` / `write_file` calls after the last user message under "Editing now", since cards appear only when a run ends. `IDEAIChangesModel` (one per window, `IDEWorkspace.aiChanges`) works each diff out off the main actor: the open unsaved buffer (`agentUnsavedBuffers()`) else the disk (files over 1 MB or not UTF-8 get a note; a missing file is "removed"), at most 200 files, restarted by `.task(id:)` when the file list, the run state or the root changes. `IDEAIUnifiedDiff.make` (pure, on `IDEDiffComputer.lineChunks`) builds hunks with 3 lines of context, merges chunks closer than two contexts, ignores a final line break that was only added or removed, and stops at 2,000 lines (a first hunk longer than that is cut, not dropped). A row expands to `IDEAgentDiffView` (moved out of `IDEAgentPanel.swift`, with `maxHeight` and `hasFileHeader: false` so a removed line starting `--` is still a removal) and opens in the diff viewer (`agent.showDiff`, which leaves AI mode like the card's button). **Revert All** is `IDEAgentConversation.revertRuns(entryIDs:)`: the same session-else-checkpoint-log path as `revert(entryID:)` over every unreverted card, newest run first (the log orders them), each card marked from the merged report; disabled while a run is going. There is deliberately no per-file revert: a run is the unit AgentKit reverts, so a file's menu would revert files the row does not show.
  - *Plan* shows the checklist (`IDEAgentTodoRow`, shared with the strip under the header, which hides itself while this tab is open) with a progress bar, and the newest `exit_plan_mode` call as `IDEAgentPlanCard(isInInspector: true)`: unboxed, since the tab scrolls, and without ⌘↩ so the transcript's card keeps the shortcut. Approve and Keep Planning work from here, they go through the same conversation methods.
  - *Browser* is SwiftUI's `WebView` over a `WebPage` (WebKit for SwiftUI, macOS 26), owned by `IDEAIBrowserModel` in `IDEWorkspace.aiBrowser`: made by `ensureAIBrowser()` when the tab first shows (not for a closing window), kept across tab and chat switches, stopped and dropped in `teardown()` (a retention test covers it). **Nothing loads until the user enters an address or picks a server** (the blank state says so). `IDEAIBrowserAddress.normalize` (pure) adds `http://` to `localhost`, loopback, private and `.local` hosts and `https://` to other hosts with a dot, and refuses everything else, including a search phrase, `file:` and `javascript:`; `IDEAIBrowserNavigationPolicy` (a `WebPage.NavigationDeciding`) cancels any navigation that is not `http`, `https`, `about`, `blob` or `data`, so a page cannot open another app. `localServers(in:)` finds `http://localhost:PORT` in a chat's tool output (not the model's prose; `0.0.0.0` shown as `localhost`) for the blank state's buttons and the toolbar's server menu. The default website data store is kept, so a login to a dev app survives. A sandboxed build needs `com.apple.security.network.client` for it (`Umbra/Resources/Umbra.entitlements` is empty today, the direct build is unsandboxed). Tests: `IDEAIInspectorTests` (summarize, diff, model, addresses, session round trip, toggle, retention), `IDEAIInspectorRevertTests` (real session, two runs, Revert All), `IDEAIModeSnapshotTests.testTheChangesPlanAndBrowserPanel` (its `render` sleeps with `Task.sleep` rather than spinning `RunLoop.main`, which does not let the main actor take the result of work a view started).

- **AI mode: Browser picker, notes and agent tools** (`Agent/AIMode/Browser/`, `Agent/IDEBrowserTools.swift`, `Agent/Mentions/IDEAgentBrowserNotesBlock.swift`; plan: the Browser tab's `WebPage` above). *Scripts and worlds* (`IDEAIBrowserScripts`, static text injected as `WKUserScript`s through `WebPage.Configuration.userContentController`, so the model builds its controller before the page): the **inspector world** (`WKContentWorld.world(name: "umbra.browser.inspector")`, isolated: the page cannot call it or see its globals) runs the overlay, picker, pins, readers and actions as one object, `window.__umbra`; the **page world** runs only a recorder of `console.*`, uncaught errors, rejections and failed `fetch`/XHR (URL without query, status, time; no headers or bodies) kept in a closure and read back through a function under a random per-page name. The page can see and spoof that recorder, so what it returns is data. Console and network cannot be seen from an isolated world, which is the only reason anything runs in the page's own. The page has no message handler (`umbraInspector` exists in the inspector world only). `IDEAIBrowserBridge` is the `WKScriptMessageHandler`; WebKit holds it strongly, so it holds the model weakly and `teardown()` removes every script and handler (retention test). Messages are JSON text, decoded and capped (`IDEAIBrowserMessage.decode`), main frame only (iframes are not inspected). *Picker*: the Select button (palette `app.aiBrowserSelect`) turns on select mode: capture-phase listeners outline what the pointer is over and swallow the click, ↑/↓ (or the Parent / Child buttons) walk the element's ancestors, a click posts the element and opens a **native popover** next to it for the note. The note editor is not in the page on purpose: a text field in the page's document would send every keystroke through the page's own hotkey listeners. Pins and the outline are in a closed shadow root with no inputs; every style is set through the CSSOM so a strict CSP cannot block it. A pin is re-found by selector (`#id`, `data-testid`, stable classes, `nth-of-type`, ` >>> ` through open shadow roots), then by tag and text, else it is dimmed and its chip says "element not found". `IDEAIElementInfo` (selector, tag, role, accessible name, text, html without input values or script bodies, styles, ancestors, framework component) is capped and credential-scrubbed on arrival (`sanitized()`); the component (React / Vue / Svelte / Angular) is read in the page world because frameworks keep it in expandos an isolated world cannot see. `IDEAIBrowserAnnotations` holds the notes per window in memory (not saved across a relaunch): numbered, `open` / `sent` / `addressed`, authored by the user or pinned by the agent (the agent's own start as `sent` and are never attached back to it as the user's request); the overlay is pushed the notes of its page (`IDEAIBrowserPageKey`: origin and path, not query or fragment) on every `ready`. *Delivery*: open user notes ride with the next message (a chip above the field, ✕ leaves them out of that message only, `IDEAgentConversation.attachesBrowserNotes`) and become `sent`; `@notes` (all not addressed), `@element` (the newest) and the notes bar's Ask Agent do the same by hand. `IDEAgentBrowserNotesBlock` keeps the trust split: **the user's note is outside `<untrusted>`**, the page's details (title, selector, text, html, styles, component) inside it, and a hostile element cannot close the wrapper. `UserText.typed` cuts at `[Browser notes from the user.` as well as at attachments, so titles and compaction keep only what was typed. *Agent tools*, on by default (Settings ▸ Agent ▸ Browser tab tools, `umbra.agent.browserTools`, in the session fingerprint; offered when the host has a Browser tab, `agentBrowserPageInfo`): the tools hold the address in `IDEAIBrowserPageInfo` (workspace-owned, lock-protected, kept current by `Observations`), because a rule is matched on it before a tool runs, and the `WebPage` itself is made only when a tool needs it (`agentBrowser()`), so a session that never browses never pays for a web view. `browser_inspect` (`.read`, `asksUnlessAllowed`, `honorsDenyRules`, offered in plan mode): `snapshot` (an outline of what is visible with refs such as `e12`, held in a map in the inspector world so the DOM is never marked; a field is `[empty]`/`[filled]`, never its value; a pointer cursor that starts on a plain element is a `clickable`), `text`, `element`, `console`, `network`, `annotations` (`resolve` note numbers, `reply`) and `annotate`. Its subject is the page's origin and path as text: `browser_inspect(https://host/*)`; pages on this Mac are allowed by default rules added in `currentRules` (`http://localhost:*/*`, `127.0.0.1`, `[::1]`; a `:*` suffix would be the command-prefix form, which is why they end in `:*/*`), so a user deny or ask rule still wins; any other site asks the first time. Output is scrubbed (`IDEAgentOutputScrubber.shape`), cut at 20,000 characters and wrapped `<untrusted source="browser:host">`. `browser_act` (`.command`: plan mode never offers it, Auto never runs it unasked): `navigate`, `back`, `forward`, `reload`, `click`, `type`, `select`, `press`, `scroll`, `wait`; there is no JavaScript verb. The card says what happens in words resolved from the page (`Click button “Save” on http://localhost:3000/form`) with an editable address for `navigate` and a suggested `browser_act(origin/*)` rule for where it goes. It sets `asksUnlessAllowed` only so that `refusalBeforeAsking` answers a bad address, a missing target or no page before any card. Typing into a password, card or one-time-code field is refused inside the page script whatever is asked. It runs only while the Browser tab is on screen (`agentRevealBrowser`: in AI mode it brings the tab up; from the editor it refuses rather than pull the window into AI mode), with a purple border, an input shield and an "Agent is controlling this page · Stop" banner (`IDEAIBrowserModel.agentActivity`; Stop is `agent.stop()`). After the agent has read page text, an action on a non-loopback site asks again even with an allow rule (`AgentTool.asksAfterUntrustedContent(for:)`, per call; AgentKit); a page on this Mac does not. Events are dispatched in the DOM, so they are not `isTrusted`: most dev UIs react, some pages ignore them. Not built: screenshots (AgentKit messages are text-only; the plan keeps them as a separate phase), iframes, notes saved across a relaunch, drag-a-region notes, a native-event click. Tests: `IDEAIBrowserInspectorTests`, `IDEAIBrowserAnnotationsTests`, `IDEAgentBrowserNotesTests` (+ `…ChatTests`), `IDEBrowserReaderTests`, `IDEBrowserInspectToolTests`, `IDEBrowserActionTests`, `IDEBrowserActToolTests` (a real `WebPage` loading fixture HTML through `IDEAIBrowserModel.load(html:baseURL:)`); AgentKit: `PerCallUntrustedGateTests`, `HarnessImprovementTests` (`UserText`).
