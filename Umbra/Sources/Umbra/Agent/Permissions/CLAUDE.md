Loaded when working under `Umbra/Sources/Umbra/Agent/Permissions`. Moved out of `Umbra/Sources/Umbra/Agent/CLAUDE.md`.

- **Agent: permissions** (`Umbra/Sources/Umbra/Agent/Permissions/`, `IDEAgentModeText`; AgentKit side: `Packages/AgentKit/CLAUDE.md`). Each chat has its own `PermissionMode` (`IDEAgentConversation.mode`, `setMode`, `cycleMode`): the chip under the message field, or ⇧Tab in it (`IDEAgentPermissionChip`, `IDEAgentComposerKeyMap`). `IDEAgentSettings.mode` is only the mode new chats start in, and no longer part of the session fingerprint, because a mode change does not need a new session (the session is told with `setMode`; the model gets a note). Rules come from files read at every send, so an edit takes effect at once (`IDEAgentPermissionFiles`): the app's `permissions.json`, `.umbra/settings.json`, `.umbra/settings.local.json` (what "Always allow in this project" writes; a file that is not valid JSON is never overwritten; the first time it is created, Umbra asks to add it to `.gitignore`), and Claude Code's `.claude/settings.json` / `settings.local.json`, read only. Every deny, ask and allow from every source counts. A chat's own rules ("Allow in this chat") last until the conversation is reset or another is loaded. The approval card's "Always…" menu (`IDEAgentApprovalView.alwaysAllowMenu`) offers the rule AgentKit suggests, or "Accept all edits in this chat"; `IDEAgentConversation.approve(callID:shortcut:)` applies it and approves the call. Settings ▸ Agent ▸ Permissions (`IDEAgentPermissionsSection` over `IDEAgentPermissionsModel`) lists every rule by file, adds and removes rules in the files Umbra owns, and checks "would this command run?". `IDEGradleTool` / `IDERunTestsTool` expose `gradle …` as their `permissionSubject`, so `Bash(gradle build:*)` matches them. Tests: `IDEAgentPermissionsTests`, `IDEAgentPermissionFilesTests`, `IDEAgentPermissionsModelTests`, `IDEAgentSessionsTests`.
