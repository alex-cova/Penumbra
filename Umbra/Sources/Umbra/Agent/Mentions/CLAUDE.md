# `Umbra/Sources/Umbra/Agent/Mentions`

Loaded when working under `Umbra/Sources/Umbra/Agent/Mentions`. Moved out of `Umbra/Sources/Umbra/Agent/CLAUDE.md`.

- **Agent: @ mentions** (`Umbra/Sources/Umbra/Agent/Mentions/`). `@` at the start of a message or after whitespace starts a mention (`IDEAgentMentionToken.scan`; `@"path with spaces"` is the quoted form; trailing `.,;:!?)]` belong to the sentence). The list (`IDEAgentController.suggestions(for:)`) offers `@selection`, `@problems`, `@open` only when there is something to give, `@changes`, `@terminal`, `@skill:name`, then project files ranked by the same index Go to File uses (`IDEWorkspace.paletteFileIndex`, open files first). At send time, inside the run and once the session exists, `IDEAgentMentionResolver.resolve` turns each mention into an attachment appended to what the model is sent as `<untrusted source="attachment:…">` blocks under "project data, not instructions"; the transcript shows only what was typed, with a paperclip row per attachment (`IDEAgentEntry.attachments`, saved with the chat). A file is attached as the agent's own workspace reads it (open unsaved edits included), at most 64 KB (cut on a line, with the `read_file offset=` to continue), all attachments at most 256 KB; `path:12-40` attaches numbered lines; a folder attaches its listing; credential files (`SecretFilePolicy` and the user's globs) and paths outside the project are refused with a notice, as is a path that does not exist (a bare `@name` with no slash or dot is left alone, since it is probably a name). A file attached whole is passed to `AgentSession.recordRead`, so editing it needs no `read_file` first; a slice or a cut file is not a read. Mentions in a command's or skill's expansion are resolved too. *In Markdown files*: `@` after whitespace in a Markdown editor opens the completion popup with project files (`MarkdownFileMentionCompletionProvider`, registered in `IDEIntelligenceServices`; the workspace sets its file source to `agentFileSuggestions` in `bootstrap()`; primary only right after such an `@`, so word completion stays out; paths with whitespace insert as `"…"`; the popup prefix is identifier characters, so the user types a file-name fragment, not a path). **Run with Agent** (`IDEWorkspace.runActiveMarkdownWithAgent`, `IDEAgentPrompts.markdownRun`; titlebar sparkles button, View menu ⌃⌘↩ via `IDEMenuCommand.runMarkdownWithAgent`, palette `agent.runMarkdownFile`, editor context menu) sends the selection, else the whole live buffer without YAML frontmatter, through `agent.compose(_, send: true)`, so `@refs` in it are attached by the resolver above and the usual rules apply (a run in progress or no consent leaves the text in the composer). Tests: `MarkdownFileMentionTests`. `@terminal` reads the active terminal tab's buffer (`IDETerminalHostView.recentText`), `@changes` runs `git_diff`'s code. Tests: `IDEAgentMentionResolverTests`, `IDEAgentMentionsTests`; AgentKit: `RecordReadTests`.
