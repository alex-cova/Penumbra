# `Umbra/Sources/Umbra/Agent/Panel`

Loaded when working under `Umbra/Sources/Umbra/Agent/Panel`. Moved out of `Umbra/Sources/Umbra/Agent/CLAUDE.md`.

- **Agent: transcript rows and scrolling** (`Panel/IDEAgentTranscriptRows.swift`, `IDEAgentWorkGroupView`, `IDEAgentFollowingScrollView`; plan: `docs/AGENT_UI_PLAN.md` items 1 and 4). *Work groups*: `IDEAgentTranscriptRows.make` (pure, O(entries), run on every body pass) folds two or more consecutive tool calls into one row, "Worked · 14 steps · 3 files edited · 2 commands" (`IDEAgentWorkSummary`: files from `edit_file`/`write_file` paths and `apply_patch`'s `+++ b/` lines, the only arguments parsed; commands are `run_command`, `gradle`, `run_tests`, `maven`). A call that asks the user something or failed never folds: a pending approval, a question or elicitation, `exit_plan_mode`, an error output. A notice between two calls goes inside, one after the last call stays outside. A group's id is its first entry's, so the row keeps its identity as it grows. The group the running turn is still in (`isLive`: only notices after it) shows open with a spinner and closes when the run moves past it, unless the user toggled it (`IDEAgentPanel.groupToggles`, by group id, not saved: a reopened chat shows its groups closed). AI mode's Chat has no tools and draws entries as before. *Scrolling*: both transcripts (the panel in every placement and AI Chat) sit in `IDEAgentFollowingScrollView`, which follows new output only while pinned. `IDEAgentScrollPin.isPinned` (pure) pins whenever the view reaches the bottom (40 pt), unpins when the user scrolls up (`onScrollPhaseChange`, or an offset that moved up while content and viewport stayed the same, for a wheel that reports no phase), and otherwise keeps the old answer, so content growth never unpins. Pinned, growth scrolls to the bottom (from `onScrollGeometryChange`, so live command output and an opened group follow too). Unpinned, a pill at the bottom says "New activity" once something arrived, "Waiting for you" while the chat needs an answer (`isAwaitingUser`), else "Jump to latest"; it, sending (`pinKey`: the last user entry) and switching chats (`resetKey`) pin again. `IDEAgentTranscriptRows.rowID(containing:in:)` is the row to scroll to for an entry inside a group. Tests: `IDEAgentTranscriptRowsTests`, `IDEAgentScrollPinTests`; the grouped row shows in `IDEAIModeSnapshotTests` (`inspector-changes`).

- **Agent: Changes line in the docked panel and page** (`Panel/IDEAgentChangesPill.swift`; plan: `docs/AGENT_UI_PLAN.md` item 3). Under the header (and the checklist strip), outside AI mode, while the selected chat's runs have changed files that are not all reverted: "3 files changed +120 −34 ›". A click opens AI mode's Changes list (`IDEAIChangesTab(onDismiss:)`, the same view, 460 × 440) in a popover: a diff per file, Open in Diff Viewer, Open File, Revert All; Escape, opening a diff or opening a file closes it (`onDismiss`, which in the inspector stays `nil` and Escape focuses the editor as before). The +/− totals come from the window's `aiChanges` model, which the line keeps current itself (`View.ideAIChangesRefresh`, the same `.task(id:)` the tab uses), so they show before the list is opened; AI mode hides the docked panel, so the two never compute for different chats. No per-file revert, for the reason under *AI mode: Changes*. Tests: `IDEAgentChangesPillTests`; `IDEAIModeSnapshotTests.testTheDockedChangesLine` (`docked-changes-line`, totals, gone after Revert All).

- **Agent: find in the chat and the minimap** (`Panel/IDEAgentTranscriptFind.swift`, `IDEAgentFindBar.swift`; plan: `docs/AGENT_UI_PLAN.md` items 5 and 10). *Find*: ⌘F while the agent's message field (`IDEAgentComposerTextView`) or its find field has the keyboard goes to the chat, not the editor: `IDEWorkspace.showFind` checks that first (before the terminal), sets `agent.isFindBarOpen` (on the controller, so a panel rebuilt docked ↔ page keeps it) and bumps `findRequest` (focuses the field). The find field reports its real focus (`isFindFieldFocused`), so ⌘F in the editor with the bar still open finds in the editor. Not in AI mode's Chat tab (its own conversation, no bar). `IDEAgentTranscriptFind.matches` (pure, case- and diacritic-insensitive) looks at message text, a tool call's title (never its raw JSON arguments, which would match `"path"` everywhere), its output, live command output, plan and question, and a changes card's paths; it runs 120 ms after typing stops and again as the transcript grows (without moving the view unless the current match is gone). "3 of 12" counts rows; Return / ⇧Return / the chevrons step with wrap-around, Escape or × closes and gives the message field the keyboard. The current row gets an accent outline (`ideFindHighlight`); a match folded in a work group opens the group first (`reveal`, then the panel's `scrollTarget`). Words inside a row are not highlighted. *Minimap*: from four user messages on and a transcript at least 380 pt wide, a 12 pt rail on the trailing edge (`IDEAgentMinimapRail`) has a tick per user message (`IDEAgentMinimapItems.make`: position by entry index, accent when the turn changed files that are not reverted, orange while it waits for the user; tooltip: the prompt and the turn's last reply) and a band for what is on screen. The band reads `IDEAgentScrollPosition`, an `@Observable` the scroll view writes on every scroll, so a scrolled frame redraws the rail, not the panel. Both are approximate (index, not pixel, positions). Tests: `IDEAgentTranscriptFindTests`, `IDEAgentMinimapItemsTests`; `IDEAIModeSnapshotTests.testFindInChatAndTheMinimap` (`docked-find-minimap`, ⌘F routing including AI Chat).

- **Agent: commands drawer and scheduled-run log** (`Panel/IDEAgentCommandsDrawer.swift`, `Schedules/IDEAgentScheduleRun.swift`; plan: `docs/AGENT_UI_PLAN.md` items 9 and 11). *Commands drawer*: once the chat has run a command (by tool name only, so the header does not parse arguments on every streamed update), a terminal button in the header toggles a 260 pt drawer between the transcript and the message box (`agent.isCommandsDrawerOpen`, on the controller, not saved). `IDEAgentCommandLog.items` (pure) lists `run_command` (with `!command`), `gradle`, `run_tests` and `maven` in order with their line (`IDEAgentToolSummary.commandLine`, plus `mvn goals options`), state and output (the streamed output when there is one, like the card, else the result). The newest is selected until another is picked; its output is a read-only `NSTextView` (`IDEAgentOutputTextView`, since outputs reach 200 KB) that follows the end unless scrolled up, with Copy Output and Show in Transcript. A view over what the transcript holds, not a shell; the terminal tab mirror (`agentShowCommand`) is unchanged. *Run log*: each run a schedule starts is recorded (`IDEAgentScheduleRun`: schedule id and name, the chat's `conversationID`, start, end, outcome, files changed, cost) in `<project folder>/schedule-runs.json` (0600, newest 200, `IDEAgentScheduleRunLog`). `IDEAgentScheduler.run(at:)` adds it when the run starts; the controller's `onAttention` `.finished` hook calls `scheduler.runEnded`, which fills in the newest unfinished run of that chat (a chat that is not a scheduled run is ignored; outcome "Completed" or `IDEAgentToolSummary.endingMessage`). The Schedules sheet's Runs section lists the newest 50 (`IDEAgentScheduleRunRow.describe`: time, duration, outcome, files, cost; "Running" while its chat runs, "No ending recorded" when Umbra or the chat closed first) with Open (`agent.resume`). Tests: `IDEAgentCommandLogTests`, `IDEAgentScheduleRunLogTests`, `IDEAgentSchedulerTests.testAScheduledRunIsLoggedWhenItStartsAndWhenItEnds`; `IDEAIModeSnapshotTests.testTheCommandsDrawer` (`docked-commands-drawer`).

- **Agent: toasts, undo close, copy path, long prompts, queued edits, image preview** (`Panel/IDEAgentToast.swift`, `IDEAgentPathCopy.swift`, `IDEAgentQueuedMessages.swift`, `IDEAgentImagePreview.swift`, `Composer/IDEAgentComposerLimits.swift`; ported from t3code). *Toasts*: `IDEAgentController.showToast` / `dismissToast`, one at a time (a new one replaces it), drawn by `IDEAgentToastLane` at the top of the composer and announced to VoiceOver. Panel-only on purpose: not `IDENotificationCenter`, so they are not in the bell's list and Do Not Disturb does not hide them. *Undo close*: `close(_:)` and `closeOthers` remove the chats as one `ClosedGroup`, call `IDEAgentConversation.stopForClose()` at once (loop ended, run stopped as Stop would, file claims released) and keep the session for `closeUndoWindow` (8 s); the toast's Undo (`undoClose`) puts them back at their indices and selects the first. `release()` (`endSession` + host cleared; `teardown()` is `saveInterrupted` + `release`) runs when the window passes, on the next close (only the latest close can be undone), on `resume`/`deleteConversation` of a conversation in the group, and in the controller's `teardown()`. The last chat is still emptied (`reset()`, no undo); `close(_:undoable: false)` is the old immediate close, used by `deleteConversation` and a scheduled run that did not start. *Copy path*: `IDEAgentCopyPathButton` beside each row of the "files changed" card and on an edit approval's header (path from the diff's `+++ b/` line, `IDEAgentPathCopy.path(fromUnifiedDiff:)`); the Changes tab's Copy Path uses the same `IDEAgentPathCopy.copy`; a refused write shows an error toast. *Long prompts*: over `IDEAgentComposerLimits.maxPromptCharacters` (100,000 UTF-16 units, constant time per keystroke) a red line under the field says so; Send stays enabled. *Queued edits*: the pencil on a queued row opens a popover editor; `updateQueued(_:text:)` returns false once the run took the message (an empty edit takes it back), and an edit whose message was delivered while open goes into an empty field (`keepEditOfDeliveredMessage`) or onto the pasteboard, with a toast. *Image preview*: a click on an image chip opens a sheet with the full image (`MagnifyGesture` and ⌘+/⌘− between 25% and 800%, drag to pan, double-click or ⌘0 fits, Esc closes; arithmetic in `IDEAgentImageZoom`). Tests: `IDEAgentTabsTests` (undo close), `IDEAgentQueueTests` (queued edits), `IDEAgentPanelExtrasTests` (limits, diff path, pasteboard, zoom).
