# Diagrams (`Umbra/Sources/Umbra/Diagrams`)

Loaded when working under `Umbra/Sources/Umbra/Diagrams`. Split out of `Umbra/CLAUDE.md`.

- **Diagrams** (`Umbra/Sources/Umbra/Diagrams/`, `IDEWorkspace+Diagram.swift`), built on [DiagramKit](https://github.com/alex-cova/DiagramKit) (the `Umbra` target's only user; import it only in `Diagrams/` and the workspace extension, since its names are short). UML class diagrams of Java code and Gradle dependency diagrams open as editor tabs the way diffs do: a `WorkbenchDocument` with `contentKind == .diagram` (never restored) whose `IDEDiagramSession` lives in `IDEWorkspace.diagramSessions`; the pane host lays `IDEDiagramViewerView` (an `NSHostingView` of `IDEDiagramRootView`) over its editor (`showDiagramDocument`), and `openDiagram(_:)` reuses the tab whose `IDEDiagramRequest.id` matches. Requests: `.classes(JavaClassGraphScope)` (file, package, types, project), `.gradleModules`, `.gradleLibraries(projectPath:configuration:)`. The graphs come from pure JavaIntelligence types (`JavaClassGraphBuilder`, `GradleDependencyGraph`; see its CLAUDE.md), `IDEDiagramDocumentBuilder` turns them into an `IDEDiagramDocument` (boxes keep content-derived ids, so selection and the viewport survive a reload) and `IDEDiagramLayoutEngine` places them (DiagramKit layouts; supertype edges are fed reversed so parents sit above). The session loads and lays out off the main actor and drops a result when a newer load started; the loaders are closures the workspace sets (index plus open buffers; the module graph from the synced model; the library graph from `IDEGradleProjectSystem.resolveDependencyGraph`, which shares `isBusy`, the trust prompt and the Gradle console with the other Gradle actions and caches by build-file fingerprint until Reload). A request is a value with an id. A language module or a project system implements `loadDiagram` and returns nil when the id is not its own; the workspace tries Java and Gradle first, then each module and each system. The npm dependency diagram, the one-file TypeScript and Swift class diagrams (`IDESwiftDiagram`: extensions fold into their type, conformances are realizations) and the SwiftPM target graph (`IDESwiftPMDiagram`) are built that way. The canvas is `DiagramCanvasView` with Umbra's editor colour as background, SwiftUI boxes (`IDEDiagramNodeView`, above 200 boxes `DiagramSceneRenderer` draws them) and edges drawn by `IDEDiagramEdgeDrawing` with UML markers from `IDEDiagramEdgeMarkers` (hollow triangle for inheritance and realization, hollow diamond at the owner for aggregation, open arrow for association and dependency, filled arrow for Gradle links); Metal edges and partial scene rebuilds are not used. A JSON file uses the same titlebar play button as Markdown preview (⌘B): it covers the editor with a diagram of the value (`JSONDiagramBuilder`, source key order, 400 boxes) and is not a diagram tab. Double-click opens the source, the context menu offers Open Source, Show Diagram Around Type, Show Dependencies of Module and Copy Name. Toolbar: layout, edge routing, what is shown (members, private members, external types, neighbour depth, or the Gradle configuration), reload, export (PNG, PDF, SVG through `IDEDiagramExporter`) and zoom. Options persist in `UserDefaults` (`umbra.diagram.*`, `IDEDiagramSettings`). Entry points: Java ▸ Diagrams, the editor's context menu (Show Class Diagram), the Explorer's Show Class Diagram for a Java file or package folder, the Gradle sidebar (module diagram button, Show Dependency Diagram on a module), and palette commands. A Gradle module diagram reloads when a sync finishes. Tests: `IDEDiagramDocumentTests`, `IDEDiagramTabTests`, `JSONDiagramBuilderTests`.
