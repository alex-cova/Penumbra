# Database (`Umbra/Sources/Umbra/Database`)

Loaded when working under `Umbra/Sources/Umbra/Database`. The drivers and rules live in `Packages/DatabaseKit/CLAUDE.md`; audit, architecture, feature matrix and UX specification in `docs/audit/database/`.

- **`IDEDatabaseModule`** is the `IDELanguageModule`: palette commands (`app.database.*`), the Database menu, the toolbar play/stop button, the sidebar tab and the Query Results bottom tab. **`IDEDatabaseSupport`** is per window: the catalog (saved sources, passwords in the Keychain only), live `SQLSession`/`MongoSession` per source, the schema cache and each console's latest results.
- **One run at a time per window.** Execute Statement or Selection (⌃⇧↩), Execute All (⌃⇧⌘↩), and gutter execution use the dialect splitter. A script runs serially and stops on error or Cancel (⌃⌘.); its completed results remain selectable. Cancel asks the running session to stop and preserves the rows the statement returned (`QueryResult.wasCancelled`).
- **SQL catalog snapshots** load in the background, refresh after console DDL and transaction boundaries, and carry generation checks. Completion, hover, diagnostics, navigation, signature help and code actions read the snapshot in memory. The editor's console header binds SQL documents to a data source. `IDEWindowSession` restores those bindings by document ID and uses the existing editor restoration for console text.
- **SQL parameters** are detected by the dialect lexer. The prompt collects typed values before any statement starts. The query text carries driver placeholders, and the values stay in the current result for paging.
- **SQLite sources** keep the file path in `DatabaseConnection.database` (`:memory:` for a private in-memory database). `addSQLiteSource` validates the file's header, never creates a file unless asked, and treats one path as one source. **`connect` leaves a connected in-memory source alone**: reconnecting would silently replace it with an empty database (Disconnect is the explicit way to discard it). A file whose header is SQLite's opens here from File ▸ Open (`IDEWorkspace.isSQLiteDatabase`, checked in `openDocument`); Open as Hex and Settings ▸ Hex still reach the bytes. The app is not sandboxed today, so plain paths work; under App Sandbox they would need security-scoped bookmarks (not implemented).
- **TLS** (connection sheet): PostgreSQL has Off / Prefer / Require; the sheet says in red that Prefer can fall back to plain text. MySQL and MongoDB keep the checkbox.
- `IDEDatabaseResultGrid` is an `NSTableView` over a viewport window of the result's typed `ResultStore`. Scrolling, the value inspector and export read that store. Header sorting previews a server rerun. Closing or replacing a result releases its store and spill file.
- Tests: `IDEDatabaseTests`, `IDEDatabaseDiagramTests`, `IDEDatabaseTLSChoiceTests`, `IDESQLiteSourceTests` (real SQLite files, no server). Server-backed tests are in `Packages/DatabaseKit/Tests` behind `UMBRA_DB_INTEGRATION=1`.
