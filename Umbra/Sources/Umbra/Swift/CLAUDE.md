# Swift intelligence and SwiftPM (`Umbra/Sources/Umbra/Swift`)

Loaded when working under `Umbra/Sources/Umbra/Swift`. Split out of `Umbra/CLAUDE.md`.

- **Swift intelligence and SwiftPM** (`Sources/SwiftIntelligence/`, `Umbra/Sources/Umbra/Swift/IDESwiftSupport.swift`, `Languages/IDESwiftLanguageService.swift`, `IDESwiftModule.swift`, `IDESwiftRunProvider.swift`, `Projects/IDESwiftPM*.swift`; see `docs/LANGUAGE_SUPPORT_PLAN.md`, "Swift, natively", and `docs/LANGUAGE_PARITY_PLAN.md`). Native and syntactic, like TypeScript, with no server process: `SwiftAnalysis.parse` runs JavaIntelligence's `JavaSyntaxParser(language: tree_sitter_swift())` on the original text. The grammar is tree-sitter-swift 0.7.4 (`Sources/TreeSitterSwift/VERSION`). It reads `nonisolated(unsafe)`, `#expect`, `#Preview` with `@available` in front of it, `await` on a call or a property in `if` / `while` / `where`, expression-valued `switch`/`if`, regex literals that include `\/` or start with an operator character, multi-pattern `case … where`, a leading `^` or `*`, an empty tuple `()`, `didSet` on an initialized property, a `///**` comment after an expression, `/*` and `*/` inside a line string, a raw string nested in another raw string's interpolation, and `(T?, Array<U>).self` (`SwiftModelTests.testModernSyntaxParsesAtTheOriginalOffsets`). Syntax problems are **warnings** (valid Swift outside this repository can still be rejected), and the compiler's errors come from the build. `SwiftModelTests.testRepositorySwiftFilesStayWithinTheSyntaxProblemCeiling` fails if a `.swift` file in this repository starts producing one. `SwiftModelWalker` is one iterative pass (explicit stack, depth cap: the index parses on a 512 KB cooperative-pool stack) producing `SwiftFileModel`: declarations (a `class_declaration` is class, struct, enum, actor or extension by its anonymous keyword), byte-range scoped bindings (`guard let` lives to the end of the block, `if let` in its body, `for`, closures, `catch`, `switch` patterns), uses with their receiver `SwiftChain`, imports and syntax problems. `SwiftIndex` (actor) keeps the project's files, merges extensions across files and inheritance into `members(ofType:)`, filters by module (a `moduleResolver` the SwiftPM system supplies from its target directories; without one the folder is one module), and replaces a file's entry from the open buffer (`noteOpenDocument`, `LanguageEnvironment.openBufferText`) without a save. `SwiftResolver` types a chain from what the text states (annotations, constructor calls, written return types, casts, literals, `for` elements) and finds the declaration a name refers to, choosing the overload by call labels. It does not infer through generics or overloads, and the standard library and SDK are not indexed: `SwiftStandardLibrary` is a hand-written table of the commonest `String`, array, dictionary and number members so `name.` is not empty. Providers (all primary for `swift`, policy disables the generic snippets, duplicate-symbol warnings and name-based hover and navigation): completion (members with extensions, static members and enum cases, implicit `.case` from an annotation, argument label, return or `==`, scope, auto-`import`), hover, definition / usages / implementations / super method / type definition, rename (resolved uses only), syntax warnings, semantic colours, structure and breadcrumbs, signature help (`SwiftCallSite` reads the argument list from the text), line markers, type and call hierarchy, and Generate (memberwise `init`, `description`, `CodingKeys`). A call or dangling dot being typed is read from bytes first (`SwiftSite.textChain`, `SwiftCallSite`), because error recovery often leaves no node for it. `IDESwiftPMProjectSystem` is registered after npm; `Package.swift` is read with the Swift grammar on open (nothing runs), and `swift package dump-package` replaces that model only for a folder the user trusted (`swiftpm-trust.json`, `IDESharedServices.swiftPMTrust`, its own sheet). Commands run through SubprocessKit (`build`, `test`, `run:<exe>`, `resolve`, `update`, `clean`); their output is read by `SwiftBuildOutputParser` and goes to `onBuildDiagnostics` → `IDEProblemsStore.setBuildDiagnostics(_:source: "swiftpm")` (a bucket of its own, so a Gradle build never replaces it; it does not go through `environment.tasksFinished`, which Java's Gradle handling would read as a Gradle build). Tests run as `swift test --filter Module.Class/method --xunit-output …/TEST-swift.xml`, read by `JUnitXMLReportParser` into Test Results; `IDETestResultsStore.rerunHandler` is how Rerun and Rerun Failed repeat a run that has no Gradle scope. Tests: `SwiftModelTests`, `SwiftIndexTests`, `SwiftIntelligenceTests`, `IDESwiftPMProjectSystemTests`, `IDESwiftRunProviderTests`, `IDEProblemsStoreTests`.
