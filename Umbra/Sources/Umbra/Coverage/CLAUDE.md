# Run with Coverage (`Umbra/Sources/Umbra/Coverage`)

Loaded when working under `Umbra/Sources/Umbra/Coverage`. Split out of `Umbra/CLAUDE.md`.

- **Run with Coverage and Profile** (`Umbra/Sources/Umbra/Coverage/`, `Profiler/`, `IDEWorkspace+Coverage.swift`, `IDEWorkspace+Profile.swift`, `Languages/IDEJavaRunProvider+Instrumentation.swift`; model and commands: `Sources/JavaIntelligence/CLAUDE.md` ▸ Coverage and profiling; plan: `docs/JAVA_COVERAGE_PROFILING_PLAN.md`). Entry points: Run ▸ Run with Coverage / Run Tests with Coverage / Profile / Profile Tests (what the caret is in, else the active file's launch; tests: the open class, else every test), the gutter's menu (`IDERunProvider.supportsInstrumentation(at:)` / `run(_:location:instrumentation:)`: "Run ‘X’ with Coverage", "Profile ‘X’"), the run configuration form's "Run with" picker (`JavaRunConfiguration.instrumentation`), palette commands, and File ▸ Open Profiler Recording…. `IDEJavaRunProvider.makeInstrumentationPlan` finds the jars, the JDK and a run directory (`IDEJavaRunProvider.artifacts`, `artifactsRootOverride` in tests) and fails with a sentence; a plain `main` carries the VM argument (`vmArguments(for:)`) and hooks `IDERunSession.onFinished` (`finishWhenSessionEnds`), a Gradle `run`/`bootRun`/test task carries `--init-script` and `-P` properties (`gradleArguments(for:)`, the arguments replace `runGradleTasks`' default `--no-configuration-cache`, so the scripts' arguments repeat it) and `pendingInstrumentation` is consumed by `projectTasksDidFinish` when the same task list ends (a build that ends meanwhile is not it; a run that never started clears it). `.singleFile` coverage is refused by the validator; `.singleFile` profiling works. **Coverage:** `IDECoverageController` (`IDEWorkspace.coverage`) holds the snapshot (`IDECoverageSnapshot`: report, run directory, the paths an HTML export needs) and which files are stale — a buffer that was dirty when the report was made starts stale, and the first edit after (`noteCoverageEdit`, from `textViewDidChange`, O(1) afterwards) removes that file's bands; the numbers stay in the tab. Bands are `TextView.lineBackgrounds` (covered green, partial yellow, missed red at low alpha; no gutter stripe), merged with the debugger's execution line in `applyExecutionLineBackground` since both share the array (coverage first, the execution line over it). The **Coverage** bottom tab (`IDEBottomPanelTab.coverage`, order 75; `IDECoveragePanel`) lists package ▸ class with line, branch and method percentages, a filter, "only below N %", Previous/Next Uncovered Line (`goToUncoveredLine`), Export HTML (`jacococli --html` with sources) and XML, Clear. Settings ▸ Java ▸ Coverage: show in editor, include test sources, clear on the next run, open the tab after a run. **Profiler:** a recording opens as an editor tab (`WorkbenchDocumentContentKind.profile`, `IDEWorkspace.profileSessions` by document id, `IDEEditorPaneHost.profileViewer` laid over the editor like the diagram viewer). `openDocument(from:)` routes a `.jfr` by magic (or by name on non-text bytes) to `openProfile(file:)` before `loadDocument`, so Reopen as Hex (`reopenProfileAsHex`) and `loadDocument(openAsHex:)` still reach the bytes; a file in a run's `Profiles/` folder brings its siblings (a Gradle test run writes one recording per JVM). `IDEProfilerSession` reads off the main actor with `JavaRecordingImporter` (`jfr` from the project JDK, then the newest installed ones: a newer tool reads older recordings), drops a result a newer load overtook, asks above Settings ▸ Java ▸ Profiling ▸ "Ask Before Reading Over" (500 MB) and says "needs a JDK" with Choose a JDK… / Open as Hex instead of an empty graph. `IDEProfilerView`: CPU · Allocations · Locks · GC, a thread filter, and the **flame graph** (`IDEFlameGraphNSView`: icicle, only boxes wider than 0.75 px are laid out and only those in the dirty rect drawn, hit-testing by binary search per row, double-click zooms, Esc zooms out, search dims the rest, tooltip with total/self, colour by package), **hot methods** (self/total by method, callers and callees of the selected one) and a lazy **call tree**; every frame's source opens through `openProfileFrame` (the declaring file by class name in the project's source roots, then the index; a library-only class reports that there is no file). Copy or save folded stacks (`a;b;c N`) for other flame-graph tools. A restored profile tab whose file was pruned is closed. Tests: `IDECoverageControllerTests`, `IDEProfilerSessionTests` (a fake `jfr` script), `IDEFlameGraphLayoutTests`, `IDEProfileRoutingTests`, `IDEInstrumentedRunWorkspaceTests` (a real JVM, JaCoCo and `jfr`), `IDEInstrumentationViewsSmokeTests`. The JaCoCo jars are not committed: `Umbra/Sources/Umbra/Tools/JaCoCo/fetch.sh` downloads the pinned release (SHA-256 checked); `Package.swift` copies them when present, the Xcode project has a Fetch JaCoCo script phase and explicit Resources references, and Umbra says "not bundled" when they are missing.

- **Swift coverage and profiles** (`Languages/IDESwiftRunProvider+Instrumentation.swift`; roadmap Phase 6). The Coverage tab and the editor bands are language-neutral: `IDECoverageSnapshot`'s `java` and `cliJar` are optional (a Swift report has `supportsJaCoCoExports == false`, which disables Export HTML/XML), everything else is shared. A SwiftPM package's coverage is `swift test --enable-code-coverage`, then `swift test --show-codecov-path`, then `LLVMCoverageJSONParser` (`Sources/JavaIntelligence/Coverage/`; target = package, file = class); `IDESwiftRunProvider.collectCoverage` publishes it, marking buffers with unsaved edits stale as the Java path does. `runInstrumented` / `runTestsInstrumented` on the workspace route to `IDESwiftRunProvider` when the active file's run provider is Swift. A Swift profile is `xcrun xctrace record --template 'Time Profiler' --launch` run as a Run-tab session on the release build, then `xctrace export` of the `time-profile` table parsed by `XCTraceTimeProfileParser` into the same `JavaProfile`; `IDEWorkspace.openSwiftProfile` makes the tab with an `IDEProfilerSession.sourceLoader` (no `jfr`), a Swift `classifyClass` (targets are project, `lib*`/`dyld` are the platform) and an `openFrame` that says Instruments records no source line. Not done: Xcode projects (`xccov`), source lines and per-line hints for Swift frames, profiling tests, a live view. Tests: `IDESwiftInstrumentationTests`, `LLVMCoverageJSONParserTests`, `XCTraceTimeProfileParserTests` (root).
