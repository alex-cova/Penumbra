# Inspections workflow (`Umbra/Sources/Umbra/Inspections`)

Loaded when working under `Umbra/Sources/Umbra/Inspections`. Split out of `Umbra/CLAUDE.md`.

- **Inspections workflow** (`Umbra/Sources/Umbra/Inspections/`, plan: `docs/JAVA_INSPECTIONS_WORKFLOW_PLAN.md`; engine: `Sources/JavaIntelligence/Inspections/CLAUDE.md`). *Profiles:* `IDEInspectionProfiles` (app-wide) keeps "Default", which **is** the `IDEPreferences` inspection keys plus one more (`com.umbra.editor.javaInspectionScopedOverrides`), and file-backed profiles in `Application Support/com.umbra.editor/InspectionProfiles/<name>.json`. `IDEWorkspaceInspections` (`IDEWorkspace.inspections`, one per window) picks the active one: the project's `.umbra/inspections.json` (`{"profile": {…}}`, shared through git, re-read from the project watcher's batch) unless the user chose a global profile for that project (`umbra.inspections.prefersGlobal.<root>`). Edit through `inspections.edit { }`: it writes the right file and calls `javaInspectionPreferencesChanged()`, which reaches `IDEJavaSupport.applyCodeInsightPreferences(inspectionProfile:projectRoot:testRoots:)` in every window. Settings ▸ Java › Inspections (`IDEPreferencesInspectionsPane`, one group at a time in a picker) has the profile picker and menu (duplicate, rename, delete, new empty, restore defaults, copy to/from the project, export/import), group toggles, the severity picker (Error, Warning, Weak Warning, Consideration, No highlighting), per-rule scopes (Tests or a path glob, ordered) and filters (Modified, Has Quick Fix, Project-Wide); `inspections.focusedRuleCode` + `requestedSettingsDomain = .java` deep-links to a rule with its group tab selected. *Inspect Code:* Java ▸ Inspect Code… (Explorer and editor context menus too) and Run Inspection by Name… (⌥⇧⌘I) show `IDEInspectCodeSheet` (scope, test sources, file masks, project-wide rules, profile; Analyze, or Fix All for a named rule that has a fix). `IDEWorkspace.startInspection` runs `JavaBatchInspector` (`IDEJavaSupport.makeBatchInspector`, text from the open buffer else the disk) into an `IDEInspectionRun` kept by `IDEInspectionRunsStore` (at most 5, never persisted). Problems has tabs: File (the active file), Project Errors (everything live, as before) and one closable tab per run (`IDEInspectionResultsView`: group by inspection / severity / directory, exclude and include, rerun, stop, previous/next, SARIF/HTML export, a detail pane, quick fixes as a menu at the pointer, "Apply fix to N problems" per inspection; fixes go through `historyRecordingApplier`, then the file is re-inspected and the result shows struck through as resolved). Rows show the rule's title, not `java-inspection`; the editor's hover does too (`EditorIntelligenceController.diagnosticTitleProvider`, `TextViewDiagnostic.code`). Closing a file clears its live inspection rows (inspections only run on open files; Inspect Code covers the rest). *Editor:* ⌥↩ offers the rule's fixes, "Fix all … in file", "Turn off highlighting … (keep fix)", "Disable inspection" and "Edit inspection settings…" (`IDEWorkspace.performCodeActionCommand`); `IDEInspectionWidget` (top right of a Java editor; Settings ▸ Editor ▸ Problem Counts in Java Editors) shows the file's counts and opens Problems ▸ File. *Commit:* the Changes ⋯ menu's "Analyze Code Before Commit" (per repository) inspects the staged Java files with the active profile (no project-wide rules) and `IDEGitCommitChecks` adds a warning with Review Problems (a run tab) and Commit Anyway. The language level of each file (`IDEJavaSupport.inspectionLanguageLevel`: its Gradle module's, else the JDK's) gates the migration rules (`instanceof` patterns, enhanced `switch`, text blocks…); `refreshInspectionLanguageLevel` runs from `refreshCompilerDiagnostics`, so a sync or a JDK change re-analyses open files. Not done: custom severities, Typo and Grammar, a baseline of known problems, a command-line runner, and fixes for the project-wide and data-flow rules. Tests: `IDEInspectionProfilesTests`, `IDEInspectionRunTests`, `IDEInspectCodeWorkspaceTests`, `IDEInspectionPreferencesTests`.

- **Inspect Code is language-neutral** (roadmap Phase 4, `docs/SWIFT_INTELLIGENCE_ROADMAP.md`). A run covers one `IDEInspectionLanguage` (`java` or `swift`, `IDEInspectionRun.language`). Its findings are `IDEInspectionFinding`s (rule id, message, `IDEInspectionSeverity`, range, and the language's own value in `origin`), so the tree, the list and the exclusions do not know the language; rule titles, summaries, groups and "has a fix" come from `IDEInspectionLanguage.rule(code:)` / `.rules` (`IDEInspectionRuleInfo`). `IDEInspectionLaunch` holds a `Backend`: `.java` (scope, profile, rules, project-wide switch; the old initialiser still builds it) or `.swift` (`SwiftInspectionScope`, the profile's options with a per-file resolver, optional rules). `beginInspection`, `reinspect`, `quickFixes(for:)`, `fixAll(ruleCodes:language:in:)` and the report switch on the backend; the Java branches are the original code. `IDEWorkspace.inspectionLanguage(of:)` routes an Explorer item or a context menu by extension; the Java menu's items pass `.java` explicitly, Swift has palette commands only. `IDEWorkspace.inspectionReport(for:root:)` builds the SARIF/HTML entries from any run. Swift shares the profiles: its choices are the `swift` section of the same global profile files and of `.umbra/inspections.json` (`JavaInspectionProfile.swift`, `IDEWorkspaceInspections.activeSwiftProfile`), the sheet shows the same profile picker, and Disable Inspection / Edit Inspection Settings / Turn Off Highlighting edit the active profile's section. The sheet's "Include project-wide inspections" applies to Swift too (`unused-declaration`, which asks the index and waits for it to be built). The unused-code rules' "Safe delete" fixes apply one at a time — Fix all and Apply fix to N problems skip them (`SwiftInspectionFix.isBatchable`) — and quick fixes for project-wide findings re-run the rule with the index (`SwiftInspectionQuickFixes` async variant). The commit check covers staged Swift files (`analyzeForCommit`; Review Problems opens a run per language) and so does the editor's `IDEInspectionWidget`.  Tests: `IDEInspectionRunTests`, `IDEInspectCodeWorkspaceTests` (Java, unchanged), `IDESwiftInspectCodeTests`.
