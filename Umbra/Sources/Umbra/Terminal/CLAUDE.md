# Terminal (`Umbra/Sources/Umbra/Terminal`)

Loaded when working under `Umbra/Sources/Umbra/Terminal`. Moved out of `Umbra/CLAUDE.md`.

- **Terminal panes** (`Terminal/IDETerminalTiling.swift` pure tree and geometry, `IDEBottomPanelModel` state, `Panels/IDETerminalPanel.swift` `IDETerminalPanes`). The bottom panel's shell tabs can be tiled: the tiling's leaves are the tabs showing, the other tabs wait in the tab bar, and the selected tab is the focused pane. Split from a tab's right-click menu (Split Right/Down/Left/Up puts that tab beside the focused pane, or opens a new shell when it is the focused one), the panel toolbar's layout menu (a pane's title strip is the tab, with its × to close the shell in place and no other buttons; double-clicking it zooms the pane), View ▸ Terminal Layout (⌃⌥\ and ⌃⌥⇧\ split, ⌃⌥⌘ arrows move between panes, ⌃⌥↩ zooms a pane) or by dragging a tab or a pane header onto a pane (the outer quarter of a side splits, the middle swaps or replaces). Layout presets are halves, thirds and quarters (`IDETerminalTiling.Preset`); the panel's own size presets (half, third, quarter of the editor column, fullscreen) are `IDEBottomPanelSize`. **This is the one place that does not use `SplitPanes`**: a shell ends when its view is dismantled and `SplitPanes` takes its panes as structural content, so a split would remount the shells that moved. Every tab stays mounted in one flat `ZStack` and is placed at the rectangle the tree gives it; `IDETerminalPanes` draws and drags the dividers (a pane keeps at least 120 pt of width or 72 pt of height, not a share of the split; double-click or Return on a focused divider shares its two panes evenly; arrow keys and VoiceOver's adjust action move it 5%). The session keeps one shell (the selected one, `makeSession`) and the panel height; the tiling and the other shells are not restored. Tests: `IDETerminalTilingTests`, `IDEBottomPanelLayoutTests`.

- **Terminal settings** (Settings ▸ Terminal, `Settings/IDEPreferencesTerminalPane.swift`; model `Terminal/IDETerminalSettings.swift`, pure). Each setting is a Ghostty configuration key (the page's search terms list them): font (the editor's or its own), row height, left and vertical padding, colours (follow the UI scheme or a custom foreground/background/cursor/selection plus the 16 ANSI colours), cursor style and blink, faint opacity, scrollback, Option as Meta (off/both/left/right), bell, copy on select, hide the pointer while typing, scroll-to-bottom on keystroke and on output, unsafe-paste confirmation, shell command/arguments/login/starting folder/`TERM`/environment, clipboard read and write (OSC 52), desktop notifications (OSC 9/777, posted under the notification centre's Terminal category), title changes and title reports. **Shared** values are `IDEPreferences.terminal` (`IDETerminalSettings`, JSON in `com.umbra.terminal.settings`, also in the preferences snapshot as an optional field, so older files restore the defaults); **on this Mac only** are the shell values, `IDEPreferences.terminalShell` (`com.umbra.terminal.shell`). Every field decodes with a default and numbers are clamped, so a hand-edited file cannot break the terminal. `IDETerminalHostRepresentable` passes the settings to `IDETerminalHostView.applyTerminalAppearance`, which resolves colours against the UI scheme and hands `GhosttyTerminalView` one `GhosttyTerminalViewConfiguration` (`vt` goes to `GhosttyVtTerminal.configure`, which sets the libghostty options; the rest the view reads). Settings reach running terminals live, except the shell, which is read by `IDETerminalLaunch.make` when a shell starts (restart the tab). The padding is the host's constraints, not the view's. A changed default cursor is shown by writing `CSI 0 q`, which a program that chose its own cursor also gets reset by. **Clipboard read "Ask"** has a limit: libghostty asks synchronously on its own queue and the main thread writes to that queue, so the prompt cannot block it. The first read is refused, the view shows an Allow/Cancel sheet, and Allow lets that terminal answer the program's *next* read. Not offered: `bold-is-bright` (the snapshot already holds flattened RGB), ligatures (the grid keeps them off) and Ghostty theme files (none are bundled). Tests: `IDETerminalSettingsTests`, `GhosttyVtTerminalTests` (configuration section), `GhosttyKeyEncoderTests` (Option sides), `GhosttyTerminalViewRenderTests` (Settings ▸ Terminal section), `IDEPreferencesSnapshotContractTests`.

- **Terminal find, size and environment** (`Terminal/GhosttyVtSearch.swift`, `GhosttyTerminalFindBar.swift`, `IDETerminalHostView` in `Panels/IDETerminalPanel.swift`). ⌘F (whatever the keymap binds to Edit ▸ Find…) goes through `IDEWorkspace.showFind`, which first asks `IDETerminalHostView.owning(window.firstResponder)`: with the terminal or its find bar focused it opens that session's bar, otherwise the editor's paths run unchanged. Each host owns its own bar and needle, so sessions never share a search. The search is libghostty-vt's own `ghostty_search_*` (screen and scrollback of both screens, ASCII case-insensitive, results pruned with scrollback); never keep a copy of the output to search. `GhosttyTerminalView` steps it off the main thread in bounded feed/tick chunks (`stepSearch`, a generation drops stale steps), re-feeds at most every 100 ms on output, resize or scroll, selects the newest match first, and draws the viewport matches (`ghostty_terminal_point_from_grid_ref`, converted on the terminal queue). Return is the next match toward older output (Ghostty's direction), Shift-Return the previous; the library scrolls to it and output does not snap the viewport away while a search is open. Escape closes the bar and gives the keyboard back to the terminal (the bar handles it, so the panel's Escape does not hide the panel). **The grid is exactly what fits** (`GhosttyGridLayout.fitting`, no 80×24 floor; a view smaller than one cell keeps its last grid): the PTY, the VT grid and the drawn rows must agree, or output, prompts and a pager's first page (psql's headers) land below the visible rows. `GhosttyPtyProcess.spawn` keeps its slave fd open until `posix_spawn` returns (closing the last slave fd resets the tty to 0×0, which anything run before the first output saw) and drops the launching terminal's variables (`LINES`, `COLUMNS`, `TERM_PROGRAM*`, `GHOSTTY_*`, `ITERM_*`…; `childEnvironment`), which Settings ▸ Terminal can still set. The wheel on the alternate screen sends cursor keys under mode 1007 (`GhosttyAlternateScroll`), so pagers scroll. Tests: `GhosttyVtSearchTests`, `IDETerminalFindTests`, `IDETerminalPtySizeTests` (its psql case runs with `UMBRA_PSQL_DB=<local db>`), `IDETerminalInteractiveTests`, `GhosttyPtyProcessTests`, `GhosttyGridLayoutTests`.
