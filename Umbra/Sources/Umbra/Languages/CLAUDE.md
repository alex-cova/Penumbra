# Language modules (`Umbra/Sources/Umbra/Languages`)

Loaded when working under `Umbra/Sources/Umbra/Languages`. Split out of `Umbra/CLAUDE.md`.

`Umbra/Sources/Umbra/Languages/` holds the chrome a language adds to Umbra, beside the intelligence its `LanguageService` provides (`Sources/EditorIntelligence/CLAUDE.md`). TypeScript intelligence lives in `Sources/TypeScriptIntelligence/` (`IDETypeScriptSupport` and `IDETypeScriptLanguageService` stay in the app). It is syntactic: a tree-sitter document parse through `LanguageSyntax`'s `SyntaxParser` / `DocumentParseCache` (language `typescript`) plus a project index of `.ts`, `.mts`, `.cts` and `.tsx`. Relative imports resolve to indexed files, and member completion and go-to-definition follow a type annotation, `new`, or an import. It does not run `tsc` or `tsserver`, does not index `node_modules`, and does not parse JSX. `IDETypeScriptModule` contributes the npm run provider for TypeScript and JavaScript, the one-file class diagram, and a symbol-palette source from the in-memory `TypeScriptIndex`. An `IDELanguageModule` is a stateless value (`IDEJavaModule`, `IDEHTTPModule`, `IDETypeScriptModule`, `IDESwiftModule`, and the chrome-only `IDEMarkdownModule`, `IDEJSONModule`, `IDECSVModule` in `IDEPreviewModules.swift`, plus `IDEHexModule` (`Umbra/Sources/Umbra/HexEditor/`); listed in `IDELanguageModules.shipped`, with `register(_:)` / `unregister(id:)` for another) that contributes palette commands, a menu-bar menu, Settings pages, tool-window stripe entries, toolbar buttons (`IDEToolbarItem`, drawn by `IDEToolbarActionCluster`), status-bar items (`IDEStatusItem`) and View menu items (`IDEViewMenuContribution`); it takes the workspace as an argument and never keeps it. `IDEWorkspace.configurePalette` registers the commands where Java's used to start, `IDEAppCommands` shows `languageModuleMenu(for:)` (one line per built-in module: SwiftUI cannot build a menu bar from a list), `IDEPreferencesDomain` is a value type whose built-in pages are static members and whose module pages go between Project and Agent, and `IDEWorkspace.toolWindows` merges built-in and module entries by `IDEToolWindow.order` (`IDEToolWindow.Order`). `IDEBottomPanelTab` is a value (an id); a module's bottom tabs are `IDEBottomTabContribution`s (strip item, panel and `IDEBottomPanelTab.Order` position), merged into `IDETerminalTabsBar` and `IDETerminalPanel` (a contribution can bring its header `controls` and `staysWhenLastShellCloses`); select any bottom tab with `showBottomTab(_:)`, read it with `isBottomTabSelected(_:)`. `IDESidebarTab` is a `RawRepresentable` string (saved in sessions, so an id must never change) and each tab is an `IDESidebarTabDescriptor` (built-in ones in `IDESidebarTabs.builtIn`, Breakpoints from the Java module). Plan: `docs/LANGUAGE_SUPPORT_PLAN.md` (phase 4); guide: `docs/ADDING_A_LANGUAGE.md` §3. Tests: `IDELanguageModuleTests`, `IDEModuleContributionTests` (toolbar, status bar, View menu, bottom tabs, and a fake Ruby module registered end to end).
