# Project systems and run providers (`Umbra/Sources/Umbra/Projects`)

Loaded when working under `Umbra/Sources/Umbra/Projects`. Split out of `Umbra/CLAUDE.md`.

Plan: `docs/LANGUAGE_SUPPORT_PLAN.md` (phase 5). Both are per-window values made with the window's services, so a second language adds one of each without editing `IDEWorkspace`.

- **`IDEProjectSystem`** (`Umbra/Sources/Umbra/Projects/IDEProjectSystem.swift`): recognizes the open folder (`isActive`), syncs the project model after asking for trust (`syncState`: `IDEProjectSyncState`, generalized from the old `GradleSyncState`), keeps a console log (`IDEProjectConsoleLog`, rendered by `IDEProjectConsoleView`), lists its `tasks`, runs tasks and a build, reports `sourceRootPaths` and whether its build files changed (`hasConfigurationChanges`, the reload banner), and contributes its tool window (`toolWindows`, `bottomTabs`, `makeSidebar`). What it asks of the host (the trust prompt, "a sync failed", "a sync ended", "a task run ended") is an `IDEProjectEnvironment` of closures the window sets in `bootstrap()`; nothing in it retains the window. `IDEProjectSystems` (`IDEIntelligenceServices.projectSystems`) holds the window's systems in the order they claim a folder; `IDEWorkspace.projectSystems.active` is the first that recognized the folder and owns the right-hand sidebar; every match stays in `activeSystems`. The shared status line ("Indexing JDK 24…", "Resolving Gradle project…") is `IDEProjectStatus`, written by a project system and by Java's indexing; each writer clears only a message it set.
- **`IDEGradleProjectSystem`** is the first (`Projects/IDEGradleProjectSystem.swift`, split out of `IDEJavaSupport`): detection, the trust gate, `GradleProjectModelExtractor` sync with the cached-model fast path, `runGradleTasks`, the dependency graphs, the build-file banner and the Gradle tool window (`IDEGradleSidebarPanel`, the console tab). The reload banner compares **content**, not events: a `GradleBuildFileSnapshot` of the build inputs (`GradleBuildFiles.inputPaths`, the same walk as the fingerprint) is taken when the project opens, when a sync starts and on Dismiss, and each build file in a batch of the window's watcher (`filesDidChange`) is re-read against it, so a save of unchanged text, `touch` or an xattr write raises nothing and an undone edit clears the banner. Paths arrive in the open folder's own spelling (the watcher maps FSEvents' `realpath` paths back) and are judged relative to it (`GradleBuildFiles.matches(path:root:)`; `node_modules`, `out`, `build` and hidden folders never count). `IDEJavaSupport` keeps the Java index and providers and is both systems' `IDEJavaModelConsumer` (weak): it indexes every model a sync produces. Gradle wins when a folder has both `pom.xml` and a Gradle marker. `IDEJDKSelection` is made by `IDEIntelligenceServices` and given to Gradle and Maven.
- **`IDEMavenProjectSystem`** (`Projects/IDEMavenProjectSystem.swift`) is the second. A root `pom.xml` makes the folder Maven unless a Gradle marker is also there (`settings.gradle`, `settings.gradle.kts`, `build.gradle`, `build.gradle.kts`, `gradlew`), in which case Gradle wins. Reading the POM is native (`MavenProjectReader`) and does not run Maven or ask for trust. Goals, tests and dependency downloads run Maven only after the folder is trusted (`maven-trust.json`, its own prompt). The model is projected into the same `JavaGradleProjectModel` Java already indexes (`gradleVersion` `"maven"`). A save of unchanged POM bytes does not re-read; a byte change re-reads after 500 ms and a parse error keeps the previous model. Profiles remember only the user's overrides. Its sidebar, console and Build Project button are its own. Settings ▸ Java holds auto-read, download, the `mvn` path, a settings file and the goal timeout.
- **`IDENpmProjectSystem`** (`Projects/IDENpmProjectSystem.swift`) is the third. It reads the root `package.json` (scripts and declared dependency names; parsing does not install packages and does not use the network), lists scripts as tasks, and runs `npm run <name>` through SubprocessKit. Trust is `npm-trust.json` and its own sheet. A decline on Reload is stored, and a decline while running a script is not; the script list stays. Its reload banner compares bytes like Gradle's: `manifestBaseline` is package.json as the last load, Reload or Dismiss read it, and a batch of the window's watcher that names it (`filesDidChange`) raises the banner only when the file now differs (a same-bytes save raises nothing, an undone edit clears it). The last chosen script is remembered per folder, except the Build button, which runs `npm run build` only when that script exists. Its console and, when it is the active system, its sidebar are its own. The dependency diagram is the declared names.
- **Order on a folder change.** `applyProjectRoot` calls `projectSystems.projectDidChange(root:)` and then `languages.projectDidChange(root:)`, both synchronous, so Java sees what Gradle decided (`gradle.isActive`, `isLoadingCachedModel`: with a cached model the whole-tree index is skipped). A Maven folder skips that index the same way while the first POM read is in flight and no model has been published (`maven.isLoadingModel`). `LanguageService` has `@MainActor projectDidChange(root:)` and `filesDidChange(_:)` hooks for this (default no-ops, `LanguageServiceRegistry` runs them in registration order); Umbra's Java service is `IDEJavaLanguageService`, which wraps `JavaLanguageService` and forwards both to `IDEJavaSupport`.
- **`IDERunProvider`** (`Run/IDERunProvider.swift`): what a language adds so Run, Debug, Run in Context and Stop work on its files — `canRun`/`canDebug`/help strings for the toolbar, `runnableLocations(in:)`, `run`, `runInContext`, `rerun`, `hasActiveWork`, `stop`, `projectTasksDidFinish`. A language module returns it from `makeRunProvider(for:)`; `IDEWorkspace.runProviders` builds them once per window and `activeRunProvider` picks by the active document's language. The process side is generic: `IDEProcessLaunch` (a program, arguments, directory, environment, optional input file), `IDERunRequest` (id, title, provider, payload, `prepare`) and `IDERunSessions.start(_:replacing:)`, which owns the "a rerun takes the tab, waits for the old process" rule; `IDERunSession` keeps a title, a provider id and an opaque payload instead of a `JavaRunConfiguration`.
- **`IDEJavaRunProvider`** (`Languages/IDEJavaRunProvider.swift`, `+Pipeline`, `+Tests`) is Java's: the run configuration derivation for the active file, validation, before-launch steps, the build, the JDK, Gradle and Maven run and test tasks, Run in Context, the ⌥↩ actions, and the compiler errors, test results and "build finished" notification a Gradle task leaves behind. It reaches the window only through `IDEJavaRunHost` (conformed to by `IDEWorkspace` in `IDEWorkspace+JavaRunHost.swift`), weakly. The debugger stays in the window (`IDEWorkspace+Debugger.swift`, Java-only) and asks the provider for the launch, the classpath, the JDK and `launchEpoch` (Stop bumps it).
- **Not generic yet**: the run configuration picker and editor (all `JavaRunConfiguration`), and `javaFileCanTest` (test discovery is Java's). Debugging is Java's JDI session or, for a Swift executable, `DAPDebugSession` behind `IDEDebugSession`. Another language's gutter run buttons are `IDERunnableLocation`s. The run flags are generic now (`runFileCanRun`, `runFileCanDebug`, `runFileURL`, `runActiveFile`, `debugActiveFile`). The right-hand tool window is saved as `projectSidebarWidth` / `isProjectSidebarVisible` (an older `last-window.json` with `gradleSidebarWidth` / `isGradleSidebarVisible` still restores). Notification categories include `.gradle` and `.maven`: each is the user-facing name of a switch in Settings and belongs to that project system.
- Tests: `IDEMavenProjectSystemTests` (detection, Gradle winning, a read with no trust prompt, the trust gate, a download that fills the local repository, re-read on a byte change, a parse error keeping the model, goal reports), `IDENpmProjectSystemTests` (manifest order, trust, a fake `npm`, the run provider, the class diagram, the symbol index, and Gradle staying active beside npm), `IDEGradleProjectSystemTests` (a fake `gradlew`; detection, trust, sync, cached start, cancel, task runs, the banner, the task list), `IDEProjectAndRunProviderTests` (the containers with fakes, `IDERunSessions.start`, the Java provider's answers, the folder reaching Java through the registry, and that none of it retains the workspace), `IDERunSessionTests`, `IDERunWorkspaceTests`.
