# Agent (`Example/Umbra/Agent`)

Loaded when working under `Example/Umbra/Agent`. Split out of `Example/Umbra/CLAUDE.md`.

- **Agent** (`Example/Umbra/Agent/`, `Packages/AgentKit`; plan: `docs/AGENT_HARNESS_PLAN.md`). The chat opens docked beside the editor by default (a trailing panel, resizable, `IDEAgentPanel` in `IDERootView`), or expanded over the editor (`IDEAgentPage`: a tab bar with Close and a Side Panel button that docks it again, the conversation in a column at most 800 pt wide, the editor kept mounted). The arrows button in the docked chat header expands it, and `IDEAgentSettings.opensAsPage` remembers the choice. The brain button in the titlebar's trailing actions (left of the gear), View ▸ Toggle Agent and the palette command toggle it (`IDEWorkspace.toggleAgentPanel` / `hideAgentPage`, state in `agent.isPanelVisible`; disabled without an open folder). Only the page layout excludes Settings and closes when a tab or file is chosen (`agent.coversEditor`, `dismissPage()`, `onPanelRequested`); docked, the chat stays open while you work. Every opener goes through `IDEAgentController.showPanel()`. `IDEWorkspace.agent` is one `IDEAgentController` per window: it owns the panel state, the saved-history list and `conversations` (see *Agent: chat tabs*) (`IDEAgentConversation`, one transcript plus one `AgentSession` each; `selected` is the one the panel shows, and the controller's `entries`/`draft`/`send()`… forward to it). A conversation has a stable tab `id` and a `conversationID` that is the saved session's identity and changes on reset or load; the provider cache key is built from the project path hash and `conversationID` (never `hashValue`, which is seeded per process). Conversations reach the window only through `IDEAgentHost` (`IDEWorkspace+Agent.swift`) via a weak `IDEAgentHostBox`, and `IDEWorkspace.teardown()` ends its run, because a session that holds the workspace keeps the window alive (retention tests in `IDEAgentTests`). Streamed text is coalesced about every 50 ms; each user message carries a short editor-state block (active file, open files, problem counts) while the system prompt and tool list stay byte-identical. Tools: `read_file`, `list_dir`, `glob`, `grep` (AgentKit, over `DiskAgentWorkspace` with `agentUnsavedBuffers()` so open edits are seen; `glob` and `grep` also take `IDEGitVisibleFiles`, the files `git ls-files --exclude-standard` lists, and fall back to the fixed ignore list when the folder is not a repository) and `diagnostics` (`IDEDiagnosticsTool`, from `IDEProblemsStore`). `edit_file` and `write_file` change files through `IDEAgentWorkspace`, which applies them with `IDEWorkspaceEditApplier` (an open file's buffer in one undo group and left dirty, a closed file rewritten atomically, a new file through `WorkspaceEdit.fileCreations` / `IDEWorkspaceEditHost.createFile`). After a run that changed files the transcript shows an "N files changed" card (`IDEAgentChangesCard`): each file opens in the diff viewer (original ↔ now), and Revert Run restores the run, leaving any file the user edited afterwards alone and marking it "changed since". Commands run in `Example/Umbra` only (`AgentCommandRunner`, a thin adapter over SubprocessKit: `/bin/zsh -c` in its own process group, stdin `/dev/null`, a built environment with the selected JDK, output bounded to head and tail; a timeout, Stop, or the command ending kills the whole group). Every command-risk call asks first on an inline card (`IDEAgentApprovalView`: Run, Edit…, Deny… with a note; `sudo`, `rm -rf` and similar are flagged): `show_file` (`IDEShowFileTool`, read-only, so Plan mode keeps it) opens a project file through `openAgentCitedFile` without changing it. `run_command`, `gradle` and `run_tests` (the last two only in a Gradle project; they go through `IDEGradleProjectSystem.runGradleTasks`, so the console, Problems, Test Results and the trust prompt apply, and the model gets `IDEGradleSummary`: compiler errors, failed tests with their first frames, Gradle's reason, never the log). A `gradle` or `run_tests` call reveals the Gradle sidebar and the Gradle console first (`agentRevealGradle`), including when the run refuses to start. `run_command` still executes through `AgentCommandRunner`; after approval its output is also fed into a new terminal tab that does not start a login shell, does not take the keyboard, and is left out of the saved session (`agentShowCommand`). Settings ▸ Agent ▸ \"Run commands in a sandbox\" (direct builds only; the toggle hides itself in the App Store build) wraps `run_command` in `sandbox-exec -p` under a workspace profile (`IDEAgentSandboxProfile`: reads everywhere except credentials, writes to the project, temp and build caches, `.git` read-only, network on unless blocked): the choice is per session, the first run carries the consent on its card, and a run the sandbox denies offers one retry outside it (pre-allowed when the rules already allowed the call, else asked). Tests: the sandbox cases in `IDEAgentCommandToolTests`. The agent's own unsaved buffers are saved before a command; the user's are only named on the card (`IDEAgentBufferTriage`). `diagnostics` compiles the Java files the run changed (`JavaCompilerDiagnosticsService.freshDiagnostics`) and says when it couldn't. `IDEAgentSettings.shared`: the provider (`IDEAgentProvider`: OpenAI Responses, OpenAI-compatible Chat Completions, Ollama) and, per provider, base URL, model and reasoning effort in `UserDefaults` (`umbra.agent.*`; the original Responses keys are unchanged), plus the local context cap. The API key is in the Keychain per endpoint host (`IDEAgentKeychain`); the first use of a remote host needs an explicit "Allow Sending" (`disclosedHosts`), and `send()` does nothing until then. A loopback endpoint (`localhost`, `127.0.0.1`, `::1`) needs neither a key nor consent, since nothing leaves the Mac. The `.mlx` provider ("On this Mac") runs a downloaded model in-process through `AgentKitMLX`: `IDELocalModelsStore` (installed models, Hugging Face search, one pausable download at a time, load/unload; models live in `Application Support/com.umbra.editor/Models`) and `IDELocalModelsView` (the sheet behind "Manage On-Device Models…"). A model whose chat template does not take tools can be downloaded but not used, and is refused before a request. The first message loads the weights with a visible "Loading…" status. For Ollama the settings load the installed models (`OllamaModelCatalog`), disable those without tool support, ask for `num_ctx = min(cap, the model's maximum)` and send `think` only to models that list it; a model the server says cannot use tools is refused before a request is made.

Only one Gradle run at a time exists in a window, so two chats that both run Gradle share it. Tests: `IDEAgentTabsTests`.

- **Agent: commands and skills** (`Example/Umbra/Agent/Commands/`). A message that starts with `/name` and a space or the end is a command (`IDEAgentSlashInvocation`; `/usr/bin is missing` is a sentence, and an unknown name is sent as an ordinary message; a lone unknown `/word` with no arguments also gets a notice saying so, since it is probably a mistyped command). Return in the field calls `IDEAgentController.submit()`: a command runs, anything else is sent. Built-ins (`IDEAgentBuiltInCommand`): `/new` `/clear` `/resume [search]` `/rewind` `/fork` `/compact` `/plan [prompt]` `/mode` `/permissions` `/model` `/history` `/export` `/init` `/cost` `/rename` `/help`, and they work before the first-use disclosure is accepted. `IDEAgentCommandCatalog` adds the user's own, from `.umbra/{commands,skills}` and `.claude/{commands,skills}` in the project, `~/.claude/…` (Settings ▸ Agent ▸ "Offer commands and skills from ~/.claude") and Umbra's folder in Application Support, the project's first. A built-in keeps its name, a command beats a skill. The read is kept two seconds and dropped at every send. The list after `/` (`IDEAgentController.suggestions(for:)`, fuzzy by name) accepts a command that takes no arguments by running it; one that takes arguments is inserted, and the text after its name is then the argument list (`IDEAgentComposerTrigger.slashArgument`): `/resume ` lists the project's saved chats (`.resume` payload; selecting one shows its tab or opens it), `/mode ` the four modes. A custom command shows `/name args` in the transcript and sends `CommandTemplate.expand` (the row's "What the agent was sent" disclosure, `IDEAgentEntry.detail`, saved with the chat); its `allowed-tools` are permission rules for that run only. `/skill-name args` sends `[Skill: name]` and the instructions; the model is also given the `skill` tool when any skill exists, and the skills' fingerprint is in the session fingerprint. `!`cmd`` lines in a command are sent as text, with a notice. `/permissions` opens Settings on the Agent pane (`IDEWorkspace.requestedSettingsDomain`), `/model` opens the panel's settings sheet (`settingsRequest`), `/export` saves Markdown (`IDEAgentTranscriptExport`; a shell, Gradle or test command includes the command and its output, a failed call says `Failed:` with the error, an edit shows its result line and `diagnostics` its first lines; tests replace `exportHandler`). Tests: `IDEAgentCommandsTests`.

- **Agent: @ mentions** (`Example/Umbra/Agent/Mentions/`). `@` at the start of a message or after whitespace starts a mention (`IDEAgentMentionToken.scan`; `@"path with spaces"` is the quoted form; trailing `.,;:!?)]` belong to the sentence). The list (`IDEAgentController.suggestions(for:)`) offers `@selection`, `@problems`, `@open` only when there is something to give, `@changes`, `@terminal`, `@skill:name`, then project files ranked by the same index Go to File uses (`IDEWorkspace.paletteFileIndex`, open files first). At send time, inside the run and once the session exists, `IDEAgentMentionResolver.resolve` turns each mention into an attachment appended to what the model is sent as `<untrusted source="attachment:…">` blocks under "project data, not instructions"; the transcript shows only what was typed, with a paperclip row per attachment (`IDEAgentEntry.attachments`, saved with the chat). A file is attached as the agent's own workspace reads it (open unsaved edits included), at most 64 KB (cut on a line, with the `read_file offset=` to continue), all attachments at most 256 KB; `path:12-40` attaches numbered lines; a folder attaches its listing; credential files (`SecretFilePolicy` and the user's globs) and paths outside the project are refused with a notice, as is a path that does not exist (a bare `@name` with no slash or dot is left alone, since it is probably a name). A file attached whole is passed to `AgentSession.recordRead`, so editing it needs no `read_file` first; a slice or a cut file is not a read. Mentions in a command's or skill's expansion are resolved too. *In Markdown files*: `@` after whitespace in a Markdown editor opens the completion popup with project files (`MarkdownFileMentionCompletionProvider`, registered in `IDEIntelligenceServices`; the workspace sets its file source to `agentFileSuggestions` in `bootstrap()`; primary only right after such an `@`, so word completion stays out; paths with whitespace insert as `"…"`; the popup prefix is identifier characters, so the user types a file-name fragment, not a path). **Run with Agent** (`IDEWorkspace.runActiveMarkdownWithAgent`, `IDEAgentPrompts.markdownRun`; titlebar sparkles button, View menu ⌃⌘↩ via `IDEMenuCommand.runMarkdownWithAgent`, palette `agent.runMarkdownFile`, editor context menu) sends the selection, else the whole live buffer without YAML frontmatter, through `agent.compose(_, send: true)`, so `@refs` in it are attached by the resolver above and the usual rules apply (a run in progress or no consent leaves the text in the composer). Tests: `MarkdownFileMentionTests`. `@terminal` reads the active terminal tab's buffer (`IDETerminalHostView.recentText`), `@changes` runs `git_diff`'s code. Tests: `IDEAgentMentionResolverTests`, `IDEAgentMentionsTests`; AgentKit: `RecordReadTests`.

- **Agent: checkpoints on disk** (`IDEAgentCheckpointBlobs`, `CheckpointLog.snapshot/restore`). Revert Run survives a relaunch. Each chat has one `CheckpointLog` for its whole life (so a settings change that starts a new session no longer drops Revert for earlier runs); it writes every original through to `<project folder in Application Support>/Agent/<hash>/blobs/<run id>/<file>` as it is recorded (LZFSE, 0600/0700), keyed by run and path, never content-addressed. The run records without the texts (`RunSnapshot`) are saved with the chat in `IDEAgentSavedTranscript.checkpoints`, and the "N files changed" card is saved (`IDEAgentPersistedEntry` kind `changes`: run, paths, which were created, reverted). Loading a chat puts the runs back into a log and the card back with its originals read from disk, so Show Diff works at once; a card whose originals are gone is not shown, since neither button could work. Revert after a relaunch needs no session and no working provider setup: with no session it reverts through the log and a workspace (`IDEAgentConversation.revert`). The user's later edits are still never overwritten (conflicts as before). Deleting a conversation removes its runs' originals, Clear History removes the project's, and each save prunes the project's oldest runs past 500 MB (`prune(keeping:)`, the chat's own runs spared). Tests: `IDEAgentRevertAfterRelaunchTests`, `IDEAgentCheckpointBlobsTests`; AgentKit: `CheckpointPersistenceTests`.

- **Agent: commands and Revert Run** (`IDEAgentSnapshots.swift`, AgentKit side: `Commands that change files`). `IDEAgentGitSnapshotter` is each chat's `WorkspaceSnapshotter`. A snapshot is a git tree built in a private copy of the repository's index (`GIT_INDEX_FILE` in a temp folder, kept for the chat so the next capture only hashes what changed): `git add -A --ignore-errors -- .` then `write-tree`, with `core.autocrlf=false`. The user's index, working tree and the Git console are untouched (it uses a plain `SystemGitRunner`, not `IDEGitSupport.runner`), `.gitignore` decides what is followed, and the blobs it writes are unreachable objects that `git gc` collects. Diffs come from `diff-tree --relative`, so a project below the repository root gets project-relative paths. Bounds: text over 1 MB or containing a NUL is `unavailable`, more than 200 changed files are counted as omitted, a capture slower than 4 s switches it off for the chat, and a folder that is not a repository switches it off at the first command. Measured 2026-10-22 on 20,000 tracked files: 30-40 ms for a capture with nothing changed, about 130 ms with 600 files changed. Limits: a repository whose `.gitattributes` converts line endings or runs a filter (LFS) makes the snapshot differ from the file, so those files are named in the note and not revertable; two chats running commands at once each see the other's changes. Commands still do not claim files in `IDEAgentFileClaims`. Tests: `IDEAgentSnapshotTests` (real git in temp repositories, including that the user's index and `status` are unchanged).

Agents come from `.umbra/agents`, `.claude/agents`, `~/.claude/agents` (with the commands-and-skills setting) and Umbra's Application Support `agents` folder, the project's first, and `AgentCatalog.fingerprint` is part of the session fingerprint. - **Agent: rewind and fork** (`IDEAgentRewind`, `IDEAgentRewindSheet`, `IDEAgentConversation.rewind/forkState`). Every user message records where it sits in the session's history (`IDEAgentEntry.itemIndex`, the index of its `.user` item; saved with the chat). That is what rewinding cuts before, so it must stay right: dropping provider-specific items (on a settings change or a load) moves the recorded positions with the items (`droppingOpaque`), and a compaction that summarizes (`summarizedItems > 0`) clears every recorded position, since the start of the history was replaced; later messages record fresh ones. `/rewind`, Esc twice in an empty message field, or the arrow on a message you hover opens the sheet (`rewindRequest`): pick a message and **Conversation only** (forget it and what followed; files stay), **Code only** (revert the files the agent changed from that message on, newest run first; the conversation stays and the cards say what happened) or **Code and conversation**; the message goes back into the field. Reverting uses the session if there is one and otherwise the checkpoint log and a workspace, so rewinding works right after a relaunch and needs no working provider. A file you edited since is left as it is and named. The history cut is `AgentSession.rewind(toBeforeItem:)` (read ledger cleared, so the model reads a file again before editing it; checklist rebuilt from what is left), or, with no session yet, the saved items themselves; the result is saved at once. Never while a run is going. **Fork** (`/fork`, the branch arrow on a message, or in the sheet) opens a new tab holding the transcript and history up to before that message (all of it for `/fork`), named "… (fork)" and saved at once; the "files changed" cards are not copied, since their originals belong to the first chat. `IDEAgentController.fork` is async. Tests: `IDEAgentRewindTests`; AgentKit: `RewindTests`.

- **Agent: prompt history** (`IDEAgentPromptHistory`, `IDEAgentPromptRecall`). What a project's chats were sent is remembered (`prompts.jsonl` beside the project's conversations, one JSON string a line, 0600, newest 500, consecutive repeats once; commands too; nothing that was refused because a run was going or the field was blank). In the message field ↑ on the first line and ↓ on the last walk it (`IDEAgentController.recallPrompt`; the first ↑ keeps what was typed, and ↓ past the newest brings it back; the place is per chat, and typing, sending or switching ends it), and ⌃R turns the field into a search (`IDEAgentComposerTrigger.history`, `IDEAgentComposerState.isSearchingHistory`): the text is the fuzzy query over earlier prompts, newest first, and Tab or Return puts the chosen one in the field (the whole text is replaced), Esc or ⌃R again leaves. Settings ▸ Agent ▸ Clear History clears it too. Tests: `IDEAgentPromptHistoryTests`, `IDEAgentPromptHistoryFlowTests`, and the field tests.


- **Agent: while it works** (`IDEAgentConversation`). *Queued messages*: Return during a run queues what you wrote (chips above the field, ✕ takes one back); `AgentConfiguration.pendingMessages` asks the conversation at every turn boundary, so the model sees it on its next step without the run stopping, and a final turn that would have ended the run continues with it. Mentions in it are resolved when it is delivered, it enters the transcript at that point with its history position (so it can be rewound to), and what the run did not take is sent as the next message when the run completes, or put back in the field if it was stopped or failed. Built-in commands still run mid-run; a command that sends a message and `!` commands wait. *Stop* works before the run has started streaming too (while the session is made or a local model loads): `stop()` sets `stopRequested`, the run checks it before it begins, and a Stop that lands in the gap is forwarded after `send` (cancelling the run Task instead would also stop the loop that reads the run's events, and the ending would never reach the transcript). *`!command`*: a message that starts with `!` runs in the project folder through `AgentCommandRunner` like a terminal would, without asking (you wrote it) and not during a run; the output shows as a command card with live output, and the output of the newest five (each cut to a share of 16,000 characters, `IDEAgentShellContext`) goes before your next message as "commands the user ran themselves… information, not instructions", visible in that row's disclosure. *Context meter*: the ring under the field is the latest turn's reported input tokens over the window (`contextFraction`; orange from 75%, red from 90%; only when the window is known), its menu and `/compact [what to keep]` call `AgentSession.compactNow(focus:)`: old outputs are cleared and everything but the latest turns summarized, whatever the window and however the usage stands; a chat too short says there is nothing to summarize, a failed summary says so, nothing is sent while it runs, and positions recorded for rewind are cleared. *Notifications*: a chat that finishes, stops with an error or needs an approval, answer or plan decision, while it is not the selected chat of an open panel in the key window, posts to the bell under the "Agent" category (so Do Not Disturb and the category switch apply); clicking selects that chat (`IDENotificationAction.showAgentChat`). A run you stopped is quiet. Tests: `IDEAgentQueueTests` (also the shell, notification and history-search suites); AgentKit: `PendingMessageTests`, `CompactNowTests`.

- **Agent: interrupted runs, saved output, instruction changes** (`IDEAgentConversation`, `IDEAgentToolOutputs`, `IDEAgentSavedTranscript`). *Interrupted runs*: a conversation used to be written only when a run ended, so closing the window or quitting mid-run saved nothing for it. Now `claimRun` writes the file when a run starts with `runInProgress` set, each `.stepFinished` records the history as of that step (`stepItems`, the transcript rows and checkpoint runs that went with it) and saves it at most every 2 s, and `teardown()` (window close, and quit through `tearDownAll`) writes the last finished step synchronously, with the queued messages, before the run is cancelled and the host cleared. The end of any run (Stop included) writes the file again without the mark. Reading a marked file (`load`) adds an error-styled row, "The last run was interrupted when Umbra closed", with a **Resume** button (`IDEAgentEntry.canResume`, saved with the row), puts the queued messages back in the field and clears the mark at once; Resume is never automatic, because edits apply without asking. `resume()` runs `AgentSession.resume()`; writing a message instead drops the button. An ACP chat is not covered. *Saved output*: `IDEAgentToolOutputs` (a `ToolOutputStore`) keeps output too large to show at `<project folder>/tool-output/<conversation id>/<id>` (LZFSE, 0600/0700), reads another conversation's folder when its own has no such id (a fork carries the model's pointers), is swept whenever a session starts (older than 7 days, then the oldest past 100 MB, empty folders) and goes with its conversation on delete and Clear History. `run_command` and `git_diff` use `headAndTailSaving`, so the middle of a long build is no longer lost; `!command` output (`format` without a context) is cut as before. *Instruction changes*: `IDEAgentProjectNotes.current(root:)` is the session's `currentInstructions`, so editing AGENTS.md (or `/init`, or a pull) mid-chat reaches the model as a diff note at the next turn without a new session. Tests: `IDEAgentSessionsTests` (interrupted runs, instruction note), `IDEAgentToolOutputsTests`, `IDEAgentCommandToolTests`.

- **Agent: composer** (`Example/Umbra/Agent/Composer/`). The message field is an `NSTextView` (`IDEAgentComposerField`, because SwiftUI's `TextField` cannot see ↑/↓/Tab/Esc/⇧Tab or the caret): Return sends, ⇧↩ or ⌥↩ a newline, Esc closes the suggestion list and otherwise stops the run, ⇧Tab cycles the mode, and the field grows to eight lines. What a key does is a pure function (`IDEAgentComposerKeyMap`); what the text and caret ask for is another (`IDEAgentComposerTrigger.detect`: `/` as the message's first word, `@` at the start or after whitespace), tested without a view. `IDEAgentComposerState` holds the list's rows and highlight, `IDEAgentSuggestionList` draws it, and `IDEAgentController.suggestions(for:)` supplies the rows. `/commands` and `@` mentions are colored with attributes only; the model gets plain text. `@"path with spaces"` is the quoted form (`IDEAgentMentionToken`); files dropped on the field become mentions. Tests: `IDEAgentComposerFieldTests` hosts the field in a window.

- **Agent: IDE depth** (`IDEAgentGitTools`, `IDEAgentNavigationTools`, `IDEAgentEntryPoints`, `IDEAgentPrices`). `git_status` / `git_diff` read through `GitRepository` and are offered inside a repository (`IDEAgentGitSource`: paths are project-relative, `SecretFilePolicy` plus the user's globs filter every diff, an untracked `dir/` is expanded with `git ls-files --others --exclude-standard`). `go_to_definition` / `find_usages` take path, 1-based line and the identifier (`IDEAgentSymbolLocator`, whole-word, `occurrence` when ambiguous) and call `IDEAgentJavaNavigating`, implemented by `IDEJavaAgentNavigator` over the window's Java providers; they are offered when `agentJavaNavigator()` returns one (a Gradle project or an open Java file). `IDEAgentHost` gained `agentJavaNavigator()` and `agentLineText(url:line:)`, with defaults, so fake hosts need no change. Entry points: `IDEWorkspace.askAgentAboutSelection` (context menu item from `agentContextMenuItems`, palette command `agent.askAboutSelection`), `fixProblemWithAgent` (Problems row hover button and context menu) and `IDEAgentController.compose(_:send:)`, which fills the composer and focuses it (`composerFocusRequest`) or sends when consent is given and no run is going. The header shows `tokens · ~$cost` from `IDEAgentSettings.cost(of:)` and `IDEAgentPrices` (editable text in Settings ▸ Agent; `IDEAgentSavedTranscript` stores the total with the conversation; nil when any turn was unpriced). A closure stored on an editor's text view must hold its pane host weakly. An `.unreadableToolCall` event adds a notice ("…Asking it to try again"); the session has already told the model. Tests that need an editor view call `workspace.bootstrap()` first (it wires the adapter). Tests: `IDEAgentNavigationTests`, `IDEAgentEntryPointsTests`.

- **Agent: checklist and questions.** The controller adds `TodoTool` and `AskUserTool` to every session. `.todosUpdated` fills `IDEAgentController.todos`, shown by `IDEAgentTodoListView` under the header and saved in `IDEAgentSavedTranscript.todos` (restored into the new session when its history no longer holds the `todo` call). `.questionAsked` puts a `UserQuestion` on the `ask_user` card (`IDEAgentQuestionView`: option buttons, a field, Skip); `answer(callID:text:)` replies and `nil` skips. Tests: `IDEAgentInteractionTests` (the real-model one is opt-in).

- **Agent: web search** (`IDEAgentWebSearch`, AgentKit `WebSearchTool`). Off unless the Web search toggle is on (Agent Settings, and Settings ▸ Agent) and a Brave Search API key is saved under the Keychain account `api.search.brave.com`, separate from the model key. Both are in the session fingerprint, so a change starts a new session that keeps the conversation. The tool is `web_search`, placed after `show_file` and before the edit tools; it is read-only, so Plan mode keeps it. The query is sent to `api.search.brave.com` and the model gets titles, URLs and short snippets, marked untrusted. Nothing is fetched from those pages. A deny rule `web_search` blocks a call. Tests: `IDEAgentWebSearchTests`.

- **AI mode** (`Example/Umbra/Agent/AIMode/`). A window mode (`IDEWindowMode`: `editor` / `ai`, with `IDEAITab` `chat` / `code`; `IDEWorkspace.windowMode` / `aiTab`, saved in `IDEWindowSession.windowMode` / `aiTab`, which older files lack). `IDERootView` keeps the editor's `HStack` mounted and invisible and overlays `IDEAIModeView` (a list card and a conversation card, no status bar); entering clears Settings and the first responder (`prepareForAIMode`), so no keystroke reaches the hidden editor. The docked panel and expanded page are hidden while it shows. Entry points: the titlebar `bubbles.and.sparkles` button (next to the brain, and the way back in AI mode's own toolbar row, `IDEAIToolbarRow`), View ▸ AI Mode ⌃⌘I, palette `app.toggleAIMode` / `app.aiChat` / `app.aiCode`, the Welcome screen. Anything that shows a file or a diff (`openAgentCitedFile`, `agentShowDiff`, `agentOpenText`, `agentInsertAtCaret`, so `show_file` too) calls `leaveAIModeForEditor()` first. *Code* is the window's own agent: `IDEAICodeView` hosts `IDEAgentPanel(placement: .aiMode)` (no tab strip or history button, because `IDEAISidebar` lists the chats; an empty session shows a greeting with the message box in the middle; the box holds the field, a project chip `IDEAIProjectChip`, the permission chip, the context ring and the model picker). It begins with a new session (`IDEAgentController.startFresh()`, so the first send does not restore the latest saved chat) and counts as the open chat for notifications (`isShownInAIMode`). With no project Code still sends: `IDEWorkspace.agentProjectRoot` falls back, in AI mode only, to a scratch folder (`IDEWorkspace.agentScratchFolder`, `Application Support/com.umbra.editor/Scratch`), so its chats are saved and listed under that folder; the docked panel and editor entry points still need a real project. The chip and the list's Projects section open a folder through `IDEWindowRegistry.open(urls:origin:aiOpen:)`, which carries an `IDEAIOpenRequest` (show AI mode, resume this chat) to whichever window the router picks, including a new one (`IDEWorkspace.pendingAIOpen`, applied in `openProjectFolder`). The list groups `agent.history` (this project, fresh) and `SessionStore.listAll` (other projects, read off the main actor by `IDEAISessions`) by project; a row of another project opens that project in AI mode and resumes it. *Chat* is a plain conversation with any model, no project and no tools (`IDEAIChatConversation` over an `AgentSession` with `tools: []`, the chat prompt `IDEAISettings.chatSystemPrompt`, a temporary-folder workspace nothing reads), so a model without tool support is fine (`makeClient(for:requiresTools: false)`); chats are saved in their own store (`Application Support/com.umbra.editor/Chats`, root `IDEAIChatConversation.storeRoot`), shared by windows and never in a project's list. A new chat starts with the model last picked for Chat, else the global one if it is ready, else the first usable (`IDEAIChatController.defaultChoice`), and keeps the model in use at its first send. *Per-chat model*: `IDEAIModelChoice` (provider, model, reasoning, optional ACP agent) in `IDEAgentConversation.modelChoice`, saved in `IDEAgentSavedTranscript.modelChoice`; `nil` follows Settings ▸ Agent, which is how the docked panel keeps working unchanged. Every provider-dependent member of `IDEAgentSettings` has a `(for:)` variant (endpoint, key, consent, context window, cost, fingerprint, `makeClient(for:requiresTools:)`) and the old ones delegate with `currentChoice`; a chat with a choice builds its client through `choiceClientFactory`. ACP is per chat too (`acpAgent(for:)`, allowed agents only; the picker asks once). `IDEAIModelPicker` lists Claude, the configured OpenAI models, installed Ollama and on-device models (Code disables those without tool support) and, for Code, external agents; `IDEAIModelsSheet` pulls and deletes Ollama models (`IDEOllamaModelsStore`, over `OllamaModelCatalog.pull`/`delete`), opens the on-device manager, and saves provider keys and model names. Anthropic is a provider (`.anthropic`, `AnthropicMessagesClient`, key per host in the Keychain, consent per host like the others, Claude rows in the price table: a saved table nobody edited is replaced by the new default). *Model setup*: with no usable model, the red hint is replaced by a "Set up a model…" button (`IDEAISetupButton`) and a guided sheet (`IDEAIModelSetupSheet`: On This Mac with a one-click suggested download, Ollama, API key). It opens by itself once per window the first time a tab shows with an unusable model (`IDEWorkspace.offerAIModelSetupIfNeeded`, after the Ollama list is read; `hasOfferedAIModelSetup`), and whenever Send is pressed with one (`requestAIModelSetup(for:)`). Both pickers and the sheet's Use buttons go through `IDEWorkspace.selectAIModel(_:for:)`; `aiModelSetupHint(for:)` is the one "is it usable" check. Tests: `IDEAIModeTests`, `IDEAIModelChoiceTests`, `IDEAIChatTests` (with `IDEAISessionsTests`), `IDEAIModeSnapshotTests` (`AI_MODE_PNG_DIR=/path swift test --filter IDEAIModeSnapshotTests` writes PNGs of the views).
