# Agent (`Example/Umbra/Agent`)

Loaded when working under `Example/Umbra/Agent`. Split out of `Example/Umbra/CLAUDE.md`.

- **Agent** (`Example/Umbra/Agent/`, `Packages/AgentKit`; plan: `docs/AGENT_HARNESS_PLAN.md`). The chat opens docked beside the editor by default (a trailing panel, resizable, `IDEAgentPanel` in `IDERootView`), or expanded over the editor (`IDEAgentPage`: a tab bar with Close and a Side Panel button that docks it again, the conversation in a column at most 800 pt wide, the editor kept mounted). The arrows button in the docked chat header expands it, and `IDEAgentSettings.opensAsPage` remembers the choice. The brain button in the titlebar's trailing actions (left of the gear), View ▸ Toggle Agent and the palette command toggle it (`IDEWorkspace.toggleAgentPanel` / `hideAgentPage`, state in `agent.isPanelVisible`; disabled without an open folder). Only the page layout excludes Settings and closes when a tab or file is chosen (`agent.coversEditor`, `dismissPage()`, `onPanelRequested`); docked, the chat stays open while you work. Every opener goes through `IDEAgentController.showPanel()`. `IDEWorkspace.agent` is one `IDEAgentController` per window: it owns the panel state, the saved-history list and `conversations` (see *Agent: chat tabs*) (`IDEAgentConversation`, one transcript plus one `AgentSession` each; `selected` is the one the panel shows, and the controller's `entries`/`draft`/`send()`… forward to it). A conversation has a stable tab `id` and a `conversationID` that is the saved session's identity and changes on reset or load; the provider cache key is built from the project path hash and `conversationID` (never `hashValue`, which is seeded per process). Conversations reach the window only through `IDEAgentHost` (`IDEWorkspace+Agent.swift`) via a weak `IDEAgentHostBox`, and `IDEWorkspace.teardown()` ends its run, because a session that holds the workspace keeps the window alive (retention tests in `IDEAgentTests`). Streamed text is coalesced about every 50 ms; each user message carries a short editor-state block (active file, open files, problem counts) while the system prompt and tool list stay byte-identical. Tools: `read_file`, `list_dir`, `glob`, `grep` (AgentKit, over `DiskAgentWorkspace` with `agentUnsavedBuffers()` so open edits are seen; `glob` and `grep` also take `IDEGitVisibleFiles`, the files `git ls-files --exclude-standard` lists, and fall back to the fixed ignore list when the folder is not a repository) and `diagnostics` (`IDEDiagnosticsTool`, from `IDEProblemsStore`). `edit_file` and `write_file` change files through `IDEAgentWorkspace`, which applies them with `IDEWorkspaceEditApplier` (an open file's buffer in one undo group and left dirty, a closed file rewritten atomically, a new file through `WorkspaceEdit.fileCreations` / `IDEWorkspaceEditHost.createFile`). After a run that changed files the transcript shows an "N files changed" card (`IDEAgentChangesCard`): each file opens in the diff viewer (original ↔ now), and Revert Run restores the run, leaving any file the user edited afterwards alone and marking it "changed since". Commands run in `Example/Umbra` only (`AgentCommandRunner`, a thin adapter over SubprocessKit: `/bin/zsh -c` in its own process group, stdin `/dev/null`, a built environment with the selected JDK, output bounded to head and tail; a timeout, Stop, or the command ending kills the whole group). Every command-risk call asks first on an inline card (`IDEAgentApprovalView`: Run, Edit…, Deny… with a note; `sudo`, `rm -rf` and similar are flagged): `show_file` (`IDEShowFileTool`, read-only, so Plan mode keeps it) opens a project file through `openAgentCitedFile` without changing it. `run_command`, `gradle` and `run_tests` (the last two only in a Gradle project; they go through `IDEGradleProjectSystem.runGradleTasks`, so the console, Problems, Test Results and the trust prompt apply, and the model gets `IDEGradleSummary`: compiler errors, failed tests with their first frames, Gradle's reason, never the log). A `gradle` or `run_tests` call reveals the Gradle sidebar and the Gradle console first (`agentRevealGradle`), including when the run refuses to start. `run_command` still executes through `AgentCommandRunner`; after approval its output is also fed into a new terminal tab that does not start a login shell, does not take the keyboard, and is left out of the saved session (`agentShowCommand`). The agent's own unsaved buffers are saved before a command; the user's are only named on the card (`IDEAgentBufferTriage`). `diagnostics` compiles the Java files the run changed (`JavaCompilerDiagnosticsService.freshDiagnostics`) and says when it couldn't. `IDEAgentSettings.shared`: the provider (`IDEAgentProvider`: OpenAI Responses, OpenAI-compatible Chat Completions, Ollama) and, per provider, base URL, model and reasoning effort in `UserDefaults` (`umbra.agent.*`; the original Responses keys are unchanged), plus the local context cap. The API key is in the Keychain per endpoint host (`IDEAgentKeychain`); the first use of a remote host needs an explicit "Allow Sending" (`disclosedHosts`), and `send()` does nothing until then. A loopback endpoint (`localhost`, `127.0.0.1`, `::1`) needs neither a key nor consent, since nothing leaves the Mac. The `.mlx` provider ("On this Mac") runs a downloaded model in-process through `AgentKitMLX`: `IDELocalModelsStore` (installed models, Hugging Face search, one pausable download at a time, load/unload; models live in `Application Support/com.umbra.editor/Models`) and `IDELocalModelsView` (the sheet behind "Manage On-Device Models…"). A model whose chat template does not take tools can be downloaded but not used, and is refused before a request. The first message loads the weights with a visible "Loading…" status. For Ollama the settings load the installed models (`OllamaModelCatalog`), disable those without tool support, ask for `num_ctx = min(cap, the model's maximum)` and send `think` only to models that list it; a model the server says cannot use tools is refused before a request is made.

- **Agent: long sessions** (`IDEAgentController`, `IDEAgentHistory`, `IDEAgentProjectNotes`, `IDEAgentModeText`). Every run ends by saving the conversation through `SessionStore` (`Application Support/com.umbra.editor/Agent`; only `IDEWorkspace` with `isSessionPersistenceEnabled` gets a store, so tests write nothing unless they pass one). The transcript is saved as `IDEAgentPersistedEntry` rows (no live output or approval cards). The latest conversation comes back when the panel first appears or a message is first sent (`restoreLatestIfNeeded`); the panel's clock button opens a searchable list of the project's chats (`IDEAgentHistoryPopover`, fuzzy by title through `IDEAgentHistorySearch`, shared with `/resume `; a row shows the date, the number of messages, and the cost when one was saved; ⏎ opens the best match, a row's menu deletes the chat and its kept originals), New Chat starts one, and Settings ▸ Agent ▸ Clear History deletes the project's. The project root's `AGENTS.md` (else `CLAUDE.md`, `GEMINI.md` or `.cursorrules`; 16 KB; symlinks refused) goes into the system prompt when a session is created. A nested file of those names is appended to the first `read_file`, `edit_file`, `write_file` or `apply_patch` under that folder, once per directory until the next summary. Settings ▸ Agent ▸ "Load instructions from ~/.claude and Umbra's folder" (off unless the user turns it on) also loads `~/.claude/CLAUDE.md` and Umbra's Application Support `AGENTS.md` / `CLAUDE.md`, before the project's so the project wins. `IDEAgentSettings` adds `mode`, `iterationCap`, `maxRunTokens`, `maxRunSeconds`, `maxRunCostCents`, `contextWindowOverride`, `secretFilePatternsText` and `contextWindow`; all are in the session fingerprint, so a change starts a new session that keeps the conversation. The three budgets are off at `0`. A run that reaches one pauses; the next message starts with a fresh allowance. The spend limit uses the price table, and while one is on the table is part of the fingerprint so an edit applies to the next session. Settings ▸ Agent (`IDEPreferencesDomain.agent`) hosts the same `IDEAgentSettingsView` as the panel's settings sheet, with `isFullPane`. In approve-each-edit mode the approval card shows the diff (`IDEAgentDiffView`) with Apply and Reject. Tests: `IDEAgentSessionsTests`.

- **Agent: permissions** (`Example/Umbra/Agent/Permissions/`, `IDEAgentModeText`; AgentKit side: `Packages/AgentKit/CLAUDE.md`). Each chat has its own `PermissionMode` (`IDEAgentConversation.mode`, `setMode`, `cycleMode`): the chip under the message field, or ⇧Tab in it (`IDEAgentModeChip`, `IDEAgentComposerKeyMap`). `IDEAgentSettings.mode` is only the mode new chats start in, and no longer part of the session fingerprint, because a mode change does not need a new session (the session is told with `setMode`; the model gets a note). Rules come from files read at every send, so an edit takes effect at once (`IDEAgentPermissionFiles`): the app's `permissions.json`, `.umbra/settings.json`, `.umbra/settings.local.json` (what "Always allow in this project" writes; a file that is not valid JSON is never overwritten; the first time it is created, Umbra asks to add it to `.gitignore`), and Claude Code's `.claude/settings.json` / `settings.local.json`, read only. Every deny, ask and allow from every source counts. A chat's own rules ("Allow in this chat") last until the conversation is reset or another is loaded. The approval card's "Always…" menu (`IDEAgentApprovalView.alwaysAllowMenu`) offers the rule AgentKit suggests, or "Accept all edits in this chat"; `IDEAgentConversation.approve(callID:shortcut:)` applies it and approves the call. Settings ▸ Agent ▸ Permissions (`IDEAgentPermissionsSection` over `IDEAgentPermissionsModel`) lists every rule by file, adds and removes rules in the files Umbra owns, and checks "would this command run?". `IDEGradleTool` / `IDERunTestsTool` expose `gradle …` as their `permissionSubject`, so `Bash(gradle build:*)` matches them. Tests: `IDEAgentPermissionsTests`, `IDEAgentPermissionFilesTests`, `IDEAgentPermissionsModelTests`, `IDEAgentSessionsTests`.

- **Agent: chat tabs** (`IDEAgentController.conversations`, `IDEAgentTabsBar`, `IDEAgentFileClaims`). A window has several chats, each an `IDEAgentConversation` with its own session, checkpoints, draft, mode and rules, and each can run at the same time. The strip (`IDEAgentTabsBar`, over the shared `IDEChromeTabItem`, which the terminal tabs use too) appears from two chats on: a spinner while one runs, an orange dot while it waits for an approval or an answer (`isAwaitingUser`), a blue dot for a reply that finished in the background (`isUnread`); the context menu renames (stored in `IDEAgentSavedTranscript.customTitle`, so it survives a relaunch), closes, or closes the others; closing a running chat asks first, and the last chat is emptied instead of closed. A tab is named by the user, else by its first message. New Agent Chat ⌥⌘T, Next/Previous ⌥⌘]/⌥⌘[ (View menu and palette; ⌘T belongs to Git Pull or New Window Tab). `newConversation()` opens a tab unless the selected chat is empty; `clear()` empties it in place; `resume(id)` selects the tab that already shows a conversation, else fills an empty selected chat, else opens a tab, and never replaces a chat with content. `selected` is the chat the panel shows; the controller's `entries`/`draft`/`send()` forward to it. Two chats editing one file: a chat claims the files of an edit it is about to make (`IDEAgentClaimsGate`, a `PermissionGate`) until its run ends, and an edit to a file another chat's run holds asks first, naming that chat. The claims live in the window (`fileClaims`); they do not guard commands. `IDEWindowSession` keeps `agentChats` (saved conversation ids), `agentSelectedChat`, `isAgentPanelVisible` (only when docked, since a page over the editor would hide the files being restored) and `agentPanelWidth` (held by `IDEWorkspace.agentPanelWidth`, saved with the other panel widths); `IDEAgentController.restoreTabs` shows each saved conversation as a tab and reads only the selected one, the others when shown or sent to (`pendingLoadID`). `onLayoutChanged` asks the window to save; `withoutLayoutNotifications` keeps a restore from saving a half-restored window. Only one Gradle run at a time exists in a window, so two chats that both run Gradle share it. Tests: `IDEAgentTabsTests`.

- **Agent: commands and skills** (`Example/Umbra/Agent/Commands/`). A message that starts with `/name` and a space or the end is a command (`IDEAgentSlashInvocation`; `/usr/bin is missing` is a sentence, and an unknown name is sent as an ordinary message; a lone unknown `/word` with no arguments also gets a notice saying so, since it is probably a mistyped command). Return in the field calls `IDEAgentController.submit()`: a command runs, anything else is sent. Built-ins (`IDEAgentBuiltInCommand`): `/new` `/clear` `/resume [search]` `/rewind` `/fork` `/compact` `/plan [prompt]` `/mode` `/permissions` `/model` `/history` `/export` `/init` `/cost` `/rename` `/help`, and they work before the first-use disclosure is accepted. `IDEAgentCommandCatalog` adds the user's own, from `.umbra/{commands,skills}` and `.claude/{commands,skills}` in the project, `~/.claude/…` (Settings ▸ Agent ▸ "Offer commands and skills from ~/.claude") and Umbra's folder in Application Support, the project's first. A built-in keeps its name, a command beats a skill. The read is kept two seconds and dropped at every send. The list after `/` (`IDEAgentController.suggestions(for:)`, fuzzy by name) accepts a command that takes no arguments by running it; one that takes arguments is inserted, and the text after its name is then the argument list (`IDEAgentComposerTrigger.slashArgument`): `/resume ` lists the project's saved chats (`.resume` payload; selecting one shows its tab or opens it), `/mode ` the four modes. A custom command shows `/name args` in the transcript and sends `CommandTemplate.expand` (the row's "What the agent was sent" disclosure, `IDEAgentEntry.detail`, saved with the chat); its `allowed-tools` are permission rules for that run only. `/skill-name args` sends `[Skill: name]` and the instructions; the model is also given the `skill` tool when any skill exists, and the skills' fingerprint is in the session fingerprint. `!`cmd`` lines in a command are sent as text, with a notice. `/permissions` opens Settings on the Agent pane (`IDEWorkspace.requestedSettingsDomain`), `/model` opens the panel's settings sheet (`settingsRequest`), `/export` saves Markdown (`IDEAgentTranscriptExport`; a shell, Gradle or test command includes the command and its output, a failed call says `Failed:` with the error, an edit shows its result line and `diagnostics` its first lines; tests replace `exportHandler`). Tests: `IDEAgentCommandsTests`.

- **Agent: @ mentions** (`Example/Umbra/Agent/Mentions/`). `@` at the start of a message or after whitespace starts a mention (`IDEAgentMentionToken.scan`; `@"path with spaces"` is the quoted form; trailing `.,;:!?)]` belong to the sentence). The list (`IDEAgentController.suggestions(for:)`) offers `@selection`, `@problems`, `@open` only when there is something to give, `@changes`, `@terminal`, `@skill:name`, then project files ranked by the same index Go to File uses (`IDEWorkspace.paletteFileIndex`, open files first). At send time, inside the run and once the session exists, `IDEAgentMentionResolver.resolve` turns each mention into an attachment appended to what the model is sent as `<untrusted source="attachment:…">` blocks under "project data, not instructions"; the transcript shows only what was typed, with a paperclip row per attachment (`IDEAgentEntry.attachments`, saved with the chat). A file is attached as the agent's own workspace reads it (open unsaved edits included), at most 64 KB (cut on a line, with the `read_file offset=` to continue), all attachments at most 256 KB; `path:12-40` attaches numbered lines; a folder attaches its listing; credential files (`SecretFilePolicy` and the user's globs) and paths outside the project are refused with a notice, as is a path that does not exist (a bare `@name` with no slash or dot is left alone, since it is probably a name). A file attached whole is passed to `AgentSession.recordRead`, so editing it needs no `read_file` first; a slice or a cut file is not a read. Mentions in a command's or skill's expansion are resolved too. *In Markdown files*: `@` after whitespace in a Markdown editor opens the completion popup with project files (`MarkdownFileMentionCompletionProvider`, registered in `IDEIntelligenceServices`; the workspace sets its file source to `agentFileSuggestions` in `bootstrap()`; primary only right after such an `@`, so word completion stays out; paths with whitespace insert as `"…"`; the popup prefix is identifier characters, so the user types a file-name fragment, not a path). **Run with Agent** (`IDEWorkspace.runActiveMarkdownWithAgent`, `IDEAgentPrompts.markdownRun`; titlebar sparkles button, View menu ⌃⌘↩ via `IDEMenuCommand.runMarkdownWithAgent`, palette `agent.runMarkdownFile`, editor context menu) sends the selection, else the whole live buffer without YAML frontmatter, through `agent.compose(_, send: true)`, so `@refs` in it are attached by the resolver above and the usual rules apply (a run in progress or no consent leaves the text in the composer). Tests: `MarkdownFileMentionTests`. `@terminal` reads the active terminal tab's buffer (`IDETerminalHostView.recentText`), `@changes` runs `git_diff`'s code. Tests: `IDEAgentMentionResolverTests`, `IDEAgentMentionsTests`; AgentKit: `RecordReadTests`.

- **Agent: plan mode and Markdown** (`IDEAgentPlanCard`, `Agent/Markdown/`). In Plan mode (`/plan`, the chip, ⇧Tab) the model can only look, and it ends with `exit_plan_mode` (always in the session's tool list, offered only in plan mode). The plan shows as a card (`IDEAgentPlanCard`, in place of a tool card): the plan rendered as Markdown, and while it waits "Approve · Accept Edits" (⌘↩), "Approve · Manual", "Keep Planning…" (feedback goes to the model) and a button that opens the plan in an untitled editor tab (`IDEAgentHost.agentOpenText`). Approving sets the chat's mode (`IDEAgentConversation.approvePlan`), the card keeps its outcome (`planOutcome`, saved with the chat) and the plan stays readable from the call's arguments; the tab shows the orange dot while it waits. Assistant messages are drawn by `IDEAgentMarkdownView` once complete (plain text while they stream): `IDEAgentMarkdown.parse` finds headings, lists with nesting, quotes, tables (drawn aligned in monospace), rules and fenced code (an unclosed fence runs to the end, so half-streamed text looks right), and inline styling is left to `AttributedString(markdown:)`. A code block has Copy, Insert at the Caret (`agentInsertAtCaret`) and Open in a New Tab. Tests: `IDEAgentMarkdownTests` (also `IDEAgentPlanFlowTests`).

- **Agent: checkpoints on disk** (`IDEAgentCheckpointBlobs`, `CheckpointLog.snapshot/restore`). Revert Run survives a relaunch. Each chat has one `CheckpointLog` for its whole life (so a settings change that starts a new session no longer drops Revert for earlier runs); it writes every original through to `<project folder in Application Support>/Agent/<hash>/blobs/<run id>/<file>` as it is recorded (LZFSE, 0600/0700), keyed by run and path, never content-addressed. The run records without the texts (`RunSnapshot`) are saved with the chat in `IDEAgentSavedTranscript.checkpoints`, and the "N files changed" card is saved (`IDEAgentPersistedEntry` kind `changes`: run, paths, which were created, reverted). Loading a chat puts the runs back into a log and the card back with its originals read from disk, so Show Diff works at once; a card whose originals are gone is not shown, since neither button could work. Revert after a relaunch needs no session and no working provider setup: with no session it reverts through the log and a workspace (`IDEAgentConversation.revert`). The user's later edits are still never overwritten (conflicts as before). Deleting a conversation removes its runs' originals, Clear History removes the project's, and each save prunes the project's oldest runs past 500 MB (`prune(keeping:)`, the chat's own runs spared). Tests: `IDEAgentRevertAfterRelaunchTests`, `IDEAgentCheckpointBlobsTests`; AgentKit: `CheckpointPersistenceTests`.

- **Agent: rewind and fork** (`IDEAgentRewind`, `IDEAgentRewindSheet`, `IDEAgentConversation.rewind/forkState`). Every user message records where it sits in the session's history (`IDEAgentEntry.itemIndex`, the index of its `.user` item; saved with the chat). That is what rewinding cuts before, so it must stay right: dropping provider-specific items (on a settings change or a load) moves the recorded positions with the items (`droppingOpaque`), and a compaction that summarizes (`summarizedItems > 0`) clears every recorded position, since the start of the history was replaced; later messages record fresh ones. `/rewind`, Esc twice in an empty message field, or the arrow on a message you hover opens the sheet (`rewindRequest`): pick a message and **Conversation only** (forget it and what followed; files stay), **Code only** (revert the files the agent changed from that message on, newest run first; the conversation stays and the cards say what happened) or **Code and conversation**; the message goes back into the field. Reverting uses the session if there is one and otherwise the checkpoint log and a workspace, so rewinding works right after a relaunch and needs no working provider. A file you edited since is left as it is and named. The history cut is `AgentSession.rewind(toBeforeItem:)` (read ledger cleared, so the model reads a file again before editing it; checklist rebuilt from what is left), or, with no session yet, the saved items themselves; the result is saved at once. Never while a run is going. **Fork** (`/fork`, the branch arrow on a message, or in the sheet) opens a new tab holding the transcript and history up to before that message (all of it for `/fork`), named "… (fork)" and saved at once; the "files changed" cards are not copied, since their originals belong to the first chat. `IDEAgentController.fork` is async. Tests: `IDEAgentRewindTests`; AgentKit: `RewindTests`.

- **Agent: prompt history** (`IDEAgentPromptHistory`, `IDEAgentPromptRecall`). What a project's chats were sent is remembered (`prompts.jsonl` beside the project's conversations, one JSON string a line, 0600, newest 500, consecutive repeats once; commands too; nothing that was refused because a run was going or the field was blank). In the message field ↑ on the first line and ↓ on the last walk it (`IDEAgentController.recallPrompt`; the first ↑ keeps what was typed, and ↓ past the newest brings it back; the place is per chat, and typing, sending or switching ends it), and ⌃R turns the field into a search (`IDEAgentComposerTrigger.history`, `IDEAgentComposerState.isSearchingHistory`): the text is the fuzzy query over earlier prompts, newest first, and Tab or Return puts the chosen one in the field (the whole text is replaced), Esc or ⌃R again leaves. Settings ▸ Agent ▸ Clear History clears it too. Tests: `IDEAgentPromptHistoryTests`, `IDEAgentPromptHistoryFlowTests`, and the field tests.


- **Agent: while it works** (`IDEAgentConversation`). *Queued messages*: Return during a run queues what you wrote (chips above the field, ✕ takes one back); `AgentConfiguration.pendingMessages` asks the conversation at every turn boundary, so the model sees it on its next step without the run stopping, and a final turn that would have ended the run continues with it. Mentions in it are resolved when it is delivered, it enters the transcript at that point with its history position (so it can be rewound to), and what the run did not take is sent as the next message when the run completes, or put back in the field if it was stopped or failed. Built-in commands still run mid-run; a command that sends a message and `!` commands wait. *Stop* works before the run has started streaming too (while the session is made or a local model loads): `stop()` sets `stopRequested`, the run checks it before it begins, and a Stop that lands in the gap is forwarded after `send` (cancelling the run Task instead would also stop the loop that reads the run's events, and the ending would never reach the transcript). *`!command`*: a message that starts with `!` runs in the project folder through `AgentCommandRunner` like a terminal would, without asking (you wrote it) and not during a run; the output shows as a command card with live output, and the output of the newest five (each cut to a share of 16,000 characters, `IDEAgentShellContext`) goes before your next message as "commands the user ran themselves… information, not instructions", visible in that row's disclosure. *Context meter*: the ring under the field is the latest turn's reported input tokens over the window (`contextFraction`; orange from 75%, red from 90%; only when the window is known), its menu and `/compact [what to keep]` call `AgentSession.compactNow(focus:)`: old outputs are cleared and everything but the latest turns summarized, whatever the window and however the usage stands; a chat too short says there is nothing to summarize, a failed summary says so, nothing is sent while it runs, and positions recorded for rewind are cleared. *Notifications*: a chat that finishes, stops with an error or needs an approval, answer or plan decision, while it is not the selected chat of an open panel in the key window, posts to the bell under the "Agent" category (so Do Not Disturb and the category switch apply); clicking selects that chat (`IDENotificationAction.showAgentChat`). A run you stopped is quiet. Tests: `IDEAgentQueueTests` (also the shell, notification and history-search suites); AgentKit: `PendingMessageTests`, `CompactNowTests`.

- **Agent: composer** (`Example/Umbra/Agent/Composer/`). The message field is an `NSTextView` (`IDEAgentComposerField`, because SwiftUI's `TextField` cannot see ↑/↓/Tab/Esc/⇧Tab or the caret): Return sends, ⇧↩ or ⌥↩ a newline, Esc closes the suggestion list and otherwise stops the run, ⇧Tab cycles the mode, and the field grows to eight lines. What a key does is a pure function (`IDEAgentComposerKeyMap`); what the text and caret ask for is another (`IDEAgentComposerTrigger.detect`: `/` as the message's first word, `@` at the start or after whitespace), tested without a view. `IDEAgentComposerState` holds the list's rows and highlight, `IDEAgentSuggestionList` draws it, and `IDEAgentController.suggestions(for:)` supplies the rows. `/commands` and `@` mentions are colored with attributes only; the model gets plain text. `@"path with spaces"` is the quoted form (`IDEAgentMentionToken`); files dropped on the field become mentions. Tests: `IDEAgentComposerFieldTests` hosts the field in a window.

- **Agent: IDE depth** (`IDEAgentGitTools`, `IDEAgentNavigationTools`, `IDEAgentEntryPoints`, `IDEAgentPrices`). `git_status` / `git_diff` read through `GitRepository` and are offered inside a repository (`IDEAgentGitSource`: paths are project-relative, `SecretFilePolicy` plus the user's globs filter every diff, an untracked `dir/` is expanded with `git ls-files --others --exclude-standard`). `go_to_definition` / `find_usages` take path, 1-based line and the identifier (`IDEAgentSymbolLocator`, whole-word, `occurrence` when ambiguous) and call `IDEAgentJavaNavigating`, implemented by `IDEJavaAgentNavigator` over the window's Java providers; they are offered when `agentJavaNavigator()` returns one (a Gradle project or an open Java file). `IDEAgentHost` gained `agentJavaNavigator()` and `agentLineText(url:line:)`, with defaults, so fake hosts need no change. Entry points: `IDEWorkspace.askAgentAboutSelection` (context menu item from `agentContextMenuItems`, palette command `agent.askAboutSelection`), `fixProblemWithAgent` (Problems row hover button and context menu) and `IDEAgentController.compose(_:send:)`, which fills the composer and focuses it (`composerFocusRequest`) or sends when consent is given and no run is going. The header shows `tokens · ~$cost` from `IDEAgentSettings.cost(of:)` and `IDEAgentPrices` (editable text in Settings ▸ Agent; `IDEAgentSavedTranscript` stores the total with the conversation; nil when any turn was unpriced). Tests that need an editor view call `workspace.bootstrap()` first (it wires the adapter). Tests: `IDEAgentNavigationTests`, `IDEAgentEntryPointsTests`.

- **Agent: checklist and questions.** The controller adds `TodoTool` and `AskUserTool` to every session. `.todosUpdated` fills `IDEAgentController.todos`, shown by `IDEAgentTodoListView` under the header and saved in `IDEAgentSavedTranscript.todos` (restored into the new session when its history no longer holds the `todo` call). `.questionAsked` puts a `UserQuestion` on the `ask_user` card (`IDEAgentQuestionView`: option buttons, a field, Skip); `answer(callID:text:)` replies and `nil` skips. - **Agent: web search** (`IDEAgentWebSearch`, AgentKit `WebSearchTool`). Off unless the Web search toggle is on (Agent Settings, and Settings ▸ Agent) and a Brave Search API key is saved under the Keychain account `api.search.brave.com`, separate from the model key. Both are in the session fingerprint, so a change starts a new session that keeps the conversation. The tool is `web_search`, placed after `show_file` and before the edit tools; it is read-only, so Plan mode keeps it. The query is sent to `api.search.brave.com` and the model gets titles, URLs and short snippets, marked untrusted. Nothing is fetched from those pages. A deny rule `web_search` blocks a call. Tests: `IDEAgentWebSearchTests`.
