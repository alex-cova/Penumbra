# Git client (`Example/Umbra/Git`)

Loaded when working under `Example/Umbra/Git`. Split out of `Example/Umbra/CLAUDE.md`.

- **Git console and refresh policy** (`Example/Umbra/Git/`, plan: `docs/GIT_CLIENT_PLAN.md`). Every git child process Umbra starts goes through `IDEGitSupport.runner`, whose observer feeds `IDEGitCommandStore` (a process-wide, main-actor list of the last 500 commands that changed something or failed; each window reads its own repository's with `records(under:)`). The History bottom tab has a Log | Console switch (`IDEGitConsoleView`). `IDEGitStatusModel` reads `GitRepositoryState` on every refresh (`repositoryState`: HEAD and the merge/rebase/cherry-pick in progress) and reloads the log and the author list only when something called `noteRefsChanged()`: the project watcher saw `refs/**`, `packed-refs`, `HEAD`, `ORIG_HEAD`, `FETCH_HEAD` or an operation file (`IDEProjectWatcher.Batch.gitRefsChanged` / `gitOperationChanged`), the app became active, or a git action finished. A save or a stage refreshes status only. Tests: `IDEGitStatusModelHistoryTests`.

- **Remotes, branches and credentials** (`Example/Umbra/Git/`, plan: `docs/GIT_CLIENT_PLAN.md`). Network commands (`IDEGitStatusModel.runGitAction(network: true)`: fetch, update, push, delete remote branch, push tag) run one at a time with progress (`networkProgress`, `isNetworkBusy`, shown in the Changes tab) and are not cancelled by a local command; they get the askpass environment of the window's session. **Askpass**: `UmbraMain` (the `@main` type; `UmbraApp` is only the scene) runs `IDEGitAskPassClient` instead of the app when `UMBRA_ASKPASS_SOCKET` is set, so Umbra itself is `GIT_ASKPASS` / `SSH_ASKPASS` (`SSH_ASKPASS_REQUIRE=force`). `IDEGitAskPassServer` (one per process, started by the first network command) listens on a Unix socket in a 0700 temp directory, checks a per-launch token and the session id, and routes the prompt to the window's `requestCredential`, which shows `IDEGitCredentialSheet` (secure field for passwords and passphrases, a plain one for user names, Yes/No for ssh host keys; classification by wording in `IDEGitCredentialPromptKind`). Apple git's `osxkeychain` helper still stores HTTPS credentials; nothing is stored by Umbra. Closing the project or dismissing the sheet answers "cancelled" (git fails the command). Background fetch (Settings ▸ Project ▸ Version Control, off at 0) uses batch mode and never prompts. **Sheets**: one `IDEGitSheetQueue` per window (`gitStatus.sheets`), rendered by one `.sheet(item:)` in `IDERootView` through `IDEGitSheetHost`: credential, smart checkout, update, push, text prompt, confirmation, delete merged. **Branch popup** (`IDEGitBranchPopup`, the titlebar branch label): Update Project, Fetch, Push, New Branch, Checkout Tag or Revision, Delete Merged Branches, then local/remote branches (↑/↓ counts, `gone`) and tags with a context menu (Checkout, New Branch from, Compare with current, Show Diff with Working Tree, Rename, Delete). A checkout refused because local files are in the way offers **Smart Checkout** (`preservingLocalChanges`) or Force Checkout (confirmed, tracked files only). **Update Project** (⌘T) asks Merge or Rebase (default from `pull.rebase`, then the last choice; "Don't ask again" in Settings) with autostash; **Push** (⇧⌘K) shows the outgoing commits with their files, remote and branch, set upstream, force-with-lease (refused on protected branches, default `main, master`, globs allowed), tags. **Compare** opens the Compare sub-tab of the History panel (`IDEGitCompareView`): commits on each side and the differing files, each opening `IDEDiffRequest.revisions`. Tests: `IDEGitStatusRemoteTests`, `IDEGitAskPassTests`.

- **Stash** (`Git/IDEGitStatus+Stash.swift`, `IDEGitStashPanel`). The History panel's **Stashes** sub-tab: the list (title, `stash@{n}`, branch, age) beside the selected stash's files; a file opens in the diff viewer against the commit the stash was made on (`IDEDiffRequest.stashFile`; an untracked file has nothing on the left and its content comes from the stash's third parent). Context menu: Apply, Apply and Restore Staged Changes, Pop, New Branch from Stash…, Copy Revision, Drop… (confirmed); Clear All… is confirmed too. Git ▸ Stash Changes… (sheet: message, include untracked, keep staged) and Unstash…, and the Changes ⋯ menu. The list reloads with the log (`noteRefsChanged`). A conflicting apply leaves the markers and keeps the stash. Tests: `IDEGitStatusStashTests`.
- **Merge, rebase and conflicts** (`Git/IDEGitStatus+Operations.swift`, `Git/IDEGitOperationBanner.swift`, `Git/Merge/`). The operation in progress comes from `repositoryState.operation` (disk read on every refresh), so a merge started in a terminal shows too. The **banner** at the top of Changes (`IDEGitOperationPresentation` names it: "Merging feature into main", "Rebasing topic onto abc1234 · 2 of 5") has Resolve… (the first conflict in the merge tool), Continue (a merge asks for its message first; disabled while files conflict), Skip (rebase, cherry-pick, revert) and Abort (confirmed); the titlebar shows a badge beside the branch. The **Conflicts** section of the Changes list takes conflicted files out of Staged/Changes (`AA`, `DD`, `AU`… count, not only `UU`): double-click or Merge… opens the merge tool, Accept Yours / Accept Theirs resolve without opening. The branch popup's Merge into / Rebase onto start them; a merge git refuses for local changes offers Stash and Continue (`preservingLocalChanges`), a rebase uses `--autostash`. **Merge tool**: a `.diff`-kind tab (so tab handling is the diff tab's) whose `IDEMergeSession` lives in `IDEWorkspace.mergeSessions`; the pane host's `IDEDiffViewerView` shows `IDEMergeViewerView` instead of a comparison (`isMerging`, `editingTextView` is the result). Three Penumbra `TextView`s: left (stage 2), editable result, right (stage 3). The result starts as the base with every non-conflicting change applied (`IDEMergeComputer`, a pure diff3 over `IDEDiffComputer.lineChunks` that groups touching changes as git does and is checked against `git merge-file` on random edits); the left is diffed against the result and the result against the right (as IntelliJ's viewer does), so a chunk stays open until the result matches that side or the user edits it, and a conflict is a left chunk overlapping a right chunk in the result. Chevrons (⌥ appends) move a side's lines into the result as one undo step; the toolbar has Previous/Next change (⇧F7/F7), Apply Non-Conflicting from Left/Right/All, Accept Left/Right for the whole file and Apply (⌘↩: writes the file, `git add`, closes the tab, reloads clean editors). A file with a deleted side shows a message pointing at Accept Yours/Theirs. Not done: ignoring a single change (×), a notice in an editor showing conflict markers, aligned (padded) panes. Tests: `IDEMergeComputerTests`, `IDEGitStatusOperationsTests`.

- **Log actions** (`Git/IDEGitStatus+History.swift`, the commit row's context menu in `IDESourceControlPanel`). ⌘/⇧-click selects several commits (`selectedCommitHashes`; an action on a row outside the selection acts on that row alone, oldest first). The menu: Copy Revision, Checkout Revision, Compare with <branch> (the Compare tab), Cherry-Pick, Revert, New Branch / New Tag Here, Reset Current Branch to Here… (sheet: soft / mixed / hard / keep, with a warning when the commits are on a remote), Undo Commit (HEAD), Edit Commit Message… (HEAD is amended, an older commit is reworded through a plan), Squash N Commits…, Fixup Into Parent, Drop…, Interactively Rebase from Here… (`IDEGitRebaseSheet`: a list newest first, drag to reorder, an action per row, a message field for reword and for the head of a squash group), Push All up to Here…, Go to Parent/Child. A rewrite names the remote branches that already hold the commits. Stops (conflicts, an `edit` step) are reported, not failed, and the banner takes over. The log has a date menu (24 h / 7 d / 30 d), a folder filter (`historyPathFilter`), Load More (`historyLimit` +300), and under a selected commit "In branches: …". **Line history**: the editor's context menu ▸ Show History for Selection (`IDEWorkspace.showSelectionHistory`; the caret's line with no selection) replaces the log with the commits that changed those lines and their patch (`log -L`). Not supported: rewriting from the root commit. Tests: `IDEGitStatusHistoryActionsTests`.

- **Committing** (`Git/IDEGitStatus+Commit.swift`, `Git/IDEGitCommitChecks.swift`). The Changes tab's checklist menu: Amend Last Commit (prefills the last message; one-shot), Sign Off, Skip Hooks, Recent Messages (20 per repository, `IDEGitRecentMessages`), and the `fixup!` / `squash!` / `amend!` prefixes over the last ten commits; **Commit and Push…** (⌥⌘K) commits and then opens the push dialog. The repository's `commit.template` fills an empty message once (its `#` lines removed, since `-m` is used). Before a commit `IDEGitCommitChecks.evaluate` (pure, over `IDEGitCommitFacts`) looks for unresolved conflicts and a missing `user.name`/`user.email` (**blocking**), leftover conflict markers, a detached HEAD (not for an amend), files over 10 MB, and CRLF in the index when `core.autocrlf` is not `true`/`input` (**warnings**). Findings open `IDEGitCommitChecksSheet`: Commit Anyway (warnings only), Save author for this repository and commit, Convert to LF, New Branch…. Commit errors from a hook or from signing show git's message in the status line and the Git console. A commit that signs asks for passphrases through the askpass helper (`credentials: true`, no exclusive network slot). Tests: `IDEGitCommitChecksUnitTests`, `IDEGitCommitFlowTests`.
- **Web links, marker actions, palette** (`Git/IDEGitHostingURL.swift`, `IDEGitStatus+Web.swift`, `IDEWorkspace+ChangeActions.swift`, `IDEWorkspace+GitPalette.swift`). `IDEGitHostingURL` (pure) turns a remote URL (`git@host:o/r.git`, `ssh://…:22/…`, `https://tok@host/…`) into the page of a commit, a branch, or a file with lines, for GitHub, GitLab (subgroups, `/-/` paths), Bitbucket and Gitea/Forgejo/Codeberg; unknown hosts are treated as GitHub-style. The remote is the current branch's upstream's, else `origin`, else the first; a file links to the tracked branch, or the commit when it has none. Entry points: the editor's context menu (Open on Web, Copy Web Link, with the selected lines), Git menu, the Explorer's file menu, the Log's commit menu, the branch popup. **Rollback Change at Caret** (editor menu, Git menu; `IDEChangeMarkerPresentation.rollback`, pure) puts the changed block under the caret back to `HEAD` as one undo step; the stripe itself still takes no clicks, because the gutter has no hit target for it. The palette's Symbols results include matching branches, tags (Check out) and commits (Show in the log) once two characters are typed.
- **Clone, create, ignore** (`Git/IDEGitCloneModel.swift`, `IDEGitCloneSheet`, `IDEWorkspace+GitSetup.swift`). File ▸ Clone Repository… (also the Welcome page and the palette's File commands) opens a sheet with the address (prefilled from the clipboard when it holds a repository address), the parent folder, the folder name (follows the address until edited, refuses `/` and a leading `.`), submodules, Test (`ls-remote`) and live progress; Cancel stops git and removes the partial folder; a credential prompt interrupts the sheet and returns to it (`IDEGitSheetQueue.present` puts credentials first), and the model lives outside the view so nothing typed is lost. A finished clone opens through `IDEWindowRegistry.open(urls:origin:)`. Git ▸ Create Git Repository… (a project that is not one yet) runs `git init -b main` after a confirmation. The Explorer's **Add to .gitignore** (the nearest `.gitignore` above the file, else the root's) and **Add to .git/info/exclude** (shown for untracked files and any folder that is not ignored) write an anchored, escaped pattern and refresh status. Ignore files have a language ("Ignore File": `.gitignore`, `.dockerignore`, `.npmignore`, `.eslintignore`, `.prettierignore`, `.ignore`, `.slugignore`, `.gcloudignore`) from `Sources/TreeSitterGitIgnore` (shunsambongi/tree-sitter-gitignore `src/`, MIT, noted in `THIRD_PARTY_NOTICES.md`) with Penumbra's own `highlights.scm`; the grammar wants a final newline on each line, so an unterminated last line is not coloured. Tests: `IDEGitCloneAndSetupTests`, `GitIgnoreLanguageTests`, `IDEGitHostingURLTests`.
