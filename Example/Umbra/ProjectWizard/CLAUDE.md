# New Project wizard and Xcode projects (`Example/Umbra/ProjectWizard`)

Loaded when working under `Example/Umbra/ProjectWizard`. Split out of `Example/Umbra/CLAUDE.md`.

- **New Project wizard and Xcode projects** (`Example/Umbra/ProjectWizard/`, `Projects/IDEXcodeProject*.swift`). File ▸ New Project…, the welcome screen's row and the palette command show `IDENewProjectSheet` (`IDEWorkspace.isNewProjectSheetPresented`, `showNewProject()`). The sheet reads `IDEProjectTemplates.all`, a list of `IDEProjectTemplate` values: pure, they turn `IDENewProjectOptions` into `IDEGeneratedFile`s (relative path plus bytes) and name the file to open (`primaryFile`), so the preview and the tests need no disk. `IDEProjectWriter.create` writes into a hidden staging folder and renames it into place, so a failure leaves nothing and an existing folder is never touched. A template declares which inputs it uses (`fields`), and a family shows as a sheet section only when it has a template, so adding Gradle templates (family `.java`) is a conformance plus an entry in `IDEProjectTemplates.all`, with no change to the sheet. Swift ships four: `IDEXcodeProjectTemplates` (macOS App, Command Line Tool: an `XCSchema.Project` built by `IDEXcodeProjectBuilder` and written with Apple's XcodeProjectFormat as `<Name>.xcodeproj/project.xcproj`, one file-system-synchronized folder per target so adding files never edits the project; object IDs are hashed from the name, so the output is reproducible; per-configuration settings are spelled `KEY[config=Debug]`) and `IDESwiftPackageTemplates` (executable and library packages with a Swift Testing target). After Create the folder goes through `IDEWindowRegistry.open(urls:origin:)` like any other, and `IDENewProjectOpenRequests` carries "open this file once the folder is a project" to `openProjectFolder`, because which window gets the folder (this one, a replaced one, a new one) is decided by the router. The last template, organization identifier and location are kept in `UserDefaults` (`IDENewProjectDefaults`); the location is used only while it is still writable, so a sandboxed build asks again instead of writing somewhere it was never granted. `IDEXcodeProjectSystem` is registered after SwiftPM and recognizes a `*.xcodeproj` directly in the open folder (the one named like the folder, else the first by name). Syncing reads `project.xcproj` through XcodeProjectFormat or `project.pbxproj` as an ASCII property list (`IDEXcodeProjectModel`), so it needs no trust and runs nothing; building runs `xcodebuild -project … -target <name>` (or `-alltargets`) in the project's `Debug` configuration through SubprocessKit after the user trusts the folder (`xcode-trust.json`, its own file, since build phases run scripts). Compiler output goes through `SwiftBuildOutputParser` to Problems under `IDEProblemsStore.xcodeBuildSource`. The project's definition file is compared by bytes like `Package.swift` for the reload banner. Not done: running or debugging the built product, schemes and test plans, and creating a git repository for a new project (GitIntelligence has no `init`). Tests: `IDEProjectTemplateTests` (set `UMBRA_TEMPLATE_SAMPLES=<dir>` to also write one project per template for `xcodebuild` / `swift build`), `IDEXcodeProjectSystemTests`.
