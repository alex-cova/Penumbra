# Saving (`Example/Umbra/Saving`)

Loaded when working under `Example/Umbra/Saving`. Follows IntelliJ's "Save and revert changes" page. Settings ▸ Saving is `IDEPreferencesSavingPane`; every setting is in the preferences snapshot (an older file decodes to the defaults).

- **One save path.** `IDEWorkspace.saveDocument(_:reason:)` (`IDEWorkspace+Saving.swift`) writes a document of any kind: ⌘S, Save All, autosave, the agent's buffers, saves before a run or a git operation, a tab closing. `write(_:to:reason:)` is its Save As half. Never call `document.save` from anywhere else: the conflict check, the actions on save and the follow-up (Local History, git status, blame, recents, language services) live there, once. A document is found *live* (`livePane(for:)`: some host's `loadedDocumentID` is its id) or it is a background tab, written from `pendingState`; a background tab runs no actions on save because they need an editor.
- **`IDESaveReason`** says what a save may do. Only `explicit` and `saveAll` are interactive (they may show the overwrite prompt), and only `explicit` shows a save panel (Save All lists untitled buffers instead). A save made on someone's behalf (`agent`, `autosave*`, `beforeRun`, `beforeGit`, `closingTab`, `closingWindow`, `quitting`) never asks: a file that changed on disk returns `.conflict` and raises the banner (`confirmOverwriteIfDiskChanged(interactive: false)`). `runsSaveActions` is false for `agent` (its edits stay as written) and for `closingWindow` / `quitting` (the way out must be quick and must not change text). `buildProjectOnSave` follows only `explicit` and `saveAll`: an autosave every idle period must not start a Gradle build.
- **Save All** (`saveAll`, File ▸ Save All, `file.saveAll` in the palette): once per document even when several panes show it; returns an `IDESaveAllReport` (saved, untitled, conflicts, failures). ⌥⌘S in the Sublime and Default keymaps, ⌘S in IntelliJ's (where Save has no key). Reload from Disk and Reload All from Disk (`reloadAllFromDisk`: a clean tab reloads whatever the External Changes policy, a dirty one gets the banner) are in the same menu.
- **Autosave** (`IDEAutosaveController`, `autosaveAll`). `noteEdit()` runs for every keystroke and is a counter bump; one sleeping task checks the counter after the idle time, saves when nothing was typed, and goes quiet until the next edit. `canAutosaveNow` waits while an input method composes, a snippet is being filled in, or a sheet or alert is up. Focus loss: `IDEWindowRegistry` observes `didResignActive` once and every window with unsaved buffers saves; the terminal view taking the keyboard (`IDETerminalHostView.onFocus`, watched through the window's `firstResponder`) does the same. A failed autosave is reported once per file until it saves again.
- **Before something reads the files.** `saveAllBeforeRun()` runs ahead of every launch: `IDERunSessions.beforeLaunch`, `IDEProjectEnvironment.prepareToRun` (awaited by the Gradle, SwiftPM, Xcode and npm systems before a task starts) and `debugLaunch` / the JS debug launch (`afterSavingUnsaved`, which runs the action at once when nothing is unsaved). A file that cannot be written never stops the run; it is named in a notification. Git: `IDEGitStatusModel.afterSaving(before:)` saves the repository's unsaved editors (`saveUnsavedEditors`, reason `beforeGit`) and then runs the operation; a file that cannot be saved stops it ("Couldn't save X before pulling."). Commit does not wait: it commits the index, which a save does not change.
- **Closing.** The user-facing closes (`requestCloseTab` and friends, from the tab bar and ⌘W) save first (`saveForClosing`) and ask, through `closePromptResolver`, only about what cannot be saved (an untitled buffer: Save…, Don't Save, Cancel; a file that changed on disk or failed to write: Close Anyway, Cancel). The programmatic `closeTab`/`closeDocument` never save: closing a tab because its file was deleted, or a merge tab applying itself, must not write a file. Window close, Close Folder and Quit save every document with `closingWindow` / `quitting` and ask once about what is left (`confirmCloseWindow`, `IDEWindowRegistry.confirmQuit`, both async: `IDEWindowCloseGuard` refuses the first `windowShouldClose` and closes again, `applicationShouldTerminate` returns `terminateLater`).
- **Actions on Save** (`IDEWorkspace+SaveActions.swift`, pure parts in `IDESaveActions.swift`). In order, each reading the buffer as it is then and dropped when the buffer changed while it was computed: code cleanup (Java, the active inspection profile's quick fixes through `JavaBatchFixer`), optimize imports (any language whose code actions offer `source.organizeImports`; the old Java-only `javaOptimizeImportsOnSave` key is the setting), reformat (`EditorIntelligenceController.formatDocumentForSave` / `formatRangesForSave`, 2 s limit, whole file or only the lines that differ from `HEAD`, from the file on disk outside a repository), strip trailing spaces (all lines or modified lines; the caret's lines kept; never in Markdown or diff) and a final line break. The whitespace steps are one `TextEditApplicator.apply(replacements:in:)`, so they are one undo step and the carets follow. Changed rows come from `IDEDiffComputer.lineChunks` (`IDESaveActions.changedRows`).
- **Mark Modified** (`IDEPreferences.markModifiedTabs`): the tab dot, the breadcrumb dot, `NSWindow.isDocumentEdited` and the Explorer's dot (`IDEWorkspace.unsavedPaths`, refreshed by `updateUnsavedMarkers()` when a dirty flag flips and on every presentation refresh).
- Tests: `IDESaveAllTests`, `IDESaveBeforeTests`, `IDEAutosaveTests`, `IDESaveActionsTests`, `IDEMenuShortcutsTests`.
