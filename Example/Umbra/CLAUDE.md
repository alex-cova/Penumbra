# Umbra (`Example/Umbra`)

Loaded when working under `Example/Umbra`. Moved out of the root CLAUDE.md.

- **`Umbra`** (`Example/Umbra`) — the macOS editor app shipped with this repo, intended as a **Sublime Text alternative**: lightweight, fast editing with project folders, split panes, symbol-aware navigation, session restore, a Problems panel (⌘⇧M; `IDEProblemsStore`/`IDEProblemsPanel`, a bottom-panel tab selected through `IDEBottomPanelTab`), and Java completion with Gradle module and dependency sync, hover with Javadoc, go to implementation, quick fixes, and saved run configurations (Java menu: Run Last Configuration ⌃⌥R, Edit Run Configuration…, Reformat Code ⌥⌘L, Optimize Imports, Show Context Actions ⌥↩; an "Optimize Imports on Save" preference, off by default). Build Project runs through the Gradle runner (asking for trust first) so its compiler errors land in the Problems panel (Sublime keymap by default). Find Usages results go to a Usages bottom-panel tab (`IDEUsagesPanel`, `IDEBottomPanelTab.usages`); Rename… (⇧F6 in the IntelliJ keymap) prompts for a name, shows a preview sheet (`IDERenamePreviewSheet`) and applies through `IDEWorkspaceEditApplier` (live buffers via `TextEditApplicator`, closed files written atomically inside the project folder). Finished Gradle syncs/builds and git actions are posted to `IDENotificationCenter` (`Example/Umbra/IDENotifications.swift`; the titlebar bell opens `IDENotificationPanel`, a toast announces each one — errors stay until dismissed — and live sync/indexing progress stays a separate `IDEStatusToast` card; Do Not Disturb and per-category switches persist in `UserDefaults`; `IDEWorkspace.notifications` / `notifyGradleSync` / `notifyGradleTasks` are the posting sites). Every split in the app (sidebars, structure and Gradle panels, editor over terminal, editor panes, list/detail panels) is a `SplitPanes` (`Example/Umbra/SplitView/`, vendored stevengharris/SplitView via Hextech; Umbra-specific edits in its `README.md`) — don't add `HSplitView`/`NSSplitView` or hand-rolled drag handles. The left sidebar is one card with a tab bar (`IDELeftSidebar`, `IDESidebarTab`: Explorer, Structure, Changes, Breakpoints; the selected tab shows its title, the others are icons; × in a tab's context menu closes it and the + menu reopens it; `IDEWorkspace.activeSidebarTab` / `showSidebarTab` / `toggleSidebarTab`, persisted in `IDEWindowSession.sidebarTab`/`closedSidebarTabs`). Changes is `IDEChangesPanel` (branch, commit, staged/unstaged files, diff preview); the bottom panel's git tab is now History only (`IDESourceControlPanel`). Breakpoints is `IDEBreakpointsPanel`, fed by `IDEWorkspace.breakpoints`, a mirror of `JavaBreakpointStore` refreshed after every change; a disabled breakpoint stays listed and draws hollow in the gutter. Built on `Penumbra`, `EditorIntelligence`, and `JavaIntelligence`.

- **HTTP client** — `.http` parsing and sending live in the Umbra target (`Example/Umbra/HTTP/`: `HTTPRequestParser`, `HTTPClient`), called from `IDEHTTPSupport`. There is no `HTTPClient` library, and JavaIntelligence does not depend on it.

**Umbra** (`swift run Umbra`, `Scripts/build-app.sh`) is the Sublime Text–style editor product; `Example/Umbra` is its SPM executable target and source tree (app shell, views, `IDEWorkspace`, and `UmbraApp.swift`/`@main`). `Example/Umbra.xcodeproj` is a thin, separately maintained Xcode app project that compiles the same source files directly as a native app target — needed because a SwiftPM executable target can't host SwiftUI Previews (`ENABLE_DEBUG_DYLIB`); it's a dev convenience for Previews/Run/Debug only and isn't used for release builds. See `Example/README.md` for details.

**Windows.** Every window owns its own `IDEWorkspace` (`IDEWindowScene` in `UmbraApp.swift`); the menu bar (`IDEAppCommands`) acts on the focused window's workspace through `focusedSceneValue(\.ideWorkspace)`, and `IDEWindowRegistry` finds workspaces for the app delegate (Dock/Finder opens). Use `workspace.window`, never `NSApp.keyWindow`, for sheets and first-responder changes. Windows share one tabbing identifier so AppKit can merge them into native tabs. Persistence is split (`IDESessionStore.swift`): `IDEAppState` owns the recents and preferences snapshot (`app.json`) for all windows, and `last-window.json` (`IDEWindowSession`) holds the layout of the window `IDEWindowRegistry.sessionWindow` names (the most recently key one, skipping blank windows opened next to others). Only a window opened with no other open restores it. The pre-split `session.json` is migrated once and left alone. Opening a folder or file goes through `IDEWindowRegistry.open(urls:origin:)` and the pure `IDEOpenRouter`: a folder that is already open focuses its window, an empty window takes it, a window with a project asks "New Window / Replace" (the `Open folders in` setting can skip the question), and Dock/Finder opens get a new window; a file goes to the window whose project contains it. Don't call `applyProjectRoot` for a user-facing open; use `openProjectFolder` / `replaceProject`. SwiftUI must not open windows for external events itself (see the comment on the scene in `UmbraApp.swift`). Plan and status: `docs/PER_WINDOW_PROJECTS_PLAN.md`.
