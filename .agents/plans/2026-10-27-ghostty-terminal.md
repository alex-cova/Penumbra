## Goal

Replace SwiftTerm (`LocalProcessTerminalView` in the Umbra app) with Ghostty's `libghostty-vt` XCFramework from [example/swift-vt-xcframework](https://github.com/ghostty-org/ghostty/tree/main/example/swift-vt-xcframework), keeping today's terminal-panel behavior intact.

This is **not** a view swap. The example proves `libghostty-vt` is a VT parser/formatter only: `ghostty_terminal_new` → `ghostty_terminal_vt_write` → `ghostty_formatter_terminal_new` (plain-text format, `ghostty_free` on the result). It ships no `NSView`, no PTY/process spawning, no rendering, no input encoding, and no title/CWD/exit callbacks. Umbra must therefore grow three new pieces — a PTY process, a grid renderer, and an input/OSC layer — before SwiftTerm can be deleted. Budget and sequence the work accordingly; do not start by deleting the SwiftTerm dependency.

## Contract to preserve

Everything below is current behavior in [IDETerminalPanel.swift](/Users/alex/Developer/Penumbra/Umbra/Sources/Umbra/Panels/IDETerminalPanel.swift); the rewrite is done when each line has a Ghostty-backed equivalent or an explicit, recorded decision to drop it.

| Area | Current behavior (SwiftTerm) | Replacement must provide |
|---|---|---|
| Spawn | `startProcess(executable:args:environment:execName:currentDirectory:)`; login `argv[0]` (`-zsh`) via `IDETerminalShell`; shell resolved with `getpwuid_r`, `$SHELL` fallback, `/bin/zsh` last resort | Same resolution + exec name; PTY as controlling terminal; `TERM`/`COLORTERM` set explicitly; cwd honored |
| Lifecycle | `process.running` / `process.shellPid`; `restartProcess()` and `terminateProcess()` do `terminate()` then `kill(pid, SIGHUP)` because interactive shells ignore SIGTERM; `handleProcessTerminated()` auto-restarts after 0.15 s; `isShutDown` blocks resurrection during window teardown | Identical signal semantics and guards in `GhosttyPtyProcess`; exit delivered as a callback, never polled on the main thread |
| Start gating | Shell starts only when active, not shut down, not mirroring, and `bounds > 1×1`; lazy start from `layout()` | Keep the gating in the host view; the backend stays start-once idempotent |
| Output | PTY bytes → terminal; mirror tabs use `feed(text:)` with no process | `vt_write` on the backend's serial queue; mirror path feeds the parser without spawning |
| Input | Full keyboard handling, `optionAsMetaKey = true`, `send(txt:)` for Ctrl-L (`\u{0C}`) | Key→escape-sequence encoding (incl. Option-as-Meta, function keys, bracketed paste, focus in/out if enabled by the app) implemented in Umbra or via libghostty-vt if its header exposes an encoder (Gate G0) |
| Screen ops | `clearScreen()` feeds `ESC[H ESC[2J ESC[3J` then Ctrl-L; ⌘K in `performKeyEquivalent` only when the terminal is first responder | Byte-identical sequences through the new view; ⌘K stays in the host view |
| Text out | `recentText(lines:)` = `getTerminal().getBufferAsData()`, trailing blank lines trimmed, last *N* lines | Plain-text formatter output with the same trim/tail rule; verify scrollback is included (Gate G0) |
| Callbacks | Delegate (off-main, hopped via `Task { @MainActor }`): `sizeChanged`, `setTerminalTitle`, `hostCurrentDirectoryUpdate` (OSC 7), `processTerminated` | Title/CWD intercepted from OSC 0/1/2 and OSC 7 in the byte stream (or queried from libghostty-vt if it stores them — Gate G0); all callbacks land on `@MainActor` |
| Appearance | `nativeBackgroundColor`/`nativeForegroundColor`/`caretColor` from `IDEAppearance.NSToken`, `setCursorStyle(.steadyBar)`, font via `IDEEditorFonts.nsFont`, left inset `Spacing.sm`, colors repainted on scheme change | Renderer reads the same tokens/font; cursor style, blink policy and inset preserved |
| Focus | `onFocus` via `window.firstResponder` KVO (SwiftTerm's `becomeFirstResponder` is not overridable); `scheduleFocus`/`pendingFocus` through layout | Unchanged mechanism — it watches the window, not the terminal view class |
| Registry | `IDEWorkspace.registerTerminalHost` stores hosts weakly; `terminateTerminals()` ends shells on window close; `activeTerminalHost()` (first `isShownActive`) backs `agentTerminalTail` | Unchanged; new view must not self-retain (retention guard test) |

## Approach

Keep `IDETerminalHostView` / `IDETerminalPanel` as the SwiftUI boundary and swap only what sits behind the host view, in three independently testable layers, all inside the Umbra target (new folder `Umbra/Sources/Umbra/Terminal/`; the Xcode project's synchronized group picks the files up automatically):

1. **`GhosttyVtTerminal`** — a small Swift wrapper over the C API owning one `GhosttyTerminal`: `write(_ bytes:)`, `resize(cols:rows:)`, plain-text snapshot for `recentText`, and whatever cell/cursor reads Gate G0 confirms. No AppKit, no process. Unit-testable headlessly.
2. **`GhosttyPtyProcess`** — owns the PTY master fd, `shellPid`, `running`; `start(executable:execName:cwd:environment:)`, `terminate()` with the terminate-then-SIGHUP semantics above, `setWindowSize(cols:rows:)` (`ioctl(TIOCSWINSZ)` + `SIGWINCH`), and output/exit callbacks delivered from a dedicated read queue. Interactive-shell correctness (job control, `isatty`) is this layer's contract.
3. **`GhosttyTerminalView: NSView`** — renders the grid with CoreText (visible rows only), handles keyboard/mouse/selection/paste per the parity checklist, and exposes only what the host view needs: `startProcess`, `feed`, `send`, `recentText`, appearance setters, and title/CWD/exit callbacks.

Threading: PTY reads and `vt_write` happen on one serial background queue per terminal (the C terminal is assumed not thread-safe; confirm in G0); rendering snapshots are pulled on the main thread, coalesced per display frame — never one redraw per read chunk. Rendering and snapshot cost must be O(visible rows), matching the spirit of [PERFORMANCE_RULES.md](/Users/alex/Developer/Penumbra/docs/PERFORMANCE_RULES.md): a `yes`-flood or a 100 MB paste must not peg the main thread or grow memory with scrollback beyond the terminal's configured limit.

Land it behind the existing host API so SwiftTerm and Ghostty can coexist during development: the host view picks its child view from one internal switch, defaulting to SwiftTerm until Step 5 flips it and Step 6 deletes SwiftTerm. No tab/session/workspace code changes at any step.

## Risks / Open Questions

- **Biggest risk (unchanged):** `libghostty-vt` is parser-only, so PTY, rendering, input encoding and OSC handling are new code — most of the cost, and fidelity (Option-as-Meta, cursor style, ligatures off) must be re-proven. Gate G0 exists precisely to fail cheap here. Fallback if G0 fails: keep SwiftTerm (optionally with Ghostty as parser behind the same host API — only worth it if the parser itself is the goal).
- **Distribution:** a path `binaryTarget` like the example's breaks fresh checkouts and CI unless the XCFramework is checked in or built by script (G1). A checked-in binary also needs a documented update procedure (Ghostty SHA + Zig version) or it will silently fossilize.
- **Signing/notarization:** a Zig-built XCFramework inside a Hardened-Runtime app needs its signing story proven in Step 1 (ad-hoc-signed or unsigned static archives behave differently); discover this in the spike, not at release time.
- **Scope guard:** root `Package.swift` libraries stay Ghostty-free by construction; this change is Umbra-target-only. Extending `SubprocessKit` (G2 alternative) would break that guard and needs explicit sign-off.
- **Parity slices deferred past Step 6 (known gaps, not silent):** IME/marked text, VoiceOver/accessibility, file-path drag-and-drop, and the right-click context menu are not implemented in `GhosttyTerminalView` (wheel-when-untracked and scrollback viewing + scrollbar are done). The old SwiftTerm view provided these; until they land, CJK/IME input, screen-reader use, dropping paths, and the menu are regressions versus SwiftTerm. Tracked for post-Step-6 work.
